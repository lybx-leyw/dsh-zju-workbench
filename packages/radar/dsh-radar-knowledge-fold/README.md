## 为什么可能根本不该有这个包（评审第一问）

现状 `search()` 的 JSDoc 已经**如实**写了：「就是 `String.prototype.includes` 的子串匹配
（大小写敏感、不切词、不算相关度）」。所以「大小写敏感」目前是**已被声明的行为**，不是 bug。
真正值得裁的是：

- 若产品认为「检索词应宽容」→ 直接改 `service.js:282` 一行，成本 3 个字，**不需要新包**；
- 若产品认为「字面检索就该字面」→ **本包废弃**，只补一句文档。

因此本骨架的定位是**给评审一把尺**，不是一件待安装的零件。
