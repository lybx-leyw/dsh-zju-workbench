## 为什么是「强化」，不是「重复」

今天页已经会画课表了。缺的不是「再画一遍课表」，而是**同一个节次上的另一个数字**：

| 问法 | 现有实现 | 位置 |
| --- | --- | --- |
| 今天还有几节 | `dsh-zhiyun-page-today/src/agenda.js` → `projectAgenda()` | 今天页「今天」段 |
| 下一节几点 | `upcoming[0].startMs` | 今天页「下一节」卡 |
| **这门课还能缺几次** | **无** | ← 本包，同一张卡上加一行 |
| **迟到两次算不算缺勤** | **无** | ← 本包，决定上一行怎么算 |

**同一个面板**：不注册新页面、不注册 slot，就是已存在的「下一节」卡片多一行。
**功能相似正交**：现有维度是「时间」，本包补的是「余量」。

## 判据③打了折（评审时请先看这一段）

skill 要求强化式集成满足「底层多调了更优质实现」。对本包，这条**只部分成立**：

| 判据 | 结论 |
| --- | --- |
| ① 仍是同一个面板 | ✔ 不新增页面 / slot，落点是今天页已有的「下一节」卡 |
| ② 功能仍相似正交 | ✔ 时间 vs 余量，不同维度，不重复画课表 |
| ③ 更优的底层实现 | **△ 只借口径，不借实现** |

候选源 [`khalidhasan11/campuskit`](https://github.com/khalidhasan11/campuskit)（MIT）值得借的是**数据模型**：

- `Late` **计入**出勤（分子 +1，分母 +1）；
- `Excused`（请假）**剔出百分比基数**（分子分母都不动）—— 这条本仓完全没有对应概念；
- 每门课带自己的 `requiredPercentage`，默认 80%，**不是全局常数**。

但它的**数值实现有缺陷**，实测（把 `src/utils/dateAndMath.ts` 的 `computeAttendanceMetrics`
原样用 Python 复刻、对 `A∈[0,60] × T∈[A,80] × p∈{50,60,75,80,85,90,95,99,100}`
共 27,990 个用例与线性扫描真值逐一比对）：

| 缺陷 | 表现 | 用例 |
| --- | --- | --- |
| `safeMisses` 可能是**小数** | `A=31, T=40, p=75` → `1.3333…`；`A=41,T=50` → `4.6666…` | 全部「满足阈值」且 `A/T > p` 的用例 |
| 恢复次数用除法估初值再修正 | `A=98,T=100,p=99` → `100`，真值 `100`（同值但靠 while 兜住）；换个形状就偏 | 全部「未满足」用例依赖 while 修正 |

所以本包的口径是：**借字段名与业务语义，数值一律用整数重算**（见 `src/index.js`
的 `meetsRequirement()`：`attended * 10000 >= p * total`，`p` 是阈值的 100 倍整数）。
**不摘它的任何代码**，只记公式与字段名（见 `ATTRIBUTION.md`）。

## 不做什么

- **不做签到**、不做代点名、不做「自动到课」。`source-xxt` 已把这条写成产品口径，
  本包不越界；出勤率再低，也轮不到一个工作台替用户去点。
- **不把「还能缺几次」当承诺**。阈值可能中途变、记录可能滞后，文案必须带口径与截止日期。
- **不 vendor 上游**。campuskit 是 Capacitor + React 的完整 App（990 KB），
  与本仓一个页面都不共享，整包引用没有意义。
