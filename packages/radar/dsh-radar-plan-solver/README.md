## 一句话

给「规划」页补一层**硬约束可满足性**：当天卡片排不下时，告诉用户**是哪几条规则互斥**，

## 为什么现在才做它：判据③在这里才成立

在册的排课类候选（`tongge-schedule` / `schedule-gap` / `deadline-budget` 等）都停留在
「启发式塞一塞」。真正的缺口不是「再塞一次」，而是**「塞不下时说不清为什么」** ——
这需要一个 ILP 求解器，而不是又一个贪心。

## 需要人工拍板的四件事

1. **值不值一个 ILP 依赖？** `yalps` unpacked 240 KB（含 `heap`）。若产品只想要
   「别丢卡片」这一条，改成「按优先级排序 + 溢出区」可能更划算 —— 那样本包应驳回。
2. **冲突定位用「逐条移除复解」还是「最小冲突集」？** 前者慢但实现简单，后者要额外算法。
   建议先做前者，加 `maxRules` 上限。
3. **变量爆炸**：一天 40 卡 × 48 个 15 分钟槽 = 1920 变量。建议阈值 2000，
   超了就 `status: 'skipped'` 退回启发式 —— **不许**让求解器卡住 UI。
4. **不可行时的 UI**：只是提示，还是允许用户「一键放宽某条规则」重解？
   后者要改「规划」页交互，属产品决策。
