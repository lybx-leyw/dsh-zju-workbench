## 一句话

在讲义生成链路**建树之前**，把「回看 / 重复帧」从课件页序列里剔掉 ——
因为本仓的 `buildLectureTree()` 会把一页重复帧**升级成一个吞掉后续所有页的伪知识点**。

**集成方式：强化式集成（重复且可强化）：不是「全新」。**

| 判据 | 结论 | 依据 |
| --- | --- | --- |
| ① 仍是同一个面板 | ✅ | 落点是 `dsh-zhiyun-core-lecture` 的 `generateLecture()` 入口前 / parser 建树前。**不新建页面、不新增侧栏、不新增插槽**，用户看到的仍是同一份讲义 |
| ② 功能仍相似正交 | ✅ | `buildLectureTree` 回答「**这页属于哪个知识点**」（分类）；本包回答「**这页是不是同一页**」（去噪）。同一条链、相邻的环，输入相同但职责不重叠 |
| ③ 底层多调了更优质实现 | ✅ | 本仓这一维**为 0**（`grep -rn '续讲\|重复页\|重复图' packages/dsh-zhiyun-core-{parser,lecture}/src` 只命中**同一页内**的块归并）。本包补上「跨页内容判同」，并用本仓已有的服务端文本（`pageText`）+ `sharp` 做组合，**能覆盖上游覆盖不了的回看场景**（见下节实测） |

## 缺陷实测：一页回看，树从 1 个节点裂成 2 个

```js
const page = (p, t, b) => ({ page: p, text: `${t}\n${b}` });
const base = [
  { page: 1, text: '第三章 优化方法' },
  page(2, '3.1 梯度下降 Gradient Descent', '沿着负梯度方向迭代更新参数'),
  page(3, '3.2 学习率 Learning Rate', '学习率过大导致震荡，过小导致收敛慢'),
  page(4, '3.3 动量法 Momentum', '引入动量项以加速收敛'),
  page(5, '3.4 自适应学习率 Adam', '结合动量与二阶矩估计'),
];
```

| 情形 | `buildLectureTree({ slides })` 产出 |
| --- | --- |
| **G** 无回看（5 页） | `第三章 优化方法[1-5]` —— 1 个节点，正确 |
| **H** 回看第 3 页（6 页；第 4 条 = 第 3 页副本） | `第三章 优化方法[1-2]` / `2 学习率 Learning Rate[3-4]` —— **2 个节点，第 2 个吞掉后面一切** |

**机制**（`packages/dsh-zhiyun-core-lecture/src/tree.js:366`）：

```js
// 1. 在别的页也出现过 —— 标题会跨页重复。
if ((pageCountOf?.get(line) ?? 0) >= 2) return true;
```

标题判据的第一条是「**在别的页也出现过**」（真标题确实会跨页重复，这条是对的）。
但**回看的副本会让一个正文行凭空满足它**：`3.2 学习率` 的出现页数从 1 变 2，
于是它从**正文**升级为**标题**，把第 3–5 页全部收进自己名下，导致
`3.3 动量法` / `3.4 Adam` 两个真标题**彻底消失**。

> 也就是说：**重复帧不是多了一段噪声，而是把章节边界抹掉了。**

### 为什么**不能照抄**它的算法

它的 `inject.js:546-567` 只与**相邻上一张**比对：

```js
const last = mergedPpt[mergedPpt.length - 1];
if (lastUrl === currentUrl) continue;
if (await isSameImage(lastUrl, currentUrl)) continue;   // ← 只看上一张
```

对「A→B→A→C」这种**回看**（讲重点时翻回去，再翻回来继续）完全无效。实测：

```
输入：3.1@2 → 3.2@3 → 3.1@4 → 3.3@5 → 3.2@6 → 3.4@7
相邻比对后保留：3.1@2 → 3.2@3 → 3.1@4 → 3.3@5 → 3.2@6 → 3.4@7   （一页没删）
仍有重复标题：2
```

**在本仓最大的用例上命中率为 0。** 这正是不该把它当作「更优实现」锁版/移植的原因。

## 为什么本仓能做得比上游好

| 能力 | 上游（浏览器内） | 本仓（服务端） |
| --- | --- | --- |
| 有 `pageText` 吗 | ❌ 没有 OCR，只有像素 | ✅ `vision.js` 逐页转述，`parser` 已落盘 |
| 有原课件页号吗 | ⚠ 有 `time`，无 `page` | ✅ `pages[].page` |
| 图像库 | ❌ 只能 `canvas` + `getImageData` | ✅ `sharp@0.35.5` 已在 `dsh-zhiyun-core-parser` |
| 能判「回看」吗 | ❌ 相邻比对 | ✅ 全量比对 + 页号倒退信号 |

**结论**：正确形态不是「把 ZYNotes 的算法搬进来」，而是
**文本近重（主）+ 像素近重（兜底纯图页）+ 页号连续性（约束）** 三级降级。
