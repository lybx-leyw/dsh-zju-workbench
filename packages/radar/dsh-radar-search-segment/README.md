## 未决问题（评审先答这个）

**Q-1（阻塞）**：`findIn` 是**客户端函数**（跑在浏览器，「学习」页消费的是已下发的
`result`）。因此「让检索具备分词能力」= 把 2.8 MB gzip 的 wasm 送进浏览器；
不送，则「学习」页的检索仍然不切词，本骨架的价值只剩宿主侧 `knowledge.search()`。
**这一条不裁决，骨架不应落地。**

**Q-2**：为什么不用第三十六轮已锁版的 `MiniSearch`？它解决**排序**，不解决**切词**，
两者不重叠、可叠加。
