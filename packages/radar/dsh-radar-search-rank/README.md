### 现有实现缺什么（2026-10-20 实测，非自述推断）

`packages/dsh-zhiyun-page-study/src/layered-search.js` 文件头第 ⑥ 条自述：

> 匹配是**字面**子串（大小写不敏感、**不切词、不算相关度**），不是向量检索。

用本仓真实 `searchLesson()` 跑夹具，可复现三件事：

| # | 现象 | 夹具 | 结果 |
| --- | --- | --- | --- |
| 1 | **无相关度**：命中顺序 = `blocks` 数组顺序 | block#0 正文写「均值不等式」，block#1 的**摘要**写「柯西不等式」；查「不等式」 | 先出 block#0，摘要更贴题的那条不优先 |
| 2 | **摘要只在 `titleOnly` 档位参与匹配** | 同上 | `titleBody` 档位下 `tag.summary` 命中不单独出条 |
| 3 | **层被裁空时静默返回空** | `layers: []` | `empty: true`、`hits: 0`、`counts: {}`，**不报错** |

minisearch 提供 ① 字段加权 + BM25 类打分、② 前缀匹配、③ 可外接 `tokenize`（中文）。
第 ③ 条是**本仓的 bug 面**，接入前必须先修（见 TODO-0），否则会出现「明明有内容却搜不到」。

## 集成边界（评审必须逐条确认）

1. **只排序，不增删**。页面把 `searchLesson()` 算好的 `outcome.hits` 交进来，
   本包只改 `hits` 的顺序。**不得**让 `tagFilter` 档位冒出页面层/主线层的命中 ——
   那会破坏「筛了维度只有块层能出结果」这条 App 对齐规则。
2. **`counts` / `hitBlockIndexes()` / `omitted` 三个读数必须与旧实现逐字段一致**。
   排序会改变 `omitted` 截断的是谁，属**有意变更**，须写进测试并在 PR 里说明。
3. **`fuzzy` 默认关**。「∑a²」「p=mv」这类符号查询在模糊匹配下会变成噪声。
4. **不落盘**。索引每次从 `result` 现算；不引入第二真源（课改了索引没改是最坏的情况）。
