但也**没有省下人工**。

## 为什么不整库引入中文数词库（本轮最重要的一条）

同轮实测了两个最像的上游，**都不合格**：

| 输入 | 真值 | `Achuan-2/chinese_number_to_digits` | `spa5k/chinese-numbers-to-arabic` |
| --- | --- | --- | --- |
| 一千二百万 | 12000000 | **1002000000** ✗ | 12000000 ✓ |
| 十二亿三千四百万 | 1234000000 | **4204000000** ✗ | （未测出正确值） |
| 一亿二千万 | 120000000 | 120000000 ✓ | **1000020000000** ✗ |

两家各错一处、错法**方向相反**（一个把「万」吞掉，一个把「亿」与「万」串错），
所以「两个都跑、取交集 / 取多数」也不成立。

`sandbox` 里另写了一版**显式单位节点 + 按层级合并**的原型（`Fraction` 有理数），
上述 6 个用例 + `九亿九千九百九十九万九千九百九十九` 全部正确。因此骨架的
设计口径是：**中文数词支路自写（≤120 行），上游只提供 `Decimal` 这一层**。

> 这也是本包判 🟢 而非 🔵 的理由：要换的**底层**（任意精度小数）已成熟，
> 而**最容易出错的那一段**（中文数词）恰好短到可以自己写对，且能写差分测试钉死。

## 边界

- **`unknown` 绝不退化成 `correct`**：判不了就进人工，不把「像」当「是」。
- **不做语义等价**（「mitochondrion」vs「线粒体」）：那需要模型，且违反
  「AI 判分不得直接当复习调度评分」的既有纪律（`store.js` 文件头）。
- **不改 `normalizeForTrace`**：三处副本 + 一致性测试钉着，本层只在其后追加。
- **不做单位换算**（`1 km` vs `1000 m`）：同轮扫到的单位库 `HardusLom/UnitLab`
  无许可证、0★，不采用；本题域留待日后单独立项。
