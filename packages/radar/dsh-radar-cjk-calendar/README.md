## 一句话

**本仓只有一个时间刻度：公历。** 今天页的日期行只有 `HH:mm` 与 `YYYY-MM-DD`。
本包在同一行上补一段农历（`九月廿三`），**不新增面板、不新增入口** ——
**新的是刻度，不是页面**。

## 定性：**强化式集成**（不是「全新」）

| 判据 | 本包怎么满足 |
| --- | --- |
| ① 仍是同一个面板 | 只在 `dsh-zhiyun-page-today` 已有的日期行追加一段文本；不注册页面、不注册 slot、不加导航 |
| ② 功能仍相似正交 | 公历（到期 / 第几周）与农历（初几 / 哪天初一）是同一天的两个读数，不是两件事 |
| ③ 底层多调了更优质实现 | 换掉「手写农历查找表」这类常见做法，改调宿主 ICU 的 ECMA-402 `calendar: "chinese"` |

## 它补了哪一格

| 问法 | 现有实现 |
| --- | --- |
| 现在几点、这节什么时候上 | `agenda.js` `clock()`（`HH:mm`，`Asia/Shanghai`） |
| 这件事哪天到期 | `due.js` `shanghaiDay()`（`YYYY-MM-DD`，同上时区） |
| 今天是农历什么日子 | **无** |
| 寒假/开学是不是撞在元宵前后 | **无** |
| 跨年期末周与家里的安排 | **无**（要切到手机日历） |

学生赶的截止日大多挂在农历上：寒暑假起止、返校、清明端午中秋的调课、
以及**农历过年落在期末考试周**的那几年。这一格的成本极低（零依赖、< 100 行），
收益是「不用切 App」。

## 与上游的关系：**没有上游**

这是 **B 类**（非原生 DSH 插件包）候选的产物 —— 能力来自 ECMA-402 标准，
由宿主 Node 的 ICU 提供，**没有 npm 包可锁**，所以 `dependencies` 是空的。
`cordis.patch.yml` 只是把「将来评审通过后它作为一个 host 层插件挂进来」的形状摆出来。

## 三条必须守住的边界

1. **不新增面板**。渲染点是今天页已有的日期行。若评审认为「不值得为一行文本
   单独占一个插件槽位」，正确做法是**整目录删除**、把 `src/lunar.js` 的算法
   内联进 `dsh-zhiyun-page-today` —— 而不是给本包加能力。
2. **不做宜忌 / 黄历 / 生肖运势**。与学习工作台无关。
3. **不做农历生日提醒**。那是日历域，由 `dsh-radar-ics-export` 那条线的 ICS 承接。

## 已知边界（评审重点）

| 边界 | 说明 |
| --- | --- |
| 必须走 `formatToParts` | `format()` 给的是 `2026年九月23`，混着 `literal` 分隔符；`parts` 的 `type` 才稳定 |
| `relatedYear` **不是**农历年号 | 2026-01-01 的 `relatedYear` 是 **2025**（春节前与公历年差 1）。干支请读 `yearName` |
| 「日」是数字不是中文 | ICU 给 `day=23`，`廿三` 靠 `DAY_NAMES` 查表补 |
| 闰月未验 | `month` 会是 `闰六月` 形态；闰月首日应显示成什么，需用已知对照表验 |
| ICU 版本相关 | 本机 Node 22.13 / ICU 76.1 实测正常；换 Node 版本须重测 |

## 实测（骨架自证，不是测试）

```text
2026-11-01 → 九月廿三   （parts: month=九月, day=23）
2026-01-01 → 十一月十三 （parts: month=十一月, day=13）
2026-02-17 → 正月初一   （parts: month=正月, day=1）
```
