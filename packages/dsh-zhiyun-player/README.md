# dsh-zhiyun-player

**播放统计**：把一节终稿的块级数据算成「能直接画在进度条上」的数。

纯逻辑 + 空宿主半边。零 IO、零外部依赖。

## 谁在用

学习页视频栏把这些数画在回放下面：粗条是内容分段（主线 / 支线），细条是语速。
点粗条按时间跳转。终稿还没出来时不画，避免把空条说成这节课的结构。

页面经客户端入口拿函数（`import { computeSectionStats, toSeekBar } from 'dsh-zhiyun-player'`），
不把本包源码打进学习页自己的 bundle。宿主侧别的插件仍然可以：

```js
const stats = ctx.get('zhiyunPlayerStats');
const s = stats.computeSectionStats(blocks);       // 分段 / 语速 / 汇总
const bar = stats.toSeekBar(s, videoDurationMs);   // 进度条绘制输入
```

## 产出三组数据

| 产出 | 喂给 |
| --- | --- |
| `records` | 一切（每块的角色 / 维度 / 概述 / 时间戳 / 字符数） |
| `segments` | **内容进度条**：按时间轴分段 + 角色（颜色）+ 第二维 |
| `speedBuckets` | **语速热力条**：`Δ文本数 ÷ Δ时间戳` |
| 四个汇总字段 | 课程信息表（平均语速 / 知识点数 / 主线占比 / 例题数） |

## 语速算法

块恰好铺满整节时间轴，所以「相邻块起点之差」就是上一块之后到这一块开始的那段时间窗，
落在那个窗口里的文本正是**这一块自己**的正文：

```
语速(i) = 第 i 块的字符数 ÷ (第 i 块起点 − 第 i−1 块起点) = Δ文本数 ÷ Δ时间戳
```

主单位是**字/秒**，`charsPerMinute` 只是便利换算。

### 三种「不可估」返回 `null`，**不返回 0**

| 情况 | 返回 | 为什么不是 0 |
| --- | --- | --- |
| 文本数差为 0（纯过渡语 / 空块） | `null` | `0` 会被读成「老师一句话没说」，那是**假的**；`null` 才是「这一格没有信息」 |
| 时间戳差 ≤ 0（同毫秒两块 / 时间没往前走） | `null` | 除以 0 得 `Infinity`，除以负数得负语速，两者都会把热力图画成噪声 |
| 只有一块（没有「相邻」） | 不产生桶 | 没有 Δ 就没有估计，不编造 |

**展示层必须接住这个 `null` 语义**：画成中性底色，而不是"最冷"。
`toSeekBar()` 已经把 `heat` 保持为 `null`，但如果消费方自己写 `?? 0` 就前功尽弃了。

## 三个容易写错的地方（都有测试钉住）

1. **字符数按码点数**（`[...text].length`，不是 `text.length`）。
   emoji 是代理对，原生 `length` 给 2，语速的分母就错了。
2. **合并相邻块时用「已合并段的最后一块」算间隔**，不是用段的起点。
   用起点比会把三句连续的讲述拆成两段（间隔阈值 15 秒）。
3. **越界夹到 `[0,1]`**。终稿时间轴与视频总时长**常常不等**（终稿只覆盖有语音的部分，
   视频还有片头片尾），所以横轴由调用方显式给定，画出来的东西永远夹在条内。

```bash
node --test tests/player.test.mjs
```

14 项，不连网、不读磁盘。覆盖：语速公式、三种不可估、热力归一、
合并判据（含上面第 2 条那个坑）、知识点数、汇总口径、`toSeekBar` 夹紧、
