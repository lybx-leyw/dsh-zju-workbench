# @lybx-leyw/dsh-zju-page-notes

「笔记」页：**Obsidian 式笔记库** —— 文件树、多标签页、双链、反链、标签。
正文存成**普通的 `.md` 文件**。

## 版面：照着 Obsidian 的四个分区来

```
ribbon │ 文件树 │ 标签页 / 编辑器 / 状态栏 │ 右栏（默认收起）
```

每一块都对应 Obsidian 里真实存在的东西，不是装饰：

| 分区 | 内容 |
| --- | --- |
| ribbon | 开关文件树、新建笔记、新建文件夹、过滤、开关右栏 |
| 文件树 | 文件夹可折叠（▸/▾）、笔记与附件分图标、附件带类型角标、**拖到文件夹上即移动** |
| 标签页 | 同时开多篇，各自带自己的草稿与未保存圆点 |
| 面包屑 | `← →` 是打开历史；右侧是"在哪个目录里的哪一篇"与编辑/阅读切换 |
| 编辑器 | 文件名即大标题（Obsidian 的 inline title）；正文列宽封顶 700px 并居中 |
| 状态栏 | 反链条数 / 词数 / 字符数 / 链接与标签数；左端是"这是哪个库" |
| 右栏 | 改标题、删除、反向链接、指向、标签、全库标签 |

⚠️ **右栏默认收起**：宿主里这一页的可用宽度是窗口减去它自己的侧栏，再常驻一列
250px 会把正文挤到读不下去（实测状态栏都换行了）。Obsidian 的右栏同样默认收起。

配色只用壳的 `--zy-*` 变量，明暗两套自动跟随。

## 子目录：vault 就是一棵树

库里可以建文件夹，笔记放在任意深度。这件事**只改了本包的存储半边** ——
`@lybx-leyw/dsh-zju-core-vault` 的索引器早就按嵌套路径写好了（`createResolver()` 的顺序是
「精确路径 → 同目录 → 全库唯一 basename」，`renameLinks()` 也走 resolver）。
第一版没有递归列目录，才显得像是不支持文件夹。

`tree()` 返回**扁平**的条目表（笔记 / 文件夹 / 附件），树由页面自己拼：
目录结构是**展示**问题（排序、折叠、缩进都在页面里），服务端只需要如实报告
"磁盘上有什么"。给一棵拼好的树等于把展示决定提前固化到存储层。

笔记条目的 `path` **不带 `.md`** —— 那是它在 `[[双链]]` 里的写法，也是页面
标识它的键；附件与文件夹的 `path` 就是磁盘相对路径。

## 与「学习」页里的节笔记不是一回事

| | 学习页的「笔记」 | 本页 |
| --- | --- | --- |
| 单位 | **一节课**一份 | **一篇**平级笔记（可在文件夹里） |
| 键 | `账号.节次` | 相对路径（不含 `.md`） |
| 链接 | `zy://section/…` 跳回播放位置 | `[[另一篇]]` 连成知识网 |
| 性质 | 应用数据（人不需要直接看） | **用户自己的文件** |

同一段正文可以**同时**带这两种链接。各有各的用处：前者绑定课程上下文，后者跨课程连成网。

## 为什么正文是普通文件

一个 **vault 本质就是一个 `.md` 文件夹** —— 这是 Obsidian 的真实模型，不是实现细节：

- 用户能用任何编辑器打开这些笔记（不锁死在应用里）；
- 备份、同步、版本控制都按普通文件处理；
- 反之，把笔记塞进私有容器会让"笔记库"这个概念名不副实。

⚠️ 这与本仓其它领域包的取舍**不同**（那些把落盘交给宿主存储栈，例如
`@lybx-leyw/dsh-zju-core-notes`）。区别在**模型本身**：那些是应用数据，这个是用户文件。
这是一处**有意的破例**，不是随手为之。

落盘位置：`<profile>/data/zhiyun-vault-notes/`（可以是一棵目录树）。

## 分工

```
本包（页面 + 存储）              @lybx-leyw/dsh-zju-core-vault（纯索引器）
  ├─ 读/写 .md 文件                ├─ 解析 [[链接]] 与 #标签
  ├─ 路径安全（safePath）          ├─ 反链 / 图谱 / 未解析
  ├─ 目录树的建 / 移 / 删          └─ 零 IO、零解析
  └─ 改名时落盘改写结果
```

两边都不做对方的事：索引器不认识文件系统，本包不解析 Markdown。
`vault` 缺席时（`ctx.get('zhiyunVault')` 取不到）页面只是**没有反链**，正文照常读写 ——
所以它**不写进 `inject`**。

## 四条交互决定

1. **自动保存**（停顿 800ms 后写盘）。手动保存按钮在笔记应用里是反模式 —— 用户会忘。
   写失败时**不动**编辑器内容，只在状态栏如实报错。
2. **切标签页 / 关标签页之前先落盘**。未保存的改动丢在切换里是最难解释的一类数据丢失
   （也是"我明明写了"的来源）。删掉的文件则要把挂起的保存任务一并摘掉 ——
   否则那一份草稿会被下一次自动保存写回磁盘，把用户刚删的内容又救回来。
3. **反链只读**，点一条跳过去。改反链要改的是**对方**的正文，
   那属于在别人的笔记里做手术，不该在这里顺手做。
4. **标题即文件名**，改名走 `rename` —— 服务端会**一并改写全库指向它的链接**。
   不提供"只改标题不改文件"：那会让 `[[标题]]` 与文件名对不上，
   正是 Obsidian 用户最常见的困惑来源。

## 键盘：滚动、移动、区间选择、批量删除

| 键 | 作用 |
| --- | --- |
| `PageDown` / `PageUp` | 正文翻一屏（保留 15% 衔接） |
| `↑` / `↓` | 在文件树里移动游标；注意力不在树上时滚正文 |
| `Shift` + `↑` / `↓` | **从锚点到游标框出一段**，构成批量选择（行变成 accent 淡底，树上显示「已选中 N 条」） |
| `Delete` / `Backspace` | 删掉选中的那些行；没有区间选择时删游标那一条。**一律先弹确认条** |
| `Esc` | 先撤确认条；没有确认条时撤掉区间选择（游标保留） |

四条约束，每一条都对应一个真的会出事的场景：

1. **锚点是第一次按 Shift 时定下的，之后只移动游标**。往回按 Shift+↑ 会让区间
   **收缩**，而不是另起一段。所有文件管理器都是这个语义。
2. **松手后按普通 ↑/↓ 会清掉选择** —— 选择不会"粘"在上一段上，避免下一次
   Delete 删掉与当前意图无关的东西。
3. **鼠标点任何一行都清掉选择**。不提供 Shift+点击：这一页的行没有多选视觉语言，
   两条路并存会让人以为自己在操作两套东西。
4. **选择 = 屏幕上看得见的那一段**，由锚点到游标的**可见行下标**算出
   （`selectionRange()`），不是按路径字典序。折叠文件夹或输入过滤词让行变少时，
   选择跟着屏幕收缩 —— 绝不会把"折叠起来看不见的行"也算进去，然后被 Delete 删掉。

删除确认条会列出选中的条目（多于 6 条时折叠成"…还有 N 条"），
批量走**一个** `removeMany` RPC：宿主服务端按父目录优先的顺序删完，最后只刷一次索引。
逐个 `remove` 就是 N 遍全库重读 —— 删 30 篇会让界面卡几秒，中间失败还会留下
"删了一半、索引只更新了一半"的状态。

## 路径安全

单段名过 `safeName()`（去掉分隔符与 `..`、Windows 非法字符、限长 80），
相对路径过 `safePath()`（按 `/` 切段，每段过 `safeName`，剥掉 `..` 与空段，限深 12）。

两处安全性质与直觉不同，都是**刻意**的：

- **越界是"中和"而不是报错**。`../../escape` 会降级成一个普通名字 `escape`，
  于是"读穿越路径"就是一次查不到，而不是给调用方一个可区分的错误信号 ——
  那种信号本身就在帮忙探测文件系统。
- **真正兜底的不是输入清洗，而是落盘前那道断言**：`resolveIn()` 把相对路径解析成
  绝对路径后必须仍在库目录内，否则抛错。安全边界不能只由"剥离逻辑没写坏"承担。

剥光后为空时返回 `null` 由调用方报错，**不猜一个默认名** ——
猜出来的名字会让两篇笔记撞车，然后一篇覆盖另一篇。

## 正文渲染用宿主的 MarkdownText

不在本包重写 Markdown 渲染：宿主已提供渲染助手消息的**同一个**组件
（`@deepseek-ai/dsh-client-ui-primitives` 的 `MarkdownText`），论文页与讲义阅读器都在用。
自己写一套意味着代码块高亮、脚注、表格、复制按钮全要重做，而且表现与宿主不一致。

编辑器是**纯文本 textarea**，与"阅读"是同一块区域的两个模式（面包屑右侧切换），
不是折叠在下面的第二个面板 —— 那样正文会被挤成两半。不做富文本编辑器：
Markdown 的可编辑性本身就是它的价值。
