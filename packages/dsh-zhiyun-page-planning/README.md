# dsh-zhiyun-page-planning

「规划」页：读**用户自己部署的中转站**，把推上去的个人规划与日记摆成第一栏。

## 它是什么，不是什么

| 是 | 不是 |
| --- | --- |
| 一个**消费端**：从用户填的域名读数据 | 不是数据托管方 —— 我们一行数据都不存 |
| 第一栏就是那份内容 | 不是"又一张设置表单"：配置在「个人 → 设置」里 |
| 只读。读密钥只能读 | 不负责写入 —— 写要用中转站的写密钥，由用户自己的抓取脚本完成 |

数据从哪来、多久抓一次、写成什么格式，都是用户自己的事。本页只认中转站那套协议
（见仓库 `deploy/relay-service/`）。

## 为什么整页只有一栏内容

这一页**没有"自己的数据"**——它没有课程、没有课表，只有用户的。所以不该像「学习」页
那样先铺一个目录再进内容：域名配好之后，第一栏直接就是内容本身；没配的时候，
给一句能操作的引导，而不是摆一排空卡片。

## 配置放在哪

`<profile>/data/zhiyun-planning/config.json`：

```jsonc
{ "endpoint": "https://你的账号-空间名.ms.show", "readKey": "中转站里的读密钥" }
```

界面入口在「个人 → 设置 → 规划数据源」，复用壳的 `.zy-settings-group` 公共类，
与这一页其它设置项逐像素同源（折叠交互归壳管，面板自己不画卡片）。

## 为什么取数走宿主，不让页面直连

不是啰嗦，是两条硬事实：

1. **浏览器直连会被 CORS 挡。** 中转站用自定义头 `X-Zy-Read-Key` 传密钥，跨域时
   必然触发预检，而中转站是我们自己写的模板、不保证预检放行；
2. **用户在设置里填的是任意域名。** 页面直连等于让浏览器去打任意地址，
   同源策略之外还多一层 SSRF 面。

所以宿主代为发请求、代为带密钥，只把结果交给同源页面。

## 失败语义

这五种在页面上的处置完全不同，所以**不揉成一个 falsy 返回**，而是各给一个 code：

| code | 含义 | 页面上怎么说 |
| --- | --- | --- |
| `NOT_CONFIGURED` | 域名或密钥没填 | 引导去设置 |
| `KEY_REJECTED` | 401/403/404 | 「密钥不对，或这个域名上跑的不是中转站」 |
| `UNREACHABLE` | 连不上、超时 | 带上底层错误码（`ECONNRESET` 等） |
| `UPSTREAM` | 中转站自己报错 | 显示状态码 |
| `BAD_PAYLOAD` | 返回的不是中转站格式 | 提示去验 `/health` |

`401/403/404` 合并成 `KEY_REJECTED` 是有意的：中转站对未授权**一律回 404**
（不暴露"这里有入口"），所以 404 与 401 在那里同义。

## 安全边界

- 读密钥**永远不回显明文**：接口回给页面的一律是打码值 `********`，
  页面回传打码值表示"不改密钥"。
- 客户端**不写任何本地存储**（`localStorage` / `cookie` 等），有测试钉住。
- 设置路由只接受回环 Host（防 DNS rebinding），写操作要求 `x-zhiyun-planning` 头
  （跨站发不出自定义头，硬带会触发本路由不响应的预检）。
- 域名只接受 `http`/`https` 且只保留 origin；带账号密码的 URL 直接拒绝。
- 拉取路径固定为 `/entries`，用户无法借这个入口打到任意路径。
