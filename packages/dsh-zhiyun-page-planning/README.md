# dsh-zhiyun-page-planning

「规划」页：**写下要做的事**，让 AI 帮你拆成可执行条目；同时把学在浙大待办、
拼题A 题集、以及你自己中转站里的内容并到同一张表上。

## 它是什么，不是什么

| 是 | 不是 |
| --- | --- |
| **能写**：自己的规划存在本机，可增删改、可勾完成 | 不是同步服务 —— 不替你保管、也不替你跨设备同步 |
| 中转站的**消费端**：从你填的域名读内容 | 不是中转站的写入方 —— 那边仍是只读，写要用它的写密钥 |
| AI 辅助**拆分**：一句话里塞了七八件事，拆开 | 不是替你决定做什么 —— 不发明截止时间，也不给"来不来得及"的判断 |

## 「我的规划」为什么在本机，不写回中转站

中转站是 **append-only**：只有 `POST /entries`，没有更新/删除，写满 5000 条直接拒收。
而规划天然要改 —— 日期会挪、事会取消、做完了要划掉。那里**做不到**「把它改成周五」，
只能追加一条新的再想办法对账。

所以本地是一等来源（`local.json`）：

- 可增删改、可勾完成，**不需要再配一个写密钥**；
- 与 `entries.json`（中转站内容的缓存）**分成两个文件**：那份只增不改，这份必须能删能改，
  混在一起两种生命周期会打架；
- 中转站挂掉、被重建都不影响它。

想同步到中转站是将来的是，而且那时也该是"导出"，不是唯一存储。

## 拆分：AI 服务于**你自己写的**那些

页头那个「AI 自动规划」拆的是中转站里的历史条目；每条自己写的规划上还有一个
「AI 拆分」按钮，拆的是**你刚写的那一句** —— 后者才是这个功能真正要服务的对象。

两者共用同一套提示词与校验，也共用同一个约束：**原文没写时间就填 null**，
不许"根据上下文推测"。拆出来的条目带 `splitFrom`（记来源），源条目带 `splitInto`
（记拆出了哪几条），所以页面能显示"已拆 3 条"，也默认不会重复拆（拆一次花一次模型钱）。

删掉源条目时，它拆出的子项**一起删** —— 它们的存在理由就是那条原文，留着就是孤儿。

## 「做完了」覆盖到哪一步

三类条目都能勾，但**勾的含义不一样**，这个差别必须让用户看见：

| 条目 | 能勾 | 状态存在哪 | 勾了意味着 |
| --- | --- | --- | --- |
| 我的规划 | ✅ | `local.json` 的 `done` / `doneAt` | 这件事我做完了 |
| 中转站拆出的卡片 | ✅ | `plans.json` 的 `cards[i].done` | 这件事我做完了 |
| 学在浙大 / 拼题A 待办 | ✅ | `ticks.json` 的 `xzzd:id` | **只是我不需要再被提醒了** |

第三行是**本机标记**，不是平台的完成状态：勾一下不会让学在浙大认为作业交过了，
也不会让拼题A 关闭题集。所以勾掉之后那一行仍然保留外链、并且写明
「平台那边的状态没有改变」—— 不能让人以为勾了等于交了。

平台那边仍然权威：它说未提交就是未提交。本机勾选只表示"这件事不用再提醒我"。

第二行曾经是漏掉的：卡片数量往往最多，却一个都勾不了，看起来像「这页根本没做完成状态」。
它能勾但**不能改不能删** —— 内容是模型从原文拆的，改它等于改原文的意思；要删该用
「忘掉这次拆分」，否则会和 `plans.json` 的映射脱节。

重拆会**重置完成状态**：新卡片可能已经不同，"第 2 张做完了"不再对应同一件事。

### 勾选的两个硬约束

**没有稳定身份就不能勾。** 键是 `source:id`，带 source 是因为两个平台 id 都是小整数
（`xzzd:12` 与 `pta:12` 是两件事）。缺 id 的条目不给勾 —— 勾了也会在下次同步时
凭空消失，那比不能勾更让人困惑。

**清理只在两侧都读到的时候做。** 平台侧已消失的条目要清掉勾选残影，但如果某一边
读取失败，它的 `rows` 是空的 —— 按空表去清会**把用户所有勾选一次性删光**。
一次网络抖动清掉一学期的标记，是这类"顺手清理"最典型的灾难。

## 列表 / 日历两种视图

同一批数据的两种呈现，切换不发请求。

**日历只收有确定截止时间的事**，窗口是"回看 6 天 + 往后 4 周"共 34 格。没有 `due` 的
条目不进格子，下面用一句话说明还有几件，它们仍然完整地留在列表里。

这不是偷懒：把无日期的条目塞进某一天，等于替用户编了一个他没写的截止时间 ——
正是提示词里明令禁止的事。而这一页的多数条目 `due` 本来就是 null（写的时候不逼着填）。

空格子**也画出来**：「这天没安排」本身是信息，与今天页「今天没有课」是同一类判断。
过去的日子如果还有没做完的事，格子左侧标警示色。

## 与「今天」页为什么不合并

两页的空白含义完全不同，合起来用户就分不清：

| | 今天页 | 规划页 |
| --- | --- | --- |
| 依赖 | 领域包 + 登录（`zhiyunStudyController`） | 只要插槽，**领域包停用也能打开** |
| 空白的含义 | **正确性**：课表没收全就绝不画成"今天没课" | **配置**：没配中转站/没登录/没 Cookie，各有各的恢复办法 |

今天页是扫一眼就走的仪表盘，规划页是坐下来整理的工作台。合并会把规划页绑在
登录之后，还会让三种完全不同的"空"混成一个。今天页点一条到期事项进来时，列表里还有
这一条就滚到它；没有、或已经勾掉，就停在规划页本身，不报错。

真实缺口是**规划时看不见课表**，那靠"把课表读进来当上下文"就够：有条目设了截止时间
时，旁边写一句"这天有 3 节课"。读不到、没收全，或截止日期落在这次窗口外面，就一个字都不提，
也不把没读到的日子说成"这天没有课"。窗口是上海今天往前 7 天、往后 23 天。这次读取不写进
今天页那份课表。不新增依赖，也不报错。

## 原来那些读的来源

这一页仍然读中转站、学在浙大、拼题A，各自失败各有各的处置。数据从哪来、多久抓一次、
写成什么格式，都是用户自己的事。本页只认中转站那套协议（见 `deploy/relay-service/`）。

## 配置放在哪

`<profile>/data/zhiyun-planning/config.json`：

```jsonc
{ "endpoint": "https://你的账号-空间名.ms.show", "readKey": "中转站里的读密钥" }
```

界面入口在「个人 → 设置 → 规划数据源」，复用壳的 `.zy-settings-group` 公共类，
与这一页其它设置项逐像素同源（折叠交互归壳管，面板自己不画卡片）。

## 为什么取数走宿主，不让页面直连

不是啰嗦，是两条硬事实：

1. **浏览器直连会被 CORS 挡。** 中转站用自定义头 `X-Zy-Read-Key` 传密钥，跨域时
   必然触发预检，而中转站是我们自己写的模板、不保证预检放行；
2. **用户在设置里填的是任意域名。** 页面直连等于让浏览器去打任意地址，
   同源策略之外还多一层 SSRF 面。

所以宿主代为发请求、代为带密钥，只把结果交给同源页面。

## 失败语义

这五种在页面上的处置完全不同，所以**不揉成一个 falsy 返回**，而是各给一个 code：

| code | 含义 | 页面上怎么说 |
| --- | --- | --- |
| `NOT_CONFIGURED` | 域名或密钥没填 | 引导去设置 |
| `KEY_REJECTED` | 401/403/404 | 「密钥不对，或这个域名上跑的不是中转站」 |
| `UNREACHABLE` | 连不上、超时 | 带上底层错误码（`ECONNRESET` 等） |
| `UPSTREAM` | 中转站自己报错 | 显示状态码 |
| `BAD_PAYLOAD` | 返回的不是中转站格式 | 提示去验 `/health` |

`401/403/404` 合并成 `KEY_REJECTED` 是有意的：中转站对未授权**一律回 404**
（不暴露"这里有入口"），所以 404 与 401 在那里同义。

## 安全边界

- 读密钥**永远不回显明文**：接口回给页面的一律是打码值 `********`，
  页面回传打码值表示"不改密钥"。
- 客户端**不写任何本地存储**（`localStorage` / `cookie` 等），有测试钉住。
- 设置路由只接受回环 Host（防 DNS rebinding），写操作要求 `x-zhiyun-planning` 头
  （跨站发不出自定义头，硬带会触发本路由不响应的预检）。
- 域名只接受 `http`/`https` 且只保留 origin；带账号密码的 URL 直接拒绝。
- 拉取路径固定为 `/entries`，用户无法借这个入口打到任意路径。

## 去重键：为什么是内容指纹，不是"前 40 个字"

本地留存与「源条目 → 卡片」映射共用同一个键，它按**整份内容**算：

```text
kind \0 标题前 24 字 \0 sha256(kind \0 全文标题 \0 全文正文)[:32]
```

标题那 24 字**只为人眼可读**（`plans.json` 里认得出是哪条），唯一性完全由哈希保证。

早先的口径是把 `kind+title+text` 拼起来**截前 40 字**。中转站允许标题 200 字
（`deploy/relay-service/server.py` 的 `MAX_TITLE`），所以标题一长，正文一个字都进不了键：

```text
标题 45 字相同、正文完全不同的两条日记 → 同一个键 → 第二条被静默跳过、不落盘
```

这不是"偶尔重复"，是**丢数据** —— 用户写的东西在页面上永远不出现。加上"那条要是
被 AI 拆过，还会复用别人的卡片"，后果更难查。

换成内容指纹后，任意字段任意位置不同则键必不同，这一类故障在结构上消失了。

代价是**改稿算新条目**：旧口径刻意把"改一个错别字"当同一条以少些重复，但中转站是
append-only、只有追加没有更新 —— 合并改动等于让页面永远停在旧版本。这个取舍现在
明确站在"不丢、不卡在旧版"这一侧。

### 升级迁移（老安装必须有）

键换了口径，老文件里存的还是旧键。不做迁移，升级后同一批内容会算出新键、对不上旧记录：

1. `entries.json` → 整份内容**再存一遍**（页面出现重复）；
2. `plans.json` → 所有条目**重新拆一遍**（AI 调用，真花钱）。

所以 `LocalStore.load()` 会就地重算 `prefix` 并收集 `旧键 → 新键`，`apply()` 再拿它调
`PlanStore.rekey()` 改指映射。判据是"用当前内容算出的键是否等于存下来的键"，
所以对已迁移的文件是**幂等**的（算出相同就不动，不写盘、不产生映射），
也不需要在文件里加版本号字段。

## 首屏为什么先快后慢（数据链路）

四份数据**互不依赖**，所以是三路并发（中转站同步 / 学在浙大 / 拼题A），
不是逐个 `await`。那一版是串行的，等于把各自延迟相加。

拼题A 走 `with_exam: false`：这个页面只用「题集名 + 截止时间」，列表接口一次就给全；
默认行为会为**每个**题集再打一次 `/exams`（N+1），而请求又被 200ms 的 limiter 串起来。
实测 12 个题集 **13 个请求 / 3.7 秒**，关掉补齐后 **1 个请求 / 0.1 秒**。
`with_exam` 默认仍是 `true` —— 关掉会静默改变 AI 工具拿到的 `score`/`status` 字段。

学在浙大锚点：**稳定态只发 1 个请求**（`/api/todos`）。如果慢在这里，先查两件事：
① 会话是否失效导致走了一次完整 CAS 登录（`sessions/xzzd.json` 的 `saved_at` 没更新过就是）；
② `ZJU_NETWORK=auto` 时探测首次网络模式会多一次 `probe`（6 秒超时兜底）。

| 文件 | 职责 |
| --- | --- |
| `src/index.js` | 宿主半边：配置读写、中转站代理取数、待办聚合、路由（含「我的规划」CRUD） |
| `src/local.js` | **自己写的规划**：条目形状、写入校验、改/勾完成、拆分关系 |
| `src/ticks.js` | 平台待办上的**本机勾选**：键形状、清理保护 |
| `src/client.jsx` | 「规划」页正文（写入口 + 列表）+ 「个人 → 设置」里的配置分区 |
| `src/time.js` | 时间口径：分组键、日期标签、紧迫度。纯函数，页面与宿主共用一个真源 |
| `src/error.js` | 把宿主回的失败信息翻成一句能读的话 |
| `src/entries.js` | 中转站条目的去重/映射键（**内容指纹**，含旧口径迁移入口） |
| `src/plans.js` | AI 拆中转站条目：提示词、模型输出校验、映射持久化与 `rekey` 迁移 |
| `src/style.css` | 写入口、条目卡片、错误块、设置表单 |

`time.js` 与 `error.js` 从 `client.jsx` 抽出来的原因很具体：JSX 文件测试导不进来，
而这两处正是最容易坏又最难靠肉眼发现的 —— 时区错配会把凌晨的日记分成两个同名日期组，
错误对象会被字符串化成 `[object Object]`。两个 bug 都真的发生过，现在各有一条守卫测试。

## 路由动作一览

`GET /_dsh/zhiyun-planning` 回一份完整快照（`config` / `entries` / `remote` / `todos` /
`pta` / `plans` / `plannedKeys` / `local`）。所有 POST 都要 `x-zhiyun-planning: 1` 头，
且每条写操作都回**完整快照**，页面不必再补一次 GET。

| 动作 | 作用 |
| --- | --- |
| `save` / `refresh` / `pta` | 存域名与读密钥 / 重新同步 / 存拼题A Cookie |
| `plan` · `plan-force` · `plan-forget` | AI 拆中转站条目（幂等 / 强制 / 忘掉） |
| `local-create` | 新建一条「我的规划」 |
| `local-update` | 改一条（只改传了的字段；`done` 不能从这里改） |
| `local-done` | 勾完成 / 取消完成（`doneAt` 跟着对） |
| `local-remove` | 删除（级联删掉它拆出的子项） |
| `local-split` · `local-split-force` · `local-unsplit` | AI 拆自己写的那一条 / 重拆 / 忘掉拆分 |
| `plan-card-done` | 勾选中转站拆出的某一张卡片（`prefix` + `index`） |
| `todo-done` | 勾掉一条平台待办（**本机标记**，`source` + `id`） |

`local-update` 收到白名单外的字段（比如 `done`）会**报错而不是忽略** —— 静默丢弃一个
明确表达过的意图，比直接报错难查得多。

`dayKey` 收的是**秒**，`Date.now()` 给的是毫秒。少除一次 1000 不会报错，只会把"今天"
算到五万年后、让整个日历一格都对不上。这是实际发生过的错，`time.js` 里留了
`looksLikeSeconds()` 做单位护栏。

## 一个已经踩过的坑：整页白屏

新版加「日历 / 卡片完成 / 平台勾选」时，`openTodos` 等几个 `const` 写在了 `groups`
之后，而 `groups` 的 `useMemo` 体里直接引用它们。`const` 有暂时性死区，于是**首次渲染
就抛 ReferenceError，整页白屏**。

当时所有检查都是绿的：测试测的是宿主侧纯函数、构建只看语法、样式检查与渲染无关。
所以现在有 `planning-render.test.mjs`：用 esbuild 打包、打桩 UI 原语、
`renderToStaticMarkup` 真渲染一次。**改动这一页的 React 代码后，它能拦住白屏。**

写这类代码时的一条纪律：**`useMemo` 之间的依赖顺序就是求值顺序**，
被引用的 `const` 必须写在引用它的那个之前。

## 另一个坑：一个来源读不到，整页回 400

`snapshot()` 原来用 `Promise.all`，注释还写着「各链路内部都把异常收成了 error，
所以 all 不会被 reject」。这句话是错的 —— `loadTodos` 在 `zhiyunOmni` 缺席、
或 `omni.invoke` 在 try 之外抛错时**会** reject。链路是：

```text
loadTodos() reject → snapshot() 抛出 → handler 没 try → 异常冒到宿主 Web 层
→ 宿主回空 body 的 400 → 页面显示「设置接口返回 400 / 宿主侧没起来，重启一次」
```

于是「学在浙大没登录」这个**正常状态**被显示成「宿主坏了」，用户会去重启，而重启没用。

现在两层：`Promise.allSettled` 让每条链路的错误落到它自己的区块，
GET 外面再兜一层 try，回 **500 + 可读的 `SNAPSHOT_FAILED`**。
守它的是 `planning-snapshot.test.mjs`：任一来源抛错时 GET 必须仍是 200，
且「自己的规划 / 勾选 / 映射」这些**根本不依赖网络**的数据照常返回。

测试不连外网：`pullEntries` 接受注入的 `fetch`，所有失败分支都用假 fetch 覆盖。
真实中转站的联调方式见 `deploy/relay-service/README.md`。
