# 反证记录（`doc` 四条能力）

任务要求：「改坏实现确认测试会红再还原」。这份文件就是那件事的原始结果。

## 怎么做的

一个脚本（`.tmp/proof-doc.mjs`，不进仓库）对每条关键判据做**一次最小破坏**：

1. 用字符串替换改坏一处（只改一处，不改别的）；
2. 跑对应的测试文件，记录它是否变红、红的是不是**预期的那条**（脚本会检查失败输出里
   是否出现该用例的名字 —— 「别的用例连坐」不算通过）；
3. `finally` 里用**改动前的完整原文**写回，逐字节还原；
4. 全部跑完后，再用 SHA-256 对比每份源码与备份，并重跑两个测试文件确认全绿。

结果：**23 条全部变红，0 条「改坏了还是绿的」，还原后全绿。**

> 中间真出现过一次「改了还是绿」：`插件层不要求输出目录`。原因是我最初那条断言只检查
> `error.code === 'CONFIG'`，而服务层的 `createDocService({})` 也会抛同一个 code ——
> 于是「插件层那道守卫被删掉」这种情况被服务层兜住了，断言测的其实不是插件层。
> 修法不是放宽，而是让断言**咬住插件层自己的文案**（`请在 profile 里配置
> config.outputDir`）。这条修正就是反证的价值：它抓出了一条假绿。

## 这份反证**没有**覆盖的地方（如实说）

- **真实 Office 文件**。夹具是自己拼的最小 OOXML，只装了我们真读的那几个 XML 部件。
  真实 Word / Excel / PPT 的 XML 有一堆可选元素（`w:sectPr`、样式、合并单元格的
  `gridSpan`），本包会忽略它们 —— 那是「取文字」的取舍，但**没有用真实的 Office
  产出验证过**。补法是拿几份真文档喂进去对比，本轮手上没有不含个人信息的样本。
- **装有 `@deepseek-ai/libreoffice-kit` 的那条路**。本机没有那个包，所以
  `officePages()` 的 `via: 'libreoffice'` 分支只被间接测到（`combinePdf` 的注入钩子
  测了「转换结果被追加、临时目录被清掉」），没有被真的跑过。
- **加密 PDF**。`PDFDocument.load(..., { ignoreEncryption: true })` 对「只设权限密码」
  的文件能过，对「设了打开密码」的会抛 `READ_FAILED` —— 这条路径只有代码，没有夹具。
