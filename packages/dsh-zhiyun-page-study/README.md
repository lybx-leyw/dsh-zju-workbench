# dsh-zhiyun-page-study

「学习」页：**课程目录 + 课堂回放 + 整理**，一页。

这是拆分后最大的页面包，也是唯一一页承载「回到课堂」这件事的包。三块内容各占一栏：

| 区域 | 是什么 | 文件 |
| --- | --- | --- |
| 左栏（课程目录） | 课程 → 节次，就地展开；已整理 / 解析中的状态点 | `study-workspace.jsx` 的 `CourseTree` |
| 正文区「视频」栏 | 视频主视图 + 课件小窗 + 字幕，两者可互换。终稿出来后，栏顶是四个汇总，视频下有内容分段和语速条 | `video-panel.jsx` / `seek-bar.js` / `video.css` |
| 正文区「知识点」栏 | 有阅读讲义时默认就是这份讲义：目录、章节、知识点、小标题。卡片和图谱用来跳进某一则；终稿是来源 | `knowledge-board.jsx`、`lecture-reader.jsx`、`quiz-panel.jsx`、`note-panel.jsx` |

课件和字幕不另开顶栏，跟在视频里。直播也不占顶栏：从左侧「正在直播」进来，落在视频栏的直播画面上。
出题和笔记的读写在 `dsh-zhiyun-core-study`。这一页只渲染：从已选片段出填空或简答，
待审题要用户采纳才进复习队列；笔记仍按节保存，页码链和时间链都回到视频里对那一页、那一句。另一节的链接
留在原地并说明跳不过去。目录上方另有一个入口，在当前账号已整理的终稿里做字面查找；
点中一节后打开它，并把同一个词放进这一节自己的检索框。从今天页点一条已采纳的题进来时，
这一节直接停在知识点里的本节出题。

## 为什么是一页

这里曾经是**三个页面包**：「我的课」（`dsh-zhiyun-page-courses`，只列课程与节次）、
「看课」（`dsh-zhiyun-page-player`，回放的视频/课件/字幕）、「学习」（本包）。
三者读的是**同一份** `state.content`，用户走的也是同一段动线（选课 → 看回放 →
整理 → 回看），拆成三页的代价是每一步都要离开当前上下文：看课时读不到讲义，
读讲义时又回不到那一段，还得记着自己是从哪进来的。

现在播放是正文区的一栏（`zs-content-switch` 的「视频」），课程目录是左栏。
**导航因此少两项，功能一个没少**；那两个包已删除。

## 播放那几条不能破的约定

1. **`<video>` 常驻**：主视图与小窗互换只改 `data-main`（纯 CSS 换网格区域），
   绝不条件渲染 —— 摘掉节点等于 `dispose()`，声音当场断、`currentTime` 也丢。
   `video.css` 里两个舞台都无条件写在树里，正是为此。
2. **时间轴是唯一真源**：当前时刻由 `<video>` 的 `timeupdate` 驱动，课件页与字幕行
   都是它的投影。反过来（课件驱动视频）会与用户拖进度条打架。
3. **点字幕才跳**：不自动滚动。用户可能正在读某一行，自动滚走是打断。

视频地址经 `safeMedia` 过滤（只放行 http/https）—— 它来自课堂接口，属于外部数据。

## 边界

- **领域状态不在这里**：账号、课程树取数、解析任务、持久化都在 `dsh-zhiyun-core-study`
  提供的 `zhiyunStudyController` 里，本包用 `ctx.inject(['zhiyunStudyController'], …)` 惰性取。
  停用领域包时这一页空着，不会把整个前端拖成 pending。
- **检索与格式化留在本包**：`searchLesson` / `hitBlockIndexes` / `layerSpecOf` /
  `time` / `lessonWhen` 只有这一页用，属于「这一页怎么呈现」，不属于领域。
  `tests/study.test.mjs` 直接从本包 import 它们（`src/layered-search.js`）。
- `lecture-reader.jsx` 用宿主的 `@deepseek-ai/dsh-client-ui-primitives`（`MarkdownText`，种子词），
  跨包原语用 `dsh-zhiyun-shell-ui`（`useStudy` / `Notice`）—— 两个不同的包，别混。
- **两张样式表**：`style.css`（整页）与 `video.css`（视频栏）。同包内后写的赢，
  顺序是确定的，不吃挂载顺序的亏；视频栏的类名一律 `zs-video-` 前缀，与整页的
  `zs-*` 不重名，`npm run check:css` 因此不会把它们报成跨包竞争。

## 插槽

在 `zhiyun.study.content` 注册内容（`children` 声明归外壳）。`ModelSettings` 是这一页的
「生成配置」按钮浮层，读领域状态的路由配置，界面留在本包。

## 生成讲义

顶栏「生成讲义 / 重新生成讲义」将当前节次加入全局队列，默认按加入顺序每次处理一节；同一节的待处理任务自动去重。学习页已有操作区提供下载图标，点击打开浮窗，不增加顶部栏位或推移正文；浮窗支持 Esc、点击外部与关闭按钮收起，可查看正在处理、等待和最近任务；离开学习页后入口与面板隐藏，后台队列继续运行；等待任务可移出，进行中的任务可取消，失败后继续下一节。任务标题可跳回对应课堂。阶段详情集中在面板中，课程头部不再常驻进度条。阶段面板显示识别、清洗、语义分组、聚合、成稿、终审的实际完成数、耗时和平均速度；阅读区只展示 v4 生成结果，不单独触发成稿、润色或恢复旧讲义。

## 阅读排版

讲义正文使用有上限的居中阅读栏，17px 正文和 1.9 倍行距。左侧仅保留一份章节目录，可通过按钮或键盘展开、收起；收起后正文在全部可用宽度中重新居中。窄容器内目录改为正文上方的可折叠区域，代码、公式和表格各自滚动。生成完成后阶段面板默认收起，来源与复核记录按需查看。

## 供应商与 worker

「生成讲义 / 重新生成讲义」使用分体按钮：左侧直接生成，右侧箭头展开配置浮层，不占用常驻栏位。浮层读取设置中已有的供应商与模型，可多选供应商，每家选择一个模型并分配 1–32 个 worker。点击「应用配置」保存后自动关闭浮层；也支持 Esc、点击外部和关闭按钮收起。总并发为所选 worker 数之和。支持图片的模型承担课件识别，所有所选模型参与后续文字阶段，整个任务共享各供应商配额。生成期间配置只读，结束后可调整；凭据继续由设置管理。


## 直播暂缓开放

直播体验暂不在 UI 展示：目录直播折叠区、课堂直播按钮和视频直播切换统一由 `study-workspace.jsx` 的 `LIVE_UI_ENABLED` 控制，当前为 `false`。底层直播接口、组件和 HLS 播放器保留；普通课堂回放照常使用。成熟后将开关设为 `true` 可恢复入口。


## 支线黑板

课堂内容并列提供视频、知识点与支线黑板。知识点沿用主线讲义；黑板直接投影解析结果中 `tag.role === "支线"` 的块，支线采用 13px 字号的紧凑通知列表，默认一行显示摘要、视频时间及紧邻时间的标签，点击或使用键盘展开原文；检索定位时自动展开对应卡片，支持局部查找与回到视频。检索命中支线时跳到黑板对应卡片。讲义未采用的主线或不完整块不会因此被误判为支线，不新增生成步骤或模型请求。

## 按知识点出题与全局题库

导航「题库」承载跨课程、跨节次的知识点选择、出题、历史题目与练习；知识卡片内保留同一套单点出题配置。四种策略为基础巩固、理解拓展、应用变式、综合探究，可按权重组合，提供背知识、练应用、综合自测预设。题型独立选择填空、选择、判断、简答；不适用的组合明确提示。知识点分配独立选择均匀或随机，随机最多覆盖约 2/3 的知识点。生成前展示策略题数与预计覆盖，难度、权重及联网设置按需展开。

生成题目和作答记录由宿主知识库的独立 `question_banks` 表按账号保存，讲义重生成不覆盖题目历史。原节次题目在读取题库或重生成讲义前归档。练习区分未做题、复习已做题、按比例新旧交错，可筛选策略和题型；不足如实提示，不自动生成补题。题目默认待核对，开始练习是显式采纳；填空按标准答案与已知同义表达比对，简答题对照参考答案及评分要点自评并明确记录自评来源。历史题支持策略/题型筛选，展示考查角度、母题、变式说明与外部引用。概览分别统计题数、知识点、概念及考查角度，变体不会被算成新增概念。

## 出题进度与断点恢复

出题使用独立后台批次；切页和刷新不取消任务。进度面板按实际已保存题数显示完成比例，并展示当前知识点、题型、耗时、速度、预计剩余时间与步骤清单。支持暂停、继续、仅重试未完成部分，并能选择历史批次。

每批的随机分配、资料快照、改写结果、生成草稿及处理位置持久化在宿主题库中。题目与对应草稿位置原子保存；恢复不会重新抽样或重复保存完成题目。退出应用会暂停批次，重新打开后可继续；若异常退出，未结束批次也会显示为可恢复。已完整返回并保存的步骤复用缓存；尚未完整返回或未写入的模型请求可能需要重做。
