# dsh-zhiyun-core-playback

**回放观感增强**：让回放的字幕可读、让进度条不再占地方。

纯逻辑、零 IO、零网络、零模型调用。

## 两条腿

| 模块 | 职责 | 在不在生产链路 |
| --- | --- | --- |
| `transcript.js` | **字幕轨**：清洗句子替换原始碎片、合并成句、尾噪降级、烧进播放器的当前句 | ✅ 学习页视频栏直接用它 |
| `alignment.js` | **三态契约** + 投影 | ✅ 三态给"时间可不可信"用 |
| `probe.js` | 离线 Δ 探针（一次性诊断） | ❌ 不进生产；见下 |

## 一、字幕为什么需要一条"轨"

`video-panel.jsx` 原先直接读 `content.subtitles.items` —— 那是智云语音识别的
**原始碎片**。真实一节课（`course 86582 / sub 1979657`，915 条）的前四条是：

```
5s    "行。"
24s   "是。"
34s   "嗯。"
56s   "是嗯。"
```

而同一门课在「学习」栏读的是 `core-parser` 的**清洗终稿**：句子带
`startMs/endMs`（`core.js:92`），按比例拆句也在原区间内插值
（`parser.js:116-120`）。**同一节课、两块屏，一块是"行。""嗯。"，
一块是连贯的句子。**

所以我们有干净数据，只是没拿它来渲染。`resolveTrack()` 只做这一个选择：

```
有清洗句子 → 用清洗句子（kind: 'cleaned'）
没有       → 退回原始碎片（kind: 'raw'）
```

**顺序不能反** —— 反过来等于有干净数据却去显示脏数据。

`kind` 必须显示在 UI 上（右栏标题旁那个「清洗后 / 原始碎片」标签）：
两者内容长得像，但可信度完全不同。不标出来，用户会以为碎片就是这节课的全部。

### 但「纠错」不等于「成句」——必须再合并一次

2026-10-28 的真实截图暴露了这个：右栏标着「清洗后」，内容仍是

```
00:17  嗯，三，第二个。嗯，对。行行行。嗯嗯嗯嗯，你就可以。
00:26  不行，说。你说那个情况下，都高速还是还对的。这个，这。
00:28  哎。
```

因为 `core-parser` 的 `sentences` 是**逐行纠错**（`core.js:72` 就是
`rawLines.map(...)`），一条字幕行一条 sentence，**不合并**。1343 条字幕行
→ 1343 条 sentence。纠错只修了字，没修「一句话被切成十段」。

**字幕的可读性来自成句，不是来自每个字都对。** 所以 `buildCues()` 再合并一次：

| 阈值 | 默认 | 为什么 |
| --- | --- | --- |
| `maxChars` | 34 | 超过会折三行、挡住画面 |
| `maxGapMs` | 800 | 停顿超过 0.8 秒就是两句，并起来会读错语气 |
| `maxDurationMs` | 12000 | 挂太久会让人以为卡住 |
| `minChars` | 8 | 太短（"哎。"）单独成条会闪，并回邻居 |

两条额外规则：

- **时间不可信的条目不参与合并**，各自成条 —— 合并会把不可靠传给别人；
- **短尾只回并一次**，不能一路吞到开头（否则隔着几十秒空档的两句话会被粘成一句）。

实测效果：11 条碎片 → 5 条可读句。

### 尾噪条：降级，不删除

`course 86582 / sub 1979657` 的最后一条：

```js
{ startMs: 6_965_000, endMs: 9_345_000, text: '对。' }   // 跨 39.7 分钟
```

老师 6965 秒就讲完了（之后是答疑/等待），但 ASR 一直开着麦，把最后一条
的 `endMs` 撑到了录像末尾。这一条：

- **不能删**（删了等于篡改数据，用户要看见原文）；
- **不能抢高亮**（播到 8000 秒时高亮"对。"是荒谬的）；
- **不能进时间轴**（会把时长分母和末段语速全拉歪）。

所以它被标成 `located_only`：显示、退一档、不参与 `activeIndex`。

判定用**中位数**而不是均值算基数 —— 一条 40 分钟的离群值会把均值从 10 秒
拉到 600 秒，中位数不动。

## 二、字幕要烧进播放器

原先字幕是右栏一个列表，视频在别处。**用户看画面时眼睛在画面上，字幕在右栏
就等于没有字幕。** 现在字幕条贴在画面底部，与 `<video>` 同一个格子：

```js
burnLine(subtitles, nowMs)  // → { index, line, hidden, leadMs }
```

三个细节：

- **第一条之前 `hidden: true`**，不从 `lines[0]` 开始显示 —— 提前显示会剧透，
  也让"还没开始"看起来像"已经讲到"。
- **句子说完、下一句没开始时继续挂着上一句**，并给 `leadMs`（距下一句还有多久）。
  直接闪成空白会让用户以为字幕坏了。
- **用绝对定位浮在画面上**，不占 flex 高度：占高度会改变 `object-fit: contain`
  的可视区，字幕出现/消失时画面会跳。

只在主视图是视频时渲染 —— 换成课件后视频进小窗，字幕会小到看不清，那时
右栏才是读的地方。

## 三、三态契约

```js
{ state: 'matched',     offsetMs, evidence? }   // 可以应用
{ state: 'located_only', locatedAt, awaiting? } // 位置有、时间不可信 → 不应用
{ state: 'refused',      reason, detail? }      // 拒绝
```

`located_only` **禁止**携带 `offsetMs`，`validateResult()` 会拦住它 ——
带了就会被调用方顺手应用。

这也是尾噪条的表达方式：它的文字是真的，但时间不可信。

偏移符号只有一种：`查表轴 = 播放时刻 + offsetMs`。

## 四、`probe.js` 为什么不进生产

实测 `course 86582` 七节课，字幕与 PPT 的 Δ = 0（同源、同原点、无漂移）。
**当前没有偏移可校正**，所以探针不进生产链路。

它留着是因为「这份时间轴能不能信」会反复出现。三种结论 + 第四态
`inconclusive`（锚点不足或证据矛盾时**不给结论**）—— 2 个点连直线必然完美拟合。

⚠ 已知局限：`suggestAnchors()` 靠「我们看下一页」这类话术找换页，在真实语料上
**命中 0 条**（老师不说这套话，且 PPT `text` 字段全为空）。这条路只在有 OCR
或课件文字时才有意义。
