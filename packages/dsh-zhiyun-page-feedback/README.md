# dsh-zhiyun-page-feedback

「反馈」页：一个嵌在工作台里的**迷你社区**，形态照 GitHub issue 来。

```
发一条需求 → 谁都能在下面评论 → 状态推进 → 有动静的浮到最前
```

与 GitHub 唯一的差别是**没有账号**：署名是一个本机生成的随机笔名（`访客-7f3a`），
存在 `localStorage`、可一键重置、不指向任何真人。用户全程不出工作台、不注册、不登录。

## 这一页怎么用

| 动作 | 发生什么 |
| --- | --- |
| 提一条新需求 | `POST /feedback`，服务端分配编号（`F-001`…） |
| 在别人（或自己）的需求下评论 | `POST /feedback/comment` |
| 看全部讨论串 | `GET /feedback`，按最后活动时间倒序 |
| 追踪已有条目 | 提交时选「追踪已有」，在标题里写上编号 |

每条需求的卡片上直接显示评论数与「官方已答复」标记，点进去就是完整讨论串。

## 数据在哪：**只有服务端一处**

条目与评论全在收件服务（`FEEDBACK_ENDPOINT`，部署在魔搭 Studio）上，仓库里**不再有**
一份只读的公开板。这是刻意的选择：两份来源会立刻开始互相打架（服务端的条目改了，
仓库那份不知道）。代价要认 —— **实例重启可能丢数据**，那时页面显示为空社区并说明
是连不上，而不是装作"还没有人提过"。

服务端的完整做法（为什么选魔搭、怎么复刻、安全边界）见
[docs/modelscope-as-cloud-server.md](../../docs/modelscope-as-cloud-server.md)。

## 不产生身份信息

这是本页最重要的约束，因为讨论串的内容会以公开日志的形式被所有人读到：

- **提交只发白名单字段**：`kind / title / detail / name`（需求）与 `issue / body / name`（评论）。
  收件端对白名单外的字段**直接拒收**，不静默丢弃 —— 客户端要是误传了真名或学号，
  第一次调用就会 400，而不是等我们发现数据已经公开了。硬断言在
  [tests/feedback.test.mjs](../../tests/feedback.test.mjs)。
- **署名只用本地随机笔名**：`board.js` 的 `localName()`。它表达"还是同一个人"，
  但那串十六进制不指向任何真人。收件端的 `FORBIDDEN_FIELDS` 与 `realName` 守卫会拦住
  任何试图夹带真名的字段。
- 客户端与收件端的**上限逐字一致**（标题 200 / 正文 4000 / 评论 4000），有测试盯着，
  漂移的表现是"用户填得好好的却被服务端拒了"。

## 官方答复（反馈机器人）

任何人都能以「反馈机器人」的身份回帖（`POST /feedback/robot`），**不需要任何凭证**：
拿到 [robot/SKILL.md](../../robot/SKILL.md) 就能用。工具在 [robot/feedback.py](../../robot/feedback.py)。

- **没有权限体系，这是刻意的**：这是个 demo 级反馈板，「谁想处理评论都行」比
  「防住冒充」重要。代价是任何人都能以机器人身份发言，也能把别人的需求标成「不采纳」。
- 回帖的「官方答复」尾巴由**服务端统一追加**，机器人脚本漏写也不会让读者分不清谁在说话。
- 页面据此把官方答复渲染成另一种样式（左侧换成强调色、加底色与标记）。

状态推进（`open / done / declined`）同样是公开的（`POST /feedback/status`）。

## 插槽与样式

| 插槽 | 内容 | 谁声明 children |
| --- | --- | --- |
| `zhiyun.feedback.content` | 页面正文 | 外壳 `main`（`shell/src/client.jsx` 的 generator） |

只 `inject: ['slots']`，**刻意不依赖任何领域服务** —— 反馈入口是用户唯一能说「哪里坏了」
的地方，不能因为别的包停用而一起消失；收件服务连不上时也只是页面顶部一条提示，页面本身
照常可用。样式类统一 `zfb-` 前缀，颜色只取外壳的 `--zy-*` 变量。
