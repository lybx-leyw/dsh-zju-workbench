# dsh-zhiyun-page-docs

「文档」页：把协作规范搬进工作台，形态照文档站来。

```
分区 tab（入门 / 协作 / 参考）
┌─────────┬──────────────────────────┬─────────┐
│ 左侧目录 │ 正文                     │ 页内目录 │
└─────────┴──────────────────────────┴─────────┘
                      上一篇 / 下一篇
```

三栏各管一件事：**分区 tab 管「哪一片」，左侧目录管「哪一篇」，右侧目录管「这一篇里有什么」**。
翻页跨分区连着走，从头读是一条不断的路。

## 内容从哪来：**内置副本**，不是运行时读 `docs/`

正文是包内的十一篇 markdown（`src/docs/*.md`）。其中十篇摘写自
[docs/contributing/CONTRIBUTING.md](../../docs/contributing/CONTRIBUTING.md) 与
[docs/contributing/AGENTS.md](../../docs/contributing/AGENTS.md)；「Vibe coding 参与指南」
是维护者口述后整理的，仓库里没有原文，页脚已照实注明。

为什么不直接读仓库里那份：

- 浏览器没有文件系统。客户端 bundle 打完之后只剩一个 `lib/client.js`，
  运行期拿到的是一个相对路径，指向哪里全看宿主从哪个目录启动 —— 靠不住。
- 想让它可读，就得多一个 HTTP 接口去吐 `docs/`，等于为一个页面开一条读文件的通道。

代价要认：**这是摘要，不是原文**。每篇末尾都标了源路径，页脚也写明「两处冲突时以原文为准」——
文档站最怕让人以为看到的就是权威版本。新增或改动规范时，`docs/` 与这里要各改一次；
两处漂移没有自动检查，只有 `tests/docs-page.test.mjs` 盯着「清单里的每一页都真有文件、
文件开头的 `# 标题` 与清单一致」这类**形态**问题。

## 三个纯函数层，为什么不塞进组件里

| 文件 | 干什么 | 为什么单独拆出来 |
| --- | --- | --- |
| `src/docs-manifest.js` | 分区与页的清单（纯数据） | 裸 Node 能直接 import，测试不用构建、不用宿主、不用浏览器 |
| `src/outline.js` | 扫标题、摘 h1、摊平、翻页、筛选 | 全是纯函数，输入字符串出数组，一行 DOM 都不碰 |
| `src/docs-content.js` | **唯一** import markdown 的地方 | 构建期资源集中一处，新增文档只改这里 |

`src/client.jsx` 只负责把这三层拼成界面。

## 三个必须绕开的坑

这两条都是先写错、真机验出来才改的，读者照抄时别再踩一遍：

**1. 页内目录不能靠锚点。** 宿主渲染标题时不写 `id`，而 `[x](#foo)` 这种 fragment
链接还会被链接 allowlist 降级成**纯文本**。所以目录只能按「第几个标题」滚动：
`outline.js` 用同一套规则（跳过围栏代码块）扫出标题表，`client.jsx` 用
`querySelectorAll('h2, h3')[i]` 去对。序号对不齐时直接不动，不做「猜一个最近的」兜底——
跳错地方比不跳更糟。

**2. 短文档滚到底要换判据。** 只有四个小节的文档里，最后一节的标题可能永远到不了容器顶线，
按顶线判断时点它看着像**没跳**（高亮还停在前一节）。真机量过：`offsetTop=825` 的标题
在 `maxScroll=615` 的容器里最多只升到距顶 210px。所以滚到底以后改用**屏幕中线**判定。

**3. 换了判据还不够，点完还得「钉住」。** 上面那条中线判据救的是"滚到底之后"，
可点击那一刻平滑滚动还没结束、高亮已经先设成被点的那条了——滚动事件随后按位置重算，
又把它改回前一节。表现为**点最后几条目录，高亮弹回上一节**。

修法是记一个 `pinned` ref：点目录时写下"这一条是我点的"，滚动判据看到它就不接管；
直到用户自己动手（`wheel` / `touchstart` / `keydown` / `pointerdown`）才清空，位置判据重新说话。
监听的是**人的动作**而不是 `scroll` 事件——平滑滚动的动画本身会连续触发出几十个 `scroll`，
拿它来解钉等于没钉。

## 样式

类名统一 `zyd-` 前缀，颜色只取外壳的 `--zy-*` 变量，明暗两套自动跟。

这一页在壳的 `FULL_BLEED_PAGES` 里，不套 `.zy-content` 的 980px 版心——它自己就是三栏，
再套一层会把正文挤成一条缝。**滚动也由这一页自己负责**（`.zyd-main` 是整页唯一的滚动容器），
所以工作台不再纵向滚动。

不跟着宿主的 `.markdown` 类写规则：那是 CSS Modules，产物里类名是 `_markdown_1ypvv_5`
这种哈希，跟它写会**静默失效**。要覆盖排版就走 `.zyd-md > div`（渲染器的根 div）。

## 插槽与依赖

| 插槽 | 内容 | 谁声明 children |
| --- | --- | --- |
| `zhiyun.docs.content` | 页面正文 | 外壳 `main`（`shell-workbench/src/client.jsx` 的 generator） |

只 `inject: ['slots']`，**不依赖任何领域服务** —— 协作规范不能因为某个业务包停用而一起消失。
宿主侧的 `src/index.js` 是空壳，但**必须存在**：客户端 bundle 靠宿主的
`ctx.loader.entries()` 进启动图谱，没有宿主入口的包不会被扫描，`dsh.client` 声明读不到。

## 新增一篇文档要改三处

1. `src/docs/<id>.md` —— 首行是 `# <标题>`，至少两个 `##`；
2. `src/docs-manifest.js` —— 加进某个分区的 `pages`；
3. `src/docs-content.js` —— `import` 进来并挂到 `PAGE_CONTENT` 上对应的键。

漏了第 3 步，页面上是「这一篇暂时读不到」；漏了第 2 步，文件存在但没人引用。
`tests/docs-page.test.mjs` 两种情况都会报出来。

**如果这一篇不是从仓库文档摘写的**（比如「Vibe coding 参与指南」是维护者口述后整理的），
在清单条目里加一个 `source` 字段覆写页脚。默认页脚写着「摘写自仓库文档，原文见
`docs/contributing/`」—— 对没有原文的篇目，那句话会把人引去找一份不存在的东西。

```js
{ id: 'vibe', title: '…', summary: '…', file: 'vibe.md',
  source: '本页由项目维护者口述、文档页整理，没有对应的仓库原文。' }
```

## 验证

```bash
npm run build                       # 构建，末行应出现 Built dsh-zhiyun-page-docs
node --test tests/docs-page.test.mjs # 清单、扫描器、隐私红线
npm run check:css                   # 样式归属（跨包冲突、@media 倒序）
npm test                            # 全量回归
```

**构建不能只跑测试。** `.md` 走的是 esbuild 的 `text` loader（`scripts/build.mjs` 的
`loader` 表），漏配会在构建期直接报 `No loader is configured for .md files`——
但这条只在真正构建时出现，`node --test` 完全看不到。

**真机还要再看一眼。** 单测盯的是纯函数与文件形态，而目录跳转、高亮跟随、筛选、
翻页这些只在真实宿主里才成立。最少走一遍：从导轨「···」进页面 → 点页内目录第三条
（高亮要跟着到第三条）→ 左目录换篇（回到顶部）→ 下一篇 → 分区 tab → 明暗各看一次。
