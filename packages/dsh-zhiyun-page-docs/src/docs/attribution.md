# 第三方来源与协议

参考本仓库之外的任何项目之前，**先确认对方的协议**。这一步不是形式主义：没有
许可证的代码默认保留所有权利，不是"应该没关系"。

## 第一步：找许可证

在对方仓库里找 `LICENSE`、`COPYING` 或 `NOTICE`，读一遍。三种常见情况：

- **有宽松协议**（MIT、Apache-2.0、BSD）→ 可以移植，按下面的规则记录。
- **有传染性协议**（GPL、AGPL）→ **不得用于本项目**。GPL 系列会要求衍生作品
  同样开源，与我们的分发方式冲突。
- **没有任何许可证** → 默认保留所有权利，**不得复制**。只能当作思路参考，
  而且这一点也要在记录里说明清楚：「参考了它的实现思路，未引入任何代码」。

## 第二步：按引入程度记录

| 程度 | 记在哪 | 写什么 |
| --- | --- | --- |
| 只做了简单借鉴（读了实现、换了写法，没有引入对方的实现） | 根目录 `ATTRIBUTION.md` | 一两行：项目、协议、参考了什么 |
| 移植了较多代码，无法用一两行写明 | 对应插件包内的 `ATTRIBUTION.md` | 用了哪些部分、来源与提交号、依据对方哪个协议所以合法、做了哪些改动 |

第二种情况还要在根 `ATTRIBUTION.md` 里指向包内那份，让人从一处能走到底。

## 不需要声明的情况

- **同一作者自己的项目之间**互相搬运（例如 `zhiyun-pro`、`zju-mcp`）。
  但**这一点由用户确认，不要自行判断** —— "我觉得是同一个人"不算依据。
- **第三方库通过 `package.json` 正常引入**并按原协议使用（`npm install` 装进来的、
  运行时依赖的那些）。这种情况协议随包走，不需要额外说明。

## 参考源码放哪

`.ref/`（DeepSeek Harness）与 `.ref-codex-ui/` 里有大量插件包与 profile 组合的实例：
包清单、宿主半边、浏览器半边、插槽注册都能找到对应的写法。它们**不是运行依赖**，
已被 `.gitignore` 忽略，需要时按「安装与启动」那篇第 1.4 节拉取。

```bash
git clone https://github.com/deepseek-ai/deepseek-harness.git .ref
git -C .ref checkout 5badb15009ae1756c3afe0ae0cef1faafc290ccc
```

提交号要与根 `ATTRIBUTION.md` 里记的一致。参考源码用于理解实现，
**运行时兼容性仍以 `runtime.lock.json` 为准**。

## 一个提醒

"我从一个 MIT 项目抄了一段"和"我照着一个没许可证的项目重写了一遍"是两件事，
但两者都要记录 —— 后者记的是"参考思路，未引入代码"。别让这两条在记录里混成一团。
