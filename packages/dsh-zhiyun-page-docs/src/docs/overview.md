# 项目概览

这个仓库的形态是：**用 DSH 插件把 DSH 改造成浙大专属的工作台**。

DSH（DeepSeek Harness）本身是一个可组装的 agent 宿主 —— 它提供会话、模型调用、工具、
以及一个可被插件改写的前端外壳。我们做的事情是把它的外壳换成一套面向浙大学习场景的
界面，再用一层层插件包把智云、学在浙大、CC98、图书馆这些数据源接进来。

## 一个工作台，由很多个包拼出来

界面上的每一项导航，背后都是一个独立的插件包。拆包的规则很简单：
**一页一个包，改动某一页时只动对应的包**。所以你在左侧导航里看到的每一页，
在 `packages/` 下都能找到同名目录。

这个工作台本身也遵守同一条规则 —— 「文档」这一页就是 `packages/dsh-zhiyun-page-docs`。

## 一个插件包的两个半边

每个能出现在界面上的包都有两个半边，分别跑在两个进程里：

| 半边 | 入口 | 跑在哪 | 干什么 |
| --- | --- | --- | --- |
| 宿主半边 | `src/index.js` | Node | 注册服务、工具、数据读写、后台任务 |
| 浏览器半边 | `src/client.jsx` | 浏览器 | 画界面，往宿主的插槽里注册组件 |

两个半边是**可选**的：纯数据包可以只有宿主半边，纯展示包可以只有浏览器半边。
但**只要浏览器半边存在，宿主半边就必须存在**（哪怕是空壳）—— 宿主的 Loader 只扫描
有宿主入口的包，没有入口就进不了启动图谱，浏览器半边的声明也就读不到。

## 数据是怎么到页面上的

```
智云 / 学在浙大 / CC98 …        （外部服务）
        ↓  source-* 包：登录、抓取、缓存
   core-* 包：解析、索引、领域逻辑
        ↓  通过 Cordis 服务把「控制器」交给外壳
   page-* 包：在插槽里画出这一页
```

页面包**不直接连外部服务**。它拿到的是一份已经准备好的控制面（`controller`），
负责订阅与读取；真正取数、解析、缓存的活在领域包里。这样一页的界面挂掉了，
数据那一层还活着，反过来也成立。

## 这一页为什么是内置文档

「文档」页要解决的是一个具体问题：**仓库里的协作规范写得很细，但没人会在写代码时
顺手去翻 300 行的 CONTRIBUTING**。把它放进工作台里，至少让"我该找谁改这个文件"、
"提交前要检查什么"这类问题有一个比 `ctrl+f` 更快的入口。

代价是文档有两份：仓库里的原文，和这一页里的摘要。取舍写在第四篇的末尾。
