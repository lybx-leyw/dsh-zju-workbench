# Vibe coding 参与指南

面向不打算系统学编程、但愿意用 AI 把想法做成功能的人。以下流程由项目维护者口述。

## 一句话说清

把仓库链接告诉 AI，让它根据项目说明 build 一个实例出来。你体验一下，发现哪里不足
或可以添加，就直接跟 AI 说，让它根据项目当前架构整改。改完再体验一次，看是否达到预期；
确认无误就让 AI 按项目规则推送上去。

## 为什么评估比实现重要

从产品设计的角度，我们并不需要关注仓库的代码写得好不好、用了什么算法。
我们关注的是产品最终的体验效果，也就是评估才是最重要的。这个项目正是如此。

## 六步走

### 1. 接受 GitHub 邀请

维护者发出 GitHub 邀请后，登上 GitHub 点接受。

### 2. 找一个 AI 编程工具

GPT 可能有点贵，可以先用 GPT-Sol 或 Luna 版本体验和改小的内容，之后也可以试试 DeepSeek。

### 3. 建一个专门的工作文件夹，在编程工具中打开它

把项目 GitHub 链接发给 AI，要求它 clone 仓库，并告知你要参与贡献，请它按仓库的
贡献规范配置环境、起一个实例，让你体验当前版本。可以复制下面这段：

```text
仓库地址：https://github.com/lybx-leyw/dsh-zju-workbench

请做三件事：
1. clone 这个仓库到当前文件夹，并切到新分支（不要直接改 main）。
2. 我想参与贡献。请先读 docs/contributing/CONTRIBUTING.md 和
   docs/contributing/AGENTS.md，按里面的规范把环境配好。
3. 起一个实例让我在浏览器里体验当前版本。起好之后把地址告诉我，
   并说明我该从哪里开始点。

配环境的过程中如果缺东西，先告诉我你打算怎么解决，不要自己装系统级的工具。
```

### 4. 看现在的版本，想清楚要增改什么

体验当前版本，确定要增加的功能或需要改进的地方。

### 5. 告知 AI 需要增改的地方，整改后重启实例让你验收

把要改的地方告诉 AI，让它按项目当前架构整改。改完后重启实例，再验收一次。

### 6. 确认无误后推送到 GitHub

使用 VS Code 等工具可以直接连 GitHub；否则需要先在 GitHub 申请凭证再交给 AI。
这一步可以跟编程 AI 讨论。

推送时注意两点：

- **提交与推送前必须先和用户确认**（见「个人信息与提交」）。
- 走 PR，不要直推 `main`。开 PR 即可，不必合并；合并建议等项目维护者执行，
  同时由他 review 代码。

## 两点前置说明

非计科类的学生用 vibe coding 做出来的新功能，实现上可能不够专业，这没有关系 ——
维护者会审查代码并优化。
