# dsh-zhiyun-core-vault

**Obsidian 式笔记库**：双向链接、标签、知识图谱、未解析链接、重命名改链。

纯逻辑 + 薄宿主半边。解析与索引是零 IO 的纯函数。

## 与 `dsh-zhiyun-core-notes` 的关系（两者互补，不互相 import）

| | `dsh-zhiyun-core-notes` | 本包 |
| --- | --- | --- |
| 单位 | **一节课**一份笔记 | **一篇**笔记（平级） |
| 键 | `课程/节次` | 文件路径 |
| 链接 | `zy://section/…` 跳回播放位置 | `[[另一篇]]` 连到知识网 |
| 解决什么 | 「这节课我记了什么」 | 「我的笔记之间怎么连」 |

同一段正文可以**同时**带这两种链接：`[03:20](zy://section/1/2?t=200)` 跳回课程，
`[[概率论-大数定律]]` 连到另一篇笔记。

## 它提供的三样"双向"能力

`[[链接]]` 是**单向**写下的，但用户要的是双向：

1. **反向链接** —— 「哪些笔记提到了我」。`buildIndex()` 全库重算得到。
2. **未解析链接** —— 「我写了一个不存在的笔记名」（Obsidian 的"未创建笔记"）。
   分 `missing`（找不到）与 `ambiguous`（同名多篇）两种原因。
3. **孤立节点** —— 既不引用别人、也没被别人引用的笔记。用来找出"还没连起来的想法"。

## 语法按 Obsidian 的真实语义实现

朴素的 `\[\[(.+?)\]\]` 正则会错在这些地方，而它们恰好是天天在用的：

| 语法 | 含义 | 朴素正则的错法 |
| --- | --- | --- |
| `[[笔记\|别名]]` | 显示别名 | 把 `笔记\|别名` 整体当目标，解析不到 |
| `[[笔记#小节]]` | 指向某个标题 | 目标里混进 `#小节` |
| `[[笔记#^abc123]]` | 指向某个块 | 同上 |
| `[[#小节]]` | **本文内**跳转（空目标合法） | 当成错误丢掉，或误报为断链 |
| `![[图片.png]]` | 嵌入（内容搬运） | 与引用混为一谈，图谱被图片污染 |
| `#标签` | 行内标签 | 把 Markdown 标题 `# 标题` 也算成标签 |
| `https://x/a#b` | URL | 从锚点切出假标签 |
| 代码块里的 `[[x]]` | 只是示例文本 | 抽出假链接 |

这些都有测试钉住（`tests/vault.test.mjs`，32 项）。

### 标签要求 `#` 前有分隔符

`与#紧贴的` **不算**标签，`见 #标签` 算。否则中文里正常出现的 `#`
（如「第#3章」）会变成一堆用户从没打过的标签。Obsidian 同样要求分隔符。

### 解析顺序：精确路径 → 同目录 → 全库 basename

`[[b]]` 写在 `a/x.md` 里时，`a/b.md` 优先于别处的 `b.md`。
全库同名多篇时**报未解析而不是随便挑一个** —— 随便挑会让 `[[笔记]]`
静默连到别人的同名笔记上，用户看到的反向链接是无意义的。

## 用法

### HTTP（页面用）

```
GET  /api/zhiyun-vault     → 索引概况
POST /api/zhiyun-vault     → { type:'client-request', rpcId, payload:{ method, args } }
```

方法：`describe` / `notes` / `note` / `backlinks` / `tags` / `tag` /
`unresolved` / `orphans` / `graph` / `resolve` / `parse` / `candidates` / `rename`。

### 宿主侧

```js
const vault = ctx.get('zhiyunVault');
vault.setNotes([{ path: 'a.md', markdown: '[[b]] #标签' }, ...]);  // 推入笔记集
vault.index().backlinks.get('b.md');                                // 拿索引
vault.invoke('graph');                                              // 同 HTTP 的读数
```

## 两条设计决定

**索引不持久化**，每次重算。笔记量级是几千篇，重算比"维护增量索引"便宜得多，
也根除了「索引与正文不一致」这类最难查的错。调用方要缓存就缓存
`buildIndex()` 的返回值，而不是另写一套增量逻辑。

**重命名只算不写**。`renameLinks()` 返回改写后的正文列表，
由调用方决定何时落盘 —— 那里才有事务与失败重试的上下文。
本包零 IO，与本仓其他领域包同一条纪律。
