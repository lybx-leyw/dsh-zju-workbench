# 微信读书与公众号

用 `node "<SKILL>/scripts/weread.ts" <命令> [参数]`，`<SKILL>` 换成本技能的目录。目录里常有空格（`C:\Program Files\…`），脚本的路径要像这样用双引号括起来。输出是 JSON：成功为 `{"ok": true, …}`，失败为 `{"ok": false, "status": …, "message": …}`，按 message 向用户说明。

用户给了公众号文章的链接（`mp.weixin.qq.com/s…`）要你看，直接 `read --url 链接`，不要先试别的办法去抓：那样会被验证拦住。

浏览器、微信读书的登录状态和验证码识别都由校园智能体提供，不用安装依赖，也没有要配的文件。跟踪名单和「插件」页「微信公众号」里的是同一份：用户在那里加的号这里看得到，这里加的那里也看得到。跟踪的号有没有新文章，应用自己每半小时看一遍，放在「校园事务」的通知里，不用你定时去查。

| 目标 | 命令 |
|---|---|
| 某公众号最近的文章 | `list --account 名称 [--limit 数量]`；不带 `--account` 是跟踪名单里每个号的 |
| 不确定公众号叫什么 | `accounts --query 名称的一部分` |
| 把文章存成 Markdown 和图片 | `download --url 链接 --out 目录`，或 `download --account 名称 --title 标题 --out 目录` |
| 只读正文 | `read --url 链接`，或 `read --account 名称 --title 标题` |
| 开始跟踪 / 看跟踪名单 | `track --account 名称`；不带参数只列名单；加 `--cancel` 停止 |
| 跟踪的公众号有没有新文章 | `new [--account 名称]` |
| 登录、退出微信读书 | `login`；`login --check` 只看有没有登录；`logout` |

每个命令一步到位：download 自己取正文并转换，不用先 read；按名称和标题下载不用先 list。`--help` 和 `download --help` 查看参数。

## 用法要点

- 名称和标题可以只写一部分，但只能匹配到一个；匹配到多个时返回 `candidates`，换成完整名称重试。
- list 返回的每篇文章的 `url` 可以直接交给 read/download，也支持微信原文的长短链接；不支持 `/web/reader/…` 阅读页链接。
- download 的 `--out` 用这次对话的工作目录。保存为 `目录/标题-哈希/标题.md`，图片在同级 `images/`，Markdown 里用相对路径；下载失败的图片保留远程链接并列在 `images.failed`。
- new 只返回上次检查之后新出现的文章，返回过就不再返回。第一次经由某个来源检查时只记录现状。list 只看不记，不影响 new。
- 当前按标题查找最多检查最近 100 篇，跟踪每次检查最近 50 篇，不用于完整历史归档。

## 来源

只用微信读书查找公众号文章，需要先登录（`login` 会在应用里弹出扫码窗口），公众号需先在手机微信读书 App 中加入书架。公众号插件不读取本机微信聊天数据库。

文章链接由应用浏览器加载并转为 Markdown；也可以直接 `read --url` 读取公众号链接。

## 验证码

微信原文或微信读书要求验证时，当前命令自己处理。免交互验证由页面自动完成；需要答题时，「微信公众号」里的「自动识别验证码」开着就由模型在后台作答，不弹窗口，关着则弹出验证窗口等用户完成（最长约 5 分钟）。通过后继续提取正文。验证没通过时命令报错，重新执行即可；`rate_limited` 表示需要过一段时间再试。

`verification_required`、`login_required` 表示要用户本人验证或扫码，而这次没有开窗口。不要重试，请用户到「插件」页的「微信公众号」里处理。
