## 一句话结论

**小红书是「免登录只给目录，不给内容」**。网页版已全面强制登录：
发现页、搜索、笔记详情一律 302 到 `www.rednote.com/login`。
唯一免登录可用的结构化资产是 **sitemap：13 份文件、共 500,000 条**去重后无重复的笔记 URL——
但那只是 **ID 清单，不含标题、正文、图片、作者**。

## 50 万条 noteId 是什么、不是什么

### 精确的时间边界（逐份实测，非推断）

| 份 | 条数 | 时间范围 |
|---|---|---|
| 0 | 40,000 | 2023-12-22 → 2025-10-01 ⚠️ 见下 |
| 1 | 40,000 | 2025-10-01 → 2025-10-30 |
| 2 | 40,000 | 2025-10-30 → 2025-11-29 |
| 3 | 40,000 | 2025-11-29 → 2025-12-28 |
| 4 | 40,000 | 2025-12-28 → 2026-01-25 |
| 5 | 40,000 | 2026-01-25 → 2026-02-25 |
| 6 | 40,000 | 2026-02-25 → 2026-03-25 |
| 7 | 40,000 | 2026-03-25 → 2026-04-18 |
| 8 | 40,000 | 2026-04-18 → 2026-05-11 |
| 9 | 40,000 | 2026-05-11 → 2026-06-05 |
| 10 | 40,000 | 2026-06-05 → 2026-07-12 |
| 11 | 40,000 | 2026-07-12 → 2026-09-08 |
| 12 | 20,000 | 2026-09-08 → **2026-10-20**（最新） |

**关键修正（推翻了「覆盖约 3 年」的初判）**：
0 号文件虽标称 2023-12-22 起，但那只是 **4 条异常/测试样本**（2023-12-22、2024-06-19、
2024-07-07、2024-07-18），之后是 **380.3 天的空档**，真实密集起点是 **2025-08-02**。
- **2025-08-01 之前：仅 4 条**
- **2025-08-01 之后：499,996 条**
→ 实际有效覆盖 **≈14.6 个月**（2025-08-02 → 2026-10-20），不是 3 年。

**最新时间戳是 2026-10-20**（探索日 11-20）→ sitemap **滞后约 1 个月**，不是实时。

### 是什么
- 24 位 hex，**前 8 位是 unix 时间戳的 hex**（`6585468d` = 2023-12-22，`6ad6efd0` = 2026-10-20）。
- 13 份按时间**严格连续切分**、无重叠（去重后 500,000 = 原始总数，**0 重复**）。
- 每份 40000 条，12 号 20000 条（是否截断于某上限未知）。
- **无 lastmod、无 etag、无 changefreq**（note sitemap 全都没有，只有 worldcup 有）。
- 月产出稳定在 **3.5–5.2 万条/月**（2026-04 峰值 52,148）；2026-10 只有 2,039 条是**因为只到 10-20**，非真跌。

### 不是什么
- ❌ **不是内容**。没有 title / desc / 图片 / 作者 / 点赞数，只有 URL。
- ❌ **不是全站全量**。50 万条 / 14.6 个月 ≈ 3.4 万条每月，相对小红书全站体量是**搜索引擎收录子集**，是抽样。
- ❌ **不能直接换来正文**。拿 ID 打 `/explore/<id>` 一律 302 到登录页。
- ❌ **不是「全部新建笔记」**。sitemap 收录标准未知（可能只收有 SEO 价值的公开笔记），
  不能当作「小红书月产笔记数」的计量口径。

**能拿它做什么（合规范围内）**：noteId 时间戳分布 → **被收录笔记的产出速率时间序列**，
可做「量」的趋势分析。做不了任何「质」的分析（选题/内容/作者）。

## 坑

1. **`.xml.gz` 后缀是骗人的**。文件名带 `.gz`，`content-type` 却是 `application/xml`，
   `zlib.gunzipSync` 报 `incorrect header check`。**直接按纯文本读**。
2. **13 份文件字节数完全相同（3720110）极易误判为「同一份被重复返回」**。
   必须用哈希或首条 URL 验证——实测 5 份 sha8 全不同、去重后 0 重复，是真切分。
3. **「HTTP 200 + `__INITIAL_STATE__` 存在」≠ 有内容**。登录页 HTML 也有
   `__INITIAL_STATE__`（236,958 bytes），但里面是登录态空壳。
   判断标准只能是**正文文本长度 + 是否含 noteDetail**。
4. **时间戳不能只看首尾**。0 号文件首条是 2023-12，末条是 2025-10，**不代表这区间被覆盖**——
   中间有 380 天空档。必须逐条算 min/max/直方图，否则会把 4 条异常样本当成 3 年跨度。
5. **robots 把正文页只开给白名单搜索引擎**（原文）：
   - `User-agent: Googlebot` → `Disallow: /`（只 `Allow: /worldcup26`）
   - `Baiduspider / bingbot / 360Spider / Sogou / YisouSpider` → `Disallow: /` 后
     `Allow: /$`、`/explore`、`/worldcup26`、`/download`、**`/sitemap.xml`、`/sitemap-notes-`**、`/sitemap-worldcup.xml`
   - `User-agent: *` → `Disallow: /`（全禁）
   → **sitemap 是站点主动开放的**，拿 sitemap 合规；正文页没有对通用爬虫开放。
   改 UA 冒充搜索引擎去抓正文，既越界也无效（实测 302）。
6. **页面自报身份**：`window.__XHS_SEARCH_CRAWLER_FLAG__={"google":false,"bing":false}`——
   站点会自己标注当前流量是不是搜索引擎爬虫，改 UA 一目了然。
7. **移动站当前 502**（节点 PS-HND-04ez876），`m.xiaohongshu.com` 不能作为免登录旁路。
8. **`/worldcup26` 是「假的可读页」**。它是 robots 里唯一对 Googlebot `Allow` 的路径，
   `GET` 也返回 200 / **644,307 bytes** 完整 HTML，看起来像「免登录可读内容页」——**渲染后只有页脚**：
   正文文本 834 字符、`a[href*="/explore/"]` = **0**、`img` = 2。等 20 秒、滚动 4 次都不变。
   它的内容来自 `/api/sns/web/worldcup/{access_check, dots/display_period, nockout_bracket, watch_more, hightlights}`，
   无 cookie 直打结果：`display_period` → **406** `{"code":-1}`，其余 → **404 page not found**（缺 `X-s`/`X-t`）。
   → **HTML 体积不能当作「有内容」的证据**，必须渲染后数字符数和链接数。
9. **本机两条通道是同一出口**（fetch 经代理与 node:https 直连落到同一出口 IP），
   两条通道风控待遇无差别，别指望换通道绕过。

## 复现命令

```bash
# sitemap 全量枚举（13 份，串行 2.5s，约 35s）
node ~/.yonkik/sites/www.xiaohongshu.com/crawler.mjs notes --all
# 只取某一份
node ~/.yonkik/sites/www.xiaohongshu.com/crawler.mjs notes --index 0 --limit 20
# 产出 noteId 月度分布（只做「量」的分析）
node ~/.yonkik/sites/www.xiaohongshu.com/crawler.mjs timeline
```
