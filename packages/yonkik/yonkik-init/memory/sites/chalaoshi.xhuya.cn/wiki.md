## 一句话结论

**CC98 上学生查老师评分，实际是在几个「查老师」镜像之间来回找活的那个。**
2026-11-20 实测，**只有两个活着**：
- `dahua309.uk` —— 网页版的原站（Cloudflare），**能用但无 API**
- `chalaoshi.xhuya.cn` —— Vercel 上的**代理 + 结构化 API**，5 个端点全部免鉴权、支持 CORS

原站 `chalaoshi.de` **本机 DNS 解析失败**（ENOTFOUND），CC98 多帖说「被墙了/要科学上网」与此一致。

## 免鉴权 API 契约（5 个端点，全部实测通过）

基址 `https://chalaoshi.xhuya.cn`，全部 `GET`，无需任何鉴权头，支持 CORS。

| # | path | 用途 | 实测 |
|---|---|---|---|
| 1 | `/api/search?q=<姓名或拼音>` | **按名搜老师 → 拿 tid** | `q=陈建海` → `{count:1, teachers:[{tid:"1902", name, college, score:"9.8"}]}` |
| 2 | `/api/teacher/<tid>` | **老师详情：评分/人数/点名率/各课绩点** | `tid=2218` → `{name:"徐翔", score:"9.31", ratingCount:"262", rollCallRate:"21.8%", commentCount:"231", courses:[{name:"优化实用算法",gpa:"3.93",count:"465"},…]}` |
| 3 | `/api/comments/<tid>?sort=time\|rate&limit=1-100&offset=` | **评论列表（可分页排序）** | `2218&limit=3&sort=rate` → `{total:231, hasMore:true, comments:[{content, likes:74, date:"2018.09.16"}]}` |
| 4 | `/api/gpa?course=<课程名>` | **★ 按课查全部老师的平均绩点** | `course=概率论与数理统计` → `{count:14, rows:[{teacher:"梁克维",gpa:"3.85 ±0.87",count:"88"},…]}` 按绩点排序 |
| 5 | `/api/recent` / `/api/health` | 最近查询 / 存活检查 | `health` → `{ok:true, upstream:{web:[…],api:[…]}}` |

**`/api/gpa` 是这里最有价值的一条**：CC98 上大量帖子问「这门课哪个老师给分好」，
这一条直接给出**同一门课所有老师的 gpa ± 标准差 + 上报人数 + 排序**。

### 数据来源（API 自述，可核实）
> 「老师评价数据来自**匿名用户上报**，课程绩点数据来自**「课否」**；均为**历史数据**，仅供学习参考。」

## 数据可信度的真实边界（这是最该看的一节）

CC98 上对这个平台的质疑集中在三处，**全部有帖可查，且平台自己承认是历史数据**：

| 质疑（帖 id） | 具体说法 | 实测/可核实 |
|---|---|---|
| **评分太老**（6683918） | 「评分都很古早，就算有近年的评论也很少」 | ✅ **可验证**：`/api/comments/2218?sort=rate` 点赞最高的三条日期是 **2018.09.16 / 2016.05.18 / 2015.07.02**。高赞评论确实集中在多年前 |
| **新老师不更新**（6660461） | 「longlongago 在 github 提交了新老师，却迟迟没有更新」→ 回复「**一般每年更新一次**，有时也会蹭热点（比如王清风）」 | ✅ 与「手动提交 + 年度更新」的运营模式一致 |
| **均绩不可信**（6623596，13 帖） | 楼主按平台均绩推算排名，结果与实际不符；多人「听说那个菌剂有点古早了」；但也有人说「8 月做过一次数据同步，新课能看到数据了」 | ⚠️ **两方说法并存**：均绩来自「课否」（第三方），且「只统计用那个平台的人」，**样本有选择偏差**；另有用户指出「人数远高于真实选课人数」 |
| 评分被干预（6702930） | 有镜像站失联，多人猜「被封」 | ⚠️ 帖内自我修正：「**也不是被封了吧，就是有人搭的镜像站欠费了**」→ 是运营问题，不是被封 |
| 评论被篡改（6551448） | 「某些评价为什么变成了随机的知识点」 | ⬜ 未验证（示例指向特定老师，未逐条核） |

### 使用建议（据实测，非臆测）
1. **优先看 `/api/gpa?course=` 的「同课多老师对比」**，而不是老师的总分——
   总分是跨课程聚合，同一老师不同课差异大（徐翔三门课 gpa 分别 3.93 / 3.59 / 3.45）。
2. **评论按 `sort=rate` 取高赞**，但**注意日期**：高赞常是多年前的。要近期意见得 `sort=time`。
3. **`count` 字段要看**：人数少的老师（如 47 人）统计噪声大，别当定论。
4. **它替代不了问人**。CC98 多条回复都指向同一结论：
   「只做参考，可以多问问吧友或上过课的人」（6683918#1）、
   「感觉老师签不签到还是要问自己熟悉的学长」（6601217#7）。

## 坑

1. **`chalaoshi.de` 本机 DNS 直接 ENOTFOUND** —— 别把「解析失败」当成「站点下线」；
   它可能只是被墙，用代理可通（CC98 多人证实）。
2. **`chalaoshi.netlify.app` 返回 503 + `{"error":"usage_exceeded"}`** ——
   Netlify 免费额度耗尽，**不是代码问题**。
3. **`chalaoshi.xhuya.cn/api/teacher/search?q=` 会回 400**（`tid 必须是 1 至 20 位数字`）——
   搜索端点是 **`/api/search`**，不是 `/api/teacher/search`。命名极易混。
4. **`/api/search` 支持拼音**（`chenjianhai`），但**中文名要 URL 编码**。
5. **`/api/gpa` 的 `count` 是老师人数，每行的 `count` 是上报样本数** —— 两个同名字段语义不同。
6. **`gpa` 字段是带标准差的字符串**（`"3.85 ±0.87"`），不是数字，解析要 split。
7. **`/api/recent` 只存在内存，重启即清空，多实例不共享** —— 不能当「榜单」用。
8. `dahua309.uk` 与 `xhuya` **同源**：改一边的数据另一边可能滞后（缓存 25 条）。

## 原站 chalaoshi.de 校正（2026-11-22）

本 wiki 早前记「`chalaoshi.de` → **DNS ENOTFOUND**（原始站点，CC98 称被墙需代理）」。
**2026-11-22 复核：原站可访问。**

### DNS

| 域名 | 本地 DNS | 公共 DNS（DoH） |
|---|---|---|
| `chalaoshi.de` | 198.18.0.9（代理伪造） | **104.21.33.250 / 172.67.152.14**（Cloudflare） |
| `api.chalaoshi.de` | 198.18.0.10（代理伪造） | 172.67.152.14 / 104.21.33.250 |

早前那次 ENOTFOUND 是**当时的网络环境**问题（代理规则不同），不是站点消失。

### 站点可达性

| URL | 结果 |
|---|---|
| `https://chalaoshi.de/` | **200，16,267B，text/html** |
| `https://api.chalaoshi.de/` | 200，1,439B（不是 JSON API，是个网页） |

### 关键：**原站没有 `/api/gpa`**

| URL | 结果 |
|---|---|
| `https://api.chalaoshi.de/api/gpa?course=高等数学` | **404**（Flask 风格 404 页） |
| `https://chalaoshi.de/api/gpa?course=高等数学` | **404**（Apache 404） |

而 `chalaoshi.xhuya.cn/api/gpa` 是 **200 有数据**的（本 wiki 主记录的那个 API）。

**结论：结构化 GPA API 是 `xhuya.cn` 这个镜像站独有的，原站没有。**
所以要做「一次对比同课全部老师均绩」，**只能用 `chalaoshi.xhuya.cn`**，原站帮不上。

## 上游 `/gpa` 路线的核对（2026-11-22）

上游清单写的是 `GET {origin}/gpa`，本地早前只测过 `/api/gpa` 并得 404。本轮把三种 origin 都测了：

| 目标 | 结果 |
|---|---|
| `api.chalaoshi.de/gpa?course=…` | connect **ETIMEDOUT 157.240.3.8:443** |
| `api.chalaoshi.de/`（根） | 同样 ETIMEDOUT —— 不是路径问题，是该主机在本环境整体不可达 |
| `chalaoshi.de/gpa?course=…` | getaddrinfo **ENOTFOUND**（本环境解析回落，≠站点消失） |
| `dahua309.uk/gpa?course=…` | **404**（444B）——原站家族**没有** `/gpa` 这个路径 |
| `dahua309.uk/` | **200**，15,522B，网页版可用 |

**结论**：上游的 `GET {origin}/gpa` 在原站家族上取不到数据；同义能力实际由镜像 `chalaoshi.xhuya.cn` 的 `GET /api/gpa` 提供（200，结构化返回）。这不是本地漏了一个端点，而是上游那条路径本身不可用。既有 5 个免鉴权端点不变。

**DNS 提醒**：本轮三个域名分别被解析到 198.18.0.9 / .10 / .11（IANA 保留的基准测试网段），再次印证本环境 DNS 走代理，**解析结果不能当作站点存活证据**。
