# 安全边界：语义只读

判定标准只有一个：**这次调用会不会改变服务端状态？** HTTP 动词只是线索，不是判据。

## 允许 / 禁止对照

| 类别 | 例子 | 判定 |
|---|---|---|
| 读取资源 | GET 页面、详情、列表、文件下载 | ✅ |
| 查询/搜索 | POST `/api/search`、`/opac/ajax/search` | ✅ 只读语义的 POST 允许 |
| 建立会话 | 登录、CAS 跳转、token 换取 | ✅ 唯一写例外，只用用户给的凭据 |
| 创建/提交 | 下单、发帖、交作业、提交表单 | ❌ |
| 修改/删除 | 改资料、删记录、退课、取消预约 | ❌ |
| 社交动作 | 点赞、收藏、关注、评论 | ❌ |
| 状态副作用 | 标记已读、清除通知、签到 | ❌ 看似无害，仍是写 |

## 灰区怎么处理

- **退出登录**：会使 state.json 失效，探索期不调用；让会话自然过期。
- **浏览计数 / 心跳 ping**：页面自动发的随它去，不主动重放。
- **获取下载 token / 预签名 URL**：若只是读取凭证（不产生服务端记录）可调；
  拿不准就记 unverified，让用户在浏览器里点一次、从 `requests` 里观察。
- **刷新 token**：通常只读会话延续，可调；若响应里出现新资源 ID，按写处理。

## 未知 POST 的判定顺序

1. 看触发它的 UI 文案：「查询/搜索/检索/预览」→ 倾向只读；
   「提交/保存/确定/删除/报名」→ 写，不调。
2. 看路径与参数语义：`/search`、`/query`、`/list` + 关键词/分页参数 → 倾向只读。
3. 仍不确定 → **不调用**。记入 unverified，写清疑似语义和来源页面。
   一次误写的代价远大于少探一个接口。

## 下载伦理

- 串行下载，不并发轰。电子书/文献站常见并发上限 1–2，超了会封会话。
- 大文件先 HEAD 看 `Content-Length`，心里有数再下；支持 `Range` 的站优先断点续传。
- 下载链接常带时效 token：记录 token 从哪个接口来、有效期多久，写进 wiki，
  脚本里现取现用，不硬编码过期链接。

## 授权边界

- 401/403 → 记录状态码即止。不换 UA 伪装、不试绕 WAF、不遍历他人资源 ID。
- 只访问用户账号本来就有权访问的资源。WebVPN 只是通道，不扩大权限。
- robots.txt 的 Disallow 是爬取范围约定：探索期尊重它；用户明确要访问的
  自己有权的页面除外，但要在 wiki 里注明。

## 凭据卫生

- 密码：只存 `secrets/credentials.json`。脚本通过 `client.credentials()` 读取。
- 会话 cookie：只存 `sites/<key>/state.json`（gitignored）。
- 日志只打 method/path/status，不打请求头、cookie、响应体里的敏感字段。
- 往聊天/WIKI/commit 里贴内容前，扫一眼有没有密码、cookie、token 值。
