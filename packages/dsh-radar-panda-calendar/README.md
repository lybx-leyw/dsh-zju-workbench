## 接入边界（重要）

1. **这是骨架，不是实现。** `src/index.js` 的 `apply()` 刻意留空。
2. **不改上游源码。** 只锁版引入，由本包 `cordis.patch.yml` 挂载。
3. ⚠ **首要待决：与本轮 🟡 候选 `SylarLong/iztro` 划界。**

   两条**同域**（农历 / 历法底层）—— 上游的历法表**正是从 `lunar-javascript` 生成**，
   而 `iztro`（MIT，★4227）是另一套独立实现。**只能取一个**：

   | 选项 | 得到 | 代价 |
   | --- | --- | --- |
   | (a) 取本骨架 | 整包挂载，**自带 UI**，零开发 | 会带进**与本仓无关的命理排盘**模块（见第 4 条） |
   | (b) 取 `iztro` | 只有库、无 UI，依赖干净 | 历法展示**须本仓自写** |
   | (c) 都不取 | 零风险 | 「今天」页永远只有公历 |

   **建议方向（非本骨架结论）**：若本仓确定要"历法表达"，(b) 的边界更干净
   （`iztro` 作为库可只 import 历法那部分，不会有 UI 污染）；
   若只想要"最快见效"，(a) 更省事但须接受第 4 条的取舍。**须人工拍板。**

4. ⚠ **不使用上游的命理能力。** 上游依赖 `iztro` 提供**紫微斗数排盘**，
   另有天气 / 时间戳转换 / 历史上的今天。
   **本骨架只取**：公历↔农历 / 干支 / 生肖 / 节气 / 节日 —— 这五种。
   接入面上**不得出现**任何命理相关字样或入口。**属产品取向判断，须人工确认。**

5. ⚠ **上游默认会多出一个页头标签页。** 它在 `conversation.view` slot（order 30）
   注册「熊猫日历」标签。**是否允许它在会话页头出现，须人工裁决** ——
   若不允许，须找到「只引入历法模块、不注册标签页」的承载方式。

6. **注入点须核对。** 上游声明 4 个 `inject` 点（runtime / locale / ui-slots / ui-conversation），
   其中 `ui-slots` 是本仓多个 `dsh-zhiyun-page-*` 共用的挂载点，**须逐一确认不争抢**。

7. **不接入 profile。** 绝不写入 `profiles/zhiyun-bench/package.json`。
