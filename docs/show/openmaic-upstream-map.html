OpenMAIC 是 一条生产线、一间教室，
外加 一套能写课的工具。

本页按「用户能做的事」把上游拆成 9 个功能。每个功能给出一条工作流，并在每一步标注它属于哪类门控： 人在回路里拍板（人类门控）、确定性代码检查（系统门控）、还是由模型判断/打分（LLM 门控）。 外部模型服务单独标灰，避免把「调了模型」误读成「模型在把关」。 本版补充了并发与超时预算、运行期资源边界、以及「文档说 vs 代码实际」的冲突清单。

人类门控

必须有人看到并做决定：确认大纲、发布课程、学生答题/提交。人可以改内容后再放行。

系统门控

确定性代码判定：schema 校验、解析修复、字数/场景数上限、权限、并发与重试策略、评分阈值。

LLM 门控

由模型判断/打分/选路：判分、PBL 评价、导演决定谁发言、大纲决定场景类型。

外部服务

模型供应商、PDF 抽取器、TTS/图像/视频、渲染容器。它们执行任务，不替产品做准入判断。

F1

课堂生成：两阶段流水线，跑在服务端

给一句学习需求，或再附上 PDF / 文档材料，产出一门可播放的完整课堂。提交后是异步任务：关掉标签页也继续跑。

输入 requirement · materialIds · interactive · taskEngine · agents · outlineReview · voice 输出 Stage 文档：场景 + 动作 + 讲解 + 媒体 + 完成标记
  1. 01受理：建一个 generation runapp/api/generate-classroom/route.ts

    先解析 owner（cookie 身份），再校验请求体、所需模型槽位、每 owner 的活跃任务数，最后入队。

    SYSbody schema · 模型槽位齐备（400） SYS并发配额：每 owner 活跃 2 / 排队等确认 10 / 每进程 4；超限 429 ACTIVE_RUN_LIMIT SYS宿主可插 authorizeStart 钩子，在入队前拒绝
  2. 02材料分析（有 materialIds 时才跑）lib/server/generation/steps/material-analysis.ts

    调文档抽取器拿到正文与图片；图片按上限进入视觉提示。生成流水线只选一个抽取器（首选用首选，否则取首个同时支持该 MIME 与所需能力的），都不支持则整步失败；Pro 会话的抽取才按候选顺序逐个试。

    EXTPDF / 音视频抽取器 SYSMIME 与抽取格式校验；视觉图 15s 预算、连续 3 次失败熔断并降级
  3. 03研究（webSearch 槽位可用时才跑）lib/server/generation/steps/research.ts

    先用小模型把需求改写成检索式，再搜索，把结果格式化成大纲提示的上下文。

    LLM检索式改写 EXT搜索服务 SYS无槽位则整步跳过并记“什么都没做”，计划不漂移
  4. 04大纲：流式生成场景计划lib/server/generation/steps/outline.ts

    模型边写边流；每场标出类型（slide / quiz / interactive / pbl）、要点、时长、媒体请求。交互模式与职业任务引擎各有独立提示模板。

    LLM决定场景数量、类型搭配、每页要点 SYS增量括号扫描器边流边解析（大纲不走 JSON 修复）· 512KB 缓冲上限 · 最多 100 场 · 结构归一化 SYS同模型重试 2 次，再切 fallback 模型 1 次，每次重试都发事件 SYScontent-filter 安全拒绝：不重试、也不切 fallback，直接停
  5. 05大纲确认：唯一必过的人类门POST /generation-runs/:id/confirm-outline · hold-outline

    大纲落盘后，run 主动释放 worker 等确认。人可以原样放行，也可以改完再放行（改过则 revision+1）；确认后 run 才继续。

    HUMAN确认 / 编辑后确认 SYSrevision 不匹配 409 · 命令幂等（commandId）· 确认后重新计入并发额度
    wait一直等人确认。设置项“总是审大纲”打开时用它；input.ts 的 schema 缺省也是它，但真实入口很少走到。
    countdown就绪后等 2500ms 自动确认。默认产品路径（reviewOutlineEnabled 默认 false）；期间点开审阅会 hold 住。
    auto生成大纲的同一次提交里直接确认，不等人。批量/脚本入口用。
    这三档是同一个门的三种开法，不是三道门。只有 auto 会让人彻底离场。
    生成期课程对其它写者只读；标题为空的场景会挡住“确认并生成”。未产出课程前可 discard，重复 discard 或该 run 已有课程时返回 409。
    三种默认值互相矛盾：浏览器默认 countdown（2.5s 自确认），显式开关才变 wait，无头生成 API 强制 auto；input.ts 里写的缺省 wait 几乎没有真实调用方。文档里“除非 auto 否则永远等人”是过期表述。
  6. 06智能体阵容：教师 + 助教 + 学生lib/server/generation/steps/agent-profiles.ts

    按课名与大纲生成人设、头像、音色绑定；教师优先使用学习者选的旁白音色。

    LLM人设与分工 SYS质量判定：≥2 个 agent、恰好 1 个 teacher、JSON 可解析 SYS不合格或生成失败 → 静默回落内置预设（run 不暂停，事件流也看不到）
  7. 07逐场景三段：内容 → 动作 → 讲解steps/scene-content.ts · scene-actions.ts · narration.ts

    每个场景按大纲顺序跑三步；旁白生成与“把场景追加进课程”在同一次提交里完成，所以断点不会留下半个场景。

    LLM内容与动作脚本（文本即讲解词，动作即聚光灯/白板/讨论…） SYS内容解析失败返回 null → 重试：首场景 2 次，其余 5 次；再失败 run 暂停在该步 SYS动作走 jsonrepair/partial-json，并按场景类型做 action allowlist（如测验只允许 text） SYS整场装配失败 = assembly-failed；写库前 validateAppScene 再校验一次 EXT服务端 TTS：长句切分，克隆音色不可用时回落
  8. 08媒体支线：与场景并发生成lib/server/generation/run/media.ts

    大纲里的图片/视频请求按 elementId 去重后进独立泳道。媒体失败不暂停 run；放置进场景最多重试 3 次。

    EXT图像 / 视频生成服务 SYS永久失败码不提供 Retry；配额满单独说明但可重试上传
  9. 09完成与发布stages/[id]/generation-complete · publish

    生成完成只表示文档齐了；对外可见是另一个动作，需要真实账号与 course:publish 角色。

    HUMAN点发布；匿名 owner 一律拒绝 SYS角色校验 · 租约/心跳/接管保证多进程只有一个 worker 写
失败与重试语义（决定“卡住时会发生什么”）
情形类别行为
408 / 409 / 425 / 429系统按指数退避重试，带抖动；上限可配
400 / 401 / 403 / 404 / 422系统不重试，直接判定该步失败
步内重试耗尽系统run 暂停在该步；Retry 命令从该步继续，已完成检查点不重算
worker 进程死亡系统租约过期被其他进程接管；接管次数超限则暂停
媒体永久失败系统不暂停整条 run，场景保留失败元素并说明原因
每步超时预算（deadline.ts；超时按该步失败处理，可从检查点 Retry）
步骤预算说明
材料分析 / 研究 / 大纲 / 场景内容各 300s四段主链路的单步上限
场景动作60s动作脚本通常比正文短，预算更紧
旁白片段30s按片段计；TTS 慢不该拖住整场
并发与超时只决定「何时算失败」，不提高生成质量；重试是再问一次，不是审校。
F2

深度交互模式：让课堂变成可操作页面

生成阶段打开 interactive 后，大纲会把一部分场景规划成交互组件，产物是一段自带样式的 HTML，而不是幻灯片。

输入 主题 + interactive: true 输出 interactive 场景：html / widgetConfig + 动作脚本
  1. 01大纲选型：哪些页做交互、做哪一种packages/@openmaic/generation/src/outline-types.ts

    模型在大纲里给出 widgetType 与结构提示（图类型、语言、游戏类型、3D 对象、步骤与成功标准等）。DSL 里共 6 类：simulation / diagram / code / game / visualization3d / procedural-skill。其中 procedural-skill 只挂在 taskEngine 模式，普通交互模式不接收。

    LLM决定是否交互、交互形态与参数
  2. 02内容生成：按组件类型选模板产出 HTMLpackages/@openmaic/generation/templates/*-content

    每种组件有自己的 system/user 模板，输出完整 HTML（含脚本、样式），再配上交互动作脚本（高亮、设状态、标注、揭示）。

    LLM页面结构、交互逻辑、视觉呈现 SYS动作 allowlist：widget_highlight / setState / annotation / reveal
  3. 03脚本语法门：唯一对 HTML 的硬检查src/interactive-script-validator.ts

    用 parse5 找出可执行的 classic script，逐段交给 node:vm 编译，语法错误即拒绝。template 内的脚本不算可执行。

    SYS只验语法，不验语义（不会跑页面、不会点按钮）
    这里要说清楚：交互逻辑是否正确，没有程序门控。语法过关就入库，功能对不对由生成质量承担。
  4. 04后处理：依赖重写与数学公式注入src/interactive-post-processor.ts

    把 CDN 依赖改写到 pin 住的版本；页面确实含数学时才注入 KaTeX（样式、库、auto-render），不含数学就不注入。导出离线包时，外部资源可内联为 data URI。

    SYS版本兼容规则、未识别 URL 原样保留、重复处理幂等
  5. 05课堂里运行：沙箱 iframe + 观察桥lib/interactive/observation-bridge.ts

    组件在沙箱里跑；学生的操作状态可被教师智能体读到（作为现场依据），教师也能反向操作页面——高亮关键区、设条件、给提示。

    HUMAN学生动手探索 LLM教师根据观察决定引导动作 SYS沙箱 allow-scripts allow-forms allow-popups，故意不给 allow-same-origin SYS观察回传上限 32 KiB / 深度 64 / 800ms；超限返回 too-large，不抛错 SYSiframe 池按 LRU 保留 3 个，当前场景不淘汰
    这些是运行期资源边界，不是功能正确性校验；交互页只在生成期编译脚本，运行期没有「点一遍验一遍」的门。
F3

播放与多智能体现场互动

一门课不是视频，而是一串动作。回放引擎按序执行；遇到讨论就切到 live，由服务端导演循环组织智能体现场说话。

输入 Scene.actions（21 种动作）· 学生提问/打断 输出 语音、聚光灯、激光笔、白板、讨论、组件操作
  1. 01状态机：idle → playing ⇄ paused，讨论时进 livelib/playback/engine.ts

    动作原样执行，没有中间编译层。暂停、续播、结束讨论、用户打断都在这一个状态机里收敛。

    HUMAN播放/暂停/跳转/打断
  2. 02动作执行器lib/action/engine.ts · dsl/src/action.ts

    21 种动作：speech、spotlight、laser、play_video、12 种白板动作（开 / 画 / 清 / 删 / 关）、discussion、4 种组件操作。

    SYS跳转限制：视频/讨论/组件操作属于“不可安全跳转”动作，只能从可重建前缀跳 SYSFIRE_AND_FORGET：spotlight / laser 不阻塞游标，5s 后自动清除 SYS讨论卡延迟 3s 出现，再倒计时 5s 自动跳过；视频等待硬上限 5 分钟 SYS纯播放段零 LLM 调用（讨论 / 提问切 live 后才调模型）；时长常量与导出器共用 lib/choreography/timing.ts EXTTTS 音频 / 视频 / 白板渲染
  3. 03讨论触发 → Pi 导演循环lib/chat/pi/director-loop.ts · app/api/chat/pi

    讨论动作把课堂切进 live。服务端一个导演智能体只拿 4 个工具循环：read_scene、call_agent、cue_user、close_session；板书、查网页等能力由被叫到的智能体在子回合里执行。

    LLM谁先说、叫不叫学生、何时收尾 SYS工具白名单 4 项；call_agent 的 agentId 必须存在 SYSclose_session 需已有可见发言；cue_user 需已有实质教学回合且会话未关 SYS会话类型只有 qa / discussion / lecture；没有独立“圆桌辩论”循环
    这一层是真正的 LLM 门控：课堂的节奏不预设，由导演每轮判断。代价是同一门课两次播放的对话不会一样。
    两个终局工具互斥：本回合只要 sessionClosed 或 userCued 成立就结束，后续工具调用不再发生。
  4. 04学生提问 / 举手components/chat · live

    学生随时提问，教师用幻灯片、图表或白板回答；也可以被点名。学生是这条链路里的人类门控——他不问，这一段就不发生。

    HUMAN提问、举手、退出讨论
F4

测验：客观题本地判，简答题模型判

测验是场景类型之一。题量、难度、题型在生成大纲时就定好，播放时讲一段开场白，然后交给学生作答。

输入 quizConfig：题量 · 难度 · 题型 输出 分数、逐题结果、评语、交卷后的对话
  1. 01出题与开场动作templates/quiz-content · quiz-actions

    模型按大纲出单选/多选/简答；动作模板被明确限制为只能输出 text，禁止在动作里塞 discussion。

    LLM题干、选项、答案、评分要点SYS动作 allowlist 只放行 text
  2. 02学生作答lib/quiz/persistence.ts

    答案按 owner 持久化；未作答的选择题仍然是选择题，不会被改道去 AI 判分。

    HUMAN选择与提交 SYS还有题未作答时，交卷按钮保持禁用（allAnswered） SYS答题阶段只前进不回退：draft → submitted → reviewed
  3. 03单选题 / 多选题：确定性判分lib/quiz/grading.ts

    多选按集合相等比较；持久化的答案键按“值或唯一标签”精确对齐，不做大小写、空白、Unicode 归一化。

    SYS精确匹配；歧义键保持未解析而不是猜
  4. 04简答题：模型判分POST /api/quiz-grade

    把题干、满分、评分要点、学生答案交给模型，要求只回 JSON：{score, comment}。

    LLM分数与评语 SYSpoints 必须为正数；分数 clamp 到 [0, points] 并取整 SYS解析 / 网络 / 模型失败 → 兜底给 50% 分，不让判分卡住课堂 SYS前端判定“答对”的阈值是 ≥80%，不是满分
    这是典型的 LLM 门控：判对判错由模型决定，系统只保证输入合法、输出可解析。没有二次复核；离线 HTML 只判客观题，简答题不判分。
  5. 05交卷后的讲评对话lib/chat/quiz-results-for-store-state.ts · Pi 导演

    学生交卷后由平台单独触发一段对话，把逐题结果作为现场依据交给教师智能体；它不是预生成动作的一部分。

    LLM讲评重点与追问SYS结果注入有超时与失败降级，不阻塞课堂
F5

PBL v2：项目制学习是一条闭环

PBL 场景不是一页内容，而是一个小型项目空间：规划里程碑与微任务，导师陪跑，必要时进入角色扮演，最后逐级评价。

输入 项目主题 + 场景大纲 + 学习者状态 输出 PBLProjectV2：里程碑 / 微任务 / 对话 / 评价 / 能力读数
  1. 01规划：一次调用生成整个项目骨架lib/pbl/v2/agents/planner.ts · prompts-pbl/

    生成里程碑、微任务、角色、场景阶段（scenarioStage）与交付物；宿主可注入 agentic fallback，供应商选择仍归调用方。

    LLM项目结构与任务粒度 SYS最多 80 个规划步；必须调用 mark_design_complete 才停 SYS写库前跑 plannerCompletionGaps 校验
  2. 02导师回合：新任务激活时导师先开口POST /pbl/v2/open-task · /instructor（SSE）

    greeting / setup 阶段无需学生先说话；instructing 阶段回应学生。服务端无状态：客户端带整份项目，服务端回 project_patch。

    LLM讲解、追问、给脚手架SYS按当前里程碑决定暴露哪些工具
  3. 03角色扮演模拟器（仅 scenario 项目）POST /pbl/v2/simulator

    只有在 scenarioStage === 'roleplay' 的里程碑才允许进入；否则直接报错。角色第一句可主动开场。

    SYS阶段不匹配即拒绝LLM角色台词与情境推进
  4. 04学生完成任务并提交components/scene-renderers/pbl

    按微任务的交付物要求提交。是否完成不由学生自己宣布，进入评价。

    HUMAN实际动手与提交；Done / Continue 也必须由学生点击 SYS完成请求必须带 pendingTaskCompletion 事件；缺附件按 not_found 处理
  5. 05三级评价：任务 / 里程碑 / 总结POST /pbl/v2/evaluate · agents/evaluator.ts

    同一入口按 kind 分流。评价结果以 project_patch 回写：任务评价进对话卡片，里程碑评价带交接，最终评价进完成页。

    LLM打分与诊断 SYS任务通过阈值 60 分（taskEvaluationCanComplete），未达阈值不能标记完成
  6. 06内核读数：进度、熟练度、投入度src/pbl/operations/kernel/*

    每次运行时事件都会更新这三类读数，它们是确定性的状态推进，供后续导师回合与评价使用。

    SYS事件重放幂等、读数可复算 SYS内核推进全程零 LLM 调用
F6

Agent 工作台：让智能体直接写课

除了“填表生成”，上游还有一条 Pro 路径：服务端 agent 会话拿着课程文档工具，边聊边改，改的是真实的 Stage 文档。

输入 对话 + 当前课程上下文 输出 新建/改写/补音频/导 PPTX 的课程
  1. 01工具集：读、写、生成、媒体、预览lib/server/agent-runtime/course-tools.ts

    读：read_stage / grep_stage / list_scenes / read_stage_outline；写：create_stage / patch_stage / rename_stage / duplicate_scene；生成：generate_scene / generate_actions；音频与页序：generate_tts / edit_deck；导入：import_pptx；媒体：generate_image / generate_video；还有场景预览。

    LLM自己决定调用顺序与改哪一页 SYS单次工具调用默认 10 分钟；generate_scene / actions / extract_material 15 分钟，超时变结构化错误 SYS上传上限 50 MiB（文档与图片同额）
  2. 02写入串行化：防止并发写互相覆盖lib/agent-runtime/stage-writer-tools.ts

    “写课程”的工具被标成串行执行；同一批里只要有写工具，整批排队。读工具不带写归属，避免误伤用户未保存的编辑。

    SYSwriter 名单单一事实源 · 串行调度 · owner 作用域写入
  3. 03DSL 兼容提示：教模型用当前工具名dsl-tools.ts · DSL_TOOLS_PROMPT

    历史对话里可能出现过已退役的编辑器名字；提示层统一纠正，避免模型调用不存在的工具。

    SYS工具名白名单与提示同步
  4. 04实时同步：课程版本变了就推GET /stages/:id/freshness（SSE）

    工作台按 revision 拉 manifest，只重取变化的场景；流断了也只是延迟变大，低频轮询仍会收敛。

    SYS纯优化通道，按设计可降级
  5. 05人类的介入点在哪skills/openmaic/SKILL.md · UI

    产品里没有逐工具审批（代码里没有 permission/approval 门）。人类门控靠三层：对话里看结果再要求改；技能 SOP 要求在改状态前先问；发布仍要账号与角色。

    HUMAN看结果、提修改、决定发布 SYSSOP 是提示词约束，不是代码强制——这点必须说清
F7

导出与分享：四种容器，一个渲染服务

课程可以变成可编辑 PPT、一次性拷走的离线网页、完整备份包，或者一段 MP4。选择权在人，转换本身是确定性的。

输入 课程文档 + 媒体 输出 .pptx / 资源包 / 离线 .html / .maic.zip / .mp4
  1. 01选导出形态components · use-export-*

    PPTX、教学资源包、离线 HTML（可选含旁白）、课堂 ZIP。超过 400MB 的课只能导出 ZIP。

    HUMAN选格式与选项 SYS总闸：没有未完成/失败的大纲，且每条媒体任务都是 done 或 failed SYS体积上限决定可用格式（离线 HTML 100 MiB 告警 / 400 MiB 硬上限）
  2. 02PPTX：可编辑 + 占位页lib/export/use-export-pptx.ts · latex-to-omml.ts

    幻灯片元素转成可编辑形状与文本；公式走 LaTeX → OMML；交互/测验/PBL 保留为原位占位页，带“在线打开”按钮与二维码。

    SYS元素类型逐类映射；无法映射的降级为占位而不是丢页
  3. 03离线 HTML：一个文件播完整课lib/export/standalone-html

    旁白、聚光灯、激光笔、视频、测验、交互全带上；KaTeX / Three.js / 字体等外部依赖内联为 data URI，断网也能播。抓不到的资源保留原 URL。

    SYS资源清单逐项内联；单资产 8 MiB、3 次重试（只重试 429/5xx，404/403 立即放弃） SYSCSP 默认 default-src 'none'，离线页不能外联 SYS失败项记录并降级，不阻断整包
  4. 04ZIP：备份与迁移lib/export/classroom-zip-*

    课程结构 + 媒体一起打包；导入时先把音频、图片、视频、封面写回服务器资源池，再存课程，所以别的浏览器也能读。

    SYS导入先落资源池再落文档，避免指向本地缓存 SYS条目数上限 · 单条与总解压上限 · 路径穿越拒绝
  5. 05MP4：可选渲染服务render-service/ · /api/export-video/*

    浏览器先把课堂编译成自包含 Hyperframes 工程 ZIP，渲染服务用无头 Chromium 逐帧抓、FFmpeg 编码。没配服务就退化为下载工程 ZIP。

    EXTChromium + FFmpeg 容器 SYS能力探测未就绪则菜单不展示 MP4；任务按 owner 绑定，换 owner 一律 404 SYS成片以 300 MiB 流式回传，不先在内存里拼整段 HUMAN提交渲染并等待

材料与知识库：把 PDF 变成可用的上下文

上传的材料先落所有者资产池，再按类型抽取正文和图片；正文可切片入检索索引，图片按视觉优先级进入提示。

输入 PDF / DOCX / PPTX / 音视频 / 图片 输出 正文、图片、切片、检索命中
  1. 01上传与归属app/api/materials/*

    材料属于 owner，生成 run 与上传者必须是同一个 owner；匿名模式要复用同一个 cookie 罐。同一 owner 重复上传相同字节时，会复用已完成的抽取结果。

    HUMAN选择文件 SYSMIME / 体积 / owner 围栏 SYS配额：最多 100 个文件 / 2 GiB，单文件 50 MiB SYS按 sha256 复用抽取结果，但只在同一 owner 内
  2. 02抽取：按 MIME 与能力选定抽取器lib/document/extractors/registry.ts

    生成流水线只选一个抽取器：有首选用首选，否则取第一个同时支持该 MIME 与所需能力的；都不支持则该步失败。音视频走语音识别。Pro 会话的材料抽取是另一条路径，会按候选顺序逐个试。

    EXT抽取器 / ASR SYSMIME + capabilities 匹配；需服务但未配置则明确拒绝 SYS外部抽取器回传的图片只允许白名单域（阿里云 OSS），防 SSRF
  3. 03视觉图筛选lib/server/generation/vision-images.ts

    按文档顺序与视觉优先级取图，最多 MAX_VISION_IMAGES；解析预算 15 秒，连续 3 次不可解析就停，带着已解析的继续。

    SYS预算 + 熔断，宁可降级不失败
  4. 04切片与索引lib/rag/chunking · providers

    真实产品路径里没有向量检索：检索是字面匹配扫描，命中带来源定位。仓库里的 lib/rag/（切片 / 词法索引）只有测试引用，是死代码，不要把它当成在线知识库。

    SYS字面匹配 + 来源定位；没有 embedding / 向量库 SYSlib/rag/ 仅测试引用，未接入运行时 LLM阅读检索命中并写进讲解

容易误读：文档说过的，代码不一定这么做

下面这些点最容易把「设计意图」当成「运行时事实」。冲突处以代码为准。

文档 / 直觉 vs 代码实际
看起来是这样代码里其实这样
“大纲永远等确认，除非 auto”还有第三种 countdown（2.5s 自确认），而且浏览器默认就走它；无头 API 又强制 auto
“两阶段流水线：大纲 → 场景”4 段 + 每场景 3 步 + 媒体旁路（材料分析 → 调研 → 大纲 → 花名册 → 逐场景 content / actions / narration）
“会做 JSON 修复”大纲流不走 JSON 修复，而是手写括号扫描器增量解析；修复只用于场景内容 / quiz / PBL
“Roundtable Debate：多智能体辩论”不存在独立辩论类型；SessionType 只有 qa / discussion / lecture
“多智能体主动发起讨论”讨论是生成期写进场景的动作，到点弹卡；不是智能体自己决定发起
“离线 HTML 只有聚光灯和激光”还有 4 种 widget_* 动作；但白板动作被显式丢弃，简答题不判分
