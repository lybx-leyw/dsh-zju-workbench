# 讲义资源终稿与阅读讲义

“讲义资源终稿”是结构加工阶段的产物：知识点及其内容归属已经划分，保留来源字幕、课件、主支线标记和时间信息。“阅读讲义”以这份资源为依据，继续优化表达、推导衔接、符号定义、重复内容和整体阅读顺序。

资源阶段完成不等于事实与语义已经完全正确。资源也可能处于部分完成状态：有未清洗字幕、失败页面、未标记内容、来源缺失或未生成可信的语义分组时，应展示缺陷，不能因为改名而显示为全部完成。

解析结果中的 `resource` 描述这一层：

- `structureStatus`：`allocated` 为本轮结构加工完成，`incomplete` 为仍有缺陷，`unverified` 为缺少详细语义分组。
- `topicCount`：语义知识点数量；没有可信分组时为 `null`，不能拿 token 切片数冒充。
- `partCount`：实际内容切片数。
- `unanchoredUncleanedSentenceCount`：没有课件锚点且处理未完成的字幕数。纠错限额退回原文的句子不计入。
- `unverifiedPageSentenceCount`：失败页里仍未通过处理校验的字幕数。同一页已经通过的句子，以及被限额退回原文的句子，不计入；不能把这个数读成整页都没清洗。
- `semanticOptimized`：资源阶段为 `false`，不声称已经通过更高层语义验收。

资源的版本和来源编号是阅读讲义的依据。后续表达优化沿用这些引用；若审核发现知识点边界本身错误，应回到资源阶段修订并生成新版本，再使旧阅读讲义失效。不能把边界冻结理解为永远不允许纠错。

界面使用“讲义资源终稿”和“阅读讲义”两个名称。内部兼容字段及导航标识保留原有值，避免旧记录和定位链接失效。

## 断点续跑与失败成本

填充成功的知识点请求按模型路由、提示词、正文及课件依据缓存；来源或模型变化会重新计算。缓存读取仍经过响应和正文检查，不保存失败回包。输出截断不原样重发相同预算的请求；这类失败保留原稿和诊断，不能算作完整成稿。

正式组织的 JSON 格式失败，或整组没有任何可采纳正文时，最多修复一次。已经返回正文但缺了个别编号时，采用这些正文，缺号保留原文并标草稿，不再为同一个缺号重发。知识点分组覆盖失败仅重试分组方案，不重跑识别和清洗。终审允许删除冗余片段，忽略不产生修改的占位项，但拒绝清空正文、例题题干或解答，仍校验全部来源引用。

结构校验、模型终审和人工语义验收是三种不同证据。即使资源状态为allocated或终审合回成功，仍可能存在错误推导、适用条件遗漏、口语段落和知识点边界问题；不能仅凭状态或关键词统计宣称质量通过。

阅读讲义另有一条程序复核：正文若先写明两个量的上界或等式，再把二者之差写成另一个能逐项相加的线性式，程序比较该差与相减结果。不一致时知识点保持草稿，说明里写出两边的式子，不改正文。解析不了的公式不因此降级。
