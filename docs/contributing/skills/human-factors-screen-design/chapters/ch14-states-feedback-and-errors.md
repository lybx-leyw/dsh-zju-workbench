# Ch 14 · States, feedback and errors

> **状态声明：本章是交互实践，不是标准原文。**
> 时延阈值引用 ch05，不在此重复；对比度与颜色引用 ch03；目标尺寸引用 ch06。

---

## 14.1 每个交互元素都要有完整状态

不要只设计 default 与 hover。缺一个状态，实现时就会各写各的。

| 状态 | 必须回答的问题 |
|---|---|
| `default` | 用户第一眼看到什么 |
| `hover` | 鼠标移上去有没有反馈（桌面必需） |
| `focus-visible` | 键盘用户能否看见焦点（ch12） |
| `active/pressed` | 按下有没有即时反馈 |
| `selected/current` | 当前项如何与其它项区分（不能只靠颜色） |
| `disabled` | 为什么不可用？给出原因或提示 |
| `loading` | 操作进行中，能否重复点击 |
| `empty` | 没有数据时说什么 |
| `error` | 出错时用户能做什么 |
| `partial` | 部分成功/部分失败（批量操作） |

**验收方式**：把这张表当成组件的 checklist；缺项就是设计债。

---

## 14.2 空状态：解释 + 下一步

空状态不是「暂无数据」四个字。三件事：

1. **为什么空**（还没创建 / 筛选无结果 / 加载失败 —— 三者文案不同）；
2. **下一步做什么**（一个主操作）；
3. **不要误导**：加载失败不能显示成「暂无数据」（本仓库反馈页的 robot 流程已遵守这条）。

```
✓ 「还没有课程。导入课表后，这里会按周显示。」
✗ 「暂无数据」
```

## 14.3 加载与反馈

时延分级**引用 ch05**（1 s / 2 s / 15 s / 60 s 的反馈阶梯），不重复数字。实践补充：

| 场景 | 做法 |
|---|---|
| <1 s | 不显示加载态（闪一下更糟） |
| 1–2 s | 按钮内 spinner；禁用重复提交 |
| >2 s | 进度条或骨架屏；说明在做什么 |
| 不确定时长 | 不要用假进度条（会破坏信任） |
| 可取消 | 给「取消」，而不是只能等 |

**骨架屏 vs spinner**：结构已知（列表/表格）用骨架屏；结构未知用 spinner。
骨架屏的形状要接近真实内容，否则加载完会「跳」。

## 14.4 错误信息的公式

```
发生了什么 + 为什么 + 怎么修
```

| 差 | 好 |
|---|---|
| 「输入有误」 | 「邮箱缺少 @，请检查格式」 |
| 「操作失败」 | 「保存失败：网络断开。已保留草稿，恢复后会自动重试」 |
| 「错误 500」 | 「服务暂时不可用，请稍后重试（错误码 500）」 |

规则：

- **说人话**，错误码放括号里给支持人员用；
- **不要责怪用户**（「你输入错了」→「这里需要一个日期」）；
- **给出可执行的下一步**；
- 表单错误要**定位到字段**（`aria-invalid` + `aria-describedby`，见 ch12）。

---

## 14.5 预防优于报错

- 能约束就不要事后校验：日期选择器 > 让用户手输再报错。
- 输入时给格式提示（示例值），而不是提交后才说格式不对。
- 即时校验只对**格式**（邮箱、日期）；**语义校验**（这个学号存不存在）放提交时。
- 不要一边输入一边报红（用户还没输完）。

---

## 14.6 破坏性操作：撤销 > 确认

- **优先给撤销**（5–10 秒的 undo），而不是弹确认框。确认框会被无脑点掉。
- 必须确认时，**确认文案要具体**：
  ```
  ✓ 「删除《高等数学》笔记？此操作不可恢复。」[取消] [删除]
  ✗ 「确定吗？」[确定] [取消]
  ```
- 危险按钮**不要**做默认焦点（ch07 已规定破坏性操作不是默认）。
- 批量删除要显示**数量**（「删除 12 项」）。

---

## 14.7 乐观更新与回滚

- 低频、可回滚的操作（点赞、标记已读）可以乐观更新：先改 UI，后台失败再回滚并提示。
- **不可回滚**的操作（支付、删除）不要乐观更新。
- 回滚时必须**告知**，否则用户以为成功了。

---

## 14.8 部分失败

批量操作最容易被忽略：

- 明确「成功 N 项，失败 M 项」；
- 失败项**保留可重试**，不要整批回滚；
- 不要在只失败一项时说「操作失败」（会让用户以为全错）。

---

## 14.9 本仓库检查点

- 「插件」页启停：需要 `loading` 与 `disabled` 状态，防止连点。
- 「反馈」页提交：需要成功/失败/重试三态，且失败不能显示成空列表。
- 「学习」页解析：长任务需要进度或阶段提示（ch05）。
- 账号对话框：关闭后焦点归还（ch12）。
