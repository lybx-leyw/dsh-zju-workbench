# Ch 19 · Decision priority and evidence grading（元规则）

> **状态声明：本章是方法论，不是标准。**
> 它不给出新阈值，只规定：**当规则冲突、或规则缺失时，按什么顺序做决定、按什么等级采信证据。**

---

## 19.1 证据分级

引用一个数字或做法前，先看它属于哪一级。**等级低的不能冒充等级高的。**

| 等级 | 类型 | 例 | 采信方式 |
|---|---|---|---|
| **E1** | 标准原文（可追溯条款号） | FAA HF-STD-001B §5.6.2.5、WCAG 2.2 1.4.3 | 直接采用；偏离需记录理由 |
| **E2** | 同行评审研究 / 官方指南 | WAI-ARIA APG、Nielsen Norman Group 的实证综述 | 可采用，注明来源 |
| **E3** | 平台规范 | Microsoft Fluent、Apple HIG、Material | 在与 E1/E2 不冲突时采用 |
| **E4** | 社区惯例 / 成熟产品做法 | 主流产品的导航模式 | 只作参考；不作为"必须" |
| **E5** | 个人经验 / 推断 | 本文多数"建议" | **必须标注**；不得写成规则 |

**本 skill 的分工**：

- ch01–ch10：E1（`SOURCES.md` 可追溯）
- ch11：**E5 推导**（顶部已声明）
- ch12：E2（WCAG + ARIA APG）
- ch13–ch18：**E2–E5 混合**，逐条尽量注明；未注明处按 E5 对待
- `repo-profile.md`：E1 阈值 + 本仓库实测（可复核）

## 19.2 冲突裁决顺序

当两条要求不能同时满足，**从高到低**：

```
1. 安全（不造成数据丢失 / 误操作 / 隐私泄露）
2. 可访问（键盘可达、对比度、不依赖单一通道）
3. 可读（字号、行高、行宽、对比度）
4. 一致（同一概念同一表现）
5. 效率（少点击、少等待）
6. 美观（视觉精致、动效）
```

**解释**：

- 安全高于一切：一个"更好看"的删除按钮如果容易误触，就是错的。
- 可访问是**底线**，不是加分项：不能为了密度牺牲对比度。
- 可读高于一致：如果一致的样式导致读不清，允许**局部**破例并记录。
- 美观永远最后：它不能成为违反前五条的理由。

## 19.3 什么时候可以偏离规则

允许偏离，但必须**同时**满足：

1. 有明确的**用户收益**（不是"我觉得好看"）；
2. 已尝试过合规方案且不可行；
3. 影响范围**局部**（不扩散成全站惯例）；
4. 在 PR 或 `repo-profile.md` 的「已知偏差」里**登记**：位置、原因、替代方案、复审时间。

**不允许**的偏离：

- 为了塞更多信息而缩字号（违反 ch01/ch11）；
- 为了"高级感"降低对比度（违反 ch03）；
- 为了省事把交互做成 `div`（违反 ch12）；
- 用 `overflow: hidden` 掩盖布局问题（违反 ch18）。

## 19.4 不可协商项（硬底线）

| 项 | 依据 |
|---|---|
| 中文正文 ≥12 px（本仓库取 ≥13） | ch11 / repo-profile |
| 正文对比度 ≥4.5:1，大字/图标 ≥3:1 | ch03 |
| 状态不能只靠颜色 | ch03 规则 3 |
| 交互目标 ≥24×24（命中区） | ch06 |
| 键盘可完成主流程 | ch12 |
| 焦点可见 | ch12 |
| `prefers-reduced-motion` 被尊重 | ch10 |
| 破坏性操作不是默认 | ch07 |

这些**不因"设计稿如此"或"时间紧"而豁免**。

## 19.5 偏离记录模板

```markdown
### DEV-001 · 卡片标题用 12px

- **位置**：`page-xxx/style.css:123`
- **规则**：ch11 要求正文 ≥13px
- **原因**：卡片宽度固定 280px，13px 会换行导致高度不齐
- **替代方案**：已尝试缩短文案、加宽卡片，均影响布局
- **影响**：仅该卡片标题，正文未动
- **复审**：2026-12-01 或下次布局改版时
```

登记位置：`repo-profile.md` §5。

## 19.6 决策记录（ADR 轻量版）

对**跨页面、不可逆**的设计决策，写一份短 ADR：

```markdown
## ADR-003 · 侧栏改为纯图标导轨

- 背景：侧栏展开占 280px，挤压内容
- 选项：A 可折叠（280/56） / B 纯图标 55 / C 顶部横向导航
- 决定：B
- 理由：内容区优先；图标 + tooltip 可识别；键盘 focus 也出 tooltip
- 代价：新用户需要一次学习；已用首次提示缓解
- 复审：页面数超过 10 时重新评估
```

放在 `docs/` 或包内 `README.md`；不必长，关键是**留下理由与代价**。

---

## 19.7 本 skill 的边界（再次强调）

- **不是合规证书**：E1 条款也要结合上下文，套错场景仍是失败。
- **不覆盖**：真机读屏、认知障碍、竖排、医疗/工业等专业域。
- **不替代用户测试**：任何规则都不能替代 5 个真实用户的一次任务测试。
- **经验会过期**：E4/E5 的结论要随产品与平台演进复审。

---

## 19.8 使用顺序（推荐）

1. 先读 `repo-profile.md`（本仓库事实与已知偏差）；
2. 命中数值问题 → 查 ch01–ch10；
3. 命中交互/结构问题 → ch13–ch18；
4. 规则冲突或缺失 → 回到本章的优先级与证据分级；
5. 做了偏离 → 登记。
