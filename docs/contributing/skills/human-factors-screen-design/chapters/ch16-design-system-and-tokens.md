# Ch 16 · Design system and tokens

> **状态声明：本章是工程实践，不是工效学标准。**
> 具体阈值（字号/间距/对比度/目标尺寸）引用 ch01–ch07 与 `repo-profile.md`，本章不重复。

---

## 16.1 单一真值

- **一个值只定义一次**。颜色、字号、间距、圆角、阴影都必须来自 token。
- 组件里出现 `#00479d`、`13px`、`24px` 这类字面量，就是设计债。
- 例外：**一次性布局值**（如某个插画的绝对定位）可以硬编码，但要注释说明。

---

## 16.2 三层 token

| 层 | 作用 | 例 |
|---|---|---|
| **基础（primitive）** | 原始值，不含语义 | `--zy-blue-500: #00479d` |
| **语义（semantic）** | 表达用途，可换主题 | `--zy-accent`、`--zy-muted`、`--zy-fs-base` |
| **组件（component）** | 仅某个组件用 | `--zpl-badge-bg` |

规则：

- 组件只消费**语义层**；不要直接用基础色（换主题会漏）。
- 语义层要能回答「这是什么用途」，而不是「这是什么颜色」。
- 本仓库现状：`--zy-*` 是语义层；`--dsw-alias-*` 是宿主语义层。**不要混用**
  （插件页曾混用，已统一到 `--zy-*`）。

---

## 16.3 命名

```
--<前缀>-<类别>-<变体>
```

| 类别 | 例 |
|---|---|
| 颜色 | `--zy-text`、`--zy-secondary`、`--zy-muted`、`--zy-line` |
| 字号 | `--zy-fs-meta` … `--zy-fs-display` |
| 间距 | `--zy-space-1` … `--zy-space-16` |
| 圆角 | `--zy-radius-sm/md/lg` |

- 不要用 `--zy-color-1`、`--zy-big` 这种无语义命名。
- 一个 token 改名要**全仓替换**，不能留别名超过一个迭代。

## 16.4 禁止硬编码的检查

- `scripts/check-hf.mjs` 目前查字号/对比度/目标尺寸。
- 建议增加（未实现）：扫描 `color:#…`、`padding:…px` 是否可用 token 替代。
- PR 评审时，看到裸 hex 与裸 px 就要求说明理由。

---

## 16.5 作用域与顺序（本仓库特有）

CSS 在本仓库是**按包挂载**的，每包一个 `<style>`，顺序影响胜负：

- 同特异性下，**后挂载的赢**；跨包覆盖会变成「死规则」（曾真实回归，见
  `ui-primitives/style.css` 与 `page-courses/style.css` 的注释）。
- 覆盖必须与被覆盖的**基规则同包**；跨包覆盖只能靠提高特异性（如加 `body[data-zhiyun]`）。
- `scripts/check-css-order.mjs` 是门禁：**跨包 @media 顺序依赖 0 条**才算过。
- 新增页面样式：用本包前缀（`zpl-`、`zs-`、`zp-`），不要改 `.zy-*`。

---

## 16.6 组件状态矩阵

见 ch14.1。工程上：

- 每个组件先定义状态表，再写样式；
- 状态用**数据属性**表达（`data-state="loading"`），不要靠多个类名拼；
- 禁用态要同时处理 `pointer-events`、`aria-disabled`、视觉（不能只降透明度）。

---

## 16.7 变更与弃用

- **新增** token 不破坏旧值；**修改**语义值要评估全仓影响（对比度可能掉）。
- **弃用**流程：标注 `@deprecated` + 替代项 + 计划删除版本；至少保留一个迭代。
- 破坏性改名要走 PR 说明影响面（哪些包/页面）。
