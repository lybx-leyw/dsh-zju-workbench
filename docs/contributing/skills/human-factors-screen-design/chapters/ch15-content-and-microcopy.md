# Ch 15 · Content and microcopy

> **状态声明：本章是写作规范，不是工效学标准。**
> 字号与行宽引用 ch01/ch02/ch11；颜色语义引用 ch03。本章只管「字写什么、怎么写」。

---

## 15.1 按钮：动词 + 对象

| 差 | 好 |
|---|---|
| 「确定」 | 「保存修改」 |
| 「导出」 | 「导出课表」 |
| 「提交」 | 「提交反馈」 |
| 「更多」 | 「更多页面」（若上下文已明确可简写） |

- 同一动作在不同页面用**同一个词**（全站「导出」就不要有的地方叫「下载」）。
- 取消类按钮用「取消」，不要「返回」「关闭」混用（语义不同：返回是导航，关闭是收起）。
- 危险动作直接说后果：「删除笔记」而不是「确定」。

---

## 15.2 空状态文案

三段式：**是什么 + 为什么没有 + 能做什么**。

```
✓ 「还没有收藏的论文。在阅读页点 ☆ 就会出现在这里。」[去论文页]
✗ 「暂无数据」
```

- 区分三种空：**从未创建** / **筛选无结果** / **加载失败**（第三种要给重试）。
- 空状态不要放巨大的插画挤走主操作（ch02 的密度规则）。

---

## 15.3 错误文案

公式见 ch14.4。文案层面补充：

- 用**主动语态**：「保存失败」而不是「保存未被完成」。
- 不甩锅、不卖萌、不道歉过度：「抱歉，出了点小问题」没有信息量。
- 给出**具体字段/文件/条目**：「第 3 行的日期格式不对」，而不是「有错误」。
- 技术细节放**次要位置**（折叠的「详情」），不要占主文案。

---

## 15.4 语气（与仓库既有约定一致）

本仓库 `robot/SKILL.md` 已规定反馈答复的语气，这里推广到全产品：

- **中文、简洁**；不堆敬语，不用感叹号，不写「亲」。
- 像一位了解产品的维护者说话，而不是客服话术。
- 不用「我们」「您」过度包装；直接说事。
- 幽默可以有，但**不能牺牲信息**；错误场景不幽默。

## 15.5 术语与中英混用

| 类型 | 规则 | 例 |
|---|---|---|
| 专有名词 | 保留英文原文 | DSH、Cordis、PDF、ICS |
| 动作/状态 | 中文 | 导出、已答复、未接入 |
| 行业缩写 | 首次出现给中文 | 「跨站请求伪造（CSRF）」 |
| 产品内造词 | 先登记再使用 | 见 `glossary.md` |

**一个概念一个词**：同一功能不要在不同页面叫不同名字（ch13.6）。

## 15.6 数字、日期、单位

| 项 | 规则 |
|---|---|
| 千分位 | 四位以上用空格或逗号，全站统一（本仓库用逗号） |
| 小数 | 与数据精度一致；不要「3.00 分」这种假精度 |
| 百分比 | 保留一位小数以内；不要 99.999% |
| 日期 | 绝对日期用 `2026-10-17`；相对时间（「3 分钟前」）只用于近期 |
| 时间 | 24 小时制；跨时区要标注 |
| 单位 | 数字与单位之间留空格（`12 px`、`5 kg`）；中文单位可紧贴（`5 个`） |
| 范围 | 用「–」而不是「-」（`3–5 项`） |
| 计数 | 表格/统计用 `tabular-nums`（ch02 已有） |

## 15.7 截断与省略

- 单行截断用 `text-overflow: ellipsis`，**必须**给 `title` 或可展开查看全文。
- 多行截断（`-webkit-line-clamp`）要保证**最后一行不是半句话**；宁可少显示一行。
- **不要截断关键信息**：错误信息、金额、日期、按钮文字不截断。
- 中文截断按字符，不要按字节（会切坏多字节字符）。

---

## 15.8 文案长度预算

| 位置 | 建议上限 | 理由 |
|---|---|---|
| 按钮 | 2–6 个汉字 | 过长会挤爆工具栏 |
| 导航项 | ≤6 个汉字 | 导轨/侧栏宽度有限 |
| 标题 | ≤20 个汉字 | 超过要换行或降级为副标题 |
| 提示条 | ≤2 行 | 超过改用对话框或详情页 |
| 错误 | ≤3 句 | 超过说明该给帮助文档 |

---

## 15.9 本仓库检查点

- 反馈页的官方答复：固定话术优先（`需求已实现。` / 我得请示…），不展开。
- 插件页状态：`已启用 / 已停用 / 待确认`，不要用「ON/OFF」混排。
- 课程页：`第 N 周`、`周一 3–4 节`，格式统一。
- 设置项：标题 + 一句说明（`small`），说明不重复标题。
