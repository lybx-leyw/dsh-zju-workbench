# 逐项检查表

一次执行结束后，逐条打钩。**没打钩的项不能靠「大概做了」结案**，要么补做，要么写进「未探索 / 已省略」并给理由。

## 0 · 开工前

- [ ] 已确认外部插件的许可证（找 `LICENSE` / `COPYING` / `NOTICE` 并读过）；无许可证的按「保留所有权利」处理，只能参考思路
- [ ] 已确认它的运行形态（Cordis 插件 / 独立进程 / 库 / 前端应用）
- [ ] 已确认它的数据源清单（它连了哪些外部系统）
- [ ] 已确认它是否需要模型调用、谁的 key、走什么厂商
- [ ] 已声明**探索范围**：读了哪些目录/文件，没读哪些、为什么

## 1 · 泳道图

- [ ] 用 [tools/lanes.py](tools/lanes.py) 生成，没有手写 HTML（手写必漏改，见 SKILL.md 第 1 步）
- [ ] 一条泳道 = 一条完整数据流（不是一层、不是一个模块）
- [ ] 每个节点写了 `in` / `out`（入什么形态 → 出什么形态）
- [ ] 节点带了 `pkg`（包名或模块路径）
- [ ] 一条泳道内的多支流用 `rows` 拆开，没有依赖自动折行
- [ ] 终端用 `kind` 区分了 `ui` / `tool`；`preset` 与 `skill` 已单独确认
- [ ] `provide` 存在但无消费者的模块用 `kind: "ghost"`
- [ ] 与本次无关的目录画在图外，但在 `footer` 里说明了为什么不画
- [ ] `footer` 有「怎么读」「为什么没画 X」「与代码的一致性」三节
- [ ] `--check` 通过

## 2 · 遗漏校验

- [ ] 已列出全部可执行入口：路由 / IPC / CLI / 导出函数 / cron / 事件订阅 / 按钮 / prompt
- [ ] 每个入口都映射到某条泳道，或明确标注「不可达 / 未实现 / 无关」+ 理由
- [ ] **范围内未映射项 = 0**
- [ ] 补画后重跑过一次映射
- [ ] 「未探索范围」单独成节，写清没读什么

## 3 · 交付给用户

- [ ] 用 present 交付 HTML
- [ ] 消息里点明了：哪几条泳道是断的、哪些模块无下游、哪几处是推测
- [ ] 没有用文字复述图的内容
## 4 · 数据源剪枝

- [ ] 问了用户「集成哪些数据源、到什么程度」
- [ ] 粒度可执行：全量 / 只读子集 / 指定接口 / 不集成
- [ ] 被剪掉的泳道用 `"cut": true` 保留为删除线，没有物理删除
- [ ] 剪枝后跑过 `--check`，没有「已剪仍供数」或「起点悬空」
- [ ] 没有悬空起点

## 5 · 处理链路剪枝

- [ ] 跑过 `--report`，把前驱/后继清单贴给了用户
- [ ] 逐条泳道问过用户「剪还是留」
- [ ] 用户对每条的答复都写明了 **泳道编号 + 泳道名**
- [ ] 用户对每条的答复都写明了 **前驱与后继**
- [ ] 指代不明的答复被打回重写，没有自行脑补
- [ ] 每次剪枝后重跑过 `--report`（前驱后继已重算）
- [ ] 「既无终端也无后继」的泳道告警已处理
- [ ] 「全留」被记录为明确决定，不是默认值

## 6 · 清单

- [ ] 表格含：# / 泳道 / 保留节点 / 类型 / 本项目现状 / 待办
- [ ] 「本项目现状」每格有证据（包名 / 文件 / 测试名）
- [ ] 无证据的写「未核实」，没有写成「已有」
- [ ] 清单定稿后，第 7–9 步只围绕清单裁决，未回头改图

## 7 · 数据源比对

**不存在的数据源**

- [ ] 已询问：新建的数据源**要不要走 WebVPN**
- [ ] 已确认鉴权方式（一卡通 / 自有账号 / 无鉴权）
- [ ] 已确认是否只读
- [ ] 新建包保持本仓分层（数据源只提供事实、不做变换、不含 UI）

**已存在的数据源**

- [ ] 已逐字段比对：外部需要的字段/接口本项目有没有
- [ ] 结论明确三选一：无需扩展 / 需要扩展（列出方法+字段）/ 模型不兼容（说明冲突点）
- [ ] 已告知用户
- [ ] 若扩展：已按版本与引用规则同步（改内部包版本前先全局搜引用方）

## 8 · core 链路比对

- [ ] 清单里每条 `proc` 都归入 A / B / C
- [ ] A 类（本项目明显没有）：已说明它依赖哪些数据源与服务
- [ ] B 类（相近但算法/代价不同）：已给量化对比表
  - [ ] 时间/空间量级
  - [ ] 单次调用的模型请求数
  - [ ] token 预算（输入/输出）
  - [ ] 并发上限与背压
  - [ ] 缓存命中面（键、失效条件）
  - [ ] 失败粒度（整条 / 单页 / 单块）
- [ ] B 类已判断「是否需要为此扩展数据源接口协议」，并告知用户
- [ ] C 类（互补/加强）：已写清补的是哪块缺口、代价是什么
- [ ] C 类区分了「互补」与「加强」，并说明回滚代价不同
- [ ] B、C 两类都有**用户明确裁决记录**（谁、裁决成什么、理由）
