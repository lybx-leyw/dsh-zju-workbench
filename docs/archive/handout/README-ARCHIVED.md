# 已归档：讲义 ⇄ 笔记库联动的**旧**设计方案

> ⚠️ **本目录下的四份文档描述的是已被放弃的架构。不要照着它实现。**
>
> 当前实现是「**单向导出**」：把 `record.lecture` 编码成 md 写进笔记库，
> 每次新写一份、重名加 `（2）` 后缀、不覆盖、不参与生成。
> 权威说明见 [`packages/dsh-zhiyun-core-handout/README.md`](../../../packages/dsh-zhiyun-core-handout/README.md)，
> 实测结果见 [`reports/handout-regression.md`](../../../reports/handout-regression.md)。

## 归档原因

这批材料是 2026-10 那次实现中途的交接单。它设计的是一套**深度挂钩**的方案：

- 版本 =（AI 基线, 讲义 md），二者同生同灭
- `讲义归档/<课程>/<节次>/v<N>/` 存放历史版本
- 重新生成换版、旧版进归档、回退时对调正文与基线（swap）
- 让笔记库里的 md 成为**真源**，学习页与检索改读它

最后一条是它被放弃的根本原因：要让 md 成为真源，必须改掉四处读取路径
（学习页渲染、`layered-search` 讲义层、`knowledge/service` 讲义层、出题与知识点导航），
跨四个包。而需求后来收敛为「导出只是一份给用户自己编辑的副本」，那整套机制
连同它的复杂度一起失去存在理由。

## 仍然有效的部分

- **md 的形状**：`##` 章、`###` 知识点、`#### 类型 · 小标题`、例题用 `##### 解答` 分隔。
  编码器 `src/codec.js` 一行未改，它的 10 条测试仍在跑。
- **零 IO 纪律**：领域包不碰 `node:fs`，全部经注入的笔记服务。
- **错误态度**：认不出的块类型降级成「讲解」并留 warning，不抛错。
