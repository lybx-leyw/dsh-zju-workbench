## 3. 本轮实测（全部实跑，不是推测）

### 3.1 环境与装配

```text
Node 22.13.1 · citeproc@2.4.63 · @retorquere/bibtex-parser@13.0.11
样式：china-national-standard-gb-t-7714-2015-numeric.csl（15,530 B）
locale：locales-zh-CN.xml（18,641 B）
```

⚠ 样式文件名是**坑**：按常识写 `chinese-gb7714-2015-numeric.csl` 会 **404**，
真实文件名是 `china-national-standard-gb-t-7714-2015-numeric.csl`。

### 3.2 渲染结果（原样）

```text
ZH 4 作者 + 卷期页：
  [1]张三, 李四, 王五, 等. 基于深度学习的课堂注意力分析[J]. 计算机学报, 2023, 46(5): 1023-1038.
ZH + DOI：
  [1]…[J/OL]. 计算机学报, 2023, 46(5): 1023-1038. DOI:10.11897/SP.J.1016.2023.01023.
EN book + edition：
  [1]KNUTH D E. The art of computer programming, volume 1[M]. 3 版. Addison-Wesley, 1997.
正文角标：<sup>[1–3]</sup>
```

**中文侧是对的**（`[J]`、`等`、`46(5)`、`1023-1038`、`[J/OL]` 全部符合 2015 版）。
问题全在**接缝**与**混排**。

### 3.3 四个接缝坑（评审接入前必读）

| # | 现象 | 根因 | 后果 |
| --- | --- | --- | --- |
| 1 | `type: 'article'` 渲染成 **`[A/OL]//…`** | 样式第 131 行注释：`article 为预印本，符合"科技档案"` | **静默错误**：整条形态都变了，且不报错 |
| 2 | 页码渲染成 `023-1038` | 解析器把 `1023--1038` 归一化成 **en-dash `–`**；样式 `page-range-format="expanded"` 只认 `-` | 第一版我用 `String.replace(/[–—]/,'-')` **只换首个匹配**，同时把 `page-first` 切成 `1` |
| 3 | `retrieveItem` 收到 `"[object Object]"` | `engine.updateItems()` 必须传**字符串 id 数组**，传对象会静默取不到 | 条目全丢，报错信息在 `JSON.parse` 处，极难定位 |
| 4 | `processCitationCluster` 崩在 `citationsPost.length` | 它要三个参数 `(citation, pre, post)`，只传两个 | 渲染书目成功、一取角标就炸 |

另：`citeproc` 是 **CJS**，导出里**没有 `Cite`**（网上示例多是 `new CSL.Engine`）；
ESM 下必须 `import pkg from 'citeproc'; const { Engine } = pkg;`。

### 3.4 **中英混排的「等」—— 本轮最重要的一条**

英文条目渲染成：

```text
[1]LEE Z, SMITH J A, BROWN M, 等. Retrieval-augmented generation for course notes[J]. Journal of Documentation, 2023.
```

我试了五条路，**全部无效或更糟**：

| 尝试 | 结果 |
| --- | --- |
| 条目加 `language: 'en'` | 仍是「等」 |
| `<bibliography default-locale="en">` | 仍是「等」 |
| `new Engine(sys, style, 'en-US')` + 同时提供 `en-US` locale | 仍是「等」 |
| `<locale xml:lang="zh">` 改为 `zh-CN` | 不影响 et-al |
| `<layout suffix="." locale="en">` | **citeproc-js 直接崩**：`Level mismatch error: wanted bib_entry but found undefined` |

**定论**：样式第 433 行已写明 ——

> `<!-- 取消这部分注释可以开启 CSL-M 的多语言功能：按照文献的语言输出"et al."等术语 -->`

即：**该样式有意默认关闭多语言**。所以「等」不是 bug，是**该样式的设计选择**。
对学生而言这是**可见错误**（英文文献被写成中文的「等」）。三条出路：

1. **条目级后处理**：英文条目把「等」→「et al.」，但作者缩写规则（`LEE Z` vs `Lee Z.`）也要一起改 → 变成自写规则；
2. **自写两段 layout 的 CSL**：脱离「引用上游样式」，且要自行维护；
3. **只做中文文献**：笔记本就只排中文条目，英文条目走「手动粘贴」→ 功能打折。

→ 已写进骨架 README「未解的一条」，**定为评审第一件事**。
