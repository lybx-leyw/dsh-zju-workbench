**为什么值得记**：它是本仓**第一次见到的、把「英语精读」做成完整体验**的 DSH 插件——

- **逐句模式**：听朗读（词级高亮）、**跟读打字**（就地输入、错词标红、语速跟随）、**朗读比对**（语音识别逐词对齐，读对绿线/读错红波/漏读琥珀虚线）。
- **本地优先的朗读**：本地 **Kokoro-82M** 模型，缺了才回退云端（MiniMax），界面直接标「现在是谁在说话」。
- **实时判定**：每 1.9 秒转写一次增量音频，边读边染色；静音 2 秒自动停录。
- **Auto 开关**：≥80% 自动翻页并开录下一句，<80% 留在原地 —— 这就是一个**无需手动的口语训练环**。
- **6 个阅读辅助**：词高亮 / 逐词释义 / 全文翻译 / 模糊 / bionic reading / 限制查词次数。
- **生词 → 复习队列**：存词即入队，排 1/2/4/7/15/30 天。

**为什么 🟡 而不是 🟢**：① `@local/reader` + `private:true` ⇒ **没有可锁的版本**，锁版引进这条路直接不可用；② 它自带完整侧栏面板，与本仓「学习页 / 笔记页」是**面板二选一**关系，不是同面板内的增量；③ 17 MB 含大量 demo 资产。

**与 §4.2 的关系**：`study-tutor` 管**判分与证据**，`dsh-reader` 管**输入侧的练习形态**（说/打/听）。两者不冲突，但本轮**只出 1 个骨架**（任务书 L2 上限），故 `dsh-reader` 只登记不出骨架。

**与现有功能的关系：重复可强化（但强化的是「复习调度」这一环）**。本仓已有 `dsh-radar-fsrs-scheduler`（锁版 `ts-fsrs` 5.4.2，FSRS 算法）。上游用的是 **SM-2**（ease factor + interval + lapses），比 FSRS 老旧 —— 所以**算法层不值得抄**。

**值得抄的是三条工程口径**（这三条与算法无关）：

1. **「可选 AI」默认关**：不配 OpenAI 兼容端点时**完全不走网络**，只用本地词典。本仓多个功能默认就要调模型。

3. **只读模型工具**：`english_study(stats|dict|due)` 三个只读动作，让 agent 能答「今天该复习什么」但**不能改数据**。本仓把状态暴露给 agent 时值得照抄这个「只读 + 枚举动作」的形状。

**判 🟡 但不出骨架**：硬依赖 Python 进程 + YouTube 可达性，在国内校园网环境下这两条都不成立；且与本仓 FSRS 路线算法冲突。登记备查。
