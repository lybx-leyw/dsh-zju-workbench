## 1. 本轮结论

一句话：**`runtime.lock.json` 里的两个宿主版本不是「可选的上下界」，而是两个互斥的完整快照；而 61 条锁版依赖里，没有一条能同时对上两个。**

r80 量的是「装得上」（存在层）、r81 量的是「声明了没」（声明层）。中间还漏了一层最要命的：**上游声明的 peer 区间，与你锁的那个版本的那个宿主，对不对得上**。这件事 `npm install` 不会告诉你 —— 因为 `npm install` 只看**这一次**的树，而骨架是要长期跟着宿主换代的。

实测（§3）三个结论，按重要性排：

| 编号 | 结论 | 证据 |
| --- | --- | --- |
| **M-3** | **宿主是「快照」，不是「版本区间」**：`@deepseek-ai/dsh-tools@0.2.1-alpha.1` 把自己同代包（`dsh-llm`/`dsh-agent`/`dsh-session`…）的 peer 写成**精确版本**；把两个快照混搭直接 `ERESOLVE` | §3.4 三组实测 |
| **M-4** | **没有一个锁版包同时满足两个快照**：11 个可判 → 5 个只对 rc、1 个只对 alpha、6 个两个都不对 | §3.2 |
| **M-2** | **判「锁的版本」而不是「包的 latest」**：`dsh-panda-calendar` 锁 `1.2.4`（**无 peer**），`latest` 是 `1.2.5`（四条 peer）—— 拿 latest 去评锁版，会凭空造出一个不相容 | §3.3 |

M-3 把 r79 的那句「自带 patch ⇒ 只能 🟡」**替换成了一条更硬的约束**：不是「它多了一个入口所以降级」，而是**它只能挂在某一个快照上，换代时要整组重锁**。

### 3.3 M-1：第一版把框架层当成了宿主层（已纠正）

首版按 `@deepseek-ai/*` 前缀收 peer，于是 `@deepseek-ai/cordis: ^4.0.1` 被拿去和 `0.2.0-rc.2` 比 —— **13 个包当场全判 `❌`**，看起来像「生态大面积不兼容」。

真实情况：`@deepseek-ai/cordis` 的版本线是 **4.x**（npm latest `4.0.5`），它对应 `runtime.lock.json` 的 `cordisMajor: 4`，**不是**宿主的 `0.2.x`。改成：宿主层只认 `@deepseek-ai/dsh-*`，框架层单独对 `cordisMajor` 求值。

**如果没有这次自检，本轮会发出一份「13 个包全不相容」的假报告。**

### 3.4 M-2：判锁版，不判 latest（已纠正）

`dsh-panda-calendar`：锁 `1.2.4`（registry 上该版本 **`peerDependencies: undefined`**），`dist-tags.latest` 已是 `1.2.5`（四条 `^0.1.0-rc.6 || ^0.2.0-rc.1`）。首版用 latest 的 peer 去评 1.2.4，凭空判出一个 `DRIFT`。

改成**按 `包@锁版` 逐条取 manifest**后，它归入 `NO_HOST_PEER`。同时输出「锁的版本落后 latest」作为**信息**（不当失败）：本轮 17 条落后，含 `dsh-context@0.71.0 → 0.77.0`、`dshmarket@1.66.21 → 1.71.1`。

> 这与 r46 记的「npm 可锁 ≠ 能锁到最新」是同一条教训的**第四种形态**：
> ① 没 publish（404）② 只有预发布 ③ 仓库比 npm 新 ④ **npm 上有更新的版本，而新版本的 peer 和旧版本不一样**。

### 3.5 M-3：宿主是快照（本轮核心）

用真实 `npm install` 做三组，全部在 `/tmp` 的裸目录里（不碰本仓）：

| # | 依赖 | 结果 | 装出来的版本 |
| --- | --- | --- | --- |
| ① | `@deepseek-ai/dsh-tools@0.2.0-rc.2` | 放行 | `tools/llm/agent/session` 全为 `0.2.0-rc.2` |
| ② | `@deepseek-ai/dsh-tools@0.2.1-alpha.1` | 放行 | `tools/llm/agent/session` 全为 `0.2.1-alpha.1` |
| ③ | `tools@0.2.0-rc.2` + `llm@0.2.1-alpha.1` | **拒绝（`ERESOLVE`）** | — |

原因在宿主自己的 manifest 里：`dsh-tools@0.2.1-alpha.1` 的 peer 是

```json
{ "@deepseek-ai/dsh-llm": "0.2.1-alpha.1", "@deepseek-ai/dsh-agent": "0.2.1-alpha.1",
  "@deepseek-ai/dsh-session": "0.2.1-alpha.1", "…": "0.2.1-alpha.1" }
```

—— **精确版本，不是区间**。`0.2.0-rc.2` 同理。所以两个宿主各自是一组**版本互锁**的快照，
「宿主版本窗口」这个说法本身有误导：它不是一个可以取中间值的区间。

**对雷达的直接后果**：骨架里的锁版清单与宿主快照是**绑定的**。以后给骨架升级宿主，
不是改 `runtime.lock.json` 一行，而是要把这一批上游包的锁版**整组重算**。

### 3.6 M-4：没有交集，一条都没有

11 个可判的包里，**双快照同时满足的是 0 个**。这不是巧合 —— 由 M-3 推得：
上游包要么对 `^0.2.1-rc.x`（只放 alpha 及以上）、要么对 `>=0.2.0-rc.2 <0.3.0`（放 rc、不放 alpha），
而两者在 semver 里**互斥**（`alpha < rc`）。所以：

> 「同时支持两个宿主」不是「努力一下能做到」，而是**必须放弃 `^`、改写成显式 `||` 白名单**。

`@nanmicoder/dsh-agent-teams@0.1.25` 正好是这么写的：`0.2.1-rc.3 || 0.2.1-rc.2 || … || 0.2.0-rc.2 || …`（10 项），于是它成了本轮唯一一个「rc 过、alpha 不过但**写法上留了位置**」的包 —— 它只要把 `0.2.1-alpha.1` 加进白名单就能双栈，而其余包要改区间语义。
