GitHub 元数据给的是 `license.spdx_id = NOASSERTION`，按流程它只该进「待人工核验」。**但它是 `license.name == "Other"`，必须点开原文**：

  b. Small Internal Use by fewer than three total Users …

且 `LICENSES/` 目录下除 `MIT-legacy.txt` 外还挂着 `LicenseRef-GSAP-Standard.txt`（GSAP 自定义许可）。⇒ **既不是宽松白名单、也不是「待核」，而是明确红线**，与 `thu-info-app`（BUSL-1.1）同类，判 ⛔、不摘任何代码。

### 3.2 `gorwayne/dsh-gor-tasks` —— 形态最漂亮，**npm 上没有**

**硬伤②：没有可拆任务的落点。**

| 探测 | 结果 |
| --- | --- |
| 本仓是否有 markdown 任务列表渲染 / 解析 | 全仓 `grep -rniE "\- \[ \]|taskList|gfm|remark-gfm"` → **0 个实现**（只有 4 处注释提到「不引 remark-gfm」） |

## 4. 词面与口径校准（本轮真正的产出）

### 4.1 `pushed:>` 里的 `>` 必须 URL 编码

同一条件两种写法，结果完全不同：

| 写法 | 返回 |

| `q=dsh+plugin+pushed:%3E2026-10-20` | `total_count = 6 590` |

本轮前 3 次因此空转。**已确认：脚本里 `>` → `%3E`、`<` → `%3C`。**

### 4.2 A 组两头都饱和

| 轴 | 观测 | 结论 |
| --- | --- | --- |

⇒ **建议下一轮 A 组改扫「中星段」`dsh plugin stars:20..200 sort=updated`** —— 这是唯一还没被扫过、又已滤掉噪声的区间。**未在本轮执行，因搜索额度已用满 10 次。**

### 4.3 A 类候选的「第一道闸」应前移到 npm

`gorwayne/dsh-gor-tasks` 与 r123 的 `luobosibing2/dsh-jev-plugin` 是同一个坑：**形态齐全、许可证 MIT、当天在推，唯一问题是 npm 上没有**。两次都是读了好几处源码之后才发现。

> **流程改进（建议写入 skill）**：A 类候选拿到 `owner/name` 后，**第一个请求**就是 `registry.npmjs.org/<scope>%2F<name>`；404 或 `versions` 为空 ⇒ 直接 🔵 归档，不读 package.json、不评估功能。这能省掉每轮 2–4 次无效源码请求。

### 4.4 `license.name == "Other"` 必须点开原文

`iPolloWork` 是第 3 例（前两例 `thu-info-app` BUSL-1.1、`See-Sol-Lab/DeepSeekGUI`）。只看 `spdx_id = NOASSERTION` 会把它归到「待人工核验」；点开原文才看得见「<3 人 / 非商业」的授权边界 → 应当直接 ⛔。
