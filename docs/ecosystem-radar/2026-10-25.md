## 3. 本轮的实质发现：重复页会**撕裂知识树**（实测）

### 3.1 起点

本轮一开始想找的是「智云课堂 → 讲义」这条链上的外部增强，注册表里这条链已有 3 条（`learnpilot`、
`Learning-at-ZJU-Helper`、`ZYNotes` 都是）但**都不在 JS 栈 / 未接入**。于是改为**先读本仓代码找断环**，
再回头看外部项目有没有对应能力 —— 这样即便候选全落选，报告仍有可执行结论。

读 `packages/dsh-zhiyun-core-lecture/src/tree.js`（821 行）时注意到：
`buildLectureTree({ slides })` 的 `slides` 来自 `dsh-zhiyun-core-parser/src/organize.js:51`
（`pages.map(p => ({ page, text: p.transcription?.pageText }))`），而**全仓没有任何一处判定「这一页和前面某一页是同一张」**：

```bash
grep -rn "续讲\|同页\|重复页\|重复图\|slide.*dedup\|相邻" packages/dsh-zhiyun-core-{parser,lecture}/src
# 只命中 tree.js 里「同页的叶合并成一组」—— 那是**同一页内**的块归并，不是**跨页去重**
```

`dsh-zhiyun-core-parser/src/vision.js:27` 里的 `duplicate` 集合是**一次拼图批处理内的页号重复**
（模型把同一页吐了两次），与「第 4 页的画面和 第 2 页相同」无关。

### 3.2 实测：一页回看，树从 1 个节点裂成 2 个

```js
const page = (p, t, b) => ({ page: p, text: `${t}\n${b}` });
const base = [
  { page: 1, text: '第三章 优化方法' },
  page(2, '3.1 梯度下降 Gradient Descent', '沿着负梯度方向迭代更新参数'),
  page(3, '3.2 学习率 Learning Rate', '学习率过大导致震荡，过小导致收敛慢'),
  page(4, '3.3 动量法 Momentum', '引入动量项以加速收敛'),
  page(5, '3.4 自适应学习率 Adam', '结合动量与二阶矩估计'),
];
```

| 情形 | `buildLectureTree` 产出的知识点 |
| --- | --- |
| **G** 无回看（5 页） | `第三章 优化方法[1-5]` —— **1 个节点，正确** |
| **H** 老师回看第 3 页（6 页，第 4 条是第 3 页的副本） | `第三章 优化方法[1-2]` / `2 学习率 Learning Rate[3-4]` —— **2 个节点，且第 2 个节点吞掉了后面一切** |

**为什么后果比「多一页」严重得多**：`tree.js` 的标题判据是「**在别的页也出现过** → 它是标题」
（`looksLikeTitle` 第 1 条，`pageCountOf.get(line) >= 2`）。回看产生的副本让「3.2 学习率」
的**出现页数从 1 变成 2**，于是它**从正文行升级成标题**，把第 3–5 页全部收进自己名下。

也就是说：**重复帧不是多了一段噪声，而是把一个章节标题变成了一个吞掉三页的伪知识点。**
而 §3.2 的 H 里，`3.3 动量法` / `3.4 Adam` 两个真标题**彻底消失了**。

此外，「章」也被误判：`第三章 优化方法[1-2]` 说明第 2 页被归进了章里 —— 一棵 5 页的课件被拆成了两个不同层级的东西。

### 3.3 所以外部项目**不能照抄**：ZYNotes 的算法对回看无效

`Auspiow/ZYNotes` 的 `inject.js:546-567` 做的是**只与相邻上一张**比对（32×32 缩略图逐通道差 < 30 记同像素，
同像素率 ≥ 0.9 判同）：

```js
const last = mergedPpt[mergedPpt.length - 1];
if (lastUrl === currentUrl) continue;
if (await isSameImage(lastUrl, currentUrl)) continue;
```

把它原样搬过来，对「A→B→A→C」这种**回看**（老师翻回上一节讲重点，再翻回去继续）**完全无效**：

```
输入：3.1@2 → 3.2@3 → 3.1@4 → 3.3@5 → 3.2@6 → 3.4@7
相邻比对后保留：3.1@2 → 3.2@3 → 3.1@4 → 3.3@5 → 3.2@6 → 3.4@7   （一页没删）
仍有重复标题：2
```

> **这是本轮最有价值的一条结论**：如果按「外部有更优实现 → 接进来」的直觉去接 `ZYNotes`，
> 会引入一个**在本仓最大用例（回看）上命中率为 0** 的组件。

### 3.4 正确的形态：按**内容**判定，不按**位置**判定

本仓有一个外部项目没有的结构性优势：**每一页都已经被 OCR 转述成文本了**（`vision.js` 的 `pageText`）。
在浏览器里，ZYNotes 只能拿像素；在服务端，我们可以同时拿**文本**和**像素**。于是：

| 判据 | 能用什么 | 为什么比上游强 |
| --- | --- | --- |
| 文本近重（主判据） | `pageText` 归一化后比对 | 回看的帧**文本必然一致**；像素会因动画/光标/缩放而变化 |
| 像素近重（兜底） | `sharp` 已在本仓（`dsh-zhiyun-core-parser/package.json:16`，锁 `0.35.5`） | 只处理「纯图无字」的页（公式、示意图），这类页文本为空、只能看像素 |
| 页号连续性 | `page` 单调性 | 回看时 `page` 会**倒退**，这是最强的信号 —— 上游根本没有 `page` 字段可用 |

**去重后必须保留原页号**（`page` 不能重编）：`buildLectureTree` 的 `fromPage/toPage`、`slideEvidence`
（`organize.js` 的 `Math.abs(n - p.page) <= 1`）都以**原课件页号**为坐标。重编号会让所有页码引用错位。

## 7. 方法论增量（写入 `rotation-state.md` 之外，供后续轮次复用）

1. **`in:name,description,readme` 是无效放大器**。它把单字词扩到全库 OR 匹配，
   1014 条结果、前 10 无关。B/C 组的正确形态是 `关键词 in:description language:<x>`（单限定符）。
2. **中文关键词（`浙江大学` / `智云课堂`）在 GitHub 上是噪声发生器**：高星无关项目会稳定占满前 10
   （本轮 `智云课堂` 的前 10 里有 4 条政治性仓库、`浙江大学` 前 10 里有 25170 星的无关书单）。
   → 中文词只在**英文词已经搜完**时作为补充，且**只看 100 条以内**再决定要不要放弃。
3. **「外部有更优实现」必须先问一句：它在我的主用例上命中吗？**
   本轮 ZYNotes 的相邻比对在本仓最大用例（回看）上命中率为 **0**（§3.3 实测）。
   若不实测就直接锁版/移植，等于把一个 0 收益的层写进链路 —— 这正是 skill 里
   「重复且无增益 ⛔」那条判据要拦的东西。
4. **无许可证项目的正确用法是「问题证据」而不是「代码来源」。**
   `ZYNotes` 让我们知道重复帧真实存在，这个信息价值很高；它的代码一行都不能拿。
