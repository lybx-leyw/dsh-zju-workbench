**它的底层选型恰好是我们要的（这是 🟢 而非 🟡 的关键）：**

| 格式 | 上游用的库 | 版本 | 许可证 | 为什么比自己选强 |
| --- | --- | --- | --- | --- |
| DOCX | `mammoth` | 1.13.0 | **BSD-2-Clause** ✅ | 纯 JS、维护活跃、**直接输出 Markdown**（不是裸文本，保留标题/列表/表格结构，正合笔记与考点提炼） |
| XLSX | `read-excel-file` | 9.3.14 | **MIT** ✅ | 上游注释明写「**replaces `xlsx@0.18.5` which carries prototype-pollution CVEs**」—— 规避了 SheetJS 社区版的已知原型污染漏洞 |

**⚠ 一个必须点名的坑（不影响判 🟢，但决定骨架怎么写）：**

> **npm 上的 `dsh-files` 不是它。** `https://registry.npmjs.org/dsh-files` 返回 `0.0.1`，作者 `dushaobindoudou`，description 写着 *"File manager panel for the dsh web GUI - **name reserved**; first release in development."*，tarball 里**只有 `package.json` + `README.md`，零代码**。
> 而上游仓库 `package.json` 的 `name` 恰恰就是 `dsh-files`、`version` 已 `0.7.0` —— **上游从未成功发布到 npm**（`@taxueseek/dsh-files`、`@taxueseek/files`、`dsh-files-toolkit` 全 404，scope 搜索结果 0）。
> ⇒ **不能写 `"dsh-files": "0.7.0"`**，那会装到陌生人的占位包上。骨架因此改为**锁版引入它的三个底层库**（`mammoth@1.13.0` / `read-excel-file@9.3.14` / `word-extractor@1.0.4`），由本仓兼容层自己做 `read_document` 编排。
> ⇒ **这是本雷达第一条「npm 同名不同物」案例**，与 r145 的「npm 404 即封」构成一对：**A 类第一步既要查「存不存在」，也要查「是不是同一人」**（比对 `repository.url` / `dist.tarball` 的 `package.json` 与 upstream git 地址）。
