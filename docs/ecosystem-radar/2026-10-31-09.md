| 锁版核验 | `npm view @guowenzhang/dsh-whiteboard version license` → `0.4.0` / `Apache-2.0` ✅；编辑器依赖 `@guowenzhang/dsh-drawioedit@1.2.1` 同步核过 |
| 关系 | **重复可强化**（笔记页、论文页仍是原面板；功能仍相似正交；底层多调了上游画布） |

**三条同时成立**的论证：

1. **仍是同一个面板** —— 不新增左侧「Whiteboards」导航；①画板挂到 `dsh-zhiyun-core-notes` 的 `zy-asset` 解析链
   （`board://<id>`），②论文页挂「批注板」（`paper://<docId>#<page>` → 板 id）。两个入口都在既有页面里。
2. **功能仍相似正交** —— 还是「在笔记/论文旁边记下想法」，只是从**只能写字**扩展到**能画**；不与笔记正文抢内容、
   不与精读抢阅读器。
3. **底层多调了更优质实现** —— 画布渲染、`.drawio` 读写、导出全由上游承担，本仓不自造画布。

**评审必须面对的两个坑（已写进骨架 README）**：

- 上游 `dsh.client.inject` 含 `dsh-client-ui-layout` / `-sidebar` / `-sidebar-right` / `-workspace`，
  会**自建左侧导航** ⇒ 骨架**只挂宿主半边**，不引入 `./client`（与 `dsh-radar-market` 不接 settings 同一理由）。
- 上游把画板存在**插件自己的 `files/` 目录**（其 README 明写，不在 workspace）⇒ 「笔记 ↔ 画板」映射只能旁挂索引，
  **索引格式须先定死**（建议 `.board-index.json`，键 `sectionId`/`docId`）。

**与已登记条目的取舍**：registry r112 已登记 `amumulam/dsh-tldraw-canvas`（同一「右栏画布」域，★0，MIT）。
本轮的 whiteboard 比它多一条**开放格式（`.drawio`，可外部编辑、可 diff）**，但也多一条**自建导航**的风险。
⇒ **二者一替一，不要都接**。若评审更看重随手草图，可改取 tldraw；届时本骨架整目录删除。
