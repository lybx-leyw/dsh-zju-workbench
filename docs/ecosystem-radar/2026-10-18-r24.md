### 2.0 为什么是这一轴（本轮方法论点）

本轮不是从「生态里有什么」出发，而是从**本仓自己的一个空洞**出发：

> `dsh-zhiyun-vault` 的 README 第 3 行写的是「双向链接、标签、**知识图谱**、未解析链接」，
> `graph` RPC 也在（`packages/dsh-zhiyun-vault/src/index/vault-index.js` 产出
> `{ nodes: [{id,title,inDegree,outDegree,tags}], edges }`）。
>
> 但 `packages/dsh-zhiyun-page-notes/src/client.jsx`（694 行）里**一个 `graph` 都没调用** ——
> 右栏只有「反向链接 / 指向 / 标签」三段。**数据算好了，没有视图在画。**

这条轴与已跑各轮正交：往轮问的是「插件能做什么」，本轮问的是
**「我们自己的数据链在哪一段断了」** —— 断在渲染层，于是去生态里找渲染层。

## 3. 新候选

### 3.1 🟢 可直接集成 —— 本轮唯一

| 仓库 | 类型 | 许可证 | 学生场景 | 与现有功能 | 分级 | ★ | 最近 push |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `cytoscape/cytoscape.js` | **B 其他JS**（纯库） | **MIT** ✅ | 笔记（知识网） | **全新**（补一个缺的视图，非强化） | 🟢 | 11239 | 2026-10-15 |

- **是什么**：图论 / 网络可视化库。`dependencies: {}`（**零运行时依赖**，npm 3.34.4 实核）。
  内置图算法（连通分量、最短路径、最短路/桥/割点），两套渲染器（Canvas / SVG），
  `cy.mount()` 直接挂 DOM，**不需要 React 绑定**。
- **为什么是它，不是 sigma.js / react-force-graph**：见骨架 README 的对照表。
  一句话：**零依赖 + 单包 + 内置图算法 + 可导 SVG**，正好对上「侧栏里一张小图」的尺寸，
  而 sigma 要两个包、react-force-graph 绑 three。
- **强化三判据 —— 判据 ③ 不成立，已如实标注**：

| 判据 | 本条 |
| --- | --- |
| 仍是同一个面板 | ✅ 「笔记」页右栏折叠区块，不新增导航项 |
| 功能仍相似正交 | ✅ 同一批笔记、同一份链接数据；从「一篇的反链列表」到「全库的链接网」 |
| 底层多调了更优质实现 | ❌ **不成立** —— 本仓**没有**任何图谱渲染器。这是「无 → 有」 |

- **因此按「全新」登记**，README / `src/upstream.js`（`BASELINE_HAS_GRAPH_RENDERER = false`）都写死了这一点。
  **雷达没有为它编造强化叙事** —— 之前 `dsh-radar-temml` 也遇到过同样的「基线为空」情形，
  那次记为 🟢 并加了人工确认项，本轮沿用同一处置。
- **它凭什么进 🟢 而不是 🔵**：因为**不需要新建任何东西**。图数据已由 vault 产出，
  缺的只是一个渲染器；接入点是「右栏加一个折叠区」，不是「新开一页」。
  这是本轮唯一一条「接进来就有东西看」的候选。

## 6. 需要人工 review 的重点

1. **⚠ 定性：这是「全新」，不是「强化」**（见 §3.1）。若产品判断「笔记页不做图谱」，
   本骨架应直接关闭，而不是降级保留 —— 保留一个「补缺视图」的骨架会持续占用评审注意力。
2. **⚠ 挂载形态二选一**（骨架 README「已知风险 1」）：**纯库包**（由 page-notes import，删 `cordis.patch.yml`）
   还是**独立 bundle 行**（需要 page-notes 先有「右栏插件位」，否则是凭空新增挂载点）。**建议前者。**
3. **右栏默认收起 → 功能默认不可见**。这是「做了没人发现」的典型。建议把状态栏的
   「链接 / 标签数」做成可点入口，点开右栏并展开图谱区。
4. **布局阻塞主线程**：fcose 在几千节点是秒级。骨架定了「>800 篇转 `preset` + 手动布图」，
   但**阈值必须用真实库量校准**（本仓无真实笔记库样本）。建议首版**只用内置 `cose`**，
   验证后再决定是否引入 fcose（可少一个传递依赖）。
5. **与 `dsh-radar-knowledge-graph` 的画布归属**：语义图骨架上轮已指出「上游自带整页 UI」，
   若两者都要落在同一个画布，**必须先把这个画布归 page-notes 所有**（本骨架是前提，不是并行项）。

## 7. 方法论沉淀（供后续轮次复用）

- **从「自己的空洞」出发的扫描效率最高。** 本轮唯一 🟢 不是搜来的，是**装配时发现的**：
  vault 算了 `graph`、页面没画 → 直接去搜「渲染库」。**建议每轮开场先跑一条自检：
  「哪个 RPC / 导出字段没有消费者」**（本仓可脚本化：`grep` 每个 `case 'xxx'` 的消费方）。
- **产品名 + 视图名是最好用的关键词形态**：`obsidian graph view`(289) 一次捞到全部形态；
  而抽象词 `knowledge graph visualization library`(20) 全是课程作业。
- **1 次搜索判词面撞车**：`wallet filter` 一次即证明「过滤词表」被加密钱包占满 → 该轴封板。
  **比读 README 便宜一个数量级，建议常规使用。**
- **图谱轴已封板**：本轴 3 个月内不再扫 `obsidian graph view` 的 updated 视图（全是 ★0–1 的当周插件）。
