**本仓实测缺口**（逐条核对代码，非凭描述）：

- `grep -ril "charger|充电|neptune|尼普顿" packages/ apps/ profiles/`（排除 `packages/radar/`）
  → **0 命中**。
- `packages/source/` 九个 source（`campus`/`cc98`/`classroom`/`http`/`login`/`netproxy`/`webvpn`/`xxt`/`zdbk`）
  **均无尼普顿**。
- 本仓唯一的定时/时间轴能力是 `packages/client/page-today/src/agenda.js` 的
  `projectAgenda()`（**纯投影**，不执行任何动作）与 `page-planning` 的**周期**日历规则。
  「**单次 + 有限重试窗 + 超期作废**」的执行器形态**确实没有**。

**三条强化判据**（同时成立）：

1. **仍是同一个面板** —— 不开新页面；「今天」页 `projectAgenda()` 继续是唯一入口，
   只在次日 06:00–08:00 段插一行状态。
2. **功能仍相似正交** —— 时间轴上同一段（清晨），内容是「桩开没开」而不是「上什么课」。
3. **底层多调了更优质实现** —— 上游有抓包还原的真实协议（`getUserInfo`/`getDeviceInfo`/
   `isChargeing`/`offCharge` 两段式）+ 北京时区锚定的 `nextChargeTime()`，本仓 0 行。

**为什么可以出骨架，而不是一行登记**：真正的可复用物不是「充电」，
而是 `serve` 里那套**预约队列语义**——

- 重试窗：桩 06:35 才上线，06:30 打过去必失败 ⇒ **15 分钟窗口内轮询 `isChargeing`**；
- 过期丢弃：队列中超 1 小时直接丢（**不补执行**，避免早上 10 点给用户开电）；
- 队列由外部写、执行器每 20 s 重读（可被 UI 侧写入）。

这三条能复用给**任何 campus 写操作**（占座、报修、缴费），不限于充电。

**⚠ 明确标记的偏离**：r152 口径写「`created` 距今 < 7 天 ⇒ 最高 🟡」。本轮判 🟢，
理由：① 上游是**单文件 375 行、零依赖**，不存在「明天接口重写」的锁版风险；
② 骨架**不 vendor、不写 `dependencies`**，`apply()` 为空，`upstream.js` 三个导出全 `throw` ——
即「锁版=钉在会变的 API 上」这一风险在本骨架里**不适用**。
若评审认为该口径不可破，本包降 🟡，骨架内容不变。
