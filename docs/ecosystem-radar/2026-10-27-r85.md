## 1. 本轮结论

一句话：**在浙大论文这个生态里，最像一个"可集成的底层"的项目（`Shuenhoy/modern-zju-thesis`，★107、MIT、Typst），恰恰是最不能摘的那个 —— 它的参考文献能力是三层嵌套的 AGPL/CPAL 产物。**

这条结论的价值不在「又排除一个」，而在它给出一条**可执行的许可证审计动作**：
**看一个仓库的 `spdx_id` 是不够的，必须看它有没有 `dist/third-party-licenses.txt`。**

`modern-zju-thesis` 的 GitHub `license.spdx_id` 是 **MIT**，`LICENSE` 首行是 `MIT License / Copyright (c) 2024 OrangeX4` —— 单看这两处，它是干净的。
但它的参考文献页 `pages/bibliography.typ` 只有 8 行，真正的实现全在 `utils/citext/`：

| 层 | 路径 | 声明许可 | 实际性质 |
| --- | --- | --- | --- |
| L1 | 仓库根 `LICENSE` | **MIT**（OrangeX4, 2024） | 模板主体的版权声明 |
| L2 | `utils/citext/LICENSE` | **MIT**（mgt, 2023） | **嵌套的第三方副本**，`README.md` 明写 "copied from https://github.com/Shuenhoy/citext" |
| L3 | `utils/citext/dist/third-party-licenses.txt` | —— | **真正的依赖清单**，12 个包逐条列明 |

L3 里有一条是致命的：

```
Name: citeproc    Version: 2.4.63    License: CPAL-1.0 OR AGPL-1.0
```

**`CPAL-1.0` 与 `AGPL-1.0` 都不在宽松白名单内**。按本 skill 的硬边界 —— **⛔ 只登记「仅供参考」，不得摘取任何代码**。

> 这一条正好合上了 r55 留下的那个洞。`packages/dsh-radar-refs-import/README.md` 第 46 行写着：
> 「引文样式、插引用、文献表生成**明确不在范围** …… 本骨架不做引文输出，**故不触碰 `citeproc-js` = NOASSERTION 那个未决点**」。
> 当时把「越过去」的策略定成**绕开**。本轮证明：**这条路绕不过去** —— 想在本仓做 CSL 输出，
> 无论照抄 `modern-zju-thesis`、还是照抄它抄的 `citext`，落点都是同一个 `citeproc`。
> **r55 的策略是对的，而且现在有了硬证据，不再是"待评"。**

## 3. 方法层：本轮真正可复用的产出

### 3.1 许可证审计：三层检查，不是一层

本轮把「看 `spdx_id`」升级成三步，建议固化为后续轮次的标准动作：

```bash
# ① 表面层：GitHub 认的许可（最不可信，只看它一定翻车）
curl -s .../repos/OWNER/REPO | jq -r '.license.spdx_id'

# ② 声明层：LICENSE 首行 + 包清单里的 license 字段
#    ⚠ 陷阱：这两处可能互相矛盾（citext 的 typst.toml 写 MIT，dist 里却是 AGPL）

# ③ 实层（关键）：找嵌套副本的依赖清单
curl -s .../contents/  | grep -i "third-party\|NOTICE\|dist/"
```

**判据**：只要在 ③ 里出现 `GPL` / `AGPL` / `LGPL` / `MPL` / `CPAL` / `SSPL`，**整仓降为 ⛔**，无论 ①② 写得多干净。

本轮 `modern-zju-thesis` 就是「①② 全绿、③ 一票否决」的典型。它的 `dist/third-party-licenses.txt` 一共 12 条：

| 包 | 许可 | 白名单 |
| --- | --- | --- |
| `@citation-js/core` 0.7.18 / `@citation-js/name` / `buffer` / `base64-js` / `sync-fetch` / `fetch-ponyfill` / `@citation-js/plugin-csl` / `@citation-js/plugin-bibtex` / `@citation-js/date` | MIT | ✅ |
| `ieee754` / `moo` | BSD-3-Clause | ✅ |
| **`citeproc` 2.4.63** | **CPAL-1.0 OR AGPL-1.0** | **⛔** |

11 条合规、1 条不合规 —— **但一条不合规就足以让整个 `citext` 不可用**，因为 CSL 排版能力**只**由那一个包提供。

### 3.2 一个反例值得记：`modern-zju-thesis` 的代码本身可能可读

需要说清的是：`modern-zju-thesis` 的**版式部分**（封面 / 中英标题页 / 声明页 / 页眉页脚 / 章节编号）**不经过 `citext`**，
那些 `.typ` 文件（`pages/graduate-cover.typ`、`documentclass/style/*.typ`）确实是 OrangeX4 的 MIT 作品。

**但本轮仍然判 ⛔，不拆开摘取**，理由有三：
1. 拆开摘 → 就要在仓库里维护一份「哪几个文件是 MIT、哪几个不是」的清单，**这种清单会随上游更新而失效**，是个长期负债；
2. 即便只摘版式，也过不了 §2 的判据②（**生产 vs 消费，不是同一面板**）—— 摘过来也没有落点；
3. 本 skill 的硬边界写的是「**不得摘取任何代码**」，未给"分文件摘"留口子。

> **留给人工评审的一个问题**：如果将来真要做「论文排版」面板，`modern-zju-thesis` 的版式文件（MIT 部分）是**可用的**，
> 但那属于**新面板立项**，不在雷达的"强化式集成"范围内。建议在 `docs/` 里记一笔，不要让它随本轮 ⛔ 被永久遗忘。
