### 4.2 为什么必须带缝合层（本轮最重要的实测）

用 commonmark + gfm 在 jsdom 下做真实往返（脚本见 `src/upstream.js` 文件头注释）：

```
✅ ```js 围栏        IDENTICAL
✅ 1. / 2. 有序列表  IDENTICAL
✅ # / ## 标题       IDENTICAL
✅ > 引用            IDENTICAL
❌ 见 [[线性代数]]   →  见 \[\[线性代数]]          ← 一票否决级
❌ 甲\n\n\n\n乙      →  甲\n\n乙
❌ 甲··\n乙          →  甲\\\n乙
❌ ---\ntags:[a]\n--- →  ***\n\n## tags: \[a]
```

第 1 条致命：`client.jsx:104` 的 `countLinks` 与整个反链体系都靠 `[[标题]]`。
**若无缝合直接 `getMarkdown()` 回写，全库双链会被静默降级成普通文本** —— 这类损失用户当场看不见。

因此 `src/upstream.js` 规定了**进出双侧私用区（`\uE000`–`\uF8FF`）占位符缝合**，并写死三条硬约束：
① 占位符必须落在不被 Markdown 解析的位置；② 占位符与还原表同生同死，中途抛错就整体放弃、退回 textarea；
③ 用户主动编辑过占位符区域时无法可靠对应 → **原样文本 + 标注，不猜**。

> **判定③的诚实写法**：判据③成立，**但前提是缝合层做到零漂移**。
> README 里已把它列为「评审前必须先回答的三个问题」之一，答「否」→ 撤销本包。

## 5. 两条可直接复用的工程口径（不摘码）

1. **「行尾逐字节保留」**（来自 `hh719509125/dsh-preview-editor` 的描述）：
   原位编辑器的第一难点不是渲染，是**不要改掉用户没碰过的字节**。本骨架的缝合策略把它升级为「整篇往返零 diff」的验收标准。
2. **焦点放行的选择器**（本仓既有实现，`client.jsx:1000 / :1128`）：
   `target.closest('input, textarea, select, [contenteditable="true"], [contenteditable=""]')` 命中即放行。
   ProseMirror 编辑区是 `contenteditable`，**天然命中** ⇒ 换成 WYSIWYG 后 PageUp/PageDown 的接管逻辑**不需要改 page-notes**。
   这条是「接入前先找既有闸门」的正例。
