## 一、本轮判定轴：CC98 的「读」已经够了，「看」还不够

B 组前几轮的结论是「浙大可嵌入 JS 库已在 10-16 扫穿」。本轮换轴：
**不再找「又一个 cc98 客户端」，而是找「本仓 cc98 正文读进来后，表达力丢在哪」**。

### 1.1 读码事实（逐条实测）

| 事实 | 位置 |
| --- | --- |
| 本仓读侧只做 **UBB → 纯文本**，全文 78 行 | `packages/dsh-zhiyun-source-cc98/src/ubb.js`（78 行） |
| 该文件内**无任何标签分派**（`grep -c 'tag\|case'` → **0**） | 同上 |
| 已有两个 cc98 渲染类骨架：`cc98-md-render`（读·保结构）、`cc98-ubb-bridge`（**写**·Markdown→UBB） | `packages/radar/dsh-radar-cc98-md-render/`、`packages/radar/dsh-radar-cc98-ubb-bridge/` |
| `bbob` 骨架只锁了 `@bbob/core` 等 6 个包，**未使用 `@bbob/preset`** | `packages/radar/dsh-radar-bbob/package.json` |

**结论**：读侧的结构丢失不是"没人做"，而是"做了两次但都停在纯文本档位"。
真正缺的是**标签语义表**——CC98 的 `[size=7]`、`[color=…]`、`[user]`、`[img=1]`（隐藏图）、
`[mp3]`/`[audio]`/`[video]` 在纯文本里全被压成内容本身。

### 1.2 与「重复且可增益」的边界

若只是"又一个 UBB→HTML 渲染器" → 与 `cc98-md-render` 重复且无增益（⛔）。
但 `griseous` 提供的不是渲染器，是**一份完整的 CC98 标签→HTML 元素的映射表（213 行 / 25+ 标签）**，
且它自己对每个标签的选择（`[img=1]`→`isHiding`、`[size]` 上限夹到 7 且换算 `n/3+0.5 rem`、
`quote`→`blockquote`）就是**上游 Forum 的原生实现**（文件首行注明出处 `ZJU-CC98/Forum/.../UbbCodeExtension.tsx`）。
这是本仓结构上给不出的东西 → **判据③成立**。

## 四、本轮三条净值最高的结论

### ① 「高 ★ 且最贴近」与「可用」是两回事 —— 本轮最典型的对照

同一次 `cc98` 查询里，★ 最高的是 `ZJU-CC98/Forum`（★224），但它是 Apache-2.0 的**桌面壳**（Electron/.NET），
与 Web 面板无可挂载面；本轮真正的产出 `CoolSpring8/griseous` 只有 **★1**。

> **判据不该写在直觉上**：★ 只是"有人喜欢"，而"可用"取决于 **许可证 × 形态 × 与本仓已有的差集**。
> 本轮 ★1 的项目之所以 🟢，是因为它**恰好**持有一份本仓没有的标签表；★224 的项目之所以不入选，是因为它的价值在客户端形态上，而形态我们不要。

### ② `OR` + 中文词的搜索式在 GitHub 上是**静默失效**的

#7 `zju 刷题 OR 题库 language:typescript` 返回 total 169 —— 与 #2 **逐条相同**。
#9、#10 同样如此。这不是"没结果"，而是**检索式被丢词后返回了一个更大集合**，看起来有结果、实际零信息。

> **校准**：B/C 组后续**禁用 `OR` 与中文关键词**；一条查询只放一个英文词 + 一个 `language:` 限定符。
> 本轮 10 次搜索里有 3 次（30%）属于此类无效消耗 —— 若按实际有效检索计，本轮仅 7 次。

### ③ 「下载无权限课件」「自动刷完视频进度」必须判 ⛔，且与许可证无关

`eWloYW8/ZJU-course-material-download` 与 `ZJU-course-video-complete` 都是 **MIT**、都在活跃维护、
都精准命中"学在浙大"场景 —— 按纯技术标准应该收录。
但它们做的事是**绕开教师设置的访问限制**与**伪造学习行为**。

> 本仓的六域服务的是"学得更好"，不是"学得更快绕过"。这类候选即使许可证宽松也一律 ⛔，
> 且在 registry 里写明原因，避免后续轮次仅凭 MIT 又重新捞回来判定。
