## 2. 本轮最有价值的产出是 L-1（缺陷/边界澄清），不是候选

### L-1 「不切词」到底缺什么 —— 实测推翻了本轮的初始假设

开场读码，`dsh-zhiyun-knowledge/src/service.js:253` 与 `page-study/src/layered-search.js:32`
都**如实自述**「字面、不切词、不算相关度」。本轮最初的假设是：
**学生搜「矩阵的秩」时，如果 ASR 把它断成「矩阵 的 秩」，就会漏检。**
实测（`jieba-wasm@2.4.0` + 直接 import 本仓真实 `findIn`）：

| # | query | 正文 | 旧 `findIn` | 说明 |
| --- | --- | --- | --- | --- |
| — | `行列式` | `…里的行列式与特征值…` | ✅ | 连续出现，字面就中 |
| — | `矩阵的秩` | `…还有矩阵的秩` | ✅ | 同上 |
| — | `秩` | `…还有矩阵的秩` | ✅ | 单字子串也能中（**这也是一条独立缺陷：召回过宽**） |
| F-1 | `泰勒展开` | `…用的是 泰勒 展开 的 二阶形式` | ❌ `null` | 中文夹空格 |
| F-2 | `行最简形` | `…化成行 最简形 之后` | ❌ `null` | 中文夹空格 |
| F-3 | `特征值` | `…求矩阵的 特征 值` | ❌ `null` | **分词同样空**（`cut_for_search('特征值') = [特征, 特征值]`） |
| C-1 | `极值点` | `…有个极值点` | ✅ | 对照组 |
| C-2 | `拉格朗日中值定理` | `…先用拉格朗日中值定理，然后` | ✅ | 对照组 |

**结论**：缺口**不是**「词被切开」，而是**写法不一致**（空格、标点、语气词）。
所以本骨架的定位只能写「写法容错」，不能写「分词检索」—— 后者会让人以为
「换成分词后召回率必然上升」，而 F-3 证明**分词反而可能更严**。

### L-2 上游的入口差异，比包本身更难查

| 平台 | 入口 | 形态 | 初始化 | 实测结论 |
| --- | --- | --- | --- | --- |
| Node | `pkg/nodejs/jieba_rs_wasm.js` | **CJS** | 顶部同步读 wasm，**无需 init** | `import { cut } from 'jieba-wasm'` **抛 SyntaxError**（CJS 无具名导出），必须默认导入 |
| 浏览器 | `pkg/web/jieba_rs_wasm.js` | **ESM** | **必须 `await __wbg_init()`**（默认导出） | 未 init 时 `cut()` 抛 `wasm is undefined` |

体积（实测 gzip）：`.wasm` **2,815,114 B**，胶水 JS 2,600 B —— 是首屏体积的十几倍。
`tag()` 词性标注对数学术语**不可靠**（`证明/n`、`函数/n`、`零/m` 全误标）→ 本骨架**不打算用词性**。

### L-3 `findIn` 是**客户端**函数，这是本轮唯一真正的阻塞项

`searchLesson()` 消费的是已下发到前端的 `result`，`findIn` 跑在浏览器里。
因此「让『学习』页检索具备分词能力」= 把 2.8 MB gzip 的 wasm 送进浏览器；
不送，则本骨架只能服务宿主侧 `knowledge.search()`，而「学习」页**仍然不切词**。
**这一条不裁决，骨架不应落地**（见骨架 README 的 Q-1，已标为阻塞）。

## 5. 新结论（供后续轮次复用）

① **「不切词」的自述是对的，但缺口被误诊了**。字面检索真正的问题有两面：
**召回过宽**（单字 `秩` 也中，且无相关度排序——这是第三十六轮的活）与
**写法过窄**（中文夹空格就漏，本轮）。**分词只解第二面的一半**，且可能加重第一面。
→ 后续轮次遇到「本仓自述不切词」，**先按写法差异构造样例，别直接假定「词被切开」**。

② **中文分词在 GitHub 上按语言家族分布，关键词检索必然先撞原版**：
`jieba in:name` 753 条，★ 前十全是 Python/Java/PHP/C#/Go/R 移植，JS 侧最大只有 ★3,234（原生模块）。
→ **中文基础能力（分词 / 数词 / 标点 / 拼音）要在 npm 按包名找，GitHub 关键词只用来发现新包**。
这条与第四十轮「图算法要按 npm 包名找」、第二十九轮「中文 NLP 搜索写法 = 名词 + language 限定」**第三次同结论**。

③ **`OR` 限定符在 GitHub 搜索里第三次确认失效**（本轮 `lunr-chinese OR elasticlunr chinese` 返 114,160 = 纯 `chinese`）。
建议直接写进 skill 的失败处理表，不再逐轮复验。

④ **同一能力「按平台分裂的入口」是 B 类可锁版的第六种死法**：
前五种是「包不存在 / `private:true` / 未 publish / 宿主版本窗口 / 默认入口在目标运行时跑不了」，
本轮新增**「入口存在且能跑，但两个平台的初始化协议不同（CJS 免 init / ESM 必须 `__wbg_init`）」** ——
锁版能锁住版本，锁不住调用约定。→ **B 类第三门应再加一问：同一份代码在两个运行时上是否需要两种初始化。**

⑤ **本仓今天的价值洼地仍在接缝，但今天这条接缝不该被治**：
F-1/F-2 两例是**构造样例**，真实讲义里「中文夹空格」的概率未知；而治它的代价是 2.8 MB。
→ 若评审决定不接，**建议把 `findIn` 的缺口写进 `layered-search.js` 的注释**（成本 0），
而不是留一个「看起来能用」的骨架。
