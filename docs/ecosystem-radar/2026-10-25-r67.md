## 1. 起点：一个矛盾，而不是一个缺口

本轮不从「找插件」开始，从 `packages/dsh-zhiyun-source-campus/docs/todos-vs-zju-mcp.md` 里的**一句没有出处的证据**开始。

那份文档（10-21 写的）的核心结论是：

> `/api/todos` 的返回项类型（`TODO_TYPE_CN`）只映射了 `homework / exam / quiz / survey` —— **没有课堂互动**。
> 所以「漏」最可能指的是课堂互动这一类。

这条结论是 `diffTodos()` 里 `missingFromFast = onlySlow.filter(type !== 'classroom')` 这行代码的**唯一依据**。
而本轮全仓检索：

```text
grep -rn "TODO_TYPE_CN" packages/ docs/   → 只命中 docs/todos-vs-zju-mcp.md:53 这一行
grep -rn "TODO_TYPE_CN" --include=*.mjs --include=*.js .  → 0 命中
```

**这个词在仓库里没有任何代码、没有 vendor 副本、没有 URL。** 也就是说：一个**判定「漏没漏」的阈值**，
建立在一句**无法复核的引用**上。这不是「缺一个库能补的能力」，是「判据本身要重新落地」。

于是本轮的关键词不是 `zju xxx`，而是 `zju cli` / `zju todos` / `chaoxing api` —— 找**别人对同一批端点做了什么取舍**。

## 3. 本轮实质发现：待办链路的三个判据都「有代码、没证据」

### 3.1 F-1 · `diffTodos` 的「漏没漏」阈值建立在一个仓库里不存在的词上

```text
docs/todos-vs-zju-mcp.md:53   → 引用 `TODO_TYPE_CN` 只映射 4 类是「结构性差异」的证据
grep -rn "TODO_TYPE_CN" .     → 只命中该文档自己这一行（0 处代码、0 处 vendor）
```

后果不是「错」，而是**无法复核**：这行 `filter(type !== 'classroom')` 决定了「聚合端点到底漏不漏」这个
**产品级判断**（信则 1 个请求，不信则 5N 个请求），但线上只有一句转述。

**本轮用第三方公开源码把这张类型表补上了**（`8eoyw/zju-learning-cli` `zju.py:739`，MIT）：
真机上活动类型至少有 **13 种**，`classroom` 只是其中之一，`forum / questionnaire / vocabulary / lesson / survey` 也都在。
→ **`filter(type !== 'classroom')` 的前提（「除课堂互动外都该两边都在」）没有任何证据支持**，
而它一旦不成立，`missingFromFast` 就会把 `forum`（讨论作业）、`questionnaire`、`survey` 全算成「真漏」，
「聚合端点漏不漏」的结论就会反着来。实测：

```text
逐课多出 material        → missingFromFast = ['material']
逐课多出 vocabulary/questionnaire/lesson → missingFromFast = ['vocabulary','questionnaire','lesson']
逐课只多出 classroom     → missingFromFast = []            ← 唯一「判对」的情形
```

### 3.2 F-2 · `published` 这个字段，只有本仓在用

```text
本仓  xzzd.js:626 / :654      published: flag(row?.published)   → isPendingTodo 第一道闸 published !== true → false
ZLA   zju.py:807-815          is_closed / is_started / end_time  → 不读 published
```

实测（本仓函数，注入 `now`）：

```text
isPendingTodo({ published: undefined, endTime: '2026-11-01T10:00' }) → false
isPendingTodo({ published: true,      endTime: '2026-11-01T10:00' }) → true
```

即：**只要上游某版 `activities` 响应里没有 `published` 字段，整门课的作业会在 `slow` 模式下全部消失**，
表现是「待办为空」，不报错。三套实现里：
- 本仓测试夹具**自己造**了 `published: 1/true`（`tests/campus-planning-contract.test.mjs:57-58`、`tests/campus.test.mjs:288`）；
- ZLA（MIT，真机跑过）**完全不读**它；
- `zju-mcp`（本仓已对照过）的 `TODO_TYPE_CN` 说法同样无法复核（F-1）。

→ **`published` 是「有测试、没真机证据」的字段**。它不是 bug，但它是**单点**：
一个字段缺失，整课待办静默清零。

### 3.3 F-3 · fast 模式把「逐端点降级」换成了「整包失败」（本轮唯一确定的行为回归）

`slow` 的 `read()` 明确按端点降级（`xzzd.js:298-310`：`FORBIDDEN` 只丢 `activities/exams/classroomList` 那一类，
且注释写着「An inaccessible activity list contributes no activities」）。`fast` 只有一条路：抛。实测：

```text
slow · classroom-list 403   → activities 1 条保住，classrooms 0（作业不受影响）   ✅
fast · /api/todos 403       → 抛 FORBIDDEN → index.js:454 catch 后 rows=[]        ✗ 整张学在浙大待办清零
```

同理 429（`RATE_LIMITED`）在 fast 下也是整包清零，而 slow 下只影响触发限流的那一门课。
→ **默认值从 slow 切到 fast（10-21 决策）在「请求数」上是对的，但把「部分失败」放大成了「全部失败」**，
且这一条**没有任何测试覆盖**（`tests/campus.test.mjs` 的 `todosFast` 三条只测了成功路径与 `API_SHAPE`）。

### 3.4 不作断言的部分

- 我**没有**验证「聚合端点到底漏不漏」——需要真机账号与一次 `ZHIYUN_TODOS=diff` 实跑，本沙箱做不到。
  本轮只证明**判据不可复核**，不宣称结论反向。
- `zju.py:739` 那张类型表是「真机上出现过」的记录，但我**没有**核实它是否覆盖全部类型，也没核实
  `forum` 是否**真的会出现在** `/api/todos` 的 `todo_list` 里。§3.1 的结论只到「前提缺证据」这一层。

## 7. 方法论增量（供后续轮次复用）

1. **「有代码、没证据」是第三种缺陷形态**（本仓第 3 次记录，形态最新）：
   r66 记的是「单测全绿但错」（断言止于返回值）、r62 记的是「有单测零调用」。
   本轮记的是**判据的引用失效**——`TODO_TYPE_CN` 在文档里被当作证据，在代码里根本不存在。
   → 建议：凡「用一句话决定产品路径」的注释/文档，**引用必须带可执行的位置**（文件:行 或 URL），否则视同无证据。
2. **B 组「找新插件」彻底封板（第 5 次确认）**：本轮 9 次搜索命中 30 余条 `zju*`，去重后**只剩 4 个新面孔**，
   其中 2 个无许可证、1 个是作业答案。B 组应按 r57 结论执行：**主词封板，起点一律「读码找断环」**。
3. **`zju+xxx` 这类限定词只有 3 个还活着**：`zju+cli`(28)、`zju+skill`(19)、`zju+webvpn`(7) 有真信息量；
   `zju+todos`(0)、`zju+api+nodejs`(0)、`zju+xuezaizheda`(0)、`chaoxing+api+typescript`(0) 全 0 →
   **产品词 + 语言限定在浙大生态里搜不到东西**（与 r57「新生态搜产品词」相反，因为浙大生态的新项目**不是插件生态**）。
4. **README 里的 feature 表比代码更能说明取舍**：`zju-learning-cli` 的 README 用一张表列了 20 个命令，
   一眼看出「它信 `/api/todos`」（`todo` 命令只有一行）——比读 1542 行代码快得多。**先读 README 的表格，再读代码。**
5. **许可证类型与语言都不能靠「看起来像」**：本轮 8 行里 4 行是 Py/C++（B 类限 JS），3 行无许可证。
   → 记录一条：**`language` 字段必须在 `repos/{owner}/{repo}` 详情里读，不能拿搜索结果页推断**（本轮 `Gvrzizo/lazy-tui` 即如此）。
