## 2. 起点：读码读出的断环（不是搜出来的）

判据来自**代码**，不来自候选。以下每条都在沙箱内直接 import 本仓真实模块跑过。

### 2.1 复习队列里**根本没有「到期」这个概念**

- `dsh-zhiyun-quiz/src/store.js:501`：`get reviewQueue() { return items.filter(q => q.status === accepted) }`
  —— 只按采纳状态过滤，**不排序、不算 due**。
- 队列项字段实测（`makeItem` 造题 → `adopt` → 读 `reviewQueue[0]`）：
  `id,courseId,sectionId,blockIndex,page,atSec,type,stem,answer,choices,distractorSourceIds,checks,warnings,status,createdAt,materialIdWith,…`
  —— **`due` 不在其中，`fsrsRating` 也不在**。
- 页面（`page-study/src/quiz-panel.jsx:32`）标题就叫「复习队列 N」，渲染成一个**不排序的清单**。

> 结论：这不是「调度器不够聪明」，是**队列里没有任何可排序的量**。

### 2.2 作答记录**没有写入路径**（R-1）

- 全仓 `grep -rn recordAttempt packages/dsh-zhiyun-*/src` → **只有 `store.js:604` 的定义**，零调用方。
- `study-core/src/workbench.js:627–630` 的路由只有 `quiz` / `quiz-generate` / `quiz-adopt` / `quiz-discard`；
  `host.js:43` 的 method 白名单与之逐字一致——**没有 `quiz-attempt`**。
- 也就是说：`masteryOf`（`store.js:678`）读的 `attempts` 数组，在页面这条链路上**永远是空的**；
  `masteryByPoint` 因此恒返回「数据不足（做过 0 题）」。

### 2.3 复载时**丢弃作答记录**（R-2）

- `workbench.js:376–379` 的 `openQuizStore()` 只做两件事：
  `store.loadItems(stored.quiz.items)` 与 `if (Array.isArray(stored.quiz.attempts)) store.loadAttempts(...)`。
  看起来是读的。但 `quiz-generate`（`:436–437`）与 `changeQuiz`（`:454`）落盘的写法是
  `await this.save(key, { ...stored, quiz: store.snapshot() })`，而
  `openQuizStore` 打开的新 `createQuizStore()` **从未被喂过 `attempts`**——去 `quiz-generate` 里看：
  `const { store, loaded } = this.openQuizStore(stored);` → `loaded` 只用于 `loadNotes`。
  **`store` 里的 `attempts` 是空数组**；紧接着 `snapshot()` 把 `attempts: []` 写回盘上。
- 实测（`makeItem` → `adopt` → `recordAttempt` → `snapshot` → **新 store 只 `loadItems`** → `snapshot`）：
  `保存前 attempts=1` → `写回 attempts=0` → **归零**；随后 `masteryOf()` 的回应是
  **「数据不足（做过 0 题，少于 3 题）」**——用户刚遗忘的那道题，系统当成**没做过**。
  ⚠ 这一跑复刻的是 `openQuizStore` 的**两步动作**（只 `loadItems`、不喂 `attempts`），
  但**没有实跑 `StudyWorkbench` 本身**（它绑文件落盘与宿主 `storageDomain`，构造成本高）。
  因此报告的措辞是「**按 `openQuizStore` 的读法推演 + store 层实证**」，
  **不声称已在运行中的页面复现**。要铁证，用一个 `storageDomain` 桩跑 `quizState → quiz-adopt` 两连击即可。
- **另有一处同类疑点**：`openQuizStore` 里 `const loaded = store.loadItems(...)` 的返回值是
  `{ loaded, notes }`（`store.js:736`），而调用方读的是 `opened.loaded.notes` ——
  `opened.loaded` 是**数字**，`notes` 取出来是 `undefined`，`?.` 兜住后**静默为空**。
  即：即便哪天 `loadItems` 想报告「第 3 条题读不回来」，这句话也**到不了用户眼前**。

> 三条合起来：**「复习」这个功能当前在数据层是不闭环的**。R-1 + R-2 都是**本仓自己的 bug**，
> 修它们不需要任何新依赖，也不在「生态雷达」的授权范围内直接改业务代码——
> 所以本轮以**报告 + 骨架外建议**的形式提出，交由 OWNER 决定。
