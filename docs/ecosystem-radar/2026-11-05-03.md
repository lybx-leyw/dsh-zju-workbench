### 2.1 🟡 `AnakinCao/dsh-md-export` —— 唯一「在做这件事」的，但为什么**不**拿它当上游

它是本轮唯一命中「笔记 → 导出」的候选，形态也最贴（A 类、MIT、`dsh.bundle` 齐全）。但三条硬伤：

| 项 | 实测 | 结论 |
| --- | --- | --- |
| npm | `https://registry.npmjs.org/dsh-md-export` → **`{"error":"Not found"}`** | **无法锁版** |
| GitHub package.json | `"version": "0.1.0"`，**无 `dependencies`、无 `peerDependencies`** | 没有可锁的上游 |
| 形态 | `dsh.client.inject` 依赖 **`dsh-better-sidebar`** 的编辑器工具栏；导出 = 「HTML（mermaid 内联）+ PDF（**走浏览器打印对话框**）」 | 与「单文件、可离线、公式不糊」不是一回事 |

> 星标 5、建仓 2026-08-26、无 npm 发布、只有 1 个 commit 层级的活跃度 ——
> **评分上 🟡 而非 🟢**：它确实在做本仓缺的那件事，但「不可锁版」使骨架无法以它作为上游。仅作**思路参照**（不摘代码、不锁版）。

### 2.2 ⛔ `rong-coder/dsh-office-tool`（★7, MIT）—— 为什么排除

9 条里唯一「真能写 docx」的 A 类插件，但：

- `peerDependencies` 含 **`dsh-better-sidebar@^0.12.2`** + **`react@^18.2.0` / `react-dom@^18.2.0`**；
  本仓 profile 的 React 侧口径与之**未经核对**，而 r84 已实证「宿主是两个互斥快照，混搭即 `ERESOLVE`」。

  这是**宿主之外的进程依赖**，违背「锁版挂载 + 外围兼容层、不改上游」的边界（没有可锁的 JS 面）。
- 结论：**⛔ 不集成**，只登记。它给出的信息比它本身更有价值 —— 见 §四-②。
