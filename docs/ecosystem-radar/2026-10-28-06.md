## 1 · 审计先行：r88 的「第四个市场」结论**判据用错了**

### 1.1 结论原文与它实际依赖的假设

r88 记：`dsh-research` 属于「第四个插件市场」，按「重复且无增益」⛔ 处理。
这个结论**依赖一个未经核实的判断**：把它当成了又一个**通用**市场。

### 1.2 逐条读 README 后，假设不成立

上游 README 原话：

> The official market already installs anything in the community registry, and does it well.
> What it cannot do is tell a researcher which of its eleven hundred plugins are theirs.
> That is the part this does.

它不是 `dsh-market` 的替代品，而是**叠在通用市场之上的一层筛选**：

| 维度 | `dsh-market`（在册 🟢，已出骨架） | `dsh-research`（本轮） |
| --- | --- | --- |
| 答的问题 | 「生态里有什么、点了就装」 | 「**我这一方向**的，有哪些」 |
| 覆盖面 | 社区 registry 全量 | 人工读过的**限定目录**（`market.json`） |
| 与对方关系 | 被叠加的底座 | **叠加方**，不替换底座 |

「第四个市场」这个说法本身没错 —— 它确实是第四个同类候选。**错在把「同类」直接等同于「替代品」**，
于是漏掉了「A 叠在 B 之上」这种形态。这类候选的判据应是：**它是否要求底座存在**。
要求 → 不是替代，是增强层。

### 1.3 对本仓的推论

`dsh-radar-market`（骨架已锁 `dshmarket@1.66.21`）与本轮 `dsh-radar-research-market`
可以共存，但**必须只有一个 `allowInstall` 开着**：

- 两者都通过 `dsh plugin --profile … add` 写同一份 `package.json`；
- 上游自己 README 也写了「两次并发 `plugin add` 会在同一份 `package.json` 上打架」；
- 结论：**一个页、两套目录、一个写开关**。这条已写进新骨架 README 的「接入前必须先做的事」第 1 条。

### 1.4 顺带修正的另一件事：市场簇的去重判据

registry 里市场类候选已有 6 个被 ⛔（`dsh-plugin-shop`、`2BingLing/dsh-market`、
`DSH_Creative_Workshop`、`dsh-webui-market-plugin`、`LivXue`…）。它们被判 ⛔ 的理由是
「本仓只需一个后端」—— 这个理由对**通用**市场成立。本轮起，市场类候选**先问一句**：

1. 它是通用目录，还是**限定目录**？
2. 它是否**要求某个通用市场存在**（叠加层）？
3. 它提供的**安装通路**是不是自己的（自己 spawn `dsh plugin`）？

三者都不同 → 不是重复；任一相同 → 按原来的「重复且无增益」处理。

## 4 · 方法层（可复用）

1. **「同类」≠「替代品」。** 判一个候选是否重复，问的是「**它是否要求另一个候选存在**」，
   不是「它属于哪个品类」。前者能识别叠加层，后者只能数人头。
2. **高星候选要先看 `files` 字段。** `dsh-synapse` ★598 看着最该做，但 `files` 只发 3 个 js，
   实现全内嵌 → 立刻知道「锁版挂载」这条路走不通。**一个字段省掉一次误判**。
3. **许可证实文必须读首行。** 本轮 39 个里有 6 个 `null`、2 个 GPL-3.0、2 个 `NOASSERTION`；
   `NOASSERTION` 里有一个 ★1607（本轮最高星）—— 星级与许可证质量**零相关**。
