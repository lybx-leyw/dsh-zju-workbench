## 3. 本轮的实质发现：**学期口径有三套，且互不可逆**

> 这是本轮最有价值的产出，**不需要任何新依赖**，只改本仓代码。以下全部为**实跑**，不是推演。

### 3.1 本仓内部的矛盾

`packages/dsh-zhiyun-source-zdbk/src/parse.js` 同一文件里：

| 位置 | 写法 | 含义 |
| --- | --- | --- |
| `parse.js:15` | `export const TERMS = ['秋', '冬', '春', '夏']` + 注释「浙大按秋/冬/春/夏分，**不是**简单的上下半学期」 | **四段制** |
| `parse.js:101` | `key.match(/^\((\d{4}-\d{4})-(\d)\)/)` → `semester: Number(m[2])` | **只认 `-1` / `-2`**，`-3`/`-4` 原样变成 `semester: 3` / `4` |

实跑（抽 `semesterOfCourseKey` 逐字符照抄，避免拉起 `dsh-zhiyun-source-campus` 依赖）：

```
(2023-2024-1)-数据结构-01   → {"academic_year":"2023-2024","semester":1}   秋冬首段
(2023-2024-2)-数据结构-01   → {"academic_year":"2023-2024","semester":2}   春夏首段
(2023-2024)-数据结构-01     → null                                        未分段的秋
(2023-2024-3)-大学英语-01   → {"academic_year":"2023-2024","semester":3}   ← 四段制的「秋」，被当成第 3 段
```

**后果**：`reads.js:159` 用 `key = ${academic_year}-${semester}` 分学期、`reads.js:126` 用
`${academic_year}${semester}` 排序。`semester: 3` 既可能是「四段制里的第 3 段（春）」，也可能是「第 3 学期」——
**下游无法区分**，而这两者在 `TERMS` 里指的不是一段时间。

补充实跑：`reads.js:126` 的排序键是**字符串直接拼接**，`2025-2026` + `1` = `"2025-20261"`，
与 `2025-20261` + `0` = `"2025-202610"` 撞车（当前数据不会出现，但键本身不单调，属于**隐患而非现症**）。
真正的现症是**同一学年内**的排序：`"2025-20264"` > `"2025-20261"` 是对的（夏在校历上晚于秋），
但 `semester` 若只取 1/2，**夏与春会被压成同一个 `semester: 2`**。

### 3.2 与上游引擎的口径对照

上游 `engine/common.py`：

```python
学期字符串 "YYYY-T"：T=A 表示学年 YYYY 的秋季，T=B 表示学年 YYYY 的春季
idx = YYYY*2 + (0 若秋, 1 若春)
```

实跑对照（脚本见 `parity2.py`）：

| 本仓学期键 | 本仓映射 | 引擎学期键 | 引擎 idx | 含义 |
| --- | --- | --- | --- | --- |
| `2023-2024-1` | `(1, 秋冬)` | `2023-A` | 4046 | 2023 秋 |
| `2023-2024-2` | `(2, 春夏)` | `2024-B` | 4049 | 2023 学年 春 |
| `2023-2024-3` | `('?', '?')` | `2023-B` | 4047 | 2023 冬（四段制） |
| `2023-2024-4` | `('?', '?')` | `2024-B` | 4049 | 2023 学年 夏（四段制） |

**三条结论**：

1. **不是一一映射**。本仓的 `-3`/`-4` 在引擎的两段制里**没有位置**；引擎的 `2024-B` **不可逆**地
   分不清是「冬」还是「夏」。
2. **直接「-1→A、-2→B」会静默出错**：浙大「春夏」横跨 `-2/-3/-4` 三段，按段位硬映射会把春、夏压进同一个桶。
   这正是 r42「静默降级」在**数据层**的同胞 —— 不报错、只是结果错。
3. **两侧都缺一个「学期 → 绝对序号」的单一真源**。本仓靠 `(学年字符串, semester)` 元组比较，
   引擎靠 `YYYY*2+0|1` 整数比较 —— 两个序号**不能互相推导**。

**建议修法（不需要上游）**：在 `parse.js` 导出一个 `semesterIndex(academic_year, segment)`：
四段制保留 4 个值（`YYYY*4 + 0..3`），再提供 `toEngineKey()` / `fromEngineKey()` 两个**带丢失标记**的转换
（`fromEngineKey('2024-B')` 返回 `{segments: [2,3,4], exact: false}`），让「不可逆」在类型上就能看见，
而不是靠注释提醒。约 30 行 + 4 个用例。

## 7. 方法论增量（供后续轮次复用）

1. **能力名不存在 ≠ 能力不存在**：`zju 学分` / `zju graduation requirement` 全 0，而用 `zju 培养方案`（total **1**）

   GitHub 因附件报 `NOASSERTION`，但授权范围没变。**判定动作是「通读 1.6 KB」**，成本 30 秒，
   比「标 ⚠ 待核然后放弃」划算得多 —— 但**不能推广成「NOASSERTION 都可放行」**，本轮是逐字读过的个例。

   本轮就是靠这个发现「冬/夏压缩」—— 只比「映射对不对」会漏掉**丢失**这一类错误。
