## 3. 候选与分级

### 🟢 `highlightjs/highlight.js` → **L2 骨架**

| 项 | 值 |
| --- | --- |
| 类型 | **B 其他JS** |
| 许可证 | **BSD-3-Clause** ✅（GitHub metadata + npm `license` 两源一致）★25002，2026-09-06 push |
| 与现有功能 | **重复且可强化**（不是全新） |
| 三条判据 | ①同一面板 ✅ ②相似正交 ✅ ③**底层更优** ✅（本仓**完全没有**高亮层） |
| 锁版 | `highlight.js@11.12.0`，`dependencies` 为空，**无构建步骤** |

**实测（沙箱 Node22，10-19）**：

```
import hljs from 'highlight.js/lib/core.js'          → OK，零依赖
hljs.highlight('x=1', {language:'python'})            → throw Unknown language: "python"
hljs.registerLanguage('python', py)                   → OK
hljs.highlight('class A:\n    def f…', …)             → <span class="hljs-keyword">class</span>…
hljs.highlightAuto('def f(x): …')                     → python（但那是全量包）
```

> **结论**：按需注册**确实成立**（未注册的语言**会抛错**，不会静默猜），
> 所以「core + 白名单懒加载」是可行路线；代价是**必须禁用 `highlightAuto()`**。

体积：npm `unpackedSize` **5.50 MB** 是全量包；`es/` ≈ 2.7 MB（190+ 语言），
`styles/` ≈ 2.4 MB（全部主题）。core-only 下的首屏量**本轮未实测**（见 L-2）。

## 4. 本轮结论（三条）

### L-1 · `highlightAuto()` 是这条路线上的**唯一真陷阱**

实测：core-only 下 `highlightAuto('def f(x):\n return x')` **仍返回 `python`** ——
因为它此时只认**已注册**的语言，返回的只是「已注册集合里最像的那个」。
这会造成**静默误判**：注册了 `python` 和 `javascript` 后，一段 C 代码会被**着色成
python 的类名**，看起来「亮了」，其实是错的。

> 因此骨架里写死：**禁用 `highlightAuto()`；围栏无语言标识 → 纯文本**。
> 验收方式不能是「有没有颜色」，必须是「**颜色对不对**」——建议评审时用 C / Python / SQL 各一段做对照。

### L-2 · 体积是本轮**没有量完**的东西，不要当结论用

本轮只量了 npm `unpackedSize`（5.50 MB，全量）与目录尺寸（`es/` 2.7 MB、`styles/` 2.4 MB）。
**core-only 在浏览器里 gzip 后到底多少，没量。** 骨架 README 里写的「数十 KB」是估算，
已在该文件与这里**双重标注为估算**。这是本轮的可核查缺口，**不应被引用为事实**。

### L-3 · 唯一的 A 类候选，问题不在「能不能接」而在「接哪个版本」

`dsh-raw-html` 这个案例值得记一条方法论：
**A 类候选要同时过三道门 —— 形态（是否原生 DSH）、许可（v1 MIT / v2 NOASSERTION）、可锁版（npm 是否发布）**。
本轮这条**三门只过了一道**（形态），所以即使它是最贴生态的候选，也停在 🔵/🟡。
以后 A 组命中后应**立刻查 npm 是否存在同名包**，这比读 README 快。
