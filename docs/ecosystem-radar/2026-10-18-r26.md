## 6. 建议人工 review 的重点

1. **粒度死结（最重要）**：runtime 图是「运行时 / 包级」，skott 图是「文件系统 / 文件级」。
   README 的 5 条 TODO 里第 1 条要求**二选一**：「补盲区」还是「只跑算法」。两条都做必然重复劳动。
2. **性能**：本仓 `packages/` 已 50 个包，skott 默认 walk 整个 workspace。
   必须收窄 entrypoints + 关掉 watch，并设 2s 冷 / 300ms 热门禁 —— 否则「插件」页会被拖慢。
3. **是否值得引入原生依赖**：`skott` 带 `@parcel/watcher`（原生二进制）。若评审认为代价过高，
   备选是只摘「循环依赖检测」这一小块语义、自己写 DFS（约 100 行，零依赖）。
4. **`dsh-capability-inspector` 的 ★1 风险**：先读源码再决定是否值得移植（可能与 `dsh-plugin-reader` 类工具重复）。
5. **审计轴封板**：本轮出现的 3 个装前审计工具全部与在册实现重复，
   建议在 `registry.md` 记「审计轴 3 个月内不再扫」。
