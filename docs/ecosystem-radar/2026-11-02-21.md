## 0. 一句话结论

> **本仓读不了 EPUB —— 这是笔记页唯一还没接上的「成书」格式，而世界上有现成的、锁得住版的那一个。**
> 笔记页 `page-notes/src/client.jsx` 的 intake 只认 `.md`（树）与 `.pdf`（`accept="application/pdf,.pdf"`，第 1279 行），
> 全仓 `grep -i epub` 在 `packages/*/src` 下 **0 命中**。`core-classroom-media` 虽有 PDF 解析，
> 但那是**转 Markdown 的文本抽取**，不是「像 PDF 那样翻页读」。
> ⇒ 这是「**无 → 有**」的格式缺口，不是重复建设。
>
> `johnfactotum/foliate-js`（★1146 · **MIT**）正是这个位置上的正确上游：
> npm `foliate-js@1.0.1` **单版本、可锁死**，`201ms` 装完、仅 2 个包共 476 KB，
> 解压依赖（zip.js / fflate）已 **vendor 进包内**，不存在「依赖没装、运行时才炸」的隐患。
> 它的形态（纯 ES 模块 + 同源 iframe 承载）与笔记页 PDF 阅读器的既有成例**完全同构**，
> 因此本轮出骨架 `packages/radar/dsh-radar-foliate-reader`，判 **🟢 强化式集成**。

一句话的反面也要写清楚：**这不是「给笔记页加一个 EPUB 按钮」那么简单**。foliate-js 的 API 自述
「*not stable, expect it to break at any time*」，且 README 建议用 git submodule 而非 npm。
锁版只能保证「装得上」，**不能保证半年后 API 不变** —— 因此骨架的 README 里把这条写成了第一条风险，
并明确「升级必须整包对照 `node_modules/foliate-js/README.md` 的接口变化」。

## 2. 本轮唯一 🟢：`johnfactotum/foliate-js`

### 2.1 为什么是它，而不是 ★28698 的那个

首屏第一名是 `koodo-reader/koodo-reader`（★28698），但它是 **AGPL-3.0** —— 硬门槛直接出局。
★第二梯队的 `FolioReader-Android`（BSD-3-Clause）是 **Java**，不在 JS 技术栈内。
真正可用的 JS 系只有四条：

| 仓库 | ★ | 许可证 | 形态 | 判定 |
| --- | --- | --- | --- | --- |
| `johnfactotum/foliate-js` | 1146 | **MIT** ✅ | **纯 ES 模块库**，可 import、可锁版 | **🟢 入选** |
| `satorumurmur/bibi` | 917 | MIT ✅ | 整站阅读器（`bibi-dist` 打包产物），npm 上无同名包（实测 404） | 🟡 锁不了版 |
| `futurepress/epubjs-reader` | 472 | MIT ✅ | 是 epub.js 的**示例页**，库本体需另采 `epubjs` | 🔵 只是 demo |
| `Janglee123/eplee` | 364 | MIT ✅ | Electron 桌面壳 | 🔵 与本仓形态不符 |

### 2.2 锁版可行性（实测，非 README 自述）

```text
npm i foliate-js@1.0.1        →  added 2 packages in 685ms
package.json: "exports": { "./*.js": "./*.js" }, "type": "module"
dependencies: { "construct-style-sheets-polyfill": "^3.1.0" }   ← 唯一运行时依赖
node_modules/foliate-js/      476 KB
  vendor/zip.js   55 KB   vendor/fflate.js  3.8 KB              ← 解压已随包发布，非 devDep
```

三个关键事实：

1. **只有一个版本 `1.0.1`**，锁死无歧义；
2. `view.js` 里 `await import('./vendor/zip.js')` / `import('./vendor/fflate.js')` —— 解压**不走 npm 依赖**，
   所以「npm 装上了但解压模块缺失」这类 lockfile 陷阱不存在；
3. `exports` 是通配 `"./*.js"`，即 `import 'foliate-js/view.js'` 这类**深导入是被官方允许的**，
   不需要 hack 内部路径。

### 2.3 强化式集成三判据

| 判据 | 结论 | 依据 |
| --- | --- | --- |
| ① 仍是同一个面板 | ✅ | 落在**笔记页已有的阅读器**（`page-notes` 的 iframe 阅读区），不新增导航项、不新增页面 |
| ② 功能仍相似正交 | ✅ | 仍是「打开文件 → 翻页阅读」，与 PDF 阅读同一件事；只是**多一种格式**，不抢 PDF 的职责 |
| ③ 底层多调了更优质实现 | ✅ | 现状是 **EPUB 打不开**（0 命中）；接入后借用 full-featured 的 paginator/CFI/目录/脚注，**本仓一行渲染代码都不用写** |

判据③成立的前提要说明白：本仓并不是「已经有个简陋的 EPUB 阅读器、现在换个好的」，
而是**根本没有**。严格按 skill 的「强化式集成」措辞，这更接近「补齐同面板内的一个格式」，
因此 README 中如实写作「**强化式集成（判据③半成立：无既有实现可对比，属格式补齐）**」，
沿用 r131 `sketchpad` 的同一标注口径，不做美化。

### 2.4 风险（写进骨架 README，不藏）

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| **API 不稳定**（高） | README 原文：*"this library itself is, however, not stable. Expect it to break and the API to change at any time."* 并建议 submodule | 锁 `1.0.1`；升级时先 diff `README.md` 的 Modules 章节 |
| **CSP `blob:` 依赖**（中） | 上游 `reader.html` 的 CSP 是 `default-src 'self' blob:`，EPUB 内容经 `blob:` URL 装进 iframe | 宿主需在阅读器路由上放行 `blob:`（笔记页 iframe 本就同源，风险可控） |
| **字体反混淆需 SHA-1**（低） | README：IDPF 算法默认用 Web Crypto，**仅 secure context 可用** | 本地 `http://localhost` 属 secure context，满足；否则需注入 SHA-1 |
| **中文排版未验** | 上游面向英文 EPUB，未实测中文竖排/CJK 断行 | 骨架仅占位，**不声称已验证** |
