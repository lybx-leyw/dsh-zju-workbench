1. **R1 默认随机 UID**：不传 `uid` 时每条事件 UID 随机（`aXPsYcWAV4xBuUE_N_2JP`）。
   而本仓课表条目**没有稳定 id**（`projectAgenda` 输出的是逐日平铺对象）。
   → 用户每导出一次，日历里就**多出一整套重复事件**，且删不掉。
   传 `uid` 后两次生成逐字相同 → 必须由 `(学期, courseTitle, startMs)` **确定性派生**。
2. **R2 无 VTIMEZONE**：`timezone: 'Asia/Shanghai'` 直接报 `unspecified keys`。
   只有「浮动时间」与「UTC」两条路：浮动 → 跨时区导入错；UTC → 时刻对、显示不好看。
   **建议 UTC**，理由见骨架 README 的「需要人工拍板」第 2 条。
3. **R3 毫秒必须显式按上海拆**：把 `Date(ms).getUTC*()` 当本地时间传，
   产出 `DTSTART` **早 8 小时且不报错** —— 这是最容易漏、最难肉眼发现的一种 bug。

**唯一的成本争议**：75 KB，其中大头是 yup 校验库（仅用来拒绝未知字段）。
若产品认为「为生成一段文本引入校验库」不划算，应改判 🔵 并改手写 RFC 5545 子集；
本报告保留 🟢 的依据是：手写要自己保证折行与转义，出错**同样不报错、同样难发现**。

> **本仓的缺口主体是「接线」，不是「依赖」。**
> 但这不等于不需要依赖：本轮缺的 iCalendar 是**真需要外部实现**的

> 「缺的是一行调用」→ 补接线；「缺的是一套规范实现」→ 才接依赖。
> 这条判别线建议写进 README 的「强化式集成」小节，防止下一轮把接线问题当依赖问题。

### 结论 2 · 本轮候选的失败模式是「不报错的错」

M2（UID 随机）、M5（浮动时间）、M7（时区拆错）三条**全部不抛异常**，
产出的文件语法完全合法，只是内容错了。
→ 建议：**凡接入「序列化 / 格式化」类上游，验收标准必须含「同一输入两次输出逐字相同」**
与「时区往返守恒」两条断言，否则这类 bug 永远测不出来。
本骨架已把这两条写进 `buildCalendar()` 的 TODO-1 与 `stableUid()`。

## 4. 读码结论与方法论（非候选，但比候选重要）

### M1 · 同名不同仓 = registry 的静默覆盖风险（**本轮最重要**）

见 §1.2。`dsh-trading` 与 `dsh-market` 各有两个 owner，**许可证一条 MIT 一条 NOASSERTION**。
人按名字回忆时，会把 ★274 的 NOASSERTION 仓库当成 MIT 的 ★41 那个。
**建议**：registry 增加自检脚本，`repo 名重复 ∧ spdx_id 不同` → 直接 fail，强制报告写消歧段。

### M2 · A 组已进入「收割尾期」，应把力气从「搜新」转向「裁决旧」

硬数据：本轮 79 个 unique 里 **44 已登记（56%）**，13 相关新候选里 **0 个 🟢**。
连续两轮（r52 A 派生轴、本轮 A 轴）**都没有 🟢**。
而 `packages/` 下已有 **52 个 `dsh-radar-*` 骨架**，其中只有 `dsh-zhiyun-*` 那 28 个被真正接入。
**52 个未裁决骨架 vs 每天 0–1 个新 🟢** —— 瓶颈已经从「发现」移到「裁决」。

> **建议**：A 组后续轮次**隔日跑**（或降为每周 2 次），腾出的轮次改为「**骨架存量审计**」：
> 按 registry 的 `status: proposed` 重新核验上游是否仍活跃、npm 版本是否仍在、许可证是否变过。
> 一个 3 个月前的 🟢 骨架，今天可能已经上游停更 —— 这比再发现一个 ★20 的新插件价值高得多。

### M3 · 「雷达」本身已成为生态公共品

`AdamPlatin123/dsh-plugin-radar` ★1484 的同名同职能项目，说明外部已有人在解决同一问题。
这不是威胁，而是**提示本仓的差异化在哪**：别人的雷达只做「列出插件 + ★数」，
本仓做的是**「与现有功能的关系」判定**（全新 / 重复可强化 / 重复无增益）——
**而这份边界只有本仓自己知道**（共 80 个包：28 个已接入 + 52 个候选骨架），外部项目做不了。差异化应继续押在这一列上。

### M4 · 主题域该建「白名单」而不是「黑名单」

主题/皮肤簇本轮再添 2 条（累计 **15 条 ⛔**）。每次都靠人读 description 判断「这个是皮肤吗」，
既慢又容易漏。建议在 `scripts/` 加一条：`topics ∩ {skin, theme, wallpapper, ui-skin} ≠ ∅ ∧ 无学生场景词` → 自动 ⛔ 预标记，人工只需复核。
