## 2. 核心结论（先看这里）

**① 本轮唯一 🟢 来自「本仓有空 RPC，生态有完整实现」——这是 B 组目前最稳定的产出模式。**
本仓 `dsh-zhiyun-omni` 的 44 个数据函数覆盖教务/学在浙大/CC98/拼题A，**但「考试与学业日程」只有
`zdbk.exams` 一条裸数据**：拿到的是「某科某天考」，拿不到**座位号 / 考场楼栋 / 距今天的倒数 /
与课表冲突**——而这些恰恰是「今天」页真正想要的形状。`DongLanQwQ0/ZJU-Tongge-Schedule` 给了
一个**零依赖**的解法（`.ics` → VEVENT 网格 → 时间重叠判定 / 同楼栋距离分级），与调度无关、可离线跑。

**② `zju zdbk`（total 4）证明「教务库代号」是最锋利的一类窄词。**
4 条里 2 条带 MIT 且是 JS，命中率远高于 `zju exam schedule`(1，非 JS) / `zju library seat`(2，全废)。
教务库有明确的内部代号（`zdbk` / `jwglxt` / `under_graduate_student_web_query`），
**代号 > 自然语言描述**——这条规律建议后续 B 组固定采用。

**③ 学在浙大（`xzzd`）侧的「下载」能力仍被上游反复重写，但都不是本仓缺的。**
`eWloYW8/ZJU-course-material-download`（★14、MIT、2026-01 停更）专解「无权限课件」；
本仓 `xzzd.download` + `dsh-zhiyun-omni` 已覆盖常规下载路径。**属重复，无增益**（⛔），
且其核心是绕过页面权限判定，与本仓「按已登录身份正规拉取」的模型冲突，不采用。

**④ 本仓在册但未覆盖的一块「选课」：**`0x000005/better-zdbk`（★2、MIT、2026-09-15）是 660KB 的
单文件 UserScript，只做**选课页面增强**（列表内联化 / 过滤 / 快速点选）。本仓没有任何「选课」面板，
短期内也不该做（学期性极强、一年用两周）→ 判 🔵 只作参考，**不做骨架**。

**⑤ 坏消息：`zju` 系新仓的「学生工具」密度在下降。**47 条新登记里，**真正与学生场景相关且 JS 栈的只有 6 条**
（🟢1 / 🟡1 / 🔵4），其余 41 条是课程资料库、区块链作业、ZJUT（浙工大）混入、以及
**完全无关的泛 `course review` 平台**（UBC / UCI / Sabancı / Chalmers……共 8 条，全部 `null` 许可证）。
B 组若还要继续，必须**只用教务/服务代号做窄词**（见 ②），否则命中率会继续掉。
