#### 🟡① `omdsh-dev/dsh-paddle-ocr` —— 本轮最高价值

| 项 | 值 |
| --- | --- |
| 仓库 | https://github.com/omdsh-dev/dsh-paddle-ocr |
| 类型 | **A · 原生 DSH 插件包**（`dsh.bundle.patch` → `./cordis.patch.yml`；`dsh.client.platform=web` + 7 个 client inject） |
| 许可证 | **BSD-3-Clause** ✅（`package.json` 与 GitHub `license` 双重确认） |
| 规模 | ★2 · size 96KB · TS · 建/推 2026-08-19（**已 2 个月未更新**）· topic `dsh-plugin` ✅ |
| 版本 | `0.1.0` · 仅 **1 个运行时依赖** `pdf-lib@^1.17.1`，其余全为 peer |
| 与现有功能 | **重复且可强化** —— 强化 `dsh-zhiyun-parser` 的**版面切分** |
| 分级理由 | 见下方「为何不是 🟢」 |

**能力**：把 PDF / 图片逐页解析为 Markdown（文字 + 图片落盘）。这不是「调一个 OCR 接口」那么简单：
它做的是**文档版面解析（layout parsing）** —— 返回段落/标题/表格/公式/图注的**块级结构 + 阅读顺序**，
再按页落 `doc_N.md` + 抽取图片。走百度 PaddleOCR-VL 云端（`PaddleOCR-VL-1.5`），
async 作业模式支持 **1000 页**、自动拆分超限 PDF、队列满（`errorCode 10010`）指数退避重试。
Token 只进 DSH 凭据保险箱，不回传、不落日志。

**增强的就是现有这处接缝**：

| `dsh-zhiyun-parser` 现状 | 本插件补的底层 |
| --- | --- |
| `vision.js`：**分组 2×2 拼图**（每组≤4 页）+ 每页 < 5MB / 4194304 像素预算 | 版面解析**按块输出**，不受拼图分辨率预算挤兑 |
| `correction-policy.js`：纠错距离上限原句 **80% / 80 字**（对误听容忍，对「看错版面」无解） | 版面模型给的是**结构化块**，而非逐页「看图如实转述」的自由文本 |
| `parser.js`：失败页单图补发；`unassignedSentences` 标 `partial` | 逐页落 md，**页粒度重试**天然对齐 |

即：**同一个解析面板 / 同一类「课件→结构化文本」任务 / 底层多调了一个专门做版面的模型**。
三条里前两条成立；**第三条只对「扫描件 / 版式复杂 PDF」成立，对智云原生课件（PPT 跳转图 + 字幕）
它给不出字幕对齐**，所以只能算**局部更优底层**，不够格「底层多调了更优质实现」⇒ 判 🟡。

**注意**：它是**云端服务**（需 aistudio 账号 token），不是本地模型。**离线/无网场景不可用**，
这与本仓「模型调用全走宿主 `ctx.llm`、无独立 API key」的原则**冲突**（见 2.5 风险）。
