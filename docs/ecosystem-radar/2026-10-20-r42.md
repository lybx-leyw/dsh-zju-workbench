## 2 · 本轮的判据更新（两条，均由实测得出）

### 2.1 A 类第五道门：**宿主编译选项**（`dsh-memory` 实测证伪）

`Jesse-njx/dsh-memory`（★1，MIT，npm `dsh-memory@0.1.0`，`dsh.bundle.patch` ✅，**A 类形态全对**）
用 `node:sqlite` + **FTS5 虚表 + 触发器**做索引。本沙箱实测：

```console
$ node -e "const {DatabaseSync}=require('node:sqlite'); new DatabaseSync(':memory:').exec('create virtual table t using fts5(x)')"
fts5 FAIL: no such module: fts5      # Node v22.13.1；fts4 / rtree 同样不可用
```

再按 Cordis 语义（`ctx.effect(fn)` **立即执行**）调 `apply()`：

```console
APPLY FAIL: ERR_SQLITE_ERROR no such module: fts5
内存 db 文件 16 KB 已被创建 —— 即「建了一半、抛错」的中间态
```

**结论**：`node:sqlite` 的 FTS5 是**编译期选项**，不同发行版不一致；插件只在首次 `apply` 时暴露，
而 `apply` 抛错在 Cordis 里意味着**整个 bundle 起不来**（不是「这个功能不可用」）。
→ **A 类第三门「可锁版」之外，须再问一句：它的存储引擎所依赖的编译选项，宿主是否一定具备？**
详见 §4 `dsh-memory` 一行。

### 2.2 判据①在 `single` 插槽下**写不出外围兼容层**（本轮骨架的阻塞项）

本仓 `dsh-zhiyun-shell/src/client.jsx:143` 把每页内容槽声明为
`[zhiyun.<page>.content]: { kind: 'single', scope: 'root' }`，另只有 `zhiyun.me.network`
一个是单点扩展。也就是说：

- **页面槽是 single**：外部插件**不能**往「我的」页里加一块面板（第二个注册者会被排除）；
- **既有扩展点只有 network 一个**：`dsh-zhiyun-net-proxy` 之所以能落在「我的」页，是因为 shell 为它**专开了一个槽**。

所以「锁版挂载上游 + iframe 承载」这条 paper 包的路子，在**需要往页面里放 UI** 的候选上**不成立**——
外围兼容层没有可注册的槽。这不是上游的问题，是**本仓插槽体系的问题**。
本轮骨架据此改成**新增一个通用 list 槽**的方案，并把这一步标成评审前置（TODO-0）。
