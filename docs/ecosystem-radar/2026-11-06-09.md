#### 3.2.1 为什么 `tejasprabhune/kern` 是 🟢，而 `ronkok/Temml`（已登记 🟢）不能顶替

两者**同在「Typst/TeX → MathML」格子**，但**输入侧完全不同**：

| | `ronkok/Temml`（已有骨架 `dsh-radar-temml`） | `tejasprabhune/kern`（本包 `dsh-radar-board-latex`） |
| --- | --- | --- |
| 输入语法 | **LaTeX**（`\frac{a}{b}`） | **Typst**（`frac(a, b)`） |
| 定位 | KaTeX 的 MathML 替代品 | KaTeX 的 **Typst 语法**替代品（README 原话「Drop-in alternative to KaTeX for projects that prefer Typst's cleaner math syntax」） |
| 本仓需要它吗 | slide 的公式是 **LaTeX**（prompt 原话「数学表达式一律用独立的 `latex` 元素」），Temml 对得上 | 对不上 —— **白板若也用 LaTeX，就只需要 KaTeX，kern 属多余** |

> **所以判据③的分量，取决于白板公式用的是哪种语法 —— 这是本轮必须说清的分歧点。**
> 骨架按「白板公式可能是 Typst」这一前提建，并把「若白板固定 LaTeX 则本包作废」写成 README 首屏的**作废条件**。
> 这不是把不确定性藏起来，是把不确定性的**处置方式**写进交付物。

**实测（本沙箱 `npm i kern-typ@0.2.0`，node ESM 直接跑）：**

```
"frac(a, b)"                       => <math ...><mfrac><mi>a</mi><mi>b</mi></mfrac></math>
"sum_(i=0)^n i = frac(n(n+1), 2)"  => <math ...><msubsup><mo largeop="true">∑</mo>…
"mat(1,0; 0,1)"                    => …<mtable><mtr><mt…
"integral_0^infinity e^(-x^2) dif x" => …<msubsup><mo largeop="true">∫</mo>…
"vec(a, b, c)"                     => …<mtable>…
"sqrt(x^2+y^2)"                    => <msqrt>…
"cases(x & \"if\" x>0, -x & \"else\")" => …<mo stretchy="true">{</mo>…<mtable columnalign="left lef…
"\\\\frac{a}{b}"                   => <mtable class="kern-eqarray kern-aligned">…   ← **LaTeX 输入不报错、静默渲成错内容**
```

- ✅ 真能出 MathML，矩阵/积分/分段函数都通；`output: 'mathml' | 'html' | 'htmlAndMathml'` 三档，API **刻意与 KaTeX 同形**（`render` / `renderToString` / `renderMathInElement`）。
- ⛔ **最后一行是硬伤**：喂 LaTeX 进去**不抛 `ParseError`**，而是渲染出一张语义错误的 `kern-eqarray` 表。KaTeX 在同位置会 `throwOnError`（本仓 `slide.jsx:239` 正是靠 `throwOnError:false` 回落原文）。**换成 kern 必须自带「是不是 LaTeX」的前置判别**，否则是把「能看见的错」换成「看不见的错」。
- 体量：`dist/kern.js` **71,232 B**（min 54,824 B），`unpackedSize` 207,445 B，**零运行时依赖**（`dependencies` 空）。是真·纯库，无 wasm、无原生模块。
- 活跃度：2026-11-02 仍在提交（`Add Typst source annotation and a real Typst parity oracle`）；npm `kern-typ@0.2.0` 停在 2026-05-16 —— **npm 落后 GitHub 半年**，锁版要锁 `0.2.0`，不能用 GitHub main。

**它不能做什么（如实）**：只有 Typst math 的**子集**（`alpha/beta/arrow.r/eq.not` 这类命名符号 + 十来个函数），
没有 `\usepackage`、没有 `\newenvironment`、没有编号公式。**它不是 Typst 编译器**（那要 wasm），是个语法翻译器。
