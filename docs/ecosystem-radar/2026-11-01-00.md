## 2 · 本轮新候选

### 2.1 🟢 `intl-cjk-calendar`（无仓库）— **本轮骨架**

| 项 | 值 |
| --- | --- |
| 类型 | **B · 标准库能力**（非仓库、非 npm 包，来自 ECMA-402） |
| 许可证 | **不适用**（ECMA-402 由宿主 ICU 提供；无代码摘取） |
| 学生场景 | 课表 / 放假 / 调课 / 跨年期末 |
| **与现有功能的关系** | **重复且可强化** ✅（今天页日期行，加一段刻度） |
| 分级 | **🟢** |

**它补了哪一格**

| 问法 | 现有实现 |
| --- | --- |
| 现在几点、这节什么时候上 | `dsh-zhiyun-page-today` `agenda.js` `clock()` → `HH:mm`（`Asia/Shanghai`） |
| 这件事哪天到期 | `due.js` `shanghaiDay()` → `YYYY-MM-DD`（同上时区） |
| 今天是农历什么日子 | **无**（全仓 `grep -ri 农历\|lunar` 业务命中 0） |

**实测（骨架自证）**

```text
2026-11-01 → 九月廿三    parts: month=九月,   day=23
2026-01-01 → 十一月十三  parts: month=十一月, day=13
2026-02-17 → 正月初一    parts: month=正月,   day=1
```

**「底层多调了更优质实现」怎么成立**

常见做法是把农历写成 1900–2100 的打包位表（各语言 `lunar.js` 几乎都是这一套，
`jadeocr/jadeocr` 一类项目里的 366 位数组）。本包改调 **宿主 ICU 的 `calendar: "chinese"`**：
农历在 Node 22.13 / ICU 76.1 下**已经内建**，月名天然带「正月 / 冬月 / 闰×月」正名。
**依赖 0、代码 < 100 行、无需打包表**。

**踩到的三个坑（骨架已写进注释）**

| 坑 | 实测 |
| --- | --- |
| `format()` 不可用 | 给的是 `2026年九月23`，混着 `literal` 分隔符 → 必须 `formatToParts` |
| `relatedYear` ≠ 农历年 | 2026-01-01 的 `relatedYear` 是 **2025**；干支要读 `yearName`（`乙巳`/`丙午`） |
| 「日」是数字 | ICU 给 `day=23`，`廿三` 靠 31 项查表补 |
| 语言标签陷阱 | `zh-CN-zh-Hans-CN-u-ca-chinese` 会 **`RangeError`**；只能 `zh-CN` + `calendar` 选项 |
| 闰月未验 | ⚠ 未用对照表验证 —— 写进骨架 TODO，不作结论 |

**判据③为什么不打折**：与 r121 的 `campuskit` 不同（那条只借了「口径」），
这一条**确实换了底层实现**，且换来的是「零依赖 + 无数据表」。
