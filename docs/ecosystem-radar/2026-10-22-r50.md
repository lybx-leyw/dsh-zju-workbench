## 1. 切片选择：为什么是「跨节深链」

第四十三轮已宣告 A 组主词「前 60 条只剩 1 个新面孔」，第四十五轮改为「`dsh plugin <学生词>`」。
本轮按前几轮验证过的做法**先读码找接缝，再定向搜**，不再跑主词。

读码对象：`dsh-zhiyun-notes`（每节一份的课程笔记）→ `dsh-zhiyun-page-study`（学习页）→ `dsh-zhiyun-shell`（导航）。

读到的事实（全部已在当前 `radar` 分支代码上复核）：

| # | 位置 | 事实 |
| --- | --- | --- |
| 1 | `note-links.js:30` `focusFromParsed()` | 目标节的 `courseId/sectionId` 与当前节不等 → 直接返回 `{ kind: 'other-section' }`，**不再尝试定位** |

| 4 | `tests/study.test.mjs:242` | 有断言 `focusFromParsed(...).kind === 'other-section'`，改行为会**先红这条测试** |

## 2. 本轮核心结论：这条"断环"是刻意留的，且跳过去会造成更严重的破坏

### 2.1 反例不是"能不能"，而是"该不该"

`selectLesson()`（`model.js:112`）切节时会**一次性清空 13 个字段**：

```js
update({ course, lesson, …, content: null, result: null, lecture: null,
         quiz: null, note: null, …, live: liveOf(...), … });
```

而**学习页的视频栏与"当前节"是同一份 `state.content`**（`page-study/README.md` 自述：
三页合并成一页的理由正是「三者读的是同一份 `state.content`」）。

⇒ 若在**播放中**从笔记里点一条跨节链，`selectLesson` 会把视频源清成 `null`，
用户看到的是**视频被掐断**，而不是"跳到那一节的那一句"。这与本仓"离开学习页也要保住播放进度"
的一贯取向**相反**。

### 2.2 结论

- 这条"断环"**不是缺陷**，是**代价换来的保护**（就地说明 > 掐断播放）。
- 若将来要做，正确形态是**不切节**的旁路：**侧栏画中画 / 新标签**，让两节各有一份 `state.content`；
  这已经**超出"强化式集成"的范围**（不是同一个面板、也不是同一个状态），属于**新功能**。
- 因此**本轮不出候选 🟢**，也**不建议**把它写进任何 backlog 的前列。

> 这是本仓第七次出现「**读码结论推翻前一版报告**」的情况（参见第四十九轮 §2.1 的 R-2 撤回）。
> **教训仍同一条：缺陷报告必须先读文档与测试，再读代码。** 只看 `note-links.js` 的 `other-section` 分支，
> 会得出"漏了一个 case"的错误结论。

## 5. 为什么本轮的"最接近"仍然不成立

### 5.1 笔记簇：本仓的链接解析比它们更完整

`dsh-zhiyun-vault/src/parse/links.js` 的文件头自己列了一张对照表（`[[A|别名]]` / `[[A#小节]]` / `[[A#^块]]` /
`[[#小节]]` / `![[图]]` / 行内标签 / URL 里的 `#` / 代码块里的 `[[x]]`），**并逐条钉了测试**。
上述 4 个 Obsidian 类候选**没有一家**的 README 提到这 8 种语法中的 4 种以上。
⇒ **接进来是"第二套更弱的实现"**，判据③（底层更优）**不成立**。

### 5.2 死链检查：扫的是 `http(s)://`，不是 `zy://`

`ZhijiangTang/dsh-dead-links` 的 `LINK_RE = /https?:\/\/[^\s<>"'`)\]}]+/g`（`index.js:20`）——
**只抓 http(s)**，逐条发 `HEAD`（403/405/网络错误降级 `GET`），返回 `{file, line, url, status}`。
它回答的是"**这篇 Markdown 里的外链还在不在**"，与"**这条 `zy://section/9.20` 指向的节还在不在**"**不同义**。

本仓真正缺的"锚点有效性"，`parseZySectionUri()` 已经返回 `null` + `code: 'BAD_SECTION_LINK'`（`note.js:197-240`），
**唯一缺的是消费方**——这与第四十九轮的结论**同一个形状**（能力已有、出口没有）。
⇒ 再次印证：「**本仓的缺口多数是接线问题，不是依赖问题**」。这一条**不需要新库**。
