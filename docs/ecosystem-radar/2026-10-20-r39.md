## 2 · 新候选

### 2.1 🟡 `xiaohajiayou/Leetcode-Mastery-Scheduler` — 本次唯一有实质价值的候选

| 项 | 值 |
| --- | --- |
| 类型 | **B 其他 JS**（Chrome 扩展，**非** DSH 插件） |
| 许可 | **MIT**（`LICENSE` 原文已核实：`Copyright (c) 2025 Hacode`，宽松白名单 ✅；`package.json` 里另写 `"license": "ISC"`，两者同属白名单，**不冲突**） |
| 规模/活跃 | ★543，JS，**最后 push 2026-04-06**（半年未动），仓库 2.3 MB |
| 学生场景 | 刷题 / 复习（力扣、codeforces、洛谷、牛客） |
| 与现有功能 | **重复且可强化**（学习页「复习队列」`quiz-panel.jsx:32`） |
| 分级 | 🟡（需移植改造：库形态是扩展，不是可 `import` 的包） |

**它到底比本仓好在哪**（读了三处源码，都是可移植的**规则**，不是可搬的**代码**）：

1. `reviewService.js:60-95` —— 每日题的排序**按 `getCurrentRetrievability` 升序**，
   即「此刻最可能忘的排最前」。本仓的 `reviewQueue`（`store.js:501`）**只按 `accepted` 过滤**，
   排序键来自 `acceptedQuiz` 的字典序。本仓已有 `attributeByPoint` / `masteryOf`（错题归因），
   但**没有任何一条路径把「记忆强度」变成队列顺序**。
2. `utils.js:168-175` —— 可提取性直接用 `ts-fsrs` 导出的 `forgetting_curve(elapsedDays, stability)`
   **和** `dateDiffInDays`，**不自己写公式**。这一点很关键：本仓若自写 `(1+t/S)^-1` 会把
   FSRS-5 的 `DECAY/FACTOR` 常数写死写错（下个月的 FSRS-6 一改就静默偏）。
3. `sort.js` —— 「推迟时长」（`getDelayedHours = now − nextReview`）单独成一个排序维度，
   且**正负都保留**：逾期是正数、未到期是负数。这正好补上本仓 `computeBacklog` 只给两个
   计数、不给顺序的缺口。

**判 🟡 而不判 🟢 的理由**（三条同时不满足「可直接集成」）：

- 不是库：没有 `main/exports` 可用的算法入口，`src/popup/service/*` 全部依赖 `store.js` / Chrome API；
- `ts-fsrs` 被锁在 **`^4.7.0`**，而本仓既有骨架 `dsh-radar-fsrs-scheduler` 锁的是 **`5.4.2`**
  → **同一个包里出现两个 FSRS 大版本**会让 `stability` 语义漂开（4.x 与 5.x 的 `w` 参数与
  `enable_short_term` 默认值不同）；
- 它自己的 `calculateNextReview` **把 1–4 整数映射成 Rating**（`qualityToRating`，
  且 `default: return Rating.Good` 兜底）。本仓 `QUIZ_SELF_RECALLS = ['again','hard','good','easy']`
  **是字符串枚举**，若照搬会多出一层映射，而兜底 `Good` 恰好踩中 `store.js:40` 明令禁止的
  「把判不了当成某一档」。

**建议集成方式（强化式，三条判据逐条对）**：
「学习」页的「复习队列」仍是**同一个面板**（`quiz-panel.jsx` 里那一块），功能仍是**同一个**（列出该做的题），
只是**底层多调两次更优质的实现**：`ts-fsrs@5.4.2` 的 `forgetting_curve` + `dateDiffInDays`。
不改 `reviewQueue` 的语义（仍只返回 `accepted`），只在**排序与截断**这一层加 `dueAt / retrievability`。
→ 判据①②③**同时成立**，属**鼓励的强化式集成**。

> ⚠ 前置依赖（本轮实测结论，且不在本候选范围内）：③号断点 `recordAttempt` 无调用方 ⇒
> 没有 `selfRecall` ⇒ **没有任何卡片能算出 `stability`** ⇒ 上表第 1 条排序在**当前代码下是空转的**。
> 因此**不建议**为这个候选出骨架 —— 先修 `recordAttempt` 的接线（那是本仓缺陷，不需要外部库），
> 排序层随后才有数据可排。**这也是本轮不出 L2 骨架的主因。**
