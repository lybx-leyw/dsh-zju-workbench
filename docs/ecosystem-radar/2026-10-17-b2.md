**`liujianqiao701/dsh-compat-vet`** —— 本轮**唯一 🟢**，也是本轮 L2 骨架来源。

- **是什么**：DSH 插件**兼容性体检**。探测本机 dsh 版本与能力（**含实测校准**），
  检查已装插件是否冲突，在页面上给出**中文预警**与**一键修复**（隔离/卸载/升级），
  并**提前预警「快要不适配」**的插件。
- **为什么可锁版挂载（决定性理由）**：npm `dsh-compat-vet@0.3.2` 的 `dsh` 字段为
  **`{ bundle: { patch: './cordis.patch.yml' }, engines: { dsh: '*' }, client: {...} }`**
  —— **标准 bundle 形状**。而同域已登记的 `rogerdigital/dsh-vet` 是
  `{ seams: [fs, shell, web] }`，**非 bundle 形状、不能以 bundle 挂载**。
  这是本轮把它选为骨架、而非给 `dsh-vet` 升级的直接依据。
- **为什么是强化而非重复**（三条同时成立）：
  1. **仍是同一个面板** —— 「插件」页（`dsh-zhiyun-page-plugins`），不新增导航项。
     ⚠ 上游自带 `./client` 可整页挂，**本骨架刻意不用** —— 那会多出一块新面板，违反本条。
  2. **功能仍相似正交** —— 现有页回答**横向**问题（「谁依赖谁、我**现在**能关掉谁」，
     读当前运行时事实）；本候选回答**纵向**问题（「**下次启动**它还能不能被加载」，
     读将来时的版本判定）。同一批插件、同一个判断的两个正交侧面。
  3. **底层多调了更优质实现** —— 本仓**没有任何**兼容性/版本矩阵判定能力。
     关键不在「能否自己写」，而在**本仓拿不到判定输入**：
     需要「本机 dsh 版本 × 每个插件 peer 范围 × **已知破坏性变更表**」，
     第三项是上游长期维护的资产，本仓从零写不划算。
- **许可证实文已核**：GitHub API `license.spdx_id = MIT`；
  拉取 `LICENSE` 实文首行 `MIT License / Copyright (c) 2026 liujianqiao` —— **已比对**。
- **npm 实包已核**：`cordis.patch.yml` 实文为 `- insert: [{ id: compat-vet, name: 'dsh-compat-vet' }]`；
  `files` 含 `lib/`（9 模块）+ `scripts/`（6 个**真机验证脚本**）+ README；
  自带 9 个 `node --test` 测试文件。
- **集成方式**：锁版引入 npm `dsh-compat-vet`（**写死 0.3.2，不用 `^`**）
  + 宿主侧取数 + 页面侧追加一列，**不搬运上游源码**。
- ⚠ **风险（务必人工核实）**：上游 **★0 / fork 0 / 建于 2026-09-30 / 当月即无更新**，
  属**极早期小项目**。采用前须在**隔离环境**实跑其 `verify-real-boot.mjs`。
  另**不得**直接暴露其「一键修复」写入口（与本仓「不另开写入口」原则冲突）。
