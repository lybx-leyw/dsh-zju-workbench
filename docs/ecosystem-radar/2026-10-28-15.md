## 2 · 实测：`lib/paper.js` 到底能不能用

> 方法：把上游 `lib/paper.js` **原样** import（不改一行），在沙箱里对**真实网络**打；
> 探针脚本见 `/tmp/probe/probe.mjs`、`probe-arxiv.mjs`、`p4.mjs`、`p5.mjs`、`p7.mjs`（本轮临时目录，不入库）。
> Node v22.13.1，`fetch` + `AbortSignal.timeout(20000)`（上游 `TIMEOUT` 常量）**未改**。

### 2.1 结论一：`auto` 模式只查 5 个源，另外 5 个是死代码

`FREE_SOURCES`（导出、README 宣传）有 **10** 个：

```
arxiv / openalex / crossref / doaj / openaire / inspire / europepmc / zenodo / hal / datacite
```

但 `source: 'auto'` 的并发计划是（`paper.js:333`）：

```js
const AUTO_SET = ['openalex', 'crossref', 'arxiv', 'doaj', 'europepmc'];
```

**`openaire / inspire / zenodo / hal / datacite` 写好了函数，`auto` 永远不会调它们**，
只有显式 `source: 'zenodo'` 这种单源调用才会走到。⇒ 「十源并发」这句话**在默认路径上不成立**，实际是**五源**。

> 实测印证：3 组查询 × 使用源 = `['doaj','openalex','europepmc','crossref','arxiv']`，**从未出现第 6 个**。

### 2.2 结论二：arXiv 源在「多词查询」上会**静默返回 0 条**

上游构造的是 `search_query=all:"<整句>"`（`paper.js:50`）。arXiv 的 `all:` 字段对**带引号的整句**很挑：

| 探针 | 形态 | 结果 |
| --- | --- | --- |
| A | `all:"spaced repetition memory"`（上游原样，20 s） | **超时**（20 003 ms） |
| B | 同 A 改 https | 超时（20 001 ms） |
| C | `all:spaced repetition memory`（去引号） | **200，5 条**（3.4 s） |
| D | A 原样，超时放宽 30 s | **200，但 `entries=0`**（2.7 s） |
| E | `ti:spaced` / `all:"spaced"`（单词） | 200，有结果 |
| F | `all:"图神经网络"`（中文整句） | **200，`entries=0`** |

**这是本轮最重要的一条**：同一个查询，**有时超时、有时 200 但 0 条** —— 两种失败都**被上游吞成 `errors` 或空数组**，
调用方看到的只是「arXiv 没结果」。12 个常见英文查询 × 单源直打：**11 成 1 超时**；
「spaced repetition memory」这一条**在 5 次重复里 2 次超时、3 次 200 空**。

⇒ 对本仓的含义：**arXiv 对「整个方向名」这一档查询可用，对「多词精确短语」不可靠，对中文一律 0 条**。
学生问「图神经网络」时，arXiv 这一源等于不存在 —— 结果全靠 OpenAlex / Crossref / DOAJ 的中文覆盖（§2.3）。

### 2.3 结论三：中文查询**能出结果**，但只有 5 条、且质量参差

| 查询 | 耗时 | 条数 | 使用源 | 首条 |
| --- | --- | --- | --- | --- |
| `graph neural network` | 2.7 s | 5 | crossref / europepmc / openalex / arxiv / doaj | OpenAlex《Graph neural networks》 |
| **`图神经网络`** | 1.2 s | 5 | doaj / arxiv / openalex / crossref / europepmc | OpenAlex《脑结构—功能耦合超图神经网络》（有 pdfUrl） |
| `spaced repetition memory` | 2.0 s | 5 | doaj / crossref / europepmc / arxiv / openalex | OpenAlex《Interpretable Memory Models for Spaced Repetition》 |

中文**没有**被上游翻译（工具描述里那句「Chinese is translated by the pipeline」在本仓不存在这条 pipeline），
是直接丢给各源做字面匹配；能出结果是因为 OpenAlex/Crossref/DOAJ 索引了中文刊。
第 3 条 DOAJ 结果是《卒中后…脑电图微状态》—— **相关性排序完全没有**，`auto` 的合并策略是**按源轮转交错**
（`paper.js:388-396`），不是相关性。

### 2.4 结论四：**整包**不能挂进宿主，但**检索这一层**可以

| 挂载面 | 上游行为 | 与本仓冲突 |
| --- | --- | --- |
| `dsh.bundle.patch` 整包 insert | 注入 `sidebar.panellist` 一个「资料馆」面板 + 24 条 `/api/ai-library/*` 路由 + 16 个 tool | ⚠ **第二个资料库面板**：本仓已有「论文」「笔记」「知识」，再来一个「资料馆」违反「仍是同一个面板」 |
| 一键安装 / 自更新 | `/install` 直接 `dsh plugin add`、`/update` 对本地目录 `git pull` | ⛔ **从 Web 面板执行包安装与 git pull**，与「只推 radar、不接 profile」的仓规正面冲突 |
| 市场同步 / 仓库卡 / 表情包 | 联网访问 `api.dshmk.com`、GitHub | ⛔ 域外 |
| **`lib/paper.js`（`searchPapers`）** | 纯函数：`{query, source, limit, keys} → {items, errors, usedSources}` | ✅ **唯一可借用的一层**（见 §4） |

> **判据 ①「仍是同一个面板」**：不接管面板 ⇒ 成立（本包只提供 model tool + 一个宿主路由）。
> 但「不接管面板」这件事**必须写进包里**，否则评审照 `package.json` 的 `dsh.bundle.patch` 一挂，就变成第二个资料库。

### 2.5 依赖闭包：可锁版，但**锁不住运行时**

- `package.json` `dependencies` 为**空** → 锁一个包就锁住了全部代码（这是优点，与 r91 的 `@bbob/*` 全 `*` 正相反）。
- 但 `vendor/` 里**随包分发** pdf.js 4.10.38、three.js、cmaps、字体 —— 版本**不在 npm 依赖图里**，
  `npm audit` / lockfile 都看不见它们。⇒ 评审要看的不是 `dependencies`，是**`vendor/` 目录的更新来源**。
- `engines.node >= 20`；本仓 `package.json` 要求 `^22.19.0 || >=24`，**兼容**。

## 5 · 骨架 `packages/radar/dsh-radar-paper-union`

A 类骨架，**锁版 `dsh-ai-library@0.3.39`**（精确版本，不用 `^`）。

```text
packages/radar/dsh-radar-paper-union/
├── package.json      # dependencies: { "dsh-ai-library": "0.3.39" }  ← 锁版
├── cordis.patch.yml  # - insert: [{ id: radar-paper-union, name: dsh-radar-paper-union }]
├── src/index.js      # 占位 + apply() 直接抛错
├── src/upstream.js   # 锁版凭据（包名/版本/仓库/许可证/5 源真相/已知缺陷）
├── README.md         # 顶部「候选骨架：未评审、未接入 profile、不可直接使用」
└── OWNERS            # Owner: shared
```

README 已写明**「强化式集成」**、**「只借用检索半边」**与四条待办：

1. **只 import `dsh-ai-library/lib/paper`，不挂 `dsh.bundle.patch`** —— 上游 `package.json` 把整包暴露成 bundle，
   本包若照抄就变成第二个「资料馆」面板；
2. `auto` 的 5 源 + arXiv 的 12 词查询 2/12 不可靠 ⇒ **必须自行加源/换查询构造**，不能原样转发；

## 7 · 本轮方法沉淀

- **「导出的常量」不等于「运行时走的路」**。`FREE_SOURCES` 导出 10 个，`AUTO_SET` 只走 5 个 ——
  两者都在同一个文件里、相隔 300 行。读 README 得到「十源」，读 `AUTO_SET` 才得到真相。
  **以后凡「N 源/N 路并发」的宣传，必须去找那个数组字面量**，别信导出名与 README。
- **一个源「失败」有三种形状**：抛错、超时、**200 但空**。第三种最危险 —— 上游把它当「没结果」吞掉，
  而实际是**这个源对这类查询失效**。判据：同一查询用**放宽超时**复打一次，若 200 且 0 条 ⇒ 是查询构造问题，不是网络问题。
  本轮正是靠「A 20s 超时 → D 30s 200 空 → C 去引号有 5 条」三步锁定了 `all:"整句"` 这个构造缺陷。
- **A 类候选的挂载面要按「entry」拆，不按「包」判**。同一个包，`dsh.bundle.patch` 整包挂是 ⛔（第二个面板 + Web 端装包），
  只 `import` 它的一个纯函数模块是 🟢。**判据要落在「挂什么」而不是「这个包好不好」**。
- **npm 版本与仓库 tag 会岔开**。`dsh-ai-library` 仓库 `0.3.54`、npm 最新 `0.3.39`。
  「可锁版」必须写成「锁的是 npm 的 X，仓库是 Y，两者在**这个文件**上逐字节相同」——
  要落到文件粒度，否则下一次评审会把 `0.3.54` 的新行为当成锁住的行为。
- **词面见底和轴见底是两件事**。本轮 5 次 `total=0`（`borrow` / `due date` / `library seat` / `reading list` / `loan`）
  说明「图书馆借阅」这一**词面**在 A 组没有对应仓库；但「论文页检索半径」这一**轴**仍有未挖的一段（引用网络/引文追踪）。
