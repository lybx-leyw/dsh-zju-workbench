**三条强化判据**

| 判据 | 结论 | 依据 |
| --- | --- | --- |
| ① 仍是同一个面板 | **需改造（可做到）** | 上游有**自己的客户端**（`dsh.client.platform=web`、`immediately: true`，外加 `Library` 侧栏页）＝**第二套布局主张**。要做到「同一个面板」，必须像 `page-paper` 对待 `@ggboy123/dsh-paper-reader` 那样：**放弃它的客户端，只借宿主侧 `host/*`**，由 `ReaderFrame` 的 iframe 承载、主题注入、接管控件 |
| ② 功能仍相似正交 | ✅ | 与现有 `page-paper` 同属「论文阅读」，但**正交在解析档位与阅读产物**：本仓锁的是 `dsh-paper-reader` 的**转录 + 会话伴读**，上游给的是**本机版面流 + 学习地图**；两者重的是「能看到 PDF」，不重的是「看到的中间表示」 |
| ③ 底层多调了更优质实现 | ✅（**局部**） | 仅 **MinerU 本机档**与 **study-map** 两处成立；翻译、批注、导出三处本仓已有等价物 |

**≠ 重复且无增益**：与在册的 `GGboya/dsh-paper-reader`（已 skeleton-created 为 `dsh-radar-paper-coach`）
不冲突 —— 后者补的是「教练闸（`study_progress`/`study_update`）」，本轮补的是「**本机解析** + 学习地图」，
是论文页的两条不同纵轴。

**⛔ 硬阻塞：锁版条件不成立（这是本轮不出骨架的唯一原因）**

```json
{ "name": "@local/dsh-reader", "version": "1.0.1", "private": true }
```

- npm `@local/dsh-reader` → **HTTP 404**（不是「未发布」，是前缀 `@local/` 本身不可公开）；
- `private: true` ⇒ 即便有私有 registry 也不允许作为依赖发布；
- 上游唯一的安装方式是 **`github:YuigahamaHawk/dsh-paperhub#v1.0.1`**（README 明写）。

⇒ 「A 类 = `dependencies` 里锁版引入上游 DSH 包」这条集成方式**在此不成立**。
若强行出骨架，`npm install` 必然失败 —— 那只是把缺陷写进仓库。本轮**不出骨架**。

**不受锁版限制、可独立复用的两条交互契约（本轮的实际产出）**

1. **MinerU 本机档的「三不」口径**（可直接借鉴、不摘代码）：解析前先 `verify_model_repo()` 核
   本地权重 → **缺就报错**而不是自动下载；`MINERU_MODEL_SOURCE=local` 锁死模型源；
   `MINERU_MODEL_VLM_SERVER_URL=''` 清空远端 VLM 端点；`MINERU_TELEMETRY_DISABLED=1`。
   本仓 `classroom-media` 的 `mineru` 分支走 HTTP 服务、**没有这三道网**，
   上课网络差时「静默下载 2GB 权重」正是 `unpdf` 缺依赖之外的第二个隐性失败点。
2. **学习地图的锚点契约**：每张重点卡片必须携带 `source-anchors`（页 + 图元几何），
   点击回到 PDF 原页 —— 与本仓 `page-paper` 已有的「第 N 页可点跳转」是同一形状，
   差别只在粒度（重点卡 vs 会话消息）。

**建议下一步**：① 向上游提 issue 询问是否发布到 npm（或改用可安装的包名）；
② 在等回复期间，只借契约 1 给 `classroom-media` 的 `mineru` 分支加「本地权重核验 + 禁止静默下载」；
③ **不**生成骨架，**不**接入 profile。
