### 2.1 🟢 `nftuoa/dsh-zotero` —— **在册复核升级（🔵 → 🟢）**

这不是新面孔：`registry.md:2560`，2026-10-23 登记，理由写得很清楚「★0 + 当日建仓 → 不评 🟢」，
另记 **M1：无非 npm 发布**。

**四天后，那两条理由都不成立了**：

| 当时 | 现在 | 证据 |
| --- | --- | --- |
| ★0，建仓当天 | ★0，但 **release + 打好的 tgz** | `v1.0.1`（2026-10-23T12:52Z）附件 `dsh-zotero-1.0.1.tgz`，4.26 MB |
| 无 npm 发布，无法锁版 | **可锁版**（tarball / `github:#v1.0.1`） | 同上；npm 仍无（包名故意叫 `@local/`） |
| 未验形态 | **标准 A 类**：`dsh.bundle.patch` + `cordis.patch.yml` | `- insert: [{ id: zotero, name: '@local/dsh-zotero' }]` |
| 未验许可 | **MIT** 清晰 | `LICENSE` 首行 |

**与现有功能的关系：重复且可强化**（不是「全新」）

- 本仓 `dsh-zhiyun-page-paper` 已有：文献库、同源 PDF 阅读（iframe）、整篇翻译、
  选中即译（悬停 260ms 触发）、会话抽屉。**功能面高度重叠**。
- 但**底层来源完全不同**：本仓的文献库是上游 paper-reader **自建**的；
  全仓 `grep -i zotero` 在 `page-paper` / `host-paper` 下**零命中**。
  也就是说 —— 用户 Zotero 里那 300 篇带高亮的 PDF，本仓**一篇都看不到**。
- 上游多出来的两件事，是本仓没有的：**Zotero 原生高亮 / 子笔记的读写**
  （写入走 Zotero 本地 API，落进 Zotero 自己的库，不自建批注存储）、
  **`zotero_search` / `zotero_paper` 两个 model tool**。

→ 按强化式三判据：② 正交 ✅、③ 更优底层 ✅、**① 同一个面板需改造**（见 §3）。

**结构上的两个意外（都影响集成方式）**：

1. **零 DSH 依赖**。`dependencies`/`peerDependencies` 皆空，`lib/` 下 `@deepseek-ai/*` 零命中。
   它靠运行期契约：`inject: ['webServer']` + 同源 `/zotero/*` + 客户端 `slots`。
   → 「锁版引入上游 DSH 包」这条惯例**不适用**，能锁的只有它自己。
2. **自带 `vendor/`**（pdf.js + KaTeX + 字体，3.7 MB）。逐项核过：
   7 项宽松 ✅，**`standard_fonts/LICENSE_LIBERATION` 是 GPL-2.0 + 字体例外** ⛔。
   字体是渲染资源不是被改编代码（pdf.js 官方发行版就这样分发），但本仓对嵌套许可证
   一贯一票否决（r55 / r85 先例）→ **已写进骨架 README 作为第 1 号待决项**，
   在决定「剔除 / 子集 / 接受」之前**不搬 vendor、不摘任何代码**。

## 3 · 骨架：`packages/radar/dsh-radar-zotero-bridge`

**A 类 · 锁版 `@local/dsh-zotero@1.0.1` · 强化式集成 · 未评审**

选了它，是因为本轮唯一同时满足「🟢 + 许可明确 + 能为现有面板补一个**完全没有的来源**」。

它也诚实地带着三个不能糊弄过去的坑（都写在 README 的待决清单里）：

1. **装不上**。`@local/dsh-zotero` 从未发布 npm，`dependencies` 必须改成 tarball URL 或
   `github:nftuoa/dsh-zotero#v1.0.1`。当前写法 `npm i` 必失败 —— 故意保留，标记待决。
2. **GPL 字体**。`vendor/pdfjs/standard_fonts/LICENSE_LIBERATION` 一票否决项，未决。
3. **面板归属**。上游客户端抢 `sidebar.panellist` + `slots.register`，是**第二套布局主张**
   （和 `dsh-zhiyun-page-paper` 的注释里说的「上游客户端会抢 sidebar.workspaces」是同一类问题）。
   要做成「同一个面板」，必须**放弃它的客户端、只借 `/zotero/*` 路由**，由 `ReaderFrame` 渲染。
   这部分改动落在 `page-paper`（本仓包），**不属于 radar 包**，本轮只出 host 半边。

另：`insert id` 必须用 `radar-zotero-bridge` 而非上游的 `zotero`，两者不能同时启用
（同 cordis 槽位互抢，与 r83 的 `plugin-manager` 同类）。
