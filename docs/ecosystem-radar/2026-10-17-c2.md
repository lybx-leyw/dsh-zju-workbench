**为什么判定为「重复且可强化」而非简单集成** —— 三条同时成立：

1. **仍是同一个面板**：产物喂给**已有的**笔记页 / 论文页导入通路，**不新增页面、不改导航**。
2. **功能仍相似正交**：两边都在做「把外来文档变成可读文本」，不是两套并列能力。
3. **底层多调了更优质实现**：本仓现状是**没有**格式转换底层（`dsh-zhiyun-parser` 是 LLM 解析，非格式转换；`pdfjs-dist` 只管 PDF 渲染）。上游按格式分派到**各格式的专用成熟库**（`mammoth` / `turndown` / `node-pptx-parser` / `xlsx` / `pdf-parse`），这正是现有链路缺的那一层。

**强化式集成的意义**：不是「本仓已有一份 docx→md，再接一份重复的」，而是「本仓**没有** docx/pptx/xlsx→md，接进来让导入通路**多出多种格式**」。若评审认为本仓**不打算**做多格式导入，则本条应降为 🔵（仅供参考）——**提请人工裁定**。

**风险与待裁项**：

- npm 最新版 **2025-03-02** 发布，GitHub 仓库最后推送同日 → **上游已停滞约 19 个月**，需评估是否接受。
- 依赖较重且含**平台强绑定**项：`exiftool-vendored`（捆绑二进制）、`fluent-ffmpeg`（需系统 ffmpeg）、`node-tesseract-ocr`（需系统 tesseract）。若只取 docx/pptx/xlsx/html 通路，可用 `turndown` + `mammoth` + `node-pptx-parser` + `xlsx` **自行收敛子集**，避免拖入二进制依赖（见骨架 README 的裁量建议）。
- `pdf-parse-tt-message-gone` 是从 `pdf-parse` fork 出的补丁包，维护风险需注意。
- ★21 体量小，社区验证不足。

**同类备选（未出骨架，📌 供二选一）**：`instax-dutta/MarkItDownJS`（★1，MIT，TS，2026-08-24 活跃）——覆盖面更广（含 EPUB/音频/压缩包），描述明确写「LLM-friendly Markdown」，但 **★1 且同样年轻**。二者**不要都接**。

## 12. ⚠ 机制缺陷：同日重复取组（建议修复）

### 现象

本轮（03:0x）与第九轮（00:01）**同日同组（C）**。这不是第一次 —— `rotation-state.md`
的「漂移说明」已记录 2026-10-15 的同类事故（当时 B 组跑了两次）。本轮为**第五次同类事故**。

### 根因（本轮实测确认）

`rotation-state.md` 里只有一句「任务开跑前先读它选组」，**但没有规定从哪里读**。
本轮的实际序列：

1. 沙箱是**独立环境**，本地无仓库 → 必须先 `clone`，此时拿到的是**快照**；
2. 读**本地快照**的 `rotation-state.md` → `last_run_at = 2026-10-15 09:00` → 判定「跨天」→ 取 C；
3. 本轮执行期间，另一路任务推送了 `radar`（含第九轮 C 组）；
4. 本地快照**已过期**，脚本无从得知 → **必然重复**。

**关键点**：`last_run_at` 陈旧**不是**脚本的错，而是**取组时点的数据源错了** ——
读了 clone 快照，而非 remote 最新。只要「本地 clone 晚于取组判断」或「取组判断早于
push 完成」，重复就不可避免。

### 建议修复（按优先级）

| # | 建议 | 说明 |
| --- | --- | --- |
| 1 | **取组前先 fetch 远端 `rotation-state.md`** | `git fetch origin radar` 后 `git show origin/radar:docs/ecosystem-radar/rotation-state.md` 读状态，**而非**读 clone 快照。这是**最小且根治**的改动 |
| 2 | **`radar` 分支不存在时，先查 `main` 上的状态** | 若远端无 `radar`，退一步查 `origin/main`。本轮两条路都空 → 说明该仓库当日**从未**成功 push 过，此时按公式取组是合理的（但需在报告中标注不确定） |
| 3 | **报告文件名加轮次后缀** | 若同日已存在 `YYYY-MM-DD.md`，本轮改用 `YYYY-MM-DD-<n>.md`（本轮已按此处理为 `-c2`）。避免覆盖/冲突 |
| 4 | **脚本增加 `--remote` 模式** | `node scripts/radar-rotation.mjs --remote` 直接从 origin 读状态，免去手工 fetch |
| 5 | **状态文件加「取组时点」字段** | 记 `group_taken_at`，便于事后判断「取组时读到的是哪一版状态」 |

> 在修复前，**同日重复取组会继续发生**。本轮已按「不覆盖、改名、去重、如实标注」处理，
> 保证不丢数据、不掩盖问题。
