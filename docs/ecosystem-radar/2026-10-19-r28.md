## 3. 核心结论（先看这里）

**① 本轮唯一 🟢：`KelaoHu/dsh-lowtide`（★174、MIT、`0.2.8` 已上 npm）—— A 类里少见的「真能锁版」的包。**
它把「白天想到的活儿先扔队列 → 到你设的时间窗口自动跑 → 第二天早上看报告」做成了一条完整流水线，
带**峰谷价判定**（Beijing 工作日 09–12 / 14–18 为峰时，其余半价）、四种执行策略（单次 / 迭代 / 采样 / 复核）、
执行报告（实花 ¥ / 已省 ¥）、以及「待裁定」人工闸门。**中文文案 383 条，原生就对中文用户友好。**

**② 它在本仓的落点不是「新增一页」，而是把「规划」页的卡片接到执行端 —— 这是本仓第一次出现「规划 → 执行」的完整闭环。**
「规划」页现在做到「卡片 + 截止时间」就停了（`packages/dsh-zhiyun-page-planning/src/plans.js`），
卡片交给谁跑、什么时候跑、跑完怎么复核，全在页面之外。lowtide 补的正好是这一段。
三条判据：**仍是同一块卡片区**（不新增页）＋ **功能相似正交**（同一批卡片，多一个"什么时候跑"的调度维度）
＋ **底层多调了更优质实现**（本仓只有「按截止时间排序」，没有窗口模型、没有峰谷价、没有执行报告）。

**③ ⚠ 但它有一处**不能照搬**：上游 `cordis.patch.yml` 会把宿主的 `permission` 行整行替换。**
patch 里那行 `- id: permission` 是**整行替换语义**（上游注释自己写了「a row patch REPLACES the targeted row's whole config」），
里面重新声明了 `read-only / workspace-write / danger-full-access` 三个基础预设，**另外新增三个 `approval: never` 的预设**
（`lt-readonly` / `lt-standard` / `lt-trusted`）。若本仓将来整包套用，本仓自己的权限预设会被**静默冲掉**；
且三个 `never` 预设在「无人值守跑批」的语境下等于**取消审批闸门** —— 这与本仓「候选包不得接进 profile」的边界、
以及「沙箱治理挂在 permission 行上」的既有事实直接冲突。**骨架只取 insert 一行，permission 块不取**，见 TODO-1。

**④ 坏消息：`dsh-plugin task planning` 的两条「规划」插件都锁不住版。**
`zriyox/dsh-goal-scaffold`（★2，MIT）**没上 npm**、`exports` 缺 `dsh.client`；
`ztl34245881-commits/dsh-task-planner`（★3，MIT）**仓库只有 5 个文件、无 `src/`**（README 说有 `plan_task` / `task_memory` 工具，
但代码与 `lib/` 都不在仓库里）—— 两者都只能源码级移植，判 🟡。

**⑤ 「任务板」这一族已确认饱和，且多数无许可证。**
`in:name dsh-task` 258 条里，前排 10 条有 4 条 `null` 许可证、3 条 `NOASSERTION`/`None`。
本仓没有「多人协作看板」的场景，**不追这一族**。
