**它做什么**（读 README + 文件树得出，不搬源码）：
不走网页套壳，直接调 CC98 开放 API，把列表/帖子以 **`cc98:` 前缀的只读 Markdown 文档**打开；
帖子标题、版面、引用楼层、翻页都是可点链接；登录后支持提醒/收藏/关注/顶踩/回复（Markdown 与 UBB 两种正文格式）；
支持 ZJU WebVPN（校验 ticket 与路由 Cookie）；刷新令牌与凭据只落 `SecretStorage`。

**强化式集成三条判据**：

| 判据 | 结论 | 依据（可指到文件/行） |
| --- | --- | --- |
| ① 仍是同一个面板 | ✅ 成立 | 不新增页面、不新增导航项。落点是「笔记」页**已有的 Markdown 阅读/渲染通路** —— `dsh-zhiyun-page-notes` 用宿主 `MarkdownText` 渲染正文（`src/client.jsx:23-28, 45`），本包只替换「这段 Markdown 由谁产生」，不换渲染器 |
| ② 功能仍相似正交 | ✅ 成立 | 现有 `source-cc98/src/ubb.js` 的 `ubbToText()` 只做 **UBB → 纯文本**（图片→`[图片: u]` 占位、引用→`> [引用]`、链接→`text (x)`），**丢失全部版式**；本包补的是「同一份 UBB → **带结构、可点击的 Markdown**」，是同一件事的**更高保真档位**，不是并列的新功能。且与 `dsh-radar-cc98-ubb-bridge`（MD→UBB，**写**方向）正好构成读写对偶，不重叠 |
| ③ 底层多调了更优质实现 | ✅ 成立 | 上游把「列表/帖子/引用楼层/翻页」建成带链接的文档图（`documents.ts` + `navigation.ts`），并单独抽出 `webvpn.ts` 校验 ticket 与路由 Cookie —— 本仓 `source-cc98` 现有实现只有纯文本，**翻页与引用楼层在纯文本后已不可回溯**（地址被压成文字，链接关系丢失） |

**与「重复且无增益」的界线**：如果只是把纯文本再包一层 diff，是本轮该 ⛔ 的情况；
但上游提供的是**保结构**的转换 + WebVPN ticket 校验，属于「底层换更优实现」，故 🟢。

**保留意见（评审必看）**：
- ★1、单人维护、无 issue 讨论记录 —— 活跃度弱，属「可用但不宜重依赖」；
- 上游是 **VS Code 扩展**，`vscode` 是虚拟模块**装不上**，只能**能力提取**（纯函数部分可搬语义），不可锁版挂载；
