| 与现有功能 | **重复且可强化** ✅ |

**它是什么**：把一节课的**录像/录音 + 课件（PDF / 照片 / 视频内幻灯片）**
变成**结构化、可溯源**的笔记，并产出**一个同步 HTML 查看器** ——
视频、带时间戳的逐字稿、要点摘要在**同一页上双向同步**：
视频播放时对应要点自动高亮并滚入视野；点要点的时间戳可跳转视频。

其 README 明确自述设计目标：

> The design goal is not "summarize a video". It is **traceability**:
> every claim in the finished note should be attachable to a moment in the

**技术构成**（决定集成难度的关键）：

| 阶段 | 脚本 | 依赖 |
| --- | --- | --- |
| 输入分类 | `route_inputs.py` | 纯 Python |
| 转写 | `transcribe_video.py` | **faster-whisper（本地 GPU）** |
| 幻灯片提取 | `extract_slides.py` / `build_slides_from_pdf.py` / `build_slides_from_images.py` | 帧提取 + 感知去重 / PyMuPDF / 图片渲染 |
| OCR | `quick_ocr.py` → `dedup_semantic.py` → `ocr_surya.py` | **Surya OCR** |
| 幻灯片语义 | `vlm_signals.py` | **本地视觉模型（VLM）** |
| **对齐** | `ground_slides.py` | 产出 **`slides_grounded.json`** |
| 综合 | Stage F（LLM） | 只在最后用 LLM 写散文 |
| 输出 | `export_web.py` | **同步 HTML 查看器** |

> **关键**：Stage A–E **全是纯 Python、零 LLM token**。
> 上游只有最后一步（写散文）用 LLM —— 这与本仓"解析器 + LLM 集成层"的分工**同构**。

| **底层多调了更优质实现** | ✅ | 上游有**时间轴对齐**与**可溯源逐字稿**；本仓**两者皆无** |

**具体增强哪个现有功能**：

> **`packages/dsh-zhiyun-lecture`（讲义装配）× `dsh-zhiyun-classroom`（课堂来源）
> 之间那条「拿到课件之后，怎么还原老师当时讲了什么」的通路。**

| 环节 | 本仓现状 | 上游带来的 |
| --- | --- | --- |
| 课件获取 | ✅ 可下载、可解析 | — |
| **音视频理解** | ❌ **完全空白** | ✅ ASR 逐字稿（带时间戳） |
| **时间轴对齐** | ❌ **完全空白** | ✅ 课件页 ↔ 语音段对齐（含"幻灯片不在视频里"的 PDF / 照片来源） |
| 讲义装配 | ✅ PPT 知识树 + 习坎填充 + 书面语验收 | ✅ 但入口只有**纯文本课件**，缺"老师原话"这一层 |
| **溯源** | ❌ 无 | ✅ 每条结论可挂到某时刻 + 某页幻灯片 |

> 本仓讲义装配是「**在课件上写字**」；上游补的是「**把老师说的话作为证据层接进来**」。
> 这正是判据 ③ 说的"更优质的底层"。

**⚠ 集成前必须裁定的事项**：

1. **技术栈错配（最大障碍）** —— 上游是 **Python 管线**，本仓是 **DSH 工作台包（JS）**，
   **不能直接挂载**。可行路线：
   - **(a) 能力提取 + 本仓自建**（**推荐**）—— 只取**对齐设计**与**证据模型**
     （`slides_grounded.json` 的形状），ASR/OCR 由本仓既有通道承担。
     且本仓**已有 `dsh-zhiyun-parser`（三阶段解析器）**，"原始材料 → 结构化文本"
     的入口**应当复用**，而非再起一套；
   - **(b) 外挂本地管线** —— 把上游 Python 管线作为本地进程运行。
     **代价高**：引入 faster-whisper / torch / GPU 依赖，**与本仓无 GPU 环境冲突**。
2. **本地算力假设与隐私（红线）** —— 上游假设"本地 GPU 跑 Whisper"。
   课堂录像/录音属**个人学习资料**，若上传第三方转写，
   **须先确认本仓的数据出境与留存策略** —— **这条不能由雷达替答**。
3. **对齐的期望管理** —— 上游目标是 **traceability 而非 accuracy**，对齐必然有误差。
   **不应把它当"自动生成准确讲义"用**；建议 UI **标注"对齐仅供参考"**，
   逐字稿作为**可核对的原始证据**呈现。

> **许可证合规**：MIT ✅ 允许借鉴，但**本轮未摘取任何代码**，故骨架不含 `ATTRIBUTION.md`。
