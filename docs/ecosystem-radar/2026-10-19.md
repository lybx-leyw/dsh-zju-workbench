**实测（沙箱 Node22，10-19）**：

## 4. 本轮结论（三条）

### L-1 · `highlightAuto()` 是这条路线上的**唯一真陷阱**

实测：core-only 下 `highlightAuto('def f(x):\n return x')` **仍返回 `python`** ——
因为它此时只认**已注册**的语言，返回的只是「已注册集合里最像的那个」。
这会造成**静默误判**：注册了 `python` 和 `javascript` 后，一段 C 代码会被**着色成
python 的类名**，看起来「亮了」，其实是错的。

> 因此骨架里写死：**禁用 `highlightAuto()`；围栏无语言标识 → 纯文本**。
> 验收方式不能是「有没有颜色」，必须是「**颜色对不对**」——建议评审时用 C / Python / SQL 各一段做对照。

### L-2 · 体积是本轮**没有量完**的东西，不要当结论用

本轮只量了 npm `unpackedSize`（5.50 MB，全量）与目录尺寸（`es/` 2.7 MB、`styles/` 2.4 MB）。
**core-only 在浏览器里 gzip 后到底多少，没量。** 骨架 README 里写的「数十 KB」是估算，
已在该文件与这里**双重标注为估算**。这是本轮的可核查缺口，**不应被引用为事实**。

### L-3 · 唯一的 A 类候选，问题不在「能不能接」而在「接哪个版本」

`dsh-raw-html` 这个案例值得记一条方法论：
**A 类候选要同时过三道门 —— 形态（是否原生 DSH）、许可（v1 MIT / v2 NOASSERTION）、可锁版（npm 是否发布）**。
本轮这条**三门只过了一道**（形态），所以即使它是最贴生态的候选，也停在 🔵/🟡。
以后 A 组命中后应**立刻查 npm 是否存在同名包**，这比读 README 快。

### L-3 · 上游 patch 里的 `!!js` 是**本仓挂载 A 类的新障碍**，必须写进规程

`@graysilver/dsh-evolve-modes@0.4.1` 自带的 patch 是：

```yaml
- insert:
    - id: dsh-evolve-modes
      name: '@graysilver/dsh-evolve-modes'
      config:
        shellTool: !!js "process.platform === 'win32' ? 'pwsh' : 'bash'"
```

本仓的补丁层不支持（也不该支持）在 YAML 里执行任意 JS。因此本轮骨架**不用**上游那份 patch，
而是：

1. 用**本仓 id** `radar-evolve-modes` 插**本仓包名**；
2. 在 `src/index.js` 运行时 `import()` 上游并调它的 `apply(ctx)`；
3. `shellTool` 这类平台配置由本包 `config` 给默认值。

> 这是「锁版挂载 + 外围兼容层」在 2026 年的新形态：**上游的 patch 不再是可直接复用的挂载点，
> 而是「上游声明了哪些挂载意图」的说明书**。以后 A 类命中，应先读上游 patch 里有没有 `!!js` / `!include`。
