## 3 · 🟢 `dsh-prompt-market`：判据③是**怎么核出来的**

这是本轮唯一 🟢，也是最容易被误判成「重复且无增益」的一条 —— 因为 registry r98 曾把它
连同 `dsh-webui-market-plugin`、`polang233/dsh-plugin-index` 等**整批并入「插件市场簇」封板**，
**从未单独看过它的能力**。本轮把它单独拎出来重过判据。

**判据③（底层多调了更优质实现）的成立，靠的不是「上游更好」，而是「本仓这块是空的」**：

| 检索（真实执行） | 结果 | 判断 |
| --- | --- | --- |
| `grep -rniE "prompt ?(template\|library\|preset\|注入\|库)\|/prompt\b" packages/dsh-zhiyun-*/src` | 命中 7 处，**全部**是出题流水线内部文案 | 词面相同、域不同：`core-classroom-generate/src/prompts.js` 是课程上下文模板，`core-lecture-tools/src/prompt-hints.js` 是**工具描述**拼装 |
| `grep -rhoE "conversation\.input\.[a-z]+" packages/dsh-zhiyun-*/src` | **0 命中** | 输入区本仓**完全没占** |
| `ls packages/radar/*prompt*` | 无 | 无同域骨架 |

⇒ 结论：这一层不是「已经有了想做更好」，而是**根本没做**。所以它不属于「简单集成重复功能」，

这一句我写进了骨架 README，免得后面有人把它当既成事实。

3. **槽位为什么是空的？** 本仓没人占 `conversation.input.left`。是「没人做」还是「宿主不给」——
   后者的话整个骨架作废。

**为什么不选 `dsh-prompt`（★92）**：功能更强、更活跃，但 `prepare: npm run build`（装包即构建）+
私有 `dsh-log@^0.3.4`（非锁版）+ `client.js` 1.0 MB。对本仓「锁版」这条硬门槛来说，它锁不住。
**但要说清楚**：如果评审认为「一个教学/学习工作台没那么多高频重复 prompt」，
正确结论是**这条轴整个不做**，而不是换个更弱的上游硬做。这句话也写进了骨架。
