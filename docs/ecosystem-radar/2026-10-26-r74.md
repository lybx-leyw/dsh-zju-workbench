## 3. 本仓实测校准（本轮真正的增量）

> 全部在沙箱 `npm i rrule@2.8.1` 后直接 `node -e` 执行，可复现；**未接入任何包**。

### 3.1 ESM 下不能具名导入（P1 · 接入即崩）

```js
import { RRule } from 'rrule';   // ✗ SyntaxError: Named export 'RRule' not found
import pkg from 'rrule';         // ✓ CommonJS 默认导出
const { RRule } = pkg;
```

`rrule@2.8.1` 的 `package.json` 只给 `main`（CJS），**没有 `exports` 字段**。本仓所有包是
`"type": "module"`（`packages/dsh-radar-ics-export/package.json` 亦然），所以**照抄 `rrule` 文档的
`import { RRule } from 'rrule'` 会在加载期直接抛错**。这条必须写进骨架 TODO-1，否则评审者按官网示例写就崩，
且报错文本（"CommonJS module…"）与「rrule 装坏了」高度相似，容易误诊为依赖缺失。

### 3.2 `byweekday` 的整数口径与 `Date#getDay()` **差一位**（P0 · 静默错日期）

```text
new RRule({ byweekday: [3],      ... })  → options.byweekday = [ 3 ]
new RRule({ byweekday: [RRule.WE], ... }) → options.byweekday = [ 2 ]
```

`rrule` 的 weekday 枚举是 **`MO=0 … SU=6`**（参照 RFC 5545 的 `BYDAY` 序号），而 JS 的
`Date#getDay()` 是 **`SU=0 … SA=6`**。直接透传 `getDay()` 结果会**整体偏移一天**，
且**不报错、不告警**：

| 传入 | 生成的 RRULE | 展开的上海日期（dtstart = 2026-09-16 周三 08:00） |
| --- | --- | --- |
| `[3]`（`getDay()` 周三的结果） | `BYDAY=TH` | **2026-09-17 周四** ×4 ❌ |
| `[RRule.WE]` | `BYDAY=WE` | 2026-09-16 周三 ×4 ✅ |

**结论**：适配层必须做 `getDay() → [RRule.SU, RRule.MO, …, RRule.SA][dow]` 的映射，
或统一走 `RRule.fromText('every wednesday')`。**不得透传数字**。

### 3.3 RRULE 在「本仓课表」上只能覆盖「无空洞」的组（P1 · 语义前提不成立）

`dsh-zhiyun-source-classroom/src/models.js:66-71` 的 `scheduleEntry()` 只有
`{courseId, subId, startMs, endMs, courseTitle, roomName, …}`，**没有周次、节次号、楼栋**。
`agenda.js` 的 `projectAgenda()` 是**逐日**把 `items[].courses[]` 拍平。

实测（4 周 × 每周 2 节 + 第 3 周 1 次调课到周六，共 9 条）：

```text
A|3|8:0|5700000 条目 4 RRULE 展开 4
A|5|10:0|5700000 条目 4 RRULE 展开 4
A|6|8:0|5700000 条目 1 RRULE 展开 1   ← 调课那节自成一「组」
条目总数 9 / 分组数 3 / RRULE 展开总数 9
```

**条数守恒，语义不守恒**：

- 那份「1 条目组」会变成 `COUNT=1` 的单次事件，**丢了「它是本周三那节课的调课」这一事实**；
- 若该学期第 8 周（国庆）停课，则分组后 `COUNT=3`，而 `BYDAY` 展开会**跳过整周** —— 即
  calendar 上那个周次**整周没有这节课**，看似正确；但一旦停课**不连续**（第 8、第 12 周各停一次），
  `COUNT` 无法表达「两次空洞」，只能退回逐日展开。

**结论**：RRULE 只在「**组内相邻两条间隔恰为 7 天**」时与逐日展开等价。
适配层必须先做 `contiguous(group)` 判定，**不连续就退回逐条**，不能一刀切。

### 3.4 对已交付骨架的一句校准

`packages/dsh-radar-ics-export/src/index.js:77-78` 现写着：

> `recurrenceRule`（课表已由 `projectAgenda` 逐日展开，再加 RRULE 会与展开后的实例**重复生成**）

这句**结论对、理由要补**：真正的风险不是「多传一个字段就重复」，而是
**逐日展开的实例 + 一个 `RRULE` 属性会被日历客户端解释成「每个实例自己再重复 N 次」**
（RFC 5545：`VEVENT` 既是独立实例又带 `RRULE` 时，实例自身是 `DTSTART`）。本轮**未修改**该骨架
（避免混淆 L2 的每日 1 个配额），只在此登记，交人工决定是否补一句。
