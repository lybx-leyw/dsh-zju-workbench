### 2.2 `adoresever/graph-memory` —— 本轮唯一「过许可门 + 过锁版门」的候选，为什么仍不接

这是全轮最值得记录的一条，因为它**逐条碰到了本仓的架构红线**：

```text
dsh.ts                81.5 KB（行数 997）
inject               ["tools","llm","systemPrompt","agentLoop","agents","sessions","credentials","tokenMeter"]  ← 8 个宿主服务
ctx.on               "agent/created" / "agent/session-start" / "session/event" / "agent/pre-step"(prepend)
数据来源              每轮已提交 turn → OpenAI 抽取实体/关系 → SQLite 图 → 自动 recall 注入上下文
npm 1.5.8            main: "index.ts"（无 dist/，TS 源码包）；peerDependencies: { openclaw: "*" }
npm 1.5.8 的 dsh     字段 = null（只有仓库 HEAD 1.6.0-beta.17 才有 dsh.bundle.patch）
```

**判据逐条**：

| 判据 | 是否成立 | 理由 |
| --- | --- | --- |
| ① 仍是同一个面板 | ❌ | 上游自带图谱 UI 页；本仓「笔记」页的图是**双链结构边**，`[[双链]]` 是权威真源。接它 = 新建第二套「记忆」页 |
| ② 功能仍相似正交 | ⚠ | 「从对话里派生图」与「从你写的笔记里读结构」是**两个真源方向**，不是同一功能的两档实现 |
| ③ 底层多调了更优实现 | ❌ | 本仓不需要「自动抽取」，需要的是「更快地读已有结构」。上游没有替换本仓任何底层 |

**另两条与架构无关的硬事实**（即便将来有人想接也要先解决）：

1. `npm graph-memory@1.5.8`（2026-10 发布）**是纯 TS 源码包**：`main: "index.ts"`、无 `dist/`、无 `dsh` 字段、peer 写的是 `openclaw` 而不是 `@deepseek-ai/dsh-*`。
   要做锁版挂载，宿主必须能 `--experimental-strip-types` 直接吃 `.ts`（`cordis.patch.yml` 里也确实用 `!!js` 表达式，说明上游假定宿主支持）。
   **本仓 `runtime.lock.json` 锁 `preferredHostVersion: 0.2.0-rc.2`，是否支持 TS 剥离未验证 → 锁版门实际未过。**
2. 依赖 `@photostructure/sqlite@^1.0.0`（→ 3.3.0）为**原生预编译二进制**，`os: [darwin, linux, win32]`、`cpu: [x64, arm64]`。
   本仓此前的记忆类骨架（`dsh-radar-me-memory`、`dsh-radar-mneme`）已因 SQLite 依赖组被压到 🔵，这里同理。

> **结论**：不是「许可不行」，也不是「质量不行」，而是**方向不对**。登记为 ⛔，并在 registry 备注里写明
> 「记忆簇第 4 次封板」—— 后续同域候选（派生式记忆 / 图谱记忆 / 会话记忆）一律 ⛔，不再逐条详评。
