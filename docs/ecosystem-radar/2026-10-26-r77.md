## 1. 本轮结论

**「错了的题再练一次」在本仓是三层同时断的，而外部没有任何一个库能补上 —— 因为缺的不是算法，是「错因」这个数据本身。**

| 层 | 现状 | 证据 |
| --- | --- | --- |
| ① 记录 | 作答**有**记录 | `core-study/src/question-bank.js:209` `bank-answer` 写 `bank.sessions[].answers[]` + `question.attempts[]` |
| ② 归因 | 归因代码**有**（且质量高） | `core-quiz/src/store.js:630` `attributeByPoint()`、`:677` `masteryOf()`、`:702` `masteryByPoint()` |
| ③ 入口 | 归因结果**零调用方** | 全仓 `grep pointMastery\|pointAttribution`（除定义文件外）→ **0 命中**；`planPractice` 的 `review` 分支只判「有没有做过」 |
| ④ 选题 | 错题与「做对过的题」**同一池** | `core-quiz/src/points.js:216` `old = eligible.filter(q => q.attempts?.length)` —— **答对也算 `old`** |
| ⑤ 跨模块 | 两条 attempts 轨**形状不同、桥接会抛错** | §3 F-1：`study` 写 `verdict`/`questionId`，`quiz` 读 `autoVerdict`/`quizId` |

结论一句话：**`review` 模式当前叫「复习」，实际是「做过」；用户答错的题和答对的题在选题时**没有任何区别**。**

## 3. 本仓实测校准（本轮真正的增量）

> 全部在沙箱用 **Node v22.13.1 直接 `import` 本仓源码**实跑，无 mock、无网络。

### F-1 · 两条 attempts 轨形状不同，桥接**抛错或静默归零**

`core-study` 的 `bank-answer` 写出的作答形状：

```js
{ id, questionId, sessionId, response, verdict, grading, at }
```

`core-quiz` 的 `loadAttempts()` 读的形状：

```js
{ id, quizId, courseId, sectionId, blockIndex, response, autoVerdict, selfRecall?, at }
```

实跑 `createQuizStore().loadAttempts([studyAttempt])`：

```
✗ loadAttempts 抛错: QuizDataError | 作答记录 a1 的 autoVerdict 认不出来：undefined
```

- 这条**抛错**实际上是**现有设计里唯一一处诚实**：`attemptFromJson` 对认不出的代号直接抛，不猜。
- 但把缺字段的条目录进去（`quizId` 缺失）则是 **静默的**：`store.js:251` `String(raw.quizId ?? '')`
  把 `undefined` 变成 `''`，`loadAttempts()` 返回 `1`（不报错），随后 `attributeByPoint()` 返回 `{}`
  —— **记录在、归因全空、无任何提示**。实测：

```
loadAttempts -> 1
snapshot.attempts[0] = {"id":"a1","quizId":"","courseId":"","sectionId":"","blockIndex":0,...}
attributeByPoint = {}
```

> 影响：任何「把学习页作答喂给题库归因」的尝试，**要么在装载时抛错整批丢，要么静默全零**。
> 这不是接入外部库能修的，是**本仓两个模块的契约不一致**。

### F-2 · `review` 模式的语义是「做过」，不是「做错过」

`points.js:216-227`：

```js
const fresh = shuffle(eligible.filter(q => !q.attempts?.length), random),
      old   = shuffle(eligible.filter(q =>  q.attempts?.length), random);
...
else chosen.push(...(mode === 'new' ? fresh : old).slice(0, count));
```

`mode==='review'` 取的是 `old` = **有过任意一次作答**的题。一道**答对过 3 次**的题与一道
**答错 3 次**的题在池里**完全等价**，只按洗牌顺序取胜者。

本仓已有 `countsAsWrong`（`store.js:200`，且**明确**「`selfRecall` 优先、`unknown` 一律不算错」）——
即「哪道题算错」这件事**已经想清楚了**，只是**没被选题用上**。

### F-3 · 错题归因的出口是「导出 JSON」，没有任何面板消费

- `exportAll()`（`store.js:708`）把 `items` + `attempts` 原样导出，**不含归因结果**；
- `masteryByPoint()` / `attributeByPoint()` 全仓**零调用方**；
- 学习页 client（`question-bank-client.js`）暴露的 8 个方法里**没有**任何 `mastery` / `wrong` 相关入口。

即：**归因能力是「写完就锁进抽屉」的**。对用户不可见，对组卷不可用。

### C-3 · 本轮否定结论：「找一个错题本库」这条路走不通

| 试过的方向 | 结果 |
| --- | --- |
| Markdown/闪卡库（`yanki` / `Lemma`） | 只会把题**导出成卡**，不提供「错→重练」路由；且 `Lemma` 是 Obsidian 插件、`yanki` 强依赖 AnkiConnect |
| 错题本 App（`ElectronicCorrectionNotebook` / `ncre-practice-desktop`） | 是**完整应用**（C# WinForm / Python Tkinter），无库无 API，**不可封装**；仅形态参考 |
| Agent Skill（`study-guide` / `study-mistake-notebook`） | 是**提示词**，不是代码；唯一可借的是「**记录错因**而不只是记错」这个数据设计 |

**结论**：错题重练缺的**不是算法**（排序、间隔重复本仓已有 `ts-fsrs` 骨架与 `countsAsWrong`），
缺的是 **「错因」这一维数据**（是概念不懂？公式记错？审题错？）。外部库都不提供它 ——
**这是本仓该自己长出的一小块，不该靠集成**。写进 registry 末尾「本轮方法论」。

| API 签名 | `getNoteFromMarkdown(markdown, options)` —— **参数顺序与常识相反** | ⚠ 首页示例按 `(path, markdown)` 写会**静默产出空 Front**（本轮踩过） |

| 实际渲染 | `~~...~~` → `{{c1::...}}` ✅；`$x$` → `\(x\)` ✅；选择题 → `Yanki - Basic` 前后卡 ✅ | ✅ **能力真实可用** |
| `deckName` | 恒为 `""` | ⚠ 课程/知识点层级**映射不进去** |

> **为什么仍登记为 🟡 而不是 ⛔**：它的**渲染层**（Markdown+公式 → Anki 字段 HTML）确实比自写好，
> 且 MIT、活跃（2026-10-16 push）。但它只能作为 `dsh-radar-fsrs-scheduler` 骨架**之后**的
> 「导出到 Anki」的可选下游，**不是**错题重练的解法。
> **建议人工评审时的判断点**：值不值得为一个非核心的「导出」功能引入 54 个依赖？
