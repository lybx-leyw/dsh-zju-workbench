## 3. 本轮的实质发现：截止时间是**点**，但学生的问题是**块**

### 3.1 本仓摘要条只覆盖 3 天，且有两套紧迫度口径（实跑）

读 `packages/dsh-zhiyun-page-planning/src/time.js`：

| 口径 | 位置 | 分档 |
| --- | --- | --- |
| `urgencyOf()` | `time.js:371` | `overdue` / `today`（24h）/ `week`（7 天）/ `later` / `none` |
| `focusOf()` | `time.js:78` | `overdue` / `soon`（24h）/ `today`（**3 天**）/ `week` / `later` / `none` |
| `focusSummary()` | `time.js:120` | 只累加 `overdue / soon / today` |
| `FocusBar` | `client.jsx:1272` | 只渲染这三档 |

实跑（`now = 2026-10-25 09:00 +08`）：

| 条目 | `urgencyOf` | `focusOf` |
| --- | --- | --- |
| 今晚 23:59 | `today` | `soon` |
| 明早 08:00 | `today` | `soon` |
| 10-27 23:59（后天） | `week` | `today` |
| 10-30 23:59（本周五） | `week` | `week` |
| 11-04 23:59（下周三） | `later` | `later` |

```
focusSummary(5 条) → { overdue: 0, soon: 2, today: 1 }  → 摘要条显示 3 条 / 实际 5 条
单条「本周五 10-30 截止」→ { overdue: 0, soon: 0, today: 0 } → 摘要条上完全不出现
```

**两件事必须分开说，不能混成一条「bug」**：

1. **可以确定的问题**：`urgencyOf` 在本仓**只剩导出、零调用**
   （`grep -rn "urgencyOf"` 只命中 `time.js:371` 的定义与 `index.js:34/547` 的转出），
   是**死代码**；而 `time.js:71` 的注释仍在用「与 `urgencyOf` 的区别」解释 `focusOf`
   —— 读代码的人会以为它还在用。这与 r63（`parse.js:15` 声明四段制、`:101` 只认两段）
   是**同一类**：**注释与实现相反**。
2. **不能武断判为问题**：摘要条只覆盖 3 天。`time.js:47` 的注释解释了 `soon` 是为了
   把「今晚 vs 明早」分开，但**没有**说「3 天外 7 天内」是否有意排除。
   本包**不假设**它是缺陷，只把差距量出来交产品拍板（TODO-2）。

### 3.2 上游「更优质」这件事，实测下来增益很小

把 `@sifiso-guy/scheduler` 的语义逐条对照本仓需要：

| 本包真正需要的 | 上游给什么 | 自写成本 |
| --- | --- | --- |
| 剩余毫秒（负值即过期） | `Deadline.msUntil(now)` | 1 行 |
| 窗口内有几个周期 | `Interval.countBetween(from,to)` | 约 6 行 |
| `due == null` 分流 | ❌ 构造即抛（`assertValidDate`） | 3 行 |
| 墙钟周期（每周一 08:00） | ❌ 只有等距 `everyMs` | 约 15 行 |
| 单双周 / 学期边界 | ❌ | 约 10 行 |

**合计约 35 行**。而上游还要先解决「npm 上不存在」
（`registry.npmjs.org/@sifiso-guy%2Fscheduler` → `{"error":"Not Found"}`）。

→ 这就是判 **🟡** 而不是 🟢 的直接依据：**「有更优实现」不成立于这一维**。
如果按「外部有实现就接进来」的直觉去锁版，等于为了省 35 行引入一个 ★0、
未发布、且**表达不了课表周期**的依赖。

### 3.3 课表周期：`Interval` 的 `everyMs` 是常数，而节次间隔有 3 种

`packages/dsh-zhiyun-source-zdbk/src/parse.js` 的 `PERIOD_TIMES` 实测：

```
第1→2节 08:00→08:50 = 50 分
第2→3节 08:50→10:00 = 70 分（大课间）
第5→6节 11:40→13:25 = 105 分（午休）
→ 13 个节次之间共 3 种不同间隔 {50, 70, 105}，12 处不等距
```

「一周 = 604800000 ms」能表达「每周同一时刻」（中国无夏令时，这个粒度侥幸不出错），
但**表达不了「第 3 节是 10:00」**。再加上单双周（`parse.js:341` 的
`weeks: 'odd' | 'even'`）与学期边界（`terms`），课表周期**必须由本仓自己算**。

### 3.4 `Deadline.compare` 不能直接替换现有排序 —— 但现有排序是对的

`client.jsx:865-869` 用 `due ? Date.parse(due) : Infinity` 排序。实跑
`今晚 → 明早 → 没填时间`，**结果正确**。而 `new Deadline(null)` 会抛错。
→ 「换成上游比较器」必须先按 `due == null` 分流。

**本包不修一个不存在的 bug**，只把正确做法写进 `SORT_CONTRACT` 常量。
