### 1.2 为什么跑这个轴：先读码找断环，再定向搜

C 组主词（课表 / 论文 / OCR / 刷题 / 锻炼）已被 r30–r54 反复扫过。本轮继续 r37 起的办法：
**先在仓里找一个断环，再为这个断环定向搜**。

读码结论（两条，可复现）：

```bash
# ① 论文页 + 宿主半边里的 BibTeX / RIS / DOI 能力
grep -rniE "\bbib\b|\.bib|ris|doi" \
  packages/dsh-zhiyun-page-paper/src packages/dsh-zhiyun-host-paper/src
# → 仅 1 条，且是 AssistantDrawer.jsx:292 的一句注释：
#   "回答里真出现外链（论文 DOI、arXiv）时按宿主的默认行为开新窗口。"
#   ⇒ 不是能力，是注释。全仓 BibTeX / RIS 解析 = 零实现。

# ② 文献库的导入路径只有一条
grep -n "uploadPaper" packages/dsh-zhiyun-page-paper/src/LibraryPanel.jsx
# → LibraryPanel.jsx:92  last = await uploadPaper({ topic, name, bytes });
#   入口是 <input type="file"> 选 PDF。没有"从文献条目起手"的入口。
```

**断环的形状**：用户手上有的是「一串 BibTeX 条目」（从 Zotero / 知网 / Scholar 导出），
而库里接受的是「PDF 文件」。**中间那一段没人做。**

这与 r53（课表 → .ics）、r54（课表 endMs → 剩余时间）**同形状**（第三次）：
**上游数据齐全、下游出口存在，中间缺一个转换器。**

| | r53（iCalendar） | r54（专注计时） | 本轮（文献条目） |
| --- | --- | --- | --- |
| 缺的是 | 一套**规范实现**（RFC 5545） | 一层**状态保证** | 一套**语法实现**（BibTeX + RIS 两种） |
| 判别 | 规范实现 → 接依赖 | 一个模型 → 接库但先证 | 语法实现 → 接依赖 |
| 结论 | 🟢 接 `ics` | 🟢 接 `xstate` | 🟢 接 `@citation-js/*` |

## 4. 实测记录（8 条，沙箱实跑）

环境：Node 22.13.0，`npm i --legacy-peer-deps @citation-js/{core,plugin-bibtex,plugin-ris}@0.9.0`（9 包，963 ms）。

| # | 断言 | 结果 |
| --- | --- | --- |
| M1 | BibTeX → CSL-JSON | ✅ `type:'article-journal'`，`author:[{given:'Donald E.',family:'Knuth'}]`，`issued:{'date-parts':[[1984]]}`，`DOI`、`page` 均正确 |
| M2 | RIS → CSL-JSON | ✅ `author:[{family:'Zhang',given:'San'}]`，`page:'10-20'`（`SP`/`EP` 合并） |
| M3 | 多条混合 | ✅ BibTeX + RIS 一起交 → `Cite#data.length === 2` |
| M4 | **中文条目** | ✅ `作者 = {王, 小明 and 李, 四}` → 两条 author；`title` 与 `container-title`（←`booktitle`）中文原样保留；`@inproceedings` → `paper-conference` |
| M5 | 非法输入 | ✅ 抛 `This format is not supported or recognized`（中文散文与随机英文都落这条）→ **唯一失败信号** |
| M6 | 版本可混装？ | ❌ `core@0.9.0 + plugin-bibtex@0.8.4` → `ETARGET`；`core@0.9.0` 单独装 → `ERESOLVE peer`。**必须三包同版本** |
| M7 | 体积 | ⚠ **698,183 B** unpacked（core 412K / plugin-bibtex 320K / plugin-ris 280K / date 28K / name 36K / moo / sync-fetch 64K） |
| M8 | 浏览器可用性 | ⏳ **未测完**。`lib-mjs/` 内 `grep` 不到 `node:` 内置依赖；但 `sync-fetch-undici` 被 core 主入口**静态** re-export（`index.js` → `util/index.js` → `fetchFile.js`）→ **必须在真实打包器里验一次**（骨架 `upstream.js` TODO-A-1 已写成阻塞项） |

**三条由实测直接得出的设计约束**（已写进骨架）：

1. **插件是副作用导入**（`import '@citation-js/plugin-ris'`）。少一行**代码照样编译**，
   用户粘 RIS 时才抛错 → 必须在 `loadUpstream()` 里三行写齐，并加一条测试钉住。
2. **格式靠内容嗅探**，所以「粘错格式」与「粘了一段散文」是**同一个**错误信号
   → UI 文案只能是「没认出这段文本的格式」，不能写「BibTeX 解析失败」（后者会误导用户）。
3. **不从上游可解析性推断可用性**：M4 证明中文能解析，但 M8 未完成 → README 把 M8 列为
   「评审前必做」，**没有**写成「已验证可在浏览器使用」。
