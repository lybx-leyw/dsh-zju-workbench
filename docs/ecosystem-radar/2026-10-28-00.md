## 1 · 实质产出：轮换器的时区缺陷（**已修，非推断**）

### 缺陷

`writeState()` 在不传 `--at` 时用 `new Date().toISOString().slice(0,16)` 取「现在」，
写进 `last_run_at` 的是 **UTC 时刻**；而 `pickGroup()` 把它的日期当**上海日**
与「今天」比较。两者在 UTC+8 的 **00:00–08:00** 恰好差一天：

```
上海 2026-10-28 00:30 跑完 B
  → 写入 last_run_at = "2026-10-27 16:30"
下一轮 03:00：今天 = 2026-10-28（新的一天）
  → last_run_at 的日期 = 2026-10-27  →  判「跨天」→ 按公式重取组
  → 当日去重被完全绕过
```

**这个窗口正好覆盖本任务凌晨的三个场次（00:00 / 03:00 / 06:00）。**
换句话说：只要哪天 00:00 场次成功提交，03:00 场次就必然「以为换天了」。

### 修法

1. 新增 `nowStamp()`：按**固定 +08:00** 取「现在」（不引 `Intl`，避开 ICU 依赖，
   也不受宿主 `TZ` 影响）。`writeState` 的默认值改为 `nowStamp()`。
2. CLI 的「今天」也改成上海日（原来 `new Date()` 是 UTC 日）。
3. 新增脏数据防护：`last_run_at` 的日期 **晚于**今天 → 按「状态不可用」回落公式
   （`formula(future-state)`），不拿一个不可能的日期当去重基准。

### 第二个缺陷：修完之后，写回状态时又踩了一次（**本轮实跑发生，已修**）

第 1 条修完、跑 `--commit B` 时发现：`last_group` 改成了 `B`，但
`last_run_at` 还停在 `2026-10-27 22:35`、`group_runs` 也没跟着 +1 —— **状态自相矛盾**。

根因：`writeState()` 用 `text.replace(REGEX, ...)` **全文**替换（无 `m` 标志）。
状态文件顶部有一张**说明表**，其中一行是：

```
| `last_run_at` | `最近一次跑的时间（YYYY-MM-DD HH:MM，UTC+8）` | … |
```

而本轮 `--at` 恰好是 `2026-10-28 00:05` —— 只要说明行里出现过**一个反引号包裹的真实时刻**，
正则就会先在说明行命中，把取值写进说明，真正的取值行**原封不动**。
（讽刺的是：手写状态文件的人为了举例，写的正是这种形状。）

修法：**以 `## 状态` 一节为边界**，只在该节内做替换；没有该节时退回「取值形状的行」。
并补一条测试钉死（说明表里故意放一个与 `--at` 相同的时刻）。

> 这与 r85 / r86 记的是**同一个坑的两侧**：那两次是**读**侧把说明表读成取值，
> 这次是**写**侧把取值写进说明表。结论：读写都必须以「同一节」为边界，不能靠正则运气。

### 验证（TDD：先写测试看它红，再改）

| # | 测试 | 覆盖 |
| --- | --- | --- |
| 1 | `nowStamp` 按 +08:00 取值，含跨年边界 | 主逻辑 |
| 2 | 同一 UTC 时刻在 `TZ=UTC/New_York/Shanghai/Kiritimati` 下结果相同 | **不随宿主漂移**（阴性对照） |
| 3 | 上海 00:30 写 B → 同日 03:00 必须识别 B 已跑过 | **缺陷本体回归** |
| 4 | 不传 `at` 时默认时间戳是上海时刻 | 默认路径 |
| 5 | 子进程 `TZ=UTC` 跑 CLI，「今天」仍是上海日 | CLI 口径 |
| 6 | `last_run_at` 晚于今天 → `formula(future-state)` | 脏数据 |
| 7 | 说明表含同一时刻时，`writeState` 仍只改状态节 | **写侧回归** |

测试合计 **19/19 通过**（原 13 + 本轮 6）。修复前该文件 1 条都跑不起来
（`nowStamp` 不存在）—— 这是**先红后绿**，不是事后补的断言。

> 方法论：这是本仓**第四次**记录「时间口径」缺陷（r69 时区、r70 存储 ISO 无法反推时区、
> r77 `revision` 每次随机）。共同点不是「时区难」，而是**写侧与读侧用了两套默认**。
> 修一处口径不够，要把「写进去的是什么日、读出来的是什么日」在同一个函数里钉死。
