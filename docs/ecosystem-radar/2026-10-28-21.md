## 1 · 本轮轴：本工作台唯一没有的工具来源通道

前几轮 A 组的轴都落在「插件管理 / 插件市场 / 插件依赖图」这一层。本轮换个问法：

> **把本仓 34 个 `dsh-zhiyun-*` 包的工具面列全，缺的是哪一类？**

实测（`grep -rli mcp packages/dsh-zhiyun-*/src`）：

| 命中文件 | 命中内容 |
| --- | --- |
| `source-campus/src/index.js:419,422` | 注释：桌面版 `zju-mcp`（`courses_list_todos.py`） |
| `source-campus/src/webvpn/protocol.js` | 注释：`MCP HTTP 传输` |
| `source-cc98/src/token.js:7,44` | 注释：`cc98-mcp` 也走 OAuth2 密码模式 |
| `source-netproxy/src/egress.js:8` | 注释：`MCP HTTP 传输` |

**8 个命中全部是注释或文档字符串，没有任何一行在实现 MCP 客户端。**
也就是说：本工作台所有的工具都是**自建**的（直连 CC98 / 学在浙大 / 智云课堂 / PTA），
用户**没有任何办法**把外部的 MCP 服务器接进来。这是结构性的缺口。

于是本轮的词面全部围绕这条通道：模板类（看别人怎么挂 bundle）、集合类（`deepseek-harness`）、
以及功能词（`pdf` / `summary` / `tool`），而不是再扫「插件市场」。

## 7 · 方法论（可复用的三条）

1. **「仓库 HEAD 版本」不能当锁版凭据** —— 必须 `npm view <pkg> version` 单独核。
   `dsh-mcp-manager` 的 HEAD 是 `0.14.0`、npm 只有 `0.6.0`；README 描述的 workspace 隔离与
   tool broker **在可锁版本里根本不存在**。若按 README 评审，会接进来一个「以为什么都有」的空壳。
2. **「自包含 bundle」要单独验一次** —— `grep 'from"' lib/index.js` 只用 `node:*` → 零传递依赖，
   锁版才是真的锁住了。这一条决定了「能不能只写一个 `dependencies`」。
3. **「本仓 grep 零命中」既可以证明全新，也可以证明不必要** —— 同一个事实（本仓没有 codegraph）
   支撑了 `codegraph` 判🟡 的一半理由，也支撑了 `mcp-manager` 判🟢 的「补空白」。
   区分二者的是 **学生场景契合**，不是技术质量。
