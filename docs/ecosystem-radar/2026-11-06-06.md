> 结论：本仓「读懂」这条链已经齐了（PDF.js 6.4.299 文本层 + 页码 + 康奈尔旁注 + 划词翻译），

#### 3.1.1 为什么 `PhysicalAI-0/dsh-paperforge` 是 ⛔ 而不是 🟢

它是本轮**最专业**的一件（MIT、原生 DSH、`dsh.bundle.patch` 齐全、两栏阅读布局、六色划词高亮、
框选截图、每篇论文一个专属会话、Markdown 块级编辑）。但判据①**不成立**：

- 它自带**论文库侧栏**（左侧「论文」列表）、**会话面板**（中间）、**笔记栏**（右侧）——
  是一整套**第二个论文工作区**，不是「同一个面板里的更优底层」；
- 本仓已有 `page-paper`（文件树 + 翻译 + 康奈尔旁注 + 助手抽屉 + 会话流），
  挂上去等于**两个论文页面并存**，违反「不得简单集成重复功能」；
- 反过来，把它当「锁版挂载」也不成立：它 `main: lib/index.js` **未发 npm**（`npm view dsh-paperforge` → 404），
  只能 `github:` 装 → **锁不住版**，且 `lib/client.js` 是 93 KB 单文件 bundle，无法按面板裁切。

**值得拿走的是实现口径，不是代码。** 但它这一条恰恰是负面的：

> `lib/client.js:409-452` 的 `lineRects()` 把选区按行合并后，只存**页内归一化矩形**
> `x0,y0,x1,y1`（0–1，四位小数），`referenceBox()` 取的是**已应用缩放**的 surface。
> 归一化除以的是 `page.width/height`（缩放后的盒），所以缩放**线性**时能对齐；
> 但 `getClientRects()` 是 subpixel 取整，在 1.5×/2× 下逐行累积误差，**长文档来回缩放会漂**。
> 它**没有存字符区间**，所以既不能「重锚定」，也不能对文本层重新可用性做降级判断。

**这正是本仓要避开的坑** —— 见 §3.3。

### 3.3 结论：本轮为什么只出一个 B 类骨架

三条判据逐一过：

| 判据 | 结论 |
| --- | --- |
| ① 仍是同一个面板 | ✅ 落点是 `page-paper` 既有阅读器 iframe（`ReaderFrame.jsx`），复用同一个 `.textLayer` 选区，不新增导航、不新增页面 |
| ② 功能相似且正交 | ✅ 现有 = 康奈尔**页级旁注**（记「这一页我想说什么」）；新增 = **行内标记**（记「这一句」）。同一份 PDF、同一个面板，两种不同粒度的留痕 |
| ③ 底层多调了更优质实现 | ⚠ **半成立** — 见下 |

**判据③的诚实陈述**：开源界没有一个「能挂在本仓上游阅读器外层」的高亮库。
两个有实力的（`agentcooper/react-pdf-highlighter`、`inklayer-react`）都**自带 viewer**
（各自锁 `pdfjs-dist 4.4.168` / `~4.3.136`，而本仓锁 **`6.4.299`** —— 装上去等于在同一页跑两份 PDF.js，
文本层坐标会打架）。所以本轮**不是「接入一个库」**，而是**「从两个上游的算法里取口径，写 150 行」**：
`agentcooper` 的 range→rect 序列化 + `dsh-paperforge` 的行合并，补上它们都缺的两件事：

1. **字符区间**（`pageNo` + 文本层 `charIndex` 起止）：缩放无关，可重锚定；
2. **重锚定失败要显式降级**（找不到 → 标「已失效」而不是静默画到错位置）。

→ 因此骨架按 **B 类**建（无上游 DSH 依赖），README 首屏写明判据③**半成立**及作废条件。

## 6. 建议下一步

1. **评审 `dsh-radar-pdf-anchor`** 时，第一件事不是看代码，而是**量两个数**：
   - 本仓用户真实场景里，读论文是**1× 固定缩放**还是**来回缩放**？若是前者，字符区间那层可以砍掉，只剩 rect 就够；
   - 划词翻译弹层与「高亮」按钮**抢同一个 `mouseup`**（都在 `.textLayer` 上）—— 现有 `dwellRef` 有停顿判定，
   新增的按钮必须在**不破坏「选中→悬停即翻译」**的前提下插入，否则等于改坏既有功能。

2. **B 组词面校准（第三次同结论）**：
   - `zju pdf reader` → **`total = 0`**（第 3 次记录：B 组「zju + 通用功能名」已见底）；
   - `pdf text highlight selection language:typescript` → **`total = 0`**（词太窄）；
   - 有效的是**「库名/数据结构名」**：`pdf annotation highlight language:javascript`(58) 与
     `pdf highlighter react`(215) 一击命中领域头部；`pdfjs annotation highlight`(13) 全部小而正。
   - `dsh plugin annotate`(29) 里 **9/10 是「会话/元素批注」**，**零个**落在 PDF 阅读器上
     ⇒ DSH 生态的「批注」= 会话批注，论文行内标记在这一格**是空的**（结构性结论，同 r134 的编辑器一格）。

3. **`PhysicalAI-0/dsh-paperforge` 值得单独读一遍 `AGENTS.md`** —— 作者写了「DSH 插件的硬约束、关键 API、踩过的坑」，
