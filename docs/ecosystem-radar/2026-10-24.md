## 1. 本轮跑了什么

### 1.1 为什么不再跑 A 组主词

A 组主词（`deepseek-harness plugin` / `cordis plugin` / `dsh plugin`）在 r43 就已宣告
「前 60 条只剩 1 个新面孔」，r45 起改为 `dsh plugin <学生词>` 起步，此后 A 组累计跑了 **30 轮**。
本轮不再跑主词，改为**先读码找断环、再定向搜** —— 这是 r53–r57 连续五轮验证有效的起点。

### 1.2 断环：插件页只答「谁依赖谁」，不答「这包从哪来、能做什么」

读 `packages/dsh-zhiyun-page-plugins`（885 行）：

```bash
# 这个页面行里到底有什么字段
grep -n "short:\|entryId\|readOnlyReason\|phase\|deps:\|dependents:\|waiting:\|leaf:\|cancellable:" \
  packages/dsh-zhiyun-page-plugins/src/runtime.js
# → 只有身份（name/short）、开关（entryId/enabled/readOnlyReason）、依赖（deps/dependents/
#   waiting）、叶判定（leaf/cancellable）、相位（phase）。**没有** version / license / 上游来源 /
#   这个包会做什么。

# 全仓有没有任何许可证口径
grep -rniE "spdx|license" packages/dsh-zhiyun-*/src
# → 0 条。
```

页面的定位是「**我不用论文，能不能把论文那一整块关掉，而别把解析也弄坏**」。这个定位本身站得住，
但它只回答了**结构**那一半。学生真正会问的第二句是：

> 「我把它关掉/打开，**它读了我的什么、往外发什么**？」以及「这个包**是谁的、什么许可**？」

这两个问题在仓库里**一个字段都没有**。而本仓恰恰是**锁版引入第三方上游**的形态
（`dsh-zhiyun-host-paper` 锁 `@ggboy123/dsh-paper-reader@1.3.1`），`ATTRIBUTION.md` 靠**人手维护**。
「哪个包带了上游、上游是什么许可」目前只能靠人记。

断环的形状与前五轮**同型（第六次）**：数据在磁盘上（每个包的 `package.json` 与源码都在
`node_modules` 里）、出口存在（插件页每一行就是那个位置），**中间缺一个「把包的身份与能力读出来」的转换器**。

而「扫包 → 出能力清单 + 证据 + 声明对账」恰好是**该用底座、不该自己写**的能力 —— 于是本轮只找「插件台账底座」。
