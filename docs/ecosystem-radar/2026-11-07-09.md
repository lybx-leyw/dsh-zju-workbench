## 3. 重点核查（每个 🟢 候选都按三条判据逐条证伪）

### 3.1 `Lucent-Snow/classroom-zju-note-extension` —— **判据③不成立，封板**

这是本轮唯一的「高相关」命中：**MIT、★2、100 KB、明确面向 `classroom.zju.edu.cn`**，功能是「智云课堂笔记增强」——字幕导出（TXT/SRT/JSON）+ 笔记导出（MD/DOCX/PDF）+ 以字幕为上下文的 AI 问答。形态上正对本仓的课堂域。但三条判据逐条走完：

| 判据 | 结论 | 依据 |
| --- | --- | --- |
| ① 仍是同一个面板 | ✅ | 字幕导出天然属于播放器/课堂面板 |
| ② 功能仍相似正交 | ✅ | 导出与字幕轨、AI 问答不冲突 |
| ③ **底层多调了更优质实现** | ❌ **反了** | 见下 |

**③ 为什么反了** —— 两条链路的数据起点根本不同：

```
上游（浏览器扩展）：
  document.querySelectorAll('.trans-item')  →  从课表 DOM 抠文本
  start = 页面上显示的 "HH:MM:SS"
  end   = start + 5 秒（写死，src/content/modules/subtitle/index.ts ~L290）
  ms    = 恒为 000（formatSRTTime 里 `const ms = 0`）

本仓：
  yjapi.cmc.zju.edu.cn /courseapi/v3/web-socket/search-trans-result  →  官方 API
  items[].startMs / items[].endMs  →  每条都有真实区间（source.js:225-227）
  toSrt(cues) 直接用 cue.startMs/endMs 格式化（core-classroom-export/src/video.js:76）
  另有 usableCues() 过滤空文本与 end<=start 的坏区间
```

本仓已有 **可用的** `toSrt` / `toVtt`（含 `normalizeText`、时间戳钳位、VTT 支持），上游的 SRT 生成器**在所有维度上都更弱**：秒级精度、结尾靠 `+5s` 猜、无 VTT、无坏区间过滤。把它接进来只会让输出变差。

**其余两个模块也不构成缺口**：
- 「AI 以字幕为上下文问答」——本仓 `source.js` 的 `getTranscript()` 已提供**分段 + 分页 + 时间戳聚合旋钮**（`timestampEverySec`），注释里明确讨论了「时间轴要每条带 `startMs`，逐字稿要可读段落」这两种用法的取舍，比上游「加载全部字幕 / 当前时段字幕」两档细得多。
- 「笔记导出 MD/DOCX/PDF」——本仓 `dsh-zhiyun-*` 侧已有导出链路，且上游导出的是**智云网页自带的 wangEditor 富文本**，本仓根本没有那个编辑器。

**唯一剩下的东西是 DOM 选择器表**（`.trans-item` / `.trans-lan` / `.item-time` / `.item-title` / `.item-origin span` / `.item-tanslate-En span`，兼容新旧两版页面，注意上游把 `translate` 拼成了 `tanslate` —— 那是站点本身的拼写错误，选择器必须照抄才对得上）。本仓全库 `grep 'trans-item\|trans-lan\|item-tanslate'` = **0 命中**，因为本仓**从不解析智云 DOM**，走的是 API + 七牛鉴权（`source.js` / `transport.js` / `stream.js`）。**选择器对 API 路线无用。**

> **封板结论**：这一类「浏览器扩展抠智云页面」的候选，在本仓 API 路线下**结构上无法成为更优底层**。后续再遇到同类（油猴脚本 / 扩展 / 页面注入），**默认 🔵，不必再逐行读源码**。已写入 registry。

## 4. 三条结构性结论

1. **「B 组主词」与「时间切面」是两个完全不同的池子。** 主词 `zju`（不限语言）返回的是**课程资料库、个人主页、实验室官网**（`zju-pil-lab.github.io`、`ZJU-ECED-DATA.github.io`、`ZJUSCT/mirror-front`、`tzhangZJU.github.io`…），**没有一个是工具**。而 `language:` + `pushed:` + `sort=updated` 的切面返回的全是可运行的软件。**B 组从此固定用切面**，与 r133 对 A 组、r143 对 C 组的处置对齐。

2. **浙大生态的 TS/JS 供给正在「横切面饱和」。** 本轮 234 个仓库（Q1+Q2）里，与「工作台能用的工具」相关的**只剩 10 个**，且 7 个拿不到许可证。这与 A 组（r142）、C 组（r143）的结论**三方同构**：**瓶颈已不在「找不到」，而在「找到了都是重复」**。
   - 本仓 radar 包 **120 个**，覆盖课表 6 / CC98 5 / 笔记 5 / 排程 3 / 训练 4 / 测验 3 …
   - 本轮 10 个新面孔 → **0 个通过判据③**。

3. **判据③（底层明显更优）在本仓已近乎「结构性关闭」。** r143 的 `nus-vacansee`（周次轴）能通过，是因为本仓**课表条目确实没有周次**——那是**真空**。一旦某维度已有实现（字幕 → `toSrt`，训练 → `fsrs-scheduler`，搜索 → `search-rank`），新候选就只剩「平行实现」一条路，而平行实现按定义过不了③。**建议：后续轮次把判据③的举证成本前置到搜索阶段** —— 先用 `grep` 确认本仓该维度**是否真的空白**，再决定要不要读上游源码。本轮如果先做这一步，`classroom-zju-note-extension` 可以省掉 4 次源码请求。
