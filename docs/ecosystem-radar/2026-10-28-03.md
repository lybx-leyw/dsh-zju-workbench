## 1 · 审计发现（先于候选，因为它决定候选是否有意义）

### 1.1 本仓的「复习队列」没有时间维度 —— **实证**

`dsh-zhiyun-core-quiz/src/store.js:501`：

```js
get reviewQueue() { return items.filter((q) => q.status === QUIZ_STATUSES.accepted); },
```

`accepted` 是题库的**采纳状态**，不是「到期」。队列即「所有采纳过的题，按数组顺序」。
全仓 `grep -n "dueAt\|nextDue\|interval" packages/dsh-zhiyun-core-*/src/*.js` 只命中两处，
都在 `generate.js` 的 `computeBacklog` 里 —— 而那个函数**测试里有、产品里没有调用方**：

```
tests/quiz.test.mjs:1703   ← 测试
tests/quiz.test.mjs:1719   ← 测试
```

`generate.js:1087 computeBacklog` 写得很好（`dueCards` 与 `newCards` **不许合并**、
空队列不许说「你没有问题」），但它是**孤儿函数**。这是本仓「排期层」的完整现状：
**积压计算写好了但没接，队列只有采纳顺序，排期器从未存在。**

### 实测跑出来的四条（写进 README「已核实事实」）

1. `f.next()` 返回 `{ card, log }`，`log` 是**平铺**的（`log.due`），不是 `log.card.due` —— 我第一版就写错了，
   运行时报 `Cannot read properties of undefined`，才查到。
2. `card` 的 `state` 与 `learning_steps` **不可丢**：丢了回灌时「还在学习步里的卡」会被当成稳定态。
3. **`Again` 不是「立即到期」**：它给 `state=3`（重学）+ `due = 作答时刻 + 10min`。
   我第一版拿 `due` 当重放游标，直接导致历史被整段跳过（实测复现）。
4. **三档自评 ↔ 四档 Rating 没有干净映射**。同一序列实测：
   - A（`correct→Good, partial→Hard, incorrect→Again`）→ `0d, 0d, 0d, 0d`：**间隔永不增长**；
   - B（`correct→Easy, partial→Good, incorrect→Again`）→ `8d, 39d, 0d, 5d`：**partial 比 correct 长**。

第 4 条是本轮最该被人看见的：**这不是 bug，是产品设计缺口**。本仓只有三档自评，
FSRS 需要四档；任何"顺手接一下"的映射都会**静默地**把复习间隔搞坏（正是 `store.js:40` 那段注释警告的同一类失败）。

## 5 · 方法层（可复用）

1. **「在册 = 已动工」是幻觉。** registry 写「已出骨架」的条目，要区分三种：骨架可执行 / 骨架是占位 /
   骨架已被推翻。`ts-fsrs` 属于第二种，挂了 14 天。→ 建议下一轮起，骨架验收加一条
   「`node -e "import('./src/index.js')"` 能过」。
2. **缩写被污染要换词，不要加限定符。** `fsrs` 在 `sort=stars` 下被 `FSR` 显卡域吃掉前 10 名；
   加 `language:` 只会让它变成 0。正解是换更长的表达（`spaced repetition scheduler`）。
3. **「没接线」比「没实现」更常见。** 本轮两处都是：`computeBacklog` 实现了但零调用；
   `fsrsRating` 实现了但零消费。审计时优先 `grep` 调用方，而不是读实现。
