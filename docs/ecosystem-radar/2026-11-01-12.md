### 1. `suanmingxing/dsh-ai-mistake-book` — 🟢 **A 类 · 全新** ← 本轮骨架

| 项 | 值 |
| --- | --- |
| 类型 | **A 原生 DSH 插件**（`dsh.bundle.patch` → `./cordis.patch.yml`，patch id `ai-mistake-book`） |
| 许可证 | **MIT**（实读 `LICENSE` 首行 `MIT License / Copyright (c) 2026 suanmingxing`；`package.json.license: MIT`）✅ |
| 语言 / 规模 | JavaScript，95 文件，1.15 MB，★1，`0.3.2`，建仓 2026-10-17，当日活跃 |
| 学生场景 | **强**：扫描试卷 / 手写笔记 → 可复习的错题卡片与电子笔记 |

**做什么**：投喂 PDF/图片 → 400 dpi 光栅化 → 模型读卷面 → 按你报的题号逐题提取
（题干、作答、划改、页边演算、知识点、**错因**、难度）→ 你确认后归档进
`library/<学科>/<卷子>/cards/*.md` → 自动重建 `index.md`（学科 → 一级 → 二级知识点）。
另有 `/note` 手写笔记转录、笔迹**颜色筛选**（只整理指定颜色笔迹）、
**OMML 原生公式**导出 PDF、回收站、会话可追溯。

**与现有功能的关系：全新**（不是重复，也不是强化）

本仓确实有「错题归因」，但**来源完全不同** —— 实测：

```text
packages/dsh-zhiyun-core-quiz/src/store.js:266  /** 一条**错题归因**（归因到知识点，而不是只记「错了几道」） */
packages/dsh-zhiyun-core-quiz/src/store.js:21   attempts | 作答记录 | 错题归因与薄弱点统计的唯一依据
```

> 那句 `attempts` 的注释说明得很清楚：归因的**唯一依据是「已经发生过的事」**
> —— 即**系统自己出的题**里你答错的那些。

而**卷面上的错**（老师发的纸质卷、拍照片、PDF 扫描件）**一条都进不来**：
`grep -rl "ocr\|OCR" packages/*/src` 命中 3 个包，全是 bilibili/课堂摘要里的**视频/字幕**
相关（`triage.js`、`playurl.js`、`state-context.js`），**没有任何卷面/图片 OCR 通路**。

所以这是**新入口**，不是「同一面板换个底层」——
按本 skill 对「强化式集成」三判据的严格要求，**不能包装成强化**，如实记为**全新**。

**与已登记 OCR 簇的关系（防重复）**：registry 里 `picturereader` / `dsh-ocr-plugin` /
`dsh-tool-ocr` 三条是**纯 OCR 视觉簇**（🔵 线索），做的是「图片 → 文本」这一层。
本条的价值**不在 OCR**，而在 OCR **之后**的整条链：题号切分 → 逐题结构化 →
知识点索引 → 归档可复习 → 带公式的打印版导出。两者**正交**，不构成重复登记。

**风险（评审必看）**

1. **图片输入硬依赖**：分析模型必须支持视觉，插件启动即校验（不支持直接报错，不静默失败）——这点设计得对；
2. `engines.dsh >= 0.2.1-rc.2`，与本仓 peer 基线需对齐；
3. `node_modules/` **随仓库提交**（`VENDOR.md` 自述：为支持 `link:` 安装）——
   **判据：不得整包 vendor 其 `node_modules/`**，只声明 `dependencies` 走正常解析即可；
4. npm 无发布，只能按 GitHub tag 锁（同 `dsh-radar-job-hunting` 的处理）；
5. 归档根目录用户可选，**需在评审时明确不落到 profile 内**。
