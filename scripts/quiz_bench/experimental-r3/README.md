# r3：从图谱编译出题想法

独立实验候选 `v2-r3-iteration4`，考法树协议仍为 `tree-ideas-r3-v9-node-capacity`，共享讲解资产协议为 `r3-teaching-capsule-v3`。以 `root.children` 为主结构保存正文、页详情、节点考法和原子树。没有接入 App，没有修改产品设置或 r1、r2 冻结实现。

## 数据流

```text
已有知识图谱树 + 讲义定稿正文
  → 叶节点局部想法（并发）
  → 父节点跨子分支想法（自下而上，同层可并发）
  → 原树逐节点持久化考法、证据、具体变体
  → 原子预留 idea × type × variant 槽位
  → 每 worker 一题，实例化与单题复核
  → 题目写回所属节点 / 保留原任务继续整改
```

不重新划分段落或重建语义树。`graphFromRecord` 将原始重建树中的 `semanticTopic` 与定稿知识点按来源块绑定，保留标题层级。缺失、重用或歧义绑定直接报错，不退回转录原文。只有 points 数据时，`graphFromDataset` 保留显式课程、节次、章节元信息；这条兼容实验输入不能代替真实重建树，课程集合不自动生成跨课程关系。

每个资产节点具有 `nodeId / text / pages / ideas / children`。`ideas` 仅包含当前节点自己的考法，子节点资产留在 `children`。不建立全局 ideas、assets 或 sources 列表，父层不累计所有后代考法。

叶节点资产包含考查目标、作答操作、固定条件、认知策略与推荐题型、逐字引文、绑定引文的答案要点、具体变体。父节点直接读取完整的嵌套子树：既能看到各子节点考法，也能看到完整讲义正文及相关页的文本、画面描述。父节点可以引用子节点考法从未选用的细节，补充真正需要至少两个直接子分支的关系任务。单子节点标题保留原子树，不复制后代考法。允许节点没有可靠局部考法，其正文与页面仍可支持上级推理。

来源使用相对树路径：当前节点 `[]`、第一子节点 `[0]`、其第二子节点 `[0,1]`。再用 `part` 选择该节点原有正文或页字段的片段编号，模型不用回传内部 ID，也不重写原句或公式。程序按路径、source、page、field、part 取回原文并绑定归属；编号越界会得到明确工具错误。编号只定位已有行/段落，不新建知识点、不截断正文。模型视图保留全部非空片段、顺序、页码和原树，最终资产仍保存完整原始字符串。修复回执包含实际工具参数与具体错误。

图谱桥接保留相关页面的 `pageText / pageVisual`，只附入该节点来源块关联的页。讲义结构化 blocks 是定稿正文，topic 顶层镜像 text 不再与 blocks 重复串接。没有文字页详情时不伪造图片内容。

沿用四策略标识 `recall / understand / apply / explore`，支持选择、填空、判断、简答。策略表示考查目标，题型表示呈现形式，由节点考法说明可用形式；不继承旧调度器的策略与题型绑定白名单，也不强制每个节点凑齐所有策略。

## 入口与组织

| 文件 | 职责 |
| --- | --- |
| `graph.mjs` | 已有图谱与定稿桥接、树约束检查 |
| `tree.mjs` | 相对路径、嵌套推理视图、引文归属、任务子树 |
| `tools.mjs` | 注册工具定义、参数校验、原生工具调用与错误回执 |
| `compiler.mjs` | 依赖调度、资产编译、证据结构校验、增量缓存 |
| `scheduler.mjs` | 幂等计划、槽位持久化、分配与状态事务 |
| `generator.mjs` | 并发单题实例化、复核、原任务整改与续跑 |
| `index.mjs` | 公共实验接口与独立文件状态存储 |
| `run.mjs` | 可调用的完整链路与真实模型 CLI |
| `common.mjs` | 限流、串行提交、解析与哈希工具 |
| `compare.mjs` | 同素材的 r1 / 原生 DeepTutor / r3 冷启动与带历史续批对照 |

`compileIdeas` 可在讲义润色完成后调用并独立保存考法树；当前只暴露接口，没有安装产品钩子。父节点等待子节点编译完成，同层独立子树可并发；只有实际模型请求占用 worker。`createScheduler` 沿选中子树递归取任务，支持局部/跨节点范围、策略、题型。选中标题表示选中其子树，不要求调用者先展开知识点列表。`createQuestionGenerator` 按任务树路径读取所属节点与考法，在同一实例内共享并发上限。`runR3` 封装独立状态目录里的完整过程，`compileOnly` 只预编译，`resumeId` 恢复原计划。

```js
import {graphFromRecord} from './index.mjs';
import {runR3} from './run.mjs';

const graph = graphFromRecord(parsedRecord, finalLecture);
await runR3({graph, directory: experimentDirectory, call, compileOnly: true});
const result = await runR3({
  graph, directory: experimentDirectory, call,
  count: 6, types: ['mcq', 'shortAnswer'], concurrency: 2,
  requestId: 'trial-1', onProgress: console.log,
});
// call(request) 必须支持 request.tools、toolChoice、toolFeedback；
// 返回供应商原生 toolCalls:[{id,name,arguments}]，不从正文解析伪调用。
```

CLI 使用 `.env` 的 `BaseURL / APIkey / ModelName`，会发送输入讲义给配置的供应商并产生费用。只在用户授权后运行，输出放入被忽略的 `artifacts/`：

```sh
node scripts/quiz_bench/experimental-r3/run.mjs <讲义工作目录> artifacts/quiz-r3 compile
node scripts/quiz_bench/experimental-r3/run.mjs <讲义工作目录> artifacts/quiz-r3 generate 6
node scripts/quiz_bench/experimental-r3/run.mjs <讲义工作目录> artifacts/quiz-r3 resume <计划ID>
```

CLI 默认 2 workers、最多 120 次调用、整轮 10 分钟。程序接口可传入受控的供应商 worker 池；编译依赖和单题复核仍按正确顺序执行。进度事件包括叶/父资产编译、资产就绪、单题实例化、单题校验、题目就绪。CLI 用输出目录锁防止两个进程同时写；嵌入接口由调用者保证同一状态目录只有一个写入者。异常退出遗留锁时须确认没有活跃进程再清理。

## 原生工具协议

节点考法逐条调用 `submit_idea`，最后调用一次 `finish_node`；可以一轮返回多个调用，也可以分多轮提交。服务器保存已接受考法，逐调用返回成功或错误，不因另一条失败而清空已成功的提交。finish 成功后父节点才开始；每次恢复最多16轮工具交互，连续无效提交按两次整改预算停止并保留检查点。题目与复核分别调用 `submit_question`、`submit_review`。节点完成备注可省略，正文和来源校验不依赖覆盖自述。`createToolTransport` 发送供应商原生 tools / tool_choice，收集 tool-call-delta。程序校验工具名、供应商 call ID、参数 schema，再校验来源与任务语义。回执使用原 assistant.tool_calls 与匹配 call ID 的 tool 消息，缓存保留参数、调用 ID、已接受考法和交互历史。

不设置供应商 `response_format`，不接受正文里的伪造工具调用。更换调用适配器时须保持原生工具消息链路；不支持工具时明确报错，不静默降级成文本 JSON。

本次迭代为每条考法保存学生需要推出的 `target`，标题考法逐分支保存 `relation.needs`，并将未知结论绑定到该分支引文。生成与复核检查必答题干原句和是否泄漏结论。实例化 worker 只接收已选考法与完整材料子树，移除未选考法的重复上下文；标题编译仍读取全文、页详情与各子节点考法。

另有 `submit_audit` 独立质疑工具：不传预设 answer 字段或原考法，核对解析中的不当推断，并检查标题题是否只是拼接子问。它仍是模型检查，解释文字可能暗示答案，因此不称为完全盲评；最终质量继续逐题人工判断。质疑失败保留原任务返工，不用删题掩盖问题。

## 缓存、挂账与整改

- 工具 schema、编译指令、节点内容、页详情与子资产哈希决定缓存键；改动叶节点只重编该节点和祖先，兄弟资产可复用。编译契约修改时自动失效，缓存响应仍须再次校验。
- 先持久化全部槽位，再开单题请求；相同 requestId 与参数返回原计划。优先覆盖基础想法，再使用显式变体。推荐题型不作为任务白名单，实际呈现形式仍须保持认知任务并通过复核。按节点配额分配发现容量不足时，可由 `reserveWithExpansion` 在原节点补充实质变体并持久化账本后重试；没有可靠扩展仍报不足，不改编号凑数。无配额的选择不足尚不自动补充。
- 未改动分支的想法槽位不会因为其他分支编辑而重新开放。旧计划绑定其资产版本，不跨版本续跑。
- 每题上下文是所属节点的原子树。叶题不读取兄弟节点，标题题能够读取自身各分支的讲义与页详情。完成题按 `nodePath` 写回结果树对应节点，来源与考法身份不由模型分配。
- 每个模型响应、题目草稿、复核结果均检查点保存；中断可恢复到相应阶段，完成计划再次恢复不发模型请求。工具参数错误在原工具阶段最多修复三轮，使用对应调用 ID 的错误回执，不因 review/audit 的格式错误重写题目；预算耗尽保留题稿待恢复。传输失败中止当前计划而非当作语义返工。磁盘写入失败停止工作，不以模型重试掩盖故障。
- 来源由程序绑定，模型可省略引用索引；单题复核仍检查方案、变体、全部必要来源、答案和解析，选择题逐项独立判真。失败保留原任务、理由和旧草稿继续整改；每次恢复最多三轮，仍失败返回 partial 与待处理任务，不静默减少数量。
- `requestRepair(planId,ticketId,reason)` 允许人工审题后归档旧稿并返工原任务：保留 slot 与题目 ID、清理旧稿准入指纹、写回同一节点。跨节点复核要求每个分支实际参与必答得分点，单纯引用、背景或可选加分不算依赖。
- 不设批后全局语义查重。保留轻量完全相同输出指纹守卫（选择项换序也会命中）；命中仍回到原任务整改，而非删题。

独立 `r3-state.json` 保存编译缓存、资产库与任务账本；CLI 的 `calls-*.json` 保留请求、回执及失败事件，`result-*.json` 记录成功或失败、token 与并发耗时。真实讲义、历史题及请求记录仅留在忽略目录中。输入/输出 token、总量、缓存命中均按供应商回执计数；缺失用量明确未知。等待时间用实际墙钟，不除以 worker 数；另记服务时间、请求并发峰值和利用率。

## 验证边界

机制测试覆盖树结构与父层正文/页详情可见性、子考法未用证据的引用、跨分支约束、选中子树、兄弟上下文隔离、并发分配、节点写回、缓存与页详情增量失效、原生工具与错误回执、引用修复、持久化失败、断点恢复、输出碰撞整改和定稿桥接。测试使用合成材料和模型替身，只验证架构机制。

树的既有正交性使任务可以提前分配，但想法提取的完整性、同节点想法的语义差异、变体价值和模型是否忠实实例化仍需人工评测。结构检查不等同于语义正确性证明；覆盖记录不是自动得到的原子考点金标准。资产复用摊还的是重复探索成本，不代表单题生成与复核不需要推理费用。

真实基准在“Codex 自判定基准集”中与冻结 r1 配对，分别报告首次编译成本、复用出题成本、总 token、真实等待、正确可用数、遗漏、跨考点质量和重复情况。尚无 r3 胜过 r1 的结论。

本轮完成部分三组真实对照，供应商余额不足使剩余阶段中断，不能标为完整验收。共同可比范围每组目标10题，r1 / 原生直调 / r3 分别交付10 / 10 / 8，严格人工确认且去重可用8 / 4 / 7；所有争议项放宽后的敏感性上界均为8。相同范围总 token 为362,681 / 279,165 / 400,376，实际阶段等待102.3 / 95.6 / 153.2秒，r3包含首次树编译。全部31份最终交付题人工逐题审阅，另抽查失败稿；没有把自动复核结果作为最终评分。候选没有晋升。

上述历史版本存在的工具阶段恢复、引用元数据和配额扩展问题已在本轮迭代处理。来源地址协议解决了长引文重抄的技术失败，仍不保证答案逻辑正确；不同槽位仍可能生成语义近重复。私有语料、逐题理由、失败调用与完整消耗仅保存在忽略目录的实验报告中。

`compare.mjs <实验规格.json> <artifacts/新目录>` 支持三组对照。规格声明 source/select、组别、两批题数、workers 和请求上限。正式模式拒绝非空目录，校验候选源码摘要并在整轮前后核对内核；给 r1 与直调桥接与 r3 等量的正文和页详情。续批保留题目历史，r1 复用考点缓存、r3 复用原树考法，直调复用磁盘资源与 home 但由原 bench facade 重启 Python 服务。记录实际外层等待（含清理）、引擎等待、真实并发与缺失 usage，失败调用不漏账。跨节点侧测单独列示，不与局部主对照混分。

当前原生工具端到端验收已实际完成：2 个叶节点与其标题编译出考法，生成2道局部选择题及1道标题简答题；人工指出标题题的装饰性跨节点引用后，原任务可以归档、复用考法树并返工。局部题人工确认可用，返工后的标题题仍有提示过多、跨节点推理偏弱的问题，不能据此认定跨考点质量达标或优于 r1。失败预跑、原稿和用量均保留在本地忽略的实验产物中。


## 本轮续跑与迭代结论

上轮余额中断的阶段已按原 v6 源码续完，原题与失败回执保留。三个原素材各请求6题，r1/原生直调/v6分别交付18/18/15，严格人工确认且去重可用15/11/12；争议项全部放宽的上界15/16/15。v7因标题失败传播与推荐题型筛选交付不足，未晋升。v8完成原三素材18题回归，严格可用11、放宽16，主试616,569 token、实际阶段等待256.6秒，含首次编译；不是准确性改善的证据。

新素材中 v8 因节点第13条考法触发旧12条上限而失败；v9将一致的节点保护边界改为64条并升级编译契约，只重跑 r3。生成/复核代码与v8完全相同，但不把v8三素材回归标成v9的完整复跑。新素材三组各6题，r1/直调/v9严格可用4/2/4，放宽5/3/6；v9主试154,792 token、107.2秒，另付v8失败编译33,272 token与34.1秒。所有成本、失败版本与跨节点侧测均另存完整账本，没有按workers再次折算墙钟。当前候选没有超过r1的稳定证据，未接入产品。

`compileIdeas` 默认仍严格失败；实验调用可显式用 `allowPartialTitles:true`，保留已完成子树与标题上已验证考法，将标题标注 `pendingReason`、统计 `partialTitles`，保留未完成工具历史。`runR3` 与比较器开启该选项并返回 `compiled-partial`，不宣称覆盖完成。后续标题修复造成资产内容变化时，树输出内容摘要也会改变，旧计划不能跨版本恢复。

同节点已完成同型题仅供新的 base 考法正交实例化参考；显式变体遵守指定变更，无需历史正交改题。此机制不能保证同一时刻并发题的语义互异，也不证明模型枚举已覆盖全部原子考点。当前首要质量限制仍是原讲义错误沿用、解释中的不当必要条件/唯一性推断、近重复和跨节点推理偏弱。


## 共享讲解资产与真正独立求解

当前 `runR3` 和三组比较器中的r3默认使用验证资产模式；原始对照可显式设置 `assetMode:'raw'` / 比较规格 `r3AssetMode:'raw'`，实验账本不跨模式冒充完成。产品默认链路未改变。系统归因、资产结构与验证边界见 [ARCHITECTURE.md](ARCHITECTURE.md)。

新增 `capsules.mjs`：按需编译带条件、原文证据、推理链、纠偏和已解例题的共享资产，独立审查后缓存；边界备注和实质问题分级。单题工作线程默认用证据包，可通过 `read_material` 原生工具取所属子树的完整材料。独立求解器看不到作者答案、解析、考法或例题，填空标记中的答案也被遮蔽；最终一致性复核单独进行。所有交互继续使用原生工具，不启用JSON输出模式。

`createCapsuleStore(...).requestRepair(ideaId, reason)` 对共享资产挂整改并保存版本；依赖旧资产的题目在再次执行时返回原任务重核。`await projectTeachingBooks(library, cache)` 不发模型请求，直接得到保留原树的讲解本和例题本结构。未编译和待整改项显式留在目录中，不发布正文；当前只是后续教材功能的数据基础。

`reuse-bench.mjs <规格.json> <artifacts/独立目录> [resume]` 固定同一考法、同一变体做三批复用对照，分别报告首次与后续成本。resume跳过已成功阶段、保留失败记录与缓存；完成的旧控制组可以显式导入并标记继承费用。素材编译、资产审查、题目、原生读取与失败请求全部计账，等待不除以workers。输出允许量只影响实验请求，不修改产品供应商配置。

本轮固定任务对照只有一个素材完成：两组各6题，原始/资产模式严格正确6/5、放宽6/6，保守去重后各3题组。后四题token减少约11.6%，等待更长；首次资产建设成本使本轮总token更高。新素材被余额不足阻断。继续保留r3为资产化实验方向，不声称质量已超越r1。
