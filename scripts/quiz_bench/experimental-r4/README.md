# r4：按需求缓构建考法树与题模

独立实验原型，尚未接入产品。先分配本批知识点和蓝图，再探索所需题模，受约束生成题目并逐题审核。
版本为 `r4-demand-v4`（题模家族身份升到 `r4-family-v3`，题模校验改为一次报全）；旧版检查点不能续跑，请换独立目录。本轮没有升级产品 r3 v9，也没有引入共享讲解资产。

## 缓构建边界

非综合任务只探索分配的叶节点。综合任务先裁剪为已分配知识点的完整材料，再由原树最近公共祖先直接读取正文和页面详情；子节点 `ideas` 为空也可以工作，不等待、不要求它们先编译考法。不读取未选兄弟材料，不自动跨课程综合。

默认蓝图轮转分配知识点，综合题采用相邻知识点对；这是可重复的分配启发式，不是经论证的教学权重。需要精确权重、认知要求或组合时传入显式蓝图。综合与非综合独立于 `recall / understand / apply / explore`，题型也不能代替认知层级。

缓存按材料、知识点子集、题型、策略、属性约束与实例上限隔离。只编译任务所属节点，其余子树保留材料，不把局部考法当作完整父节点资产。容量不足时在当前范围内有界扩展题模；不取消综合题配额，不降低审核标准，不为补数强造题模。扩展前已接受的题模保留，重复目标不允许换 key 重复注册。

## 单题流程与题模身份

```text
蓝图单元 → 局部/综合题模探索 → 预留题模 × 题型 × 参数变体
  → 作者实例化 → 参数/约束/数值答案/干扰项检查
  → 不看作者答案、解析、题模和参数的独立作答
  → 技能、作答证据、题模一致性及综合分支审核
  → 解析与共同推理质疑 → 完成或保留明确返工原因
```

编译器、调度器、生成器及工具协议从本仓冻结 r3 v9 显式分支；r4新增题模和独立作答步骤。图谱、原文绑定、树视图、通用并发等基础函数复用冻结版本；产品版本摘要保持不变。独立作答仍可读选中知识的一般材料，但提示明确禁止借原例题补实例条件。填空先遮蔽内嵌答案；选择、判断、填空的独立答案须与作者一致；数值简答同时计算比对独立答案，语义简答由审核显式返回一致性判定和理由。审核必须拒绝“只背例题临时数字”或“解析补全题设”的任务。

`itemModel` 声明技能属性、前提、不变量、可观察证据规则、解题步骤、改编依据、变量域、基础参数和错误机制。变量角色 `incidental / radical`、设计难度都只是待验证假设。显式变体必须改变参数并仍满足域与联合约束；记录改变了哪些变量以及保留的目标。改变认知操作或成立条件时应另建或重审题模，不能冒充同模换数值。

`numeric` 可为空；适合标量数值答案时使用受限算术数据树，支持 `add / subtract / multiply / divide / power` 及数值联合约束，不执行模型代码。结果必须有限，除零、越界、错误答案、错误选项计算不符均拒收。目前只接受无歧义数字字符串，不支持符号化证明、公式等价或任意求解程序；判断题应使用 `numeric:null`。非数值语义和前提充分性仍依赖模型审核。

`familyId` 使用知识点、目标、操作、技能、解题步骤和答案结构生成，仅改变基础数值不能制造新题模。它是结构身份，不是语义新颖性证明：不同措辞或属性别名仍可能造成重复题模，真实多样性需要人工抽检。同一检查点内跨蓝图单元、题型与后续批次共同计数：练习默认每题模最多2个实例，测验默认1个，可显式配置。已预留失败任务也占位，恢复原任务不会被算成新题。相同参数变体不能换编号再次预留；编译和追加变体均检查参数重复。完全相同输出在同一探索的不同资产版本间也不能重复入账。

报告分别列出题数、题模数、各蓝图单元的可用数/缺口、属性目录、M/Q。Q 的 `model-reviewed-unvalidated` 表示仅通过模型审查；不代表经验验证的诊断矩阵。只报告本批覆盖，`treeComplete:false`，不保证连续生成后穷尽考法树或能导出完整考法本。没有学生作答数据，难度、区分度、掌握度保持空值，不宣称已经实现认知诊断。

## 离线演练与冒烟

```sh
node --test tests/quiz-r4.test.mjs tests/quiz-r4-models.test.mjs
node scripts/quiz_bench/experimental-r4/demo.mjs
node scripts/quiz_bench/experimental-r4/smoke.mjs
```

入口显式使用合成材料与模型替身，不读配置、环境变量或真实凭证，不调用外部模型。`smoke.mjs` 禁用 `fetch`，使用仓库已有原子写入库保存检查点，结果写入被忽略的 `artifacts/quiz-r4-smoke/`；不向产品题库发布题目。

本轮机制验证结果：

- 31项 r4 测试通过，覆盖四种题型、蓝图、范围裁剪、属性和证据、变量域、家族上限及恢复。
- 落盘冒烟：10题 = 8道非综合 + 2道综合，5个结构题模，2次局部容量扩展；45次替身调用。
- 读取落盘检查点后恢复10题，新增调用0次。
- 预算限制为2次时停止；其后另一个批次扩展题模并完成2题，旧批次仍以固定资产恢复，用3次完成剩余审核；写入失败后停止新增调用。
- 缺题设、参数越界、干扰项错误、技能实际非必需、证据不可观察、独立数值简答矛盾六类注入全部拒收。
- 对照演练：两个选中知识点的准备阶段，v9调用3次、r4调用1次；r4包含审核总计5次。

以上只证明机制与故障处理，不证明真实模型的题目质量、通过率、延迟或费用更优。替身会直接返回审查结果，不能替代人工审题与同预算真实模型对照实验。

## 调用接口

```js
import {runR4} from './run.mjs';
const result = await runR4({
  graph, pointIds: ['a', 'b'], count: 10, compositeCount: 2,
  types: ['mcq'], strategies: ['understand'], purpose: 'practice',
  maxPerFamily: 2, maxExpansions: 1, maxCalls: 120,
  requestId: 'batch-1', call, state: previousCheckpoint,
  onCheckpoint: saveCheckpoint,
});
```

`call` 沿用原生工具接口，由调用者负责模型授权。`maxCalls` 是每次调用 `runR4` 的预算，不是整个检查点的累计上限；`maxExpansions` 是每个单元本次允许的容量扩展次数（0–3）。单题最多返工3轮；预算、协议修复或容量耗尽保留断点与原因，返回 `partial` 和蓝图缺口。每个已预留计划保留完整且固定的资产快照；后续扩展不替换旧批次所用题模。相同 `requestId` 和配置恢复原计划；新批次换 `requestId`，复用范围内题模与账本。存储失败直接抛错并停止工作，不能转成模型重试。

显式 `blueprint` 为数组，每项包含 `id / kind / pointIds / type / strategy / count`，可指定 `attributeIds`；总题数及综合题数必须匹配请求。同一范围、题型、策略、属性的重复单元应合并，以免并发抢占同一探索。蓝图是硬配额；当前容量不能满足时如实报告，不能用非综合题顶替综合题。

## 本轮自检修复

- 固定旧批次资产，覆盖“暂停旧批次→新批次扩展→恢复旧批次”的交错顺序。
- 拒绝独立数值简答矛盾；语义审核缺少明确一致性判定或理由时拒收。
- 按有效参数识别实例，拒绝重复参数及换名重复预留。
- 知识点身份重复时提前报错，避免静默选错材料。

检查点格式升为 v3，以免旧账本缺资产快照或仍使用变体编号作为实例身份。此处是 r4 的内部格式版本，不是切换到 r3。
