# Quiz 出题基准台

```powershell
npm run bench:quiz
# 固定端口、不自动打开浏览器
npm run bench:quiz -- --port 8801 --no-browser
```

与 `scripts/knowledge_tree_bench` 同样采用本机页面、真实产品插件装配、完整 JSONL 日志与事后产物查看。调用的是 `dsh-zhiyun-core-quiz.apply()` 提供的 `generatePoints`，不在基准里实现另一套出题器。接口默认值、OpenAI 兼容流式传输和日志写入器与知识树基准共用。

## 资料

- 自动列出 `scripts/knowledge_tree_bench/data/.logs` 中有终稿全文的日志。使用产品的讲义文本 codec 和知识点投影恢复正文；拒绝只有截断讲义事件的日志。
- 支持导入单个产品记录、`{records:[...]}`、v4 讲义 JSON，或同时选择原 bench 工作目录的 `parsed.json` 与 `lecture-final.json`。
- 也可导入 `{id,title,points:[{id,title,text,courseId,subId,blockIndexes}]}`。`text` 必须为完整材料。知识点使用产品的来源归属规则。
- `--sources-dir <目录>` 指定另一份知识树日志目录，`--out-dir <目录>` 指定产物目录。
- 合成教材是显式桩模式，只检验基准流程，不能说明真实模型质量。第一次可先选它试跑。

## 怎么比较

四策略与四题型交叉组成兼容的评测单元，分别测试基础巩固、理解拓展、应用变式、综合探究。不兼容组合不替换成别的题型；如果某策略没有任何兼容题型则报错。

基础巩固目标默认 `recallMode: "complete"`，可切换 `"variant"` 做对照。前者在复用底稿时结合历史补漏，后者只生成已有底稿变体。逐批 `completion` 指标记录已检查知识点、复用检查、新增概念和新增可考位置，与实际出题新增覆盖分开。合成教材刻意在首次提取时漏掉“互斥事件”的陈述，后续补全用于验证确实能追加考点；这些是流程证据，不代表真实模型的提取召回率。

每个策略/题型/题量/独立重复均冷启动；同一单元的连续批次共享概念缓存和完整历史，模拟用户连续生成。不同单元互不共享缓存，避免比较被先跑者污染。支持 1–4 个题量梯度、1–10 个连续批次、1–5 次独立重复，矩阵最多 200 批。建议先从 **每批 10 题 × 3 批 × 1 次重复**开始，再扩大范围。

种子固定知识点分配；每批的实际计划与资料均保存。模型输出与产品的随机挖空抽取仍可能波动，种子不承诺模型结果完全相同。报告保存供应商地址、模型、出题内核版本与源码摘要；配置、内核或资料变化后拒绝混入原评测继续。独立重复的 `trials` 报告平均值和总体标准差，`n` 为有观测值的次数。

逐批记录新增知识点/概念、累计覆盖、底稿内覆盖、题量分布 CV、完全重复、疑似近义重复、新拓展角度、题目家族、来源匹配、模型调用、失败、耗时和供应商返回的 token 数。没有 token 回报时保持未知；部分回报用 `usageReported` 明示，不按估算值假装实测成本。应用变式的近义相似只提示，不直接判失败。

## 真覆盖率与人工复核

当前内核独立执行 `quiz-source-check`（带边界实例推演）和 `quiz-fact-audit`（语义事实归组及逐位置审查）。`factCoverage` 报告已审查事实的总量/已考数量、被隔离位置和来源冲突；`diversity.repeatedFacts` 与文本完全/近义重复分开记录。事实身份由模型归组、程序持久化，不代表独立金标；剔除与归组会改变分母，仍须对照原文人工审核。

真实模型的底稿格式修正与无效位置剔除走产品内核，模型调用阶段包含 `quiz-rewrite-repair` / `quiz-concept-complete-repair`，均纳入预算与日志。原始回包、修正回包及底稿的 `validation.rejected` 可用于人工追溯；不得只按剔除后的底稿分母评价覆盖质量。

**底稿内覆盖以系统已提取概念为分母，不等于真实知识覆盖。** 没有独立金标时，金标覆盖、答案正确性等显示“无法判定”，不会画成通过。模型自带复核结果不是金标。

先独立编写金标，例如：

```json
{"concepts":[
  {"id":"probability-definition","label":"概率的含义","required":true,"weight":2},
  {"id":"probability-range","label":"概率取值范围","required":true,"weight":1}
]}
```

在开始前导入，或跑完后点击“下载人工复核模板”，在模板 `gold` 中补入。模板同时提供概念原文与题目，人工为它们填写 `goldIds` 并设 `reviewed:true`；题目可填写 `correct`、`answerable`、`uniqueAnswer`、`meaningfulBlank`、`leaked`、`novel` 的布尔值。然后导入模板重新计算。未知项保留 `null`，不用强填。`leaked:true` 表示发生答案泄露，其余质量布尔项的 `true` 表示符合要求。

人工映射给出概念提取召回、出题覆盖、加权覆盖与质量指标；未全量复核时只报告已确认的覆盖下界，“未在已复核题中命中”不等于确定遗漏。资料摘要不匹配、无效金标和未知题号会拒绝导入。原始报告保留，复核另存。

## 进度、预算与恢复

产品检查点缓存完整模型回包；bench 另外从已写入的 model 日志恢复相同单元、批次、阶段及完整输入的回包，避免产物已记日志但游标未提交时重复付费。复用事件为 `call-reused`，不增加调用预算；调用账本区分 `preparing` 和 `running`，模型日志含 callId。原子 JSON 使用独立临时文件，重命名遇短暂文件占用时有限重试。无法证明结果的调用仍保留未知状态，文件写入错误码写入失败记录。

模型 Key 只在内存中，从 stdin 或本机页面请求传递，不放入命令参数或磁盘；不会自动读取 App 私人凭据。本机 API 均验证一次性 token，并拒绝跨站请求。产物默认在被忽略的 `artifacts/quiz-bench/`，可能包含私人课堂资料，不应提交。

每次启动默认最多 120 次模型调用，可调 1–1000。达到预算、手动停止或关闭页面时保留 `state.json`；每个阶段和题目写入后立即更新断点。报告中可点击继续，重新填写凭据，沿用资料、分配与缓存。预算是**每次启动**的上限，恢复后的累计调用如实合计。完整完成但有缺额的批次保持缺额，不自动重试到“全绿”；新评测重新冷启动。

报告状态区分 `completed`、`partial`（有缺额）、`interrupted`、`failed`；合成模式另有明显标记。外部联网能力不在本轮控制变量内，基准默认使用课内资料。

## 命令行

```powershell
# 免费、显式合成桩演练
node scripts/quiz_bench/run.mjs --fixture --out artifacts/quiz-bench/demo
# 继续同一份评测
node scripts/quiz_bench/run.mjs --fixture --resume --out artifacts/quiz-bench/demo
```

实际模型评测从 stdin 读 JSON，字段包含 `input`（产品记录 JSON、原 bench 工作目录或 JSONL 日志）、`apiKey`、`baseUrl`、`model`，以及 `counts`、`batches`、`repeats`、`strategies`、`types`、`mode`、`difficulty`、`seed`、`maxCalls`。也可直接传入 `dataset`，或附带独立 `gold`。凭据不要写进配置文件；推荐本机页面输入。

每行事件以 `@@EV@@` 开头。每次产物包括：

| 文件 | 用途 |
|---|---|
| `events.jsonl` | 顺序事件、完整模型输入输出、概念底稿与题目，可回看 |
| `state.json` | 原始分配、历史、概念与逐题断点，供恢复 |
| `report.json` | 全量原始指标、各独立重复统计和题目 |
| `report.md` | 简要比较表 |
| `review.json` / `report-reviewed.*` | 人工复核与重新计算报告，不覆盖原始数据 |

```powershell
npm run test:quiz-bench
node scripts/test-quiz-bench.mjs
```

测试使用合成教材和可编程回包，覆盖装配、预算恢复、日志连续性、指标分母、冷/热缓存隔离、金标导入、凭据擦除及浏览器实际交互，不调用付费模型。

### 考点账本与人工复核闭环

默认 `auditPolicy: "focused"` 先做一次原子考点审查。出现来源疑点，或原文包含递推、最值、条件分支、代入推导等结构时，追加来源推演与忠实性复核；`full` 保留完整审查作为对照。程序从原文提取条件分支，要求逐条引用并核验，遗漏时只修复一次，仍失败则将相关分支标为未验证并隔离。`unchecked` 表示没有执行额外来源推演，不能显示成来源一致性通过。分支提取是有边界的规则，不保证识别所有自然语言条件。

结果中的“原文与考点复核”支持定位原文、查看关联题目和拒收原因，合并同义考点、停用考点/挖空、隔离原文并撤销最近一次修订。`corrections.json` 独立保存修订，原始 report 不覆盖；复核过程中不调用模型。考点账本保留历史身份，重审改写不会让同一位置被当成新的未考点，合并后历史题按规范身份计算覆盖。

可导出某一评测组的可复用底稿，再在新评测中导入；CLI JSON 字段为 `seedArtifact`，与整数随机种子 `seed` 分开。复用包含修订后的账本与历史题，资料摘要和内核摘要必须匹配。每次独立重复均从同一份底稿复制，结果显式记录 `cacheMode: "warm"`、`seedHash` 与历史题，新增题数不包含历史。热启动与默认冷启动应分别比较；修订不会改写原评测的逐批历史快照，暂停评测继续执行仍按原断点，验证修订效果应导入底稿另跑。

人工复核模板仍用于逐题质量判断，未知项保留 null。`humanQuality` 在没有覆盖金标时也记录已复核/明确通过的题目及每道通过题所用调用数；这与独立金标覆盖率分开，不采用模型自评分充当人工结论。

### DeepTutor 原版与集成对照

`node scripts/quiz_bench/deeptutor.mjs <资料.json> <输出目录> [local|upstream-native|integrated-parallel]` 支持既有算法、真正 vendored Python 原版门面、独立题并行集成三路对照，不复制上游提示词模拟结果。凭证从 `DEEPSEEK_API_KEY` 读取；可选 `DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`。默认使用原模型，不自动升级模型。

额外的 `local-guided` 实验组使用既有算法，仅在生成候选题时加入 `deeptutor-general-v1` 通用指引。来源是上游根 SKILL 所调用的真实出题能力提示词，而不是把 CLI 使用说明直接贴给模型。该组不调用 Python/DeepTutor，不增加固定模型阶段，不改现有考点准备、复核和整改。指引身份进入断点和模型缓存键，普通与指引组不能共用断点。独立启用方式是插件配置 `pointGuidance: 'deeptutor-general-v1'` 配合计划 `guidance` 字段；默认不启用。来源映射见 core-quiz 的 ATTRIBUTION.md。

每次启动的结果同时记录 `tokens` 和 `timing`。token 账区分输入、输出、提供方 total、缓存命中/未命中；缓存属于输入的子集，推理属于输出的子集，均不能重复加入 total。缺少 usage 的付费尝试保留 unknown，不能当作零成本。`elapsedMs` 是已经包含并行效果的实测等待时间，不再除以 workers；另由请求开始/结束事件计算累计请求耗时、峰值/平均请求并发、请求槽位利用率与吞吐量。理想服务时间下界忽略阶段依赖，不能冒充用户等待时间。缓存命中量来自供应商，应用冷启动不代表供应商缓存也冷。

原版模式执行一整批上游串行出题；集成模式执行独立题目并行，再走产品的考点准备、答案复核和统一整改；local 只运行既有知识点算法。三路使用同一传输、基础理解型选择题目标，原版提示词要求均匀分配但不修改其内部计划。可从模块调用 `runDeepTutorBench` 指定 `count`、`workers`、`seed`、`maxCalls` 和取消信号；调用上限包含准备、元数据和复核调用。每个 HTTP 请求最多 90 秒，attempts.jsonl 同时保留开始、成功和失败记录。知识点模式在同一目录保存计划和断点，再次启动可复用已完成部分；冷启动重复应另用新目录，换资料或题数也须另用输出目录。

结果目录包含原始模型往返、上游事件、每次运行记录、资源快照、集成断点及结果。它们含课程私有内容，只能留在被忽略的本地 artifacts 目录。验收应人工抽取原文、题目、答案和拒收原因交叉核对；调用数和完成率不能代替题目质量判断，也不能用这次小样本推断整体性能。

### 公开源码的外部评分器

[evaluators/README.md](evaluators/README.md) 提供固定提交的 MIT BenchMarker 原生评分器与完整 prompt 子集，可对本基准已有 `questions.json` 离线准备，再显式指定评审模型运行 19 项选择题编写规则及猜题捷径评测。默认不调用模型，不改变生成内核。保留原始评分及错误回执，解析失败不计为通过；外部量表与人工正确性、去重和覆盖率分别报告。QGEval、SAQUET 因未找到覆盖其自身实现的许可证，本次未复制引入。
