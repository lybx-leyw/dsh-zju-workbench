# 2026-11-04

## 页面壳改为锁版本 npm 依赖 `@lybx-leyw/dsh-pages`

### 做了什么

- 根 `package.json` 的 `dependencies` 里**精确锁定** `@lybx-leyw/dsh-pages`（`0.1.3`，不带 `^`/`~`）。
- profile 模板 `profiles/zju-workbench/package.json` 的 `dsh.profile.bundles` 加入
  `@lybx-leyw/dsh-pages`，并把本仓包装配层写进 `profiles/zju-workbench/cordis.patch.yml`
  的 `- id: dsh-pages`（`homePage` / `managerPage` / `pageSlot` / `classPrefix` / `defaultRailWidth`）。
- 本仓不再保留页面壳的 vendor 副本；`scripts/build.mjs` 的 vendor 探测保留为**显式报错**
  而不是静默不构建。

### 为什么

页面壳是**通用插件**，产品只该决定「怎么装配」。把它 vendor 进来意味着每次上游改动都要
重放补丁，而且会让「本仓产物」与「npm 上那一份」出现两套实现。锁版本 + 装配层配置让
「页面壳是依赖」这件事在 `package.json` 里就能看到，也让 profile 的配置成为唯一真源。

### 验证

```powershell
npm ls @lybx-leyw/dsh-pages --depth=0     # 0.1.3，来源 registry.npmjs.org
node --test tests/pages.test.mjs tests/pages-host-export.test.mjs
node scripts/profile.mjs check
```

真实浏览器（Playwright）启动 3091：导航栏渲染、10 个页面可切换、四边停靠与
「恢复默认尺寸 → 51px」都通过。

### 回滚

把根 `package.json` 的依赖换回上一个版本号、`npm install`，并从 profile 模板
`dsh.profile.bundles` 与 `cordis.patch.yml` 里去掉对应条目。页面壳的 API 只在
`0.1.x` 内演进，回滚到 `0.1.2` 会丢掉「宿主加载入口」的修复（见下一条）。

## `dsh-pages` 的 `./client` 改为条件导出（0.1.2 → 0.1.3）

### 做了什么

```json
"exports": { "./client": { "import": "./lib/client.mjs", "default": "./lib/client.js" } }
```

`lib/client.js` 仍是 `window.__ModuleLoader__.load(...)` 的注册包（DSH 宿主读这个），
`lib/client.mjs` 是普通 ESM（`import { applyWithConfig } from '@lybx-leyw/dsh-pages/client'`）。

### 为什么

0.1.2 把 `./client` 指向了 ESM 产物，而 DSH 的 `dsh-client-modules` 用
`clientExportOf()` 取 `exports["./client"].default` 的**字符串路径**当注册包。
指向 ESM 后宿主拿到一个不做 `__ModuleLoader__.load` 的文件，表现为
`loaded without registering "@lybx-leyw/dsh-pages"` 与 `web boot: 1 entry did not activate`。

条件导出让「宿主加载」和「用户 import」各取所需，两者都不需要额外字段。

### 验证

```powershell
node --test tests/pages-host-export.test.mjs
```

该测试直接调用宿主真实的 `ClientModuleRegistry.prototype.resolveMeta`，断言选中的是
`client.js` 且能注册；再 `import '@lybx-leyw/dsh-pages/client'` 断言拿到 `applyWithConfig`。

### 回滚

`0.1.2` 已发布且不可覆盖，回滚等于回退到「页面壳在宿主里激活不了」的状态，没有意义。

## 课堂两包移除 React 组件的默认导出

### 做了什么

`packages/dsh-zhiyun-core-classroom-stage/src/client.jsx` 与
`packages/dsh-zhiyun-page-classroom-play/src/client.jsx` 删掉 `export default <组件>`，
保留具名 `ClassroomStage` / `ClassroomPlay` 与插件面 `name` / `inject` / `apply`。

### 为什么

Cordis 的 `Loader.unwrapExports` **优先取 `exports.default`**。把 React 组件放在默认导出，
Loader 就会把组件当插件执行 `apply(ctx)`，第一个 hook（`useRef` / `useMemo`）在 React 外调用
直接抛错，整个 profile 报 `dsh-zhiyun-core-classroom-stage: failed`。

### 验证

```powershell
node --test tests/classroom-stage-activation.test.mjs
```

测试用隔离 VM 复现真实的模块表 + 默认导出优先的解包规则，断言两个包的插件面是被
`apply(ctx)` 调用的对象，而不是组件。

### 回滚

重新加回 `export default` 就会复现启动失败，不要回滚。

## profile 恢复全部非雷达插件（53 个 bundle）

### 做了什么

`profiles/zju-workbench/package.json` 的 `dsh.profile.bundles` 从 4 项恢复到 **53 项**：
3 个外部 bundle（`@deepseek-ai/dsh-base`、`@deepseek-ai/dsh-web-app`、`@lybx-leyw/dsh-pages`）
+ 50 个本仓**声明了 `dsh.bundle.patch`** 的包。

新增的 5 项（旧备份里没有）：`@lybx-leyw/dsh-zju-pages-default`、
`dsh-zhiyun-core-classroom-stage`、`dsh-zhiyun-host-openmaic`、
`dsh-zhiyun-page-classroom`、`dsh-zhiyun-page-classroom-play`。

本仓 60 个非雷达包中有 10 个**没有** `dsh.bundle.patch`（构建期内核与未接线的库），
它们不进 profile，但仍通过 profile 的 `node_modules` 链接供其他包 import。
`packages/radar/` 的 79 个 `dsh-radar-*` 目录继续隔离，不进 profile、不参与客户端构建。

### 为什么

「插件包装回来」需要的是 bundle 清单，而不是「把 `packages/` 下所有目录都写进去」——
把没有 patch 的包写进 `bundles` 会让 Loader 解不开那一行，整个 profile 起不来。

### 验证

```powershell
node --test tests/build-seeds.test.mjs    # 27 个客户端包都在 CLIENT_PACKAGES 且 external 面完整
node --test tests/plugins-page.test.mjs   # 接线：有客户端半边的包都进了构建清单、profile 与外壳 NAV
```

真实浏览器启动 3091：无 `Failed to load plugins`，10 个页面均有内容。

### 回滚

删掉新增的 5 项即可回到旧备份的 48 项；其余 45 项来自 `.backup/profile-bundles-20261104-095943/`。

## 归入本仓包的判据从「名称前缀」改为「目录位置」

### 做了什么

新增 `scripts/workspace-packages.mjs`：`ownPackageDirs()` 按目录位置认定本仓包，支持
平铺 `packages/<name>/` 与一层分组 `packages/<group>/<name>/`，只有 `dsh-radar-` 前缀被隔离。
`scripts/profile.mjs`、`scripts/build.mjs` 都改为从这一份推导。

配套：目录链接、`bundles` 清单、客户端构建清单、产物 banner 全部改用 **`manifest.name`**
（npm 包名）而不是目录名 —— `packages/client/pages-default/` 发布名是
`@lybx-leyw/dsh-zju-pages-default`，两者混用会让客户端模块表建不出该行，页面静默空白。

### 为什么

profile 已改名 `zju-workbench`，硬编码 `dsh-zhiyun-` 前缀会让改名变成一次到处补字符串
的重构。判据换成位置之后，加包只需要建目录。

### 验证

```powershell
node --test tests/profile.test.mjs tests/build-seeds.test.mjs tests/publish-guard.test.mjs
```

### 回滚

`workspace-packages.mjs` 是新增文件，回滚需同时改回 `profile.mjs` / `build.mjs` 的调用点，
并恢复按目录名拼路径的写法 —— 注意那会重新引入「目录名 ≠ 包名」的空白页问题。
