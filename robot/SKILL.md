# 反馈机器人

> 这份文件是**给 AI 读的工作说明**，不是需要被某个工具自动发现的 skill 注册项。
> 用它的方式是把路径直接告诉 AI，例如：「按 `robot/SKILL.md` 处理一波反馈」。

智云 Pro 工作台的「反馈」页是一个嵌在工作台里的**迷你社区**（形态照 GitHub issue）：
用户发需求、互相评论，没有任何账号体系。这份说明教你把**维护者的答复**发上去。

工具在 `robot/feedback.py`（Python，标准库）。它 **import 收件服务**复用清洗与判定逻辑，
所以工具和服务端不会对同一条规则有两种理解。

## 先拿到「该回应什么」

```bash
python robot/feedback.py brief
```

一次给全上下文，**默认 JSON**（直接喂给你自己就行）：

| 字段 | 含义 |
| --- | --- |
| `counts` | `{total, pending, answered}` |
| `pending` | 待回应队列，**最久没人管的排最前** —— 若只处理一条，取 `[0]` |
| `answered` | 已答复的（含机器人的历次答复）。**读它，避免自相矛盾** |

`pending` 里每条都带 `detail` 与全部 `comments`，通常不需要再 `show`。

需要单独看一条：`python robot/feedback.py show F-003`。

## 写一条答复

```bash
python robot/feedback.py reply F-003 --body "……"
python robot/feedback.py reply F-003 --file draft.md   # 长回复
```

**回帖前先用 `--dry-run` 看一眼**将要发出的内容，成本极低：

```bash
python robot/feedback.py reply F-003 --body "……" --dry-run
```

署名固定是「反馈机器人」（服务端决定，你传不了别的名字），并会自动追加一行
「这是一条由反馈机器人发布的公开答复」。客户端据此把它渲染成醒目的官方答复。

长回复用 `--file`。正文上限 4000 字符（服务端 `MAX_COMMENT`），工具会在本地先拦一次。

## 推进状态

```bash
python robot/feedback.py status F-003 done
```

| 状态 | 什么时候用 |
| --- | --- |
| `open` | 推进中（默认，一般不用手动设） |
| `done` | **已经实现并可用**了，不是"打算做" |
| `declined` | 明确不做，且**必须在回帖里说明理由** |

状态是给用户看的结论，**别用它代替答复**：先回帖讲清楚，再改状态。

## 怎么答复才算合格

这是唯一需要你判断的部分。用户能看到的只有你写的字。

**必须做到**

- **回应具体诉求**，不要复述一遍人家已经说过的话。
- **不确定就说不确定**。「这个要看能不能拿到 X，我下轮确认后回你」远好过编一个排期。
- **不要承诺你做不到的事**。你无法保证某个功能会被实现 —— 说清楚约束与代价，
  比给一个漂亮的日期诚实。
- **读 `answered`**。同一条下面已经答复过就接着往下说；不同需求之间口径要一致。
- **技术性拒绝要给替代方案**。例如"移动端这一轮不做，因为工作台定位是桌面本地环境"
  是合格的；"暂不考虑"不是。

**禁止**

- **不要编造**：没有的功能、不存在的编号、你查不到的排期、别处"已经在做"的假消息。
- **不要夹带身份信息**：不要写任何人的真名、学号、联系方式，也不要问用户要。
  收件端对这些字段**直接拒收**，公开日志里也不能出现。
- **不要假装是人**：署名就是「反馈机器人」，别写得像某个真人同学在回复。
- **不要为刷存在感而回**：若一条已被答复且没有新问题，不要重复回一遍。
  没有实质内容时说"这条已经答复过"就够了，或者干脆不动它。

**语气**：像一位了解这个项目、愿意把话说清楚的维护者。中文，简洁，不用敬语堆砌，
不用感叹号，不写"亲"。

## 一轮完整流程

```bash
python robot/feedback.py brief                      # 1. 看队列（JSON）
# 2. 对每条 pending：读需求与评论 → 想清楚 → 起草答复
python robot/feedback.py reply F-002 --file r.md --dry-run   # 3. 先看将发出什么
python robot/feedback.py reply F-002 --file r.md             # 4. 真发
python robot/feedback.py status F-002 done                   # 5. 只有确实做完了才改状态
python robot/feedback.py brief                      # 6. 确认它已从 pending 消失
```

第 6 步不是形式：答复成功后那条会落到 `answered`，这能证明你写的东西真的上去了。
若仍在 `pending`，说明回帖没成功（工具会以非零码退出并说明原因）。

## 不需要令牌

**回帖和推进状态都不需要任何凭证。** 拿到这份说明就能用：

> 谁想处理评论都可以 —— 任何人的 AI 都能接手。这是个 demo 级反馈板，
> 「谁都能来搭把手」比「防住冒充」重要，所以服务端那两条路径是公开的。
> 代价是任何人都能把别人的需求标成「不采纳」，这一点已知并接受。

## 数据可能丢

收件服务跑在免费实例上，`/mnt/workspace` 重启可能丢数据（已确认接受）。所以：

- 看到空社区**先别当成"没人提过"** —— 也可能是实例刚重启。工具连不上时会给明确的错误。
- 重要的结论不要只留在讨论串里，值得进仓库的要另外落地。
